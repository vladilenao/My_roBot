# Подключение Historical Broker API Emulator к экспорту My Robot

> Интерфейс реализован в My Robot в рамках change
> `durable-live-market-data-and-emulator-export`. Потребитель Historical
> Broker API Emulator должен быть реализован в его отдельном репозитории.

Контракт описан в [OpenAPI 3.0.3](openapi.yaml). При реализации My Robot
публикует его также по `/openapi.yaml` и предоставляет Swagger UI по `/docs`.
Ниже предполагается локальный адрес `http://127.0.0.1:<порт>`; порт задаётся
конфигурацией при реализации. Для доступа нужен отдельный токен экспорта.
В Swagger UI этот токен вводится через **Authorize** перед запросами данных.
Если приложения работают на разных машинах, используют TLS на внешней границе,
а не общий файл SQLite по сети.

## Порядок подключения

1. В `robot.toml` включить `[market_data] export_enabled = true`, а в
   окружении процесса задать `MARKET_DATA_EXPORT_TOKEN`. Запустить My Robot.
2. Запросить `GET /api/v1/market-data/source`. Сохранить `producer_id` и
   `min_after_id`. Если у этого `producer_id` уже есть сохранённый курсор,
   продолжить с него; новый потребитель начинает с `min_after_id`.
3. Запрашивать `GET /api/v1/market-data/changes` с `producer_id`, своим
   `after_id` и `limit`. Страница упорядочена по `change_id`.
4. Одной транзакцией эмулятора записать свечи, их версии, происхождение и
   состояния покрытия, обеспечить уникальность `(producer_id, change_id)` и
   сохранить локальный курсор `next_after_id`.
5. После commit отправить `PUT /api/v1/market-data/consumers/{consumer_id}/checkpoint`
   с тем же `producer_id` и последним сохранённым `change_id`.
6. Пока `has_more=true`, читать следующую страницу. При `has_more=false`
   повторять запрос позже или ждать очередного изменения по своему расписанию.

Пример получения источника:

```http
GET /api/v1/market-data/source HTTP/1.1
Host: 127.0.0.1:<порт>
Authorization: Bearer <токен>
```

Пример чтения после курсора 41:

```http
GET /api/v1/market-data/changes?producer_id=4b5f0d70-ef95-4929-b723-47030ec90165&after_id=41&limit=500 HTTP/1.1
Host: 127.0.0.1:<порт>
Authorization: Bearer <токен>
```

Пример подтверждения после сохранения ответа с `next_after_id=42`:

```http
PUT /api/v1/market-data/consumers/historical-emulator/checkpoint HTTP/1.1
Host: 127.0.0.1:<порт>
Authorization: Bearer <токен>
Content-Type: application/json

{"producer_id":"4b5f0d70-ef95-4929-b723-47030ec90165","change_id":42}
```

В коде потребителя сетевой вызов не должен выполняться внутри транзакции БД.
Подтверждение может быть повторено. Если страница записалась, но подтверждение
не дошло, та же страница придёт вновь; уникальный ключ уберёт дубли.

## Что именно переносить

`candle_upsert` содержит только **завершённую** версию свечи с ключом
`source + instrument_uid + interval + open_time_utc` и номером `revision`.
Новая версия старой свечи приходит как новое изменение с новым `change_id`.
`interval_status` фиксирует изменение покрытия; статус `pending` или
`unresolved` не превращается в вымышленную OHLCV-свечу.

Робот и эмулятор сохраняют происхождение данных. Эмулятор может отдельно
дозагружать у брокера дни, когда робот не работал. Данные независимой
дозагрузки и то, что реально видел робот, не следует молча смешивать в одной
версии исторического прогона.

## Ошибки и восстановление

| Ситуация | Действие потребителя |
| --- | --- |
| Сеть или сервер недоступны | Повторить с последнего **локально сохранённого** курсора; робот удерживает неподтверждённые изменения. |
| `401` | Проверить токен экспорта. |
| `409 PRODUCER_MISMATCH` | Локальная БД робота сменилась; не продолжать старый курсор, сверить архив и завести новую идентичность источника. |
| `410 CURSOR_EXPIRED` | Часть журнала больше недоступна; восстановить диапазон из независимого источника, пометить происхождение и только затем возобновить экспорт. |
| Повтор страницы | Безопасно повторить запись по уникальному `(producer_id, change_id)`. |
| Эмулятор остановлен надолго | Неподтверждённые изменения остаются в роботе; его локальный объём и отставание требуют наблюдения. |

Подтверждение курсора означает «страница долговечно сохранена у потребителя»,
а не «история рынка гарантированно полна». Полнота проверяется отдельно по
состояниям интервалов и независимым запросам брокера.
