# Стартовый обзор и живой анализ свечей

В текущем режиме робот сначала показывает **информационный обзор последней
доступной закрытой свечи каждого назначенного таймфрейма**. Это может быть свеча
предыдущей сессии: пятничная, если позже торгов не было, либо свеча выходной
сессии, если она была доступна у выбранного инструмента.

В обзоре указаны инструмент, таймфрейм, дата/время **закрытия** свечи с поясом,
время публикации, стратегии и профили, направление либо отсутствие сигнала,
краткие индикаторы и достаточность истории. Незавершённая свеча в расчёт не входит.
Если истории не хватает, диапазон последовательно расширяется с 30 до 960 дней;
по достижении предела показывается доступное/требуемое количество, а не фиктивный HOLD.
Неразрешённый пробел внутри требуемого прогрева явно отмечается.

## Обзор не является заявкой

BUY или SELL в стартовом обзоре не создаёт вход, добор, сигнальный выход или резерв.
После поступления нового закрытого бара робот рассчитывает новое решение и
проверяет текущую возможность отдельно. Поздно восстановленная старая свеча
обновляет контекст; подтверждённые сделки не переигрываются задним числом.

Каждый инструмент/ТФ обрабатывается независимо: доступный часовой SBER не ждёт
запаздывающую свечу другого инструмента, а 15m не ждёт публикацию 1h. Несколько
поступивших баров рассчитываются по времени; старые результаты обозначены как
исторический контекст, допуск возможен только для последней актуальной возможности.

## Что означают сообщения состояния

- **Рынок закрыт, ожидаем возобновления торгов** — применимое расписание подтверждает
  перерыв. Время открытия показывается, только когда оно известно.
- **Применимое расписание неизвестно** — календарь не получен либо не покрывает
  рассматриваемую дату. Это не доказательство закрытия биржи.
- **Ожидание свечи** — торговый интервал завершился, ожидается публикация.
- **Задержка данных** — исходный срок публикации завершённого интервала истёк.
- **Неполное покрытие** — в необходимом диапазоне есть реальная неразрешённая дыра.
- **Лимит API** — оба вида запросов ждут общего срока сброса брокера.
- **Данные актуальны** — условия соответствующей пары восстановлены; это не обещание
  наличия торгового сигнала.

Сообщение показывает последнюю полученную закрытую свечу и последний реально
выполненный анализ **раздельно**, с датами и поясом. Если анализа не было, его
время не выдумывается. При отсутствии успешных торговых тиков состояния и heartbeat
продолжают публиковаться. Переход состояния показывается сразу, одинаковое ожидание
повторяется не чаще `max(60, tick.timeout_secs)` секунд.

Закрытие рынка не скрывает недополученный последний интервал завершённой сессии:
состояние сессии и задержка данных независимы.

## Свежие данные и восстановление истории

Свежие запросы обслуживаются справедливой очередью пар всех ТФ. Старый пропуск
восстанавливается отдельным ограниченным бюджетом; пустой ответ не заменяет свежую
загрузку и не забирает все окна. Повтор той же дыры откладывается минимум на
`max(data_refresh_min_interval, tick.timeout_secs)`. Свечи и доказательства покрытия
хранятся отдельно от попыток recovery; перезапуск сохраняет паузу попытки.

Свежее окно включает последний ожидаемый закрытый бар целиком. Например, в
09:30 UTC часовой запрос захватывает свечу 08:00–09:00, а не отсекает её границей
08:30. Последний незавершённый источником бар закрытой сессии проверяется только
в своём диапазоне открытия–закрытия, без повторного чтения всей ночи.

Расписание применяется только к датам, которые оно действительно покрывает.
Полученные календарные доказательства позволяют переоценить прежние неразрешённые
перерывы. Пустой ответ сам по себе не подтверждает отсутствие сделок. Получение
новых свечей не продвигает исполнительный курсор через неизвестную минуту.

## Отдельный ценовой лимит входа

```toml
[trading.risk_limits]
max_entry_deviation_r = 0.25
```

Проверяется неблагоприятное движение от планового входа к текущей оценке рынка:

`max(0, direction × (current_price − entry)) / abs(entry − stop)`

`direction` равен +1 для BUY и −1 для SELL. Значение должно быть конечным и
неотрицательным. Ноль запрещает любое неблагоприятное отклонение. Движение точно
на границе допускается, благоприятное движение не отклоняет вход по этому правилу.

Пример BUY: вход 100, стоп 96, риск расстояния 4. Цена 101 соответствует 0.25R,
цена 101.2 — 0.30R и отклоняет вход при дефолте 0.25. Цена 99 благоприятна.
Гэп относительно предыдущей сессии сохраняется в диагностике и учитывается
пересчётом нового плана. Отсутствие актуальной завершённой базовой оценки цены
или неготовое исполнение открытых обязательств приводит к явному недопуску.

Это **отдельная проверка**: `max_slippage_r` продолжает ограничивать расчётные
издержки проскальзывания относительно денежного риска. Остальные проверки
экономики, размера позиции и общего риска выполняются дополнительно.

## Каналы уведомлений

Новые типы `startup_analysis` и `market_data_status` включены в консоль по умолчанию.
Явные пользовательские списки сохраняются. Если задан свой список, добавьте новые
имена для получения информационных сообщений:

```toml
[notifier.console]
events = ["startup_analysis", "market_data_status", "decision", "error", "heartbeat"]
```

Консоль показывает только значимые итоги обзора и короткие предупреждения о данных.
Чистый HOLD, обычное ожидание свечи и сообщение «данные актуальны» не печатаются
отдельно для каждой пары. Подробные поля доступны в событиях; Telegram показывает
их при явной подписке.

Telegram по умолчанию получает торговый lifecycle. Новые информационные типы можно
явно добавить к его списку `events`; они отправляются текстом, без создания карточки
сделки. Полный контракт полей — в [схемах событий](notification/event-schemas.md).

Исторический прогон сохраняет виртуальные часы, существующие границы диапазона
и порядок исполнения; ожидание живой сессии и эта проверка текущей цены к нему не
применяются.
