# Единый REST API робота

[robot-api.yaml](robot-api.yaml) — **проект** одного постоянно доступного API
My Robot. Новые маршруты ещё не реализованы. Сейчас экспорт рыночных данных
работает по [действующему контракту](../market-data/openapi.yaml). При переносе
экспорта на общий сервер его контракт и код нужно менять вместе: нельзя
показывать в работающем Swagger действия, которых сервер ещё не выполняет.

## Как UI будет им пользоваться

Это проект API третьего уровня зрелости по модели Ричардсона: ответ не только
содержит данные, но и подсказывает, **какие действия сейчас доступны и куда
обратиться**. Для представлений выбран формат Siren, в котором есть `links`
(куда перейти) и `actions` (что можно сделать и каким HTTP-методом).
Описание принципа: [модель Ричардсона](https://martinfowler.com/articles/richardsonMaturityModel.html),
[формат Siren](https://github.com/kevinswiber/siren).

1. UI запрашивает `GET /api/v1` и получает действие поиска инструмента.
2. UI отправляет введённый пользователем тикер или название в поиск.
3. В ответе приходит ссылка на карточку инструмента. UI открывает эту ссылку.
4. Если можно включить торговлю, карточка содержит действие `start-trading`.
   UI выполняет указанный там `PUT` по указанному там адресу, без тела запроса.
5. При включённой торговле карточка содержит действие `stop-trading`.
   UI выполняет указанный там `DELETE`, тоже без тела запроса.
6. После команды UI обновляет карточку или переходит по ссылке на состояние
   включения, чтобы показать пользователю результат.

Адрес ресурса выбирает сервер. UI не подставляет в него брокерский UID,
идентификатор стратегии, курсор базы или состояние торгового цикла. Тикер
используется как **текст для поиска**, а не как технический ключ команды.
Если сервер не предложил действие, UI не показывает соответствующую кнопку;
сервер в любом случае повторно проверяет право и возможность выполнить команду.

Выключение останавливает новые входы; уже отправленные заявки сверяются с
исполнениями, а незавершённые сделки продолжают сопровождаться. После
перезапуска робот восстанавливает их и продолжает управление позициями.
Пока идёт восстановление, API доступен и показывает `recovering`.

Для инструментов, которые были включены перед остановкой, ещё нужно решить
отдельный вопрос: возобновлять ли **новые входы** автоматически после
перезапуска или ждать новой команды UI. На сопровождение начатых сделок это
решение не влияет.

## Торговые настройки как объекты

Текущая программа читает `robot.toml` при запуске. Целевая модель переносит
торговые настройки в предметные объекты БД: инструмент, семейство фьючерсов,
привязки стратегий, профили фильтров и управления. TOML служит источником
для однократного переноса; последующие изменения UI работают с объектами
через API. Объектная модель, схема БД и примеры заполнения находятся в
[едином документе о торговых настройках](configuration-storage.md).

Изменения через API должны переживать перезапуск. Робот проверяет новую
версию торговой настройки до принятия команды и переключает её на границе
цикла. Открытая сделка сохраняет план и профиль управления, с которыми была
создана. Включение новых входов по конкретному инструменту — отдельная
команда от изменения его стратегии и параметров. API показывает эти объекты
в понятных пользователю названиях, без путей TOML и внутренних объектов Python.

## Что такое токен

Токен — это длинный секретный ключ, похожий на пароль. Приложение передаёт
его роботу в заголовке запроса: `Authorization: Bearer <секретный ключ>`.
Робот проверяет ключ и решает, можно ли выполнить запрос. Это **не токен
Т-Банка** и не идентификатор инструмента.

В проекте предусмотрены два разных ключа для одного API:

- `ControlToken` — ключ будущего UI: позволяет смотреть состояние и менять
  разрешение на новые сделки.
- `ExportToken` — ключ исторического эмулятора: позволяет получать рыночные
  данные и подтверждать их сохранение, но не управлять торговлей. Такой
  экспортный ключ уже существует в коде робота как
  `MARKET_DATA_EXPORT_TOKEN`; ключ для UI ещё не реализован.

Ключи не записываются в адрес запроса и не размещаются в OpenAPI-файле.
Кнопка **Authorize** в Swagger нужна только для ручной проверки API. В
обычном UI пользователь не должен каждый раз вводить этот технический ключ.

## Значения ссылок в ответах

Стандартные связи `self`, `up`, `item`, `first` и `next` описаны в
[реестре IANA](https://www.iana.org/assignments/link-relations). Следующие
связи относятся только к My Robot:

### rel-trading-activations

Коллекция инструментов, для которых торговля включена или меняет состояние.

### rel-trading-activation

Текущее разрешение на новые сделки с конкретным инструментом.

### rel-instrument

Карточка инструмента, к которому относится разрешение на торговлю.

### rel-market-data

Точка входа в поток рыночных изменений для эмулятора.
