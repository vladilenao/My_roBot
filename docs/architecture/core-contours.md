# Ядро и торговые контуры робота

> Целевая архитектура переходного периода. Это план, а не описание текущего
> кода: этапы П1–П7 реализуются отдельными change в OpenSpec. Подключение
> реального счёта описано отдельно и начинается после этого перехода.

Робот становится службой. **Ядро** запускается один раз, держит свечи и
данные свежими и само не торгует. Торговля идёт в **торговых контурах**,
которые запускаются по запросу через API отдельными процессами. Переход
делается без денег: сегодняшняя эмуляция и история переезжают в контуры, а
место для контура «Счёт» остаётся готовым.

**Торговый контур** — процесс, который ведёт один вид торговли: эмуляцию,
историю или счёт. Внутри контура работают стратегии, фильтры, TradeManager,
брокер и свой журнал. Слово «сессия» не используется: в коде оно уже занято
(`RunSession`, `MarketDataStreamSession`) и означает торговые сессии биржи.

| Что получим | Что не меняется | Чего здесь нет |
| --- | --- | --- |
| Один запуск робота. Эмуляция и прогоны истории включаются и выключаются командами API, в том числе параллельно. Привязки добавляются в эмуляцию и убираются из неё на ходу. | Стратегии, фильтры, TradeManager, симулятор, журнал SQLite, расчёты. Сделки эмуляции продолжаются после переезда. | Контура «Счёт». Он подключается, когда этот переход закончен. |

```mermaid
        A2 --> A3["Торговая часть<br/>_build_runtime: TradeManager, брокер, SQLite"]

        A4 --> A5["Один канал Telegram"]
    end
    subgraph NEXT["После перехода"]
        direction TB
        C["Ядро: работает всегда<br/>свечи, полосы, арбитр квот · календарь<br/>кластеры · паттерны · API управления"]
        C --> E["Контур «Эмуляция»<br/>процесс, свой канал"]
        C --> H["Контур «История»<br/>процесс, несколько сразу"]
        C -.-> S["Контур «Счёт»<br/>место готово"]
    end
    NOW -- разрезаем --> NEXT
```

Разрез проходит почти по готовому шву. Боевой запуск уже поднимает данные в
`_start_early_market_data` до выбора инструментов и до торговли. Ядро забирает
себе всё, что выше этого шва, а контуры всё, что ниже. Ядро и контуры — роли
процессов, а не разные программы: код один и бинарник один, каждый процесс
использует свою часть.

## 2. Известные паттерны в этой схеме

| Что у нас | Паттерн | Где так делают |
| --- | --- | --- |
| Ядро запускает контуры, следит за ними и поднимает упавшие | Supervisor, дерево надзора | Erlang/OTP, systemd, supervisord |
| Ядро пишет желаемое состояние с номером поколения, контур приводит себя к нему и сообщает применённое поколение | Желаемое и фактическое состояние, цикл согласования | Kubernetes: spec и status, generation и observedGeneration |
| API ядра управляет, контуры торгуют | Control plane и data plane | Kubernetes, сетевое оборудование |
| Каждый контур в своём процессе, падение одного не роняет другие | Bulkhead, переборки | М. Найгард, «Release It!» |
| Контур читает ленту `changes` и запоминает, докуда дочитал | Журнал событий с позициями потребителей | Kafka, CDC |
| Один источник рыночных данных кормит несколько стратегий | Feed handler и strategy engines | NautilusTrader, QuantConnect LEAN |

В одном месте выбран простой приём вместо эталонного: лента свечей читается
опросом SQLite, а не через шину сообщений (см. раздел 10).

## 4. Папки, конфиг, состояние

```text
robot/
├── robot-vX.Y.Z
├── robot.toml        # один конфиг на всё
├── .env
└── data/             # ядро
    ├── market-data.sqlite3
    ├── cluster-events.sqlite3
    ├── core.sqlite3  # желаемое, команды, пульс
    ├── robot.pid
    └── contours/
        ├── emulation/   # сюда переезжает сегодняшний журнал
        │   ├── trades.sqlite3
        │   ├── trade_event.csv
        │   ├── bot_debug.log
        │   ├── status.json
        │   └── robot.pid
        └── history/
            └── 20261024-101500/   # прогон 20261024-101500 (П7 ✓)
```

```toml
[core]
control_host = "127.0.0.1"
control_port = 8200
telegram_channel_env = "TELEGRAM_CHANNEL_ID"

[contours]
max_history_runs = 2      # одновременных прогонов (П7 ✓)

[contours.emulation]
telegram_channel_env = "TELEGRAM_CHANNEL_ID"
assignments = "all"       # стартовый состав, дальше через API
```

- В `.env` добавляется `ROBOT_CONTROL_TOKEN` — ключ ControlToken для API. Он
  сразу попадает в `secrets` логгера.
- Канал задаётся именем переменной из `.env`, а не самим id.
- У истории нет секции в конфиге: даты и привязки приходят в запросе.

### Кто пишет состояние

У каждого факта ровно один владелец, остальные только читают.

| Где | Что хранится | Пишет | Читает |
| --- | --- | --- | --- |
| `core.sqlite3` · `contours` | Желаемое: вид контура, должен ли работать, режим остановки, поколение | ядро | контур |
| `core.sqlite3` · `contour_members` | Желаемый состав: инструменты с карточками, `active`/`removed`, режим снятия (П5 ✓, решение владельца — единица состава инструмент) | ядро | контур |
| `core.sqlite3` · `contour_commands` | Журнал команд | ядро | API |
| `core.sqlite3` · `heartbeat` | Пульс ядра: pid, версия, удар раз в 5 с, `running`/`stopped` (П6 ✓) | ядро | контур |
| база контура · `contour_state` | Фактическое: применённое поколение, статусы привязок | контур | ядро |
| `contours/*/status.json` | Снимок для API, `schema_version`; `alive_at`, `core_link`, `exited_at` (П6 ✓) | контур | ядро |
| `core.sqlite3` · `history_runs` | Журнал прогонов истории: запрос, состояние, pid, итог, флаг стопа (П7 ✓) | ядро | API, прогон (свой флаг) |
| `contours/history/*/status.json` | Ход прогона: фаза, рыночное время, отказы, итог (П7 ✓) | прогон | ядро |

Контур никогда не пишет в `core.sqlite3`, ядро никогда не пишет в базу
контура. Переезд журнала эмуляции выполняется один раз и оставляет копию для
отката на прежнюю версию.

## 5. Как команда доходит до контура

```mermaid
flowchart LR
    U["Ты: «убери газ»"] --> K["Ядро<br/>ответ: поколение 7"]
    K --> D["Желаемое · core.sqlite3<br/>газ: убрать, no_entries · поколение 7"]
    D -. "читает на границе тика" .-> N["Контур<br/>применяет разницу"]
    N --> F["Фактическое · база контура<br/>поколение 7 применено · газ доживает"]
    F -. "ядро читает: 7 = 7" .-> K
```

- Команда выполнена, когда применённое поколение догнало желаемое.
- Повтор безопасен: после сбоя контур перечитывает желаемое и применяет его снова.
- «Газ убран» и «газ доживает одну сделку» — два разных факта у двух владельцев.
- Новая команда — новое поле желаемого состояния, а не новый механизм доставки.

## 6. API управления

С API 2.0 (`rework-contour-api`) у каждого контура свой ресурс: эмуляция —
`/api/v1/emulation`, прогоны истории — `/api/v1/history`; общая оболочка
`/api/v1/contours` из П1–П7 удалена. Ядро слушает только `127.0.0.1`. Ключ
передаётся только в заголовке `Authorization: Bearer`, ядро проверяет `Host` и
не отдаёт `CORS *`. Наружу желаемое, фактическое и поколение называются
`target`, `current` и `revision`; ревизия — заголовок `ETag`, `If-Match`
защищает от двух одновременных команд (`412`). Ответы несут `_links` и
`_actions`, ошибки — `application/problem+json`. Контракт —
[docs/api/openapi.yaml](../api/openapi.yaml), решения —
[docs/api/v2-decisions.md](../api/v2-decisions.md).

| Запрос | Что делает ядро |
| --- | --- |
| `GET /api/v1` | Точка входа: версия, состояние ядра, сводка эмуляции и истории, ссылки по правам ключа. |
| `GET /api/v1/core` | Состояние старта ядра (`starting`/`ready`/`retrying`/`failed`, П7 ✓), версия, пульс, готовность пар, запросы к брокеру за минуту (П6 ✓). |
| `GET /api/v1/emulation` | Эмуляция: `state`, `target`, `current`, `launch`, `process`, состав, `_actions`. |
| `PUT /api/v1/emulation/target` `{"mode": "on", "instruments": [...]}` | Запускает эмуляцию, если её нет; вторая не создаётся. До готовности ядра — `409 CORE_NOT_READY`. |
| `PUT /api/v1/emulation/target` `{"mode": "no_entries" \| "close_all"}` | Остановить весь контур. |
| `POST /api/v1/emulation/instruments` `{"instruments": ["NG-12.26"]}` | Добавить инструменты со всеми привязками: прогрев, обзор, торговля (П5 ✓). |
| `POST /api/v1/emulation/instruments/remove` `{"instruments": [...], "mode": "no_entries" \| "close_all"}` | Убрать инструменты пачкой: сделки доживают или закрываются; `no_entries` по умолчанию. |
| `GET /api/v1/emulation/log?tail=200` | Последние строки лога эмуляции. |
| `POST /api/v1/history` `{"from", "to", "pause", "instruments"}` | Прогон истории в очередь, `202` с `id` — именем папки прогона (П7 ✓). |
| `GET /api/v1/history`, `GET /api/v1/history/{id}` | Прогоны: идущие, ждущие и 20 последних, `limits` очереди; фильтры `?state=`, `?limit=`. |
| `POST /api/v1/history/{id}/stop` | Убрать из очереди или остановить с отчётом. |
| `GET /api/v1/history/{id}/report`, `…/log` | Итог из `report.json` и последние строки лога прогона. |

## 7. Жизнь контура и привязки

```mermaid
stateDiagram-v2
    [*] --> Запуск
    Запуск --> Догоняет: процесс поднят
    Догоняет --> Работает: свечи от checkpoint
    Работает --> БезВходов: stop no_entries
    Работает --> ЗакрываетВсё: stop close_all
    БезВходов --> Остановлен: последняя сделка закрыта
    ЗакрываетВсё --> Остановлен
    Работает --> Запуск: рестарт робота
```

```mermaid
stateDiagram-v2
    [*] --> Прогревается: add
    Прогревается --> Торгует
    Торгует --> Доживает: remove no_entries
    Торгует --> Закрывается: remove close_all
    Доживает --> Торгует: add снова
    Доживает --> Убрана: сделок нет

```

Состав меняется только между тиками. После рестарта контур поднимается в том
же состоянии и с тем же составом.

## 8. Как контур получает свечи

```mermaid
sequenceDiagram
    participant T as Т-Инвест
    participant C as Ядро
    participant M as market-data.sqlite3
    participant N as Контур
    T-->>C: закрытая свеча
    C->>M: свеча + строка в changes
    C->>M: готовность пары (pair_readiness)
    N->>M: снимок пар, затем changes_after(checkpoint)
    M-->>N: свечи, статусы интервалов, готовность
    N->>N: тик
    N->>M: отметки исполнения под contour_id, затем checkpoint
```

- Свечи, состояния интервалов и готовность пар пишет только ядро.
- **Исключение (П3.1, решение владельца):** контур пишет в рыночную базу свои
  отметки исполнения — закрепление входа, границу обработки, курсоры анализа —
  только под своим `contour_id`. Ядро читает их для удержания целостности:
  коррекция минуты, которую прошёл хотя бы один контур, останавливает UID.
- Кэш контура собирается снимком базы и дополняется лентой; в сеть за
  свечами контур не ходит, недостающую историю запрашивает у ядра.
- Готовность пары ядро публикует текущим состоянием в `pair_readiness`, а не
  событием: контракт `/changes` для внешних потребителей не меняется.
- Статусы интервалов идут в той же ленте: контур видит пропуски так же, как ядро.
- Checkpoint сохраняется после тика, идемпотентность журнала не даёт задвоить сделки.
- Контур читает короткими транзакциями, чтобы не раздувать файл `-wal`.
- Очистка ленты уже работает (`add-changes-retention`): строки старше
  `changes_retention_days` удаляются, но не дальше наименьшего подтверждённого
  курсора зарегистрированных потребителей. Каждый контур регистрируется под
  своим `contour_id` (курсор `contour-<вид>`, префикс закрыт для внешних
  потребителей); навсегда убранный контур снимается с регистрации.
- Контур позади удалённого края получает `410 CURSOR_EXPIRED` и догружает
  свечи из текущего состояния базы.

## 9. Рестарт

```mermaid
sequenceDiagram
    participant C as Ядро
    participant D as core.sqlite3
    participant N as Контур эмуляции
    participant G as Его канал
    C->>C: блокировка data/, полосы данных
    C->>D: что должно работать?
```

Ядро подхватывает работающий процесс контура только той же версии; иначе
просит его завершиться и запускает контур из нового бинарника (П6 ✓).

## 10. Нюансы

- **Изменение состава на ходу (П5 ✓).** Единица состава — инструмент со всеми
  привязками (решение владельца). На границе тика новый инструмент ждёт
  прогрева пар у ядра, затем проходит стартовый обзор без переигрывания
  истории; убранный доживает или закрывает сделки и выходит из цикла.
  Карточку контракта нового инструмента получает ядро.
- **Команда применяется не мгновенно (П4 ✓).** Базовый поток 1m гарантирует
  границу тика не реже раза в минуту.
- **Инструменты вне состава ядра (П5 ✓).** Ядро догревает пары, инструмент
  ждёт в `warming` не дольше `startup_wait_timeout_secs`. Инструменты без
  привязок в конфиге отклоняются `422`.
- **Спрос контура и пары ядра (П5 ✓).** Строки `contour_demand` раньше только
  копились, и ядро держало пары каждого когда-либо торговавшегося
  инструмента. Теперь контур заменяет спрос при запуске и удаляет строки
  вышедшего инструмента, а ядро снимает пару без спроса и обязательств
  через `[contours] demand_release_secs` (900 с).
- **Догон по старому курсору анализа (принято).** Возвращённый инструмент
  догоняет бары с сохранённого курсора, как после рестарта; входов по
  старым барам нет.
- **Ядро упало, контур жив (П6 ✓).** Конец stdin контур только отмечает в
  журнале. 30 с без пульса — запрет новых входов и доборов `core-lost`,
  сопровождение и неисполненные входы остаются; контур ждёт без срока
  (решение владельца). Пульс вернулся — запрет снят.
- **Тик без своего приёма данных (П3.1 ✓).** Сигнал «свеча готова» приходит из
  ленты ядра, правила опоздания свечей прежние.
- **Лента без шины сообщений (П3.1 ✓).** SQLite в режиме WAL даёт хранение, повтор
  и чтение несколькими процессами. При задержке — уведомление через Redis.
- **Закрыть всё в эмуляции (П4 ✓).** Выход на открытии следующего бара; `no_entries` снимает и неисполненные входы.
- **После рестарта ядра (П6 ✓, П7 ✓, решения владельца).** Ctrl+C
  останавливает и ядро, и контур, желаемое остаётся. Любой старт поднимает
  контур сам, когда ядро готово, если желаемое «работает» или остановка не
  дожила до `stopped`; отключение — `[contours] autostart = false`, не
  поднимать разово — `stop`. `POST` во время дожития `no_entries` —
  `409 STOPPING` (П4).
- **История — контур робота (П7 ✓, решения владельца).** Прогон — процесс
  `--contour history` в `data/contours/history/<дата-время>/`, одновременно не
  больше `max_history_runs`, остальные в очереди. Сверку импорта эмулятора
  делает робот по одной и передаёт снимок процессу; инструменты и свечи
  проверяет процесс прогона. История не зависит от ядра: свечи даёт эмулятор
  данных. Один конфиг: инструмент в истории и в эмуляции торгуется по одним
  привязкам. Ctrl+C останавливает прогоны с отчётом, очередь после рестарта
  не возобновляется; прогон, переживший `kill -9`, подхватывается по pid.
- **API раньше ядра (П7 ✓, решение владельца).** Робот стартует без
  параметров: API управления и очередь истории поднимаются до рыночной базы.
  Сбой старта ядра — повтор 30 с → 5 мин, без `TINKOFF_TOKEN` — без повтора;
  эмуляция до готовности — `409 CORE_NOT_READY`, экспорт —
  `503 MARKET_DATA_NOT_READY`. Без `ROBOT_CONTROL_TOKEN` робот не стартует.
- **Контур отдельным процессом (П3.2 ✓).** Ядро после выбора инструментов
  пишет `data/contours/emulation/launch.json` (состав, карточки контрактов,
  имя переменной канала Telegram, pid и версия ядра, `schema_version`) и
  запускает тот же бинарник с `--contour emulation`. Контур к брокеру не
  ходит: карточки контрактов запрашивает ядро своим арбитром. Календарь —
  расписание из рыночной базы без сети; `cluster-events.sqlite3` — только
  чтение, читатель Redis остаётся у ядра.
- **Потребности строками в базе (П3.2 ✓, решение владельца).** Спрос пар и
  глубины истории — `contour_demand`, обязательства незавершённых сделок —
  `contour_obligations`, обе под `contour_id`; ядро опрашивает их раз в
  `[contours] feed_poll_secs` и объединяет по контурам. Строки
  остановленного контура продолжают удерживать целостность.
- **Жизнь процесса (П3.2 ✓, П6 ✓).** Канал stdin: `stop` — остановка после
  тика. Ядро при остановке пишет пульс `stopped`, шлёт `stop`, ждёт до 30 с,
  затем завершает принудительно. Упавший контур — `failed` в API, до
  следующего старта ядра сам не перезапускается. С П6 признак жизни ядра —
  пульс, а не stdin: конец потока контур не останавливает.
- **Переезд журнала (П3.2 ✓).** Журнал эмуляции один раз копируется из `data/`
  в папку контура (SQLite — через backup), `migrated-from.json` фиксирует
  откуда и когда; файлы в `data/` остаются для отката на прежнюю версию.
- **Консоль больше не спрашивает (П1, П7 ✓).** Меню и параметры режима
  убраны: эмуляция и история — только командами API.
- **Обновление версии (П6 ✓).** Остановить всё (Ctrl+C), новая версия
  поднимает контуры. Живой контур старой версии видит пульс чужой версии и
  выходит после тика.
- **Ядро делает много (принято).** При падении ядро перезапускается.

## 11. Осознанно отложено

- **Новые привязки без рестарта** — перенос настроек в базу, ветка `feature/experiment`.
- **Разные версии ядра и контуров** — протокол уже несёт `schema_version`.
- **Приём данных отдельным процессом** — риск принят.
- **Отдельные Telegram-боты** — перед подключением счёта.
