# Proposal: Разделение привязок стратегий по классам инструментов (SHARE_STRATEGIES / FUTURE_STRATEGIES)

## Why

Единственный словарь `STRATEGY_ASSIGNMENTS` требует указывать конкретные контракты фьючерсов (`"NGU6"`), которые умирают при экспирации. После каждого роллирования приходится править конфигурацию и заново выбирать контракт — постоянное ручное сопровождение ради одной и той же привязки «природный газ → стратегия». Привязка на уровне базового актива делает конфигурацию бессрочной.

## What Changes

- **BREAKING**: словарь `STRATEGY_ASSIGNMENTS` удаляется и заменяется двумя:
  - `SHARE_STRATEGIES: dict[str, list[StrategyName]]` — акции (и прочие нефьючерсные инструменты), ключ — точный тикер;
  - `FUTURE_STRATEGIES: dict[str, list[StrategyName]]` — фьючерсы, ключ — двухбуквенный код базового актива в верхнем регистре (`"NG"`), без привязки к конкретному контракту.
- В `run_bot` lookup привязок диспетчеризируется по `instrument_type`: для `future` база выводится из тикера контракта как `ticker[:2].upper()` (`"NGU6"` → `"NG"`) и ищется в `FUTURE_STRATEGIES`; для остальных инструментов — точный тикер в `SHARE_STRATEGIES`.
- Семантика пропуска сохраняется: инструмент без привязки или с пустым списком стратегий пропускается с записью в лог.
- Fail-fast валидация имён стратегий против реестра до старта цикла распространяется на оба словаря; аннотация значений `StrategyName` (подсказки IDE) сохраняется для обоих.
- Логика интерактивного выбора инструментов (`select_instruments`) НЕ меняется: пользователь по-прежнему выбирает конкретные контракты; меняется только то, как выбранный контракт сопоставляется с привязками стратегий.

Вне scope (намеренно не решаются): автоматический перевыбор контракта при роллировании, прогрев индикаторов на новом контракте, формат лейблов уведомлений, порог ликвидности при выборе ближайшего контракта.

## Capabilities

### New Capabilities

_(нет)_

### Modified Capabilities

- `configuration`: требование «Параметры стратегии» — вместо `STRATEGY_ASSIGNMENTS` предоставляются `SLEEP_SECONDS`, `TIMEFRAME`, `SHARE_STRATEGIES` и `FUTURE_STRATEGIES` (базовый актив → стратегии).
- `orchestration`: требование «Бесконечный цикл бота» — набор стратегий определяется диспетчеризацией между двумя словарями по типу инструмента; для фьючерсов ключом служит база `ticker[:2].upper()`; валидируются оба словаря.
- `strategy-contract`: требования «Привязка инструментов к стратегиям» и «Статический перечень имён стратегий» — привязка «многие ко многим» описывается двумя словарями (точный тикер для акций, базовый актив для фьючерсов); оба аннотируются `dict[str, list[StrategyName]]` и валидируются против реестра до старта цикла.

## Impact

- **Код**: `src/config.py` (замена словаря), `src/scheduler/runner.py` (lookup + валидация двух словарей), `src/strategies/__init__.py` (`validate_assignments` — проверка обоих словарей).
- **Тесты**: `tests/unit/test_runner.py` и тесты валидации переходят на новые фикстуры (контрактные тикеры → пары «инструмент/база»); snapshot-тесты стратегий не затрагиваются (стратегии и их математика не меняются).
- **Спеки**: дельты для `configuration`, `orchestration`, `strategy-contract`.
- **Совместимость**: изменение breaking для конфигурации — после обновления старый `STRATEGY_ASSIGNMENTS` перестаёт читаться; пользовательский сценарий запуска (`run.py` → селектор → `run_bot`) внешне неизменен.
