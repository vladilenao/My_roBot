## Context

Мотивация — в `proposal.md`. `run_chain_preflight` в `src/history/preflight.py` сравнивает максимум хвоста с `CandleScheduler.previous_candle_start(segment.end)`. Фиксированный путь `_check_pair` требует `end - period`. Оба критерия требуют существования свечи в точке календарной сетки, хотя `CandleScheduler` занимается выравниванием времени, а не биржевым расписанием.

План цепочки уже поддерживает календарные границы внутри перерыва. Для NG-1.25 cutoff равен `2025-01-27 00:00 UTC`, а последний минутный бар перед ним — `2025-01-24 20:49 UTC`. Конец исследованного прогона `2025-03-15 12:00 UTC` также попадает в выходной. Предпроверка прогрева считает реальные закрытые бары; минутные данные для причинного выхода после cutoff проверяются отдельно.

Без торгового календаря нельзя доказать, что пауза является выходным, а не потерей данных. Наличие соседних свечей позволяет доказать лишь продолжение источника через ограниченный разрыв. Это согласуется с действующим правилом: внутренние разрывы показываются, но сами по себе не блокируют прогон.

Похожая ошибка есть на левой границе. Сдвиг начала в `_check_pair`/`run_chain_preflight` вычисляется по каждому таймфрейму: `first > segment.start` для старшего ТФ добавляется в общий `shifted`, а `_align_up` округляет его по **самому старшему** периоду. Дневной бар, открывшийся в `00:00` до начала `12:00`, в фильтре `times >= segment.start` не попадает в рабочие и переносит начало на следующие сутки. После пересборки сдвиг повторяется по минутному потоку, повтор в `_run_history` исчерпывается, и `_launch` возвращает `3` до старта торговли (`run.py:425-427`). Старшие таймфреймы задают контекст по закрытым барам и не должны двигать общий старт.

## Goals / Non-Goals

**Goals:**
- Единый проверяемый критерий правой границы для chain/fixed/mixed, различающий ограниченный разрыв и неподтверждённый конец истории.
- Начало диапазона определяется драйверным (наименьшим активным) таймфреймом; старшие таймфреймы проверяются по прогреву и правой границе и не переносят старт.
- Сдвиг левого начала сходится за один повтор и не возвращает служебный код `3` на втором проходе.
- Передавать доказательство конечного разрыва из предпроверки в runtime и отчёт без попадания будущих данных в торговый конвейер.
- Сохранить отдельные гарантии прогрева, выбранного контракта и причинного исполнения.

**Non-Goals:**
- Биржевой календарь, классификация праздников и восстановление утраченных свечей.
- Изменение `CandleScheduler`, интерпретации полуночной экспирации, `contract_deadline` или календарного плана.
- Смена контракта по доступности/ликвидности и перенос свечей между выпусками.
- Переработка финансовых метаданных или HTTP API эмулятора.
- Синтез баров старших таймфреймов и подмена прогрева старших фильтров минутными данными.

## Decisions

### 1. Проверять данные, а не превращать сетку в расписание

Выделить общий helper правой границы в `src/history/preflight.py`. Входы: идентичность пары, граница B, начало рабочего участка, загрузчик того же источника/снимка и доступная верхняя граница обращения. Номинальная точка `E = floor_tf(B) - period` остаётся достаточным быстрым критерием. Хвост читается в `[max(segment.start, B - LOOKAHEAD), B)` и нормализуется по UTC, сортировке, уникальности и точным границам запроса.

Если хвост доходит до E, проверка проходит без дополнительного запроса. Иначе:
1. Найти последний фактический бар L рабочего участка перед B; отсутствие L — отказ.
2. Найти первый бар R той же пары с открытием не раньше B в `[B, B + LOOKAHEAD)`, ограниченном известной границей обращения. Для автоматического контракта используется действующий deadline; бар в deadline или после него не подтверждает допустимое продолжение.
3. Проверить `R - (L + period) <= LOOKAHEAD`. Ограничение относится к разрыву целиком, а не допускает две семисуточные половины.
4. При успехе вернуть результат «подтверждён ограниченный разрыв на границе» с L, R, B, длительностью отсутствующей сетки и проверенными окнами. При пустом продолжении, превышении горизонта или ошибке чтения — отказ с причиной и фактическими пределами поиска.

Последний бар, найденный произвольно давно, не становится достаточным покрытием. Не вводить отдельную поблажку «суббота/воскресенье»: она не учитывает праздники/специальные сессии и скрывает отсутствие продолжения. Простое `expected_last = tail.max()` отвергнуто как тавтология.

### 2. Диагностические чтения отделены от причинного исполнения

Поиск R за концом диапазона разрешён исключительно предпроверке. Загрузчик использует тот же `instrument_id` и закреплённый снимок, что рабочие запросы; текущие helper-ы подсказок, которые глотают ошибки и передают `instrument_id=None`, нельзя использовать без адаптации. Для fixed-пути использовать его устойчивую идентичность из штатного разрешения инструмента.

В результат попадут только метки времени и статус проверки, а не OHLCV будущей свечи. Эти диагностические кадры не передавать в кэш стратегий, исполнительный курсор или обработку сигналов. Использование будущего наличия данных ограничено решением о возможности прогона; план цепочки и торговые решения от R не зависят.

Прогрев каждого chain-контракта и проверка минутных выходов `[cutoff, min(deadline, end))` остаются самостоятельными обязательными условиями. Подтверждение хвоста на 1d не заменяет минутный выход. Данные нового выпуска не подтверждают хвост старого.

### 3. Структурированный результат проверки границ

Расширить `PreflightReport` обратно совместимым списком записей о правых границах. Запись содержит идентичность пары, роль границы (cutoff/конец диапазона), B, E, L, R при наличии, статус, проверенные пределы и длительность разрыва. Обычная покрытая граница тоже получает запись, чтобы runtime различал отсутствие сведений и успешную проверку. Сохранять записи при объединении fixed/chain результатов и повторе после сдвига начала.

Пользовательские сообщения используют короткие имена контрактов, например `NG-1.25 1m`. Формулировка — «перерыв на границе подтверждён соседними барами», а не «данные без потерь» или «биржевой выходной». Исходные B и конец прогона не сдвигаются назад к L. Статус относится только к проверенным данным на данном снимке.

### 4. Завершение внутри подтверждённого конечного перерыва

Передать записи через сборку в `run.py` в историческую сессию/поиск данных (`src/bot/run_session.py`) и отчёт. Если runtime обработал доступные бары `[start, end)`, достиг подтверждённого конечного перерыва всех требуемых минутных/драйверных пар и не имеет пропущенных промежуточных событий плана, он может довести виртуальное время до end без создания тика с фиктивной свечой. Все календарные события строго до end обрабатываются в обычном порядке; переход ровно на end не выполняется.

Такое завершение допустимо только при совпадении идентичностей, границы и снимка с предпроверкой. Обрыв раньше подтверждённого L, ошибка источника или неподтверждённая пара сохраняют неполный охват. Старшие ТФ не подменяют минутное доказательство. Открытые позиции и незавершённые переходы сохраняются в отчёте и не закрываются по R или выдуманной цене.

В текстовый и машинный отчёты добавить записи о границах, последний обработанный бар и отдельное основание «конец диапазона внутри подтверждённого перерыва». Счётчики отсутствующей сетки конечного перерыва считать по обычной минутной политике ровно один раз в пределах `[start, end)`; диагностический участок после end не включается. Достижение календарного конца при таких данных не объявляется доказательством отсутствия пропусков.

Альтернатива — только ослабить preflight — отвергнута: runtime иначе сразу выдаст исчерпание данных на последней пятничной свече и результат будет противоречить успешно проверенному субботнему концу.

### 5. Регрессии на сессионных данных

Добавить независимо заданные временные ряды рабочих дней и ночных пауз в unit-тесты; не генерировать ожидаемый хвост через сам helper. Пример NG воспроизводит понедельничные cutoff `2025-01-27 00:00`, `2025-02-24 00:00` и субботний конец `2025-03-15 12:00` с 1m/15m/1h/4h/1d. Проверять отсутствие ожидаемых воскресных баров и наличие реального продолжения.

Отрицательные кейсы: обрезанная история без R, пустой участок, слишком длинный разрыв, R другого UID/ТФ или за deadline, ошибка диагностического запроса, недостаточный прогрев и отсутствие минутного выхода. Integration-проверка использует будущую свечу с резко отличающейся ценой, чтобы выявить утечку в исполнение/PnL, а также охватывает конечный перерыв и смешанный выбор.

### 6. Начало диапазона задаёт драйверный таймфрейм

Наименьший активный таймфрейм (обычно `1m`) — единственный якорь левого начала. Требование «рабочий бар открылся в начале» и вычисление сдвига относятся только к нему. Старшие таймфреймы считаются валидными, если у них достаточно закрытых баров прогрева до начала (`times + period <= start`) и покрыта правая граница; бар старшего ТФ, открывшийся до начала и закрывающийся после него, ДОЛЖЕН приниматься как контекст и НЕ ДОЛЖЕН переносить старт. Отсутствие рабочего бара старшего ТФ внутри `[start, end)` само по себе не является отказом и не двигает начало.

Альтернатива — оставить перенос по старшему ТФ — отвергнута: на дневных данных начало в середине дня всегда переносится на следующие сутки, хотя минутный поток и прогрев корректны.

### 7. Сходимость сдвига левого начала

Сдвиг выравнивается по периоду драйверного таймфрейма, а не по самому старшему. Предлагаемое начало — первый доступный **драйверный** бар, без добавления `warmup_span`: прогрев загружается до начала и проверяется самостоятельным условием, а «плюс прогрев» может попасть в промежуток и снова сдвинуть начало. При таком сдвиге пересобранный прогон начинается ровно на существующем драйверном баре, поэтому повторная проверка не сдвигает начало и `_launch` не возвращает `3`. Повтор в `_run_history` остаётся ровно один.

Если после сдвига источник всё же не покрывает начало или прогрев, это обычный отказ предпроверки (код `2`), а не бесконечный сдвиг. Регрессия проверяет как исходный диапазон `2025-01-15 12:00`, так и отсутствие повторного сдвига/кода `3` на пересборке.

## Risks / Trade-offs

- [Соседние бары не доказывают отсутствие потерь внутри разрыва] → Явно показывать разрыв и метод проверки; не классифицировать его как гарантированно нерабочее время.
- [Источник заканчивается в выходной и не содержит R] → Консервативный отказ; недоказанный хвост не принимать по одному дню недели.
- [Дополнительные запросы] → Только для не покрытых номинальной сеткой границ, окна ограничены семью сутками, допустимо переиспользовать результаты запросов на том же снимке.
- [Будущая свеча влияет на торговлю] → Передавать только доказательство границы; отдельные проверки отсутствия будущих fills/сигналов и изменения PnL.
- [Перерывы учтены дважды или runtime перескочил cutoff] → Идемпотентный учёт конечного хвоста и обработка календарных событий перед достижением end.
- [Старший ТФ принимает начало внутри бара без «своего» рабочего бара] → Считать валидным закрытый прогрев до начала и контекст текущего старшего бара; отдельно проверять правую границу старшего ТФ.
- [Сдвиг по драйверу оставляет начало без прогрева] → Прогрев проверяется отдельно; недостаток закрытых баров остаётся отказом (код `2`), а не молчаливым сдвигом.
- [Старые отчёты не имеют новых полей] → Добавочные необязательные поля, чтение старых артефактов с отсутствующим подтверждением границ.

## Migration Plan

1. Добавить общий критерий и структурированные записи, подключить chain/fixed, сохранить проверки прогрева/выхода.
2. Передать подтверждение конечного перерыва в runtime и оба отчёта, покрыть причинность и календарные события.
3. Определить драйверный таймфрейм как якорь начала, убрать перенос старта старшими ТФ и выравнивание по самому старшему периоду.
4. Сделать сдвиг левого начала сходящимся за один повтор и исключить возврат кода `3` на пересборке.
5. Запустить целевые unit/integration-регрессии и обновить пользовательскую документацию.
6. Конфигурация, сохранённые сделки и эмулятор не требуют миграции. При откате к прежней версии возвращается строгая проверка хвоста и прежний сдвиг начала; сохранённые отчёты не удаляются.
