## MODIFIED Requirements

### Requirement: Состояние контура
Нормативный уровень: MUST. `GET /api/v1/contours` с ключом управления ДОЛЖЕН возвращать список контуров процесса, `GET /api/v1/contours/{id}` — один контур или `404`. В режиме эмуляции в списке ДОЛЖЕН быть ровно один контур с `id` и `kind`, равными `emulation`. Поля контура:

- **Общее состояние:** `waiting_command`, `starting`, `running`, `stopping_no_entries`, `stopping_close_all`, `stopped` или `failed`.
- **О запуске:**
  - источник запуска: `cli`, `menu` или `api`;
  - время запуска;
  - эквивалентная команда;
  - отказы последней команды, если она отклонена.
- **Текущий желаемый активный состав (`instruments`):** контракты коротким именем с днями до экспирации. После изменения состава командой поле ДОЛЖНО показывать новый состав, а не состав запуска.
- **Участники (`members`):** все инструменты желаемого состава. У каждого:
  - короткое имя и тип;
  - желаемое: `active` или `removed`;
  - режим снятия;
  - фактическое из `status.json`: `warming`, `trading`, `draining`, `closing` или `null`.
- **Желаемое (`desired`)** из `core.sqlite3`:
  - `running` — `true`, если контур должен работать;
  - `stop_mode`;
  - `generation`.
- **Фактическое (`actual`)** из `status.json` контура или `null`, если файла нет или он не читается:
  - состояние;
  - `applied_generation`;
  - `open_positions`;
  - `pending_entries`;
  - `last_tick_at`.
- **Процесс контура:** `pid`, пока процесс жив, и `exit_code` после завершения.

Общее состояние ДОЛЖНО определяться так:

1. **Процесс завершился:** `stopped` при коде 0, `failed` при другом коде. Если процесс в этом запуске ядра не создавался — `waiting_command`.
2. **Процесс жив, желаемое «остановлен»:** `stopping_<режим>`.
3. **Процесс жив, контур ещё ни разу не подтвердил курсор ленты в этом запуске:** `starting`.
4. **Иначе:** `running`.

После рестарта ядра контур ДОЛЖЕН показываться в `waiting_command` с прежним желаемым из `core.sqlite3`. Сам контур НЕ ДОЛЖЕН запускаться: автоподъём — следующий этап. Ответ НЕ ДОЛЖЕН содержать сделки, баланс и секреты.

#### Scenario: Торговля запущена параметрами
- **WHEN** робот запущен с `--mode emulation --instruments NG`, контур подтвердил курсор, а затем приходит `GET /api/v1/contours`
- **THEN** контур `emulation` в состоянии `running` с источником `cli`, контрактом NG, `desired.running = true` и `pid` процесса контура

#### Scenario: Последняя команда отклонена
- **WHEN** команда запуска получила `422`, а затем приходит `GET /api/v1/contours`
- **THEN** контур в состоянии `waiting_command` и содержит отказы последней команды

#### Scenario: Процесс контура упал
- **WHEN** процесс контура завершился с кодом 1, а затем приходит `GET /api/v1/contours`
- **THEN** контур в состоянии `failed`, `pid` — `null`, `exit_code` — 1

#### Scenario: Ядро перезапущено, желаемое — работает
- **GIVEN** до рестарта ядра контур работал с поколением 5
- **WHEN** ядро запущено снова с `--wait-command`, а затем приходит `GET /api/v1/contours`
- **THEN** контур в состоянии `waiting_command`, `desired.running = true`, `desired.generation = 5`, процесс не запущен

#### Scenario: Фактическое отстаёт от желаемого
- **GIVEN** контур работает с применённым поколением 3
- **WHEN** приходит команда остановки, а `GET` выполняется до следующей границы тика
- **THEN** `desired.generation = 4`, `actual.applied_generation = 3`, общее состояние `stopping_no_entries`

#### Scenario: Состав после изменения
- **GIVEN** эмуляция запущена с NG и SBER, затем добавлен BR и убран SBER с открытой позицией
- **WHEN** приходит `GET /api/v1/contours/emulation`
- **THEN** `instruments` содержит NG-12.26 и BR-12.26, а `members` — NG `active/trading`, BR `active/warming` и SBER `removed/no_entries/draining`

## ADDED Requirements

### Requirement: Состав контура командами
Нормативный уровень: MUST. `POST /api/v1/contours/{id}/instruments` ДОЛЖЕН менять состав работающего контура без его перезапуска. Тело содержит ровно одно из полей:

- **`{"add": [токены]}`** — токены ДОЛЖНЫ разрешаться по тем же правилам, что у запуска (`POST /api/v1/contours`), в главном потоке ядра. Карточку контракта ДОЛЖНО получать ядро. Отказ строгий: если хотя бы один токен отклонён, состав НЕ ДОЛЖЕН меняться (`422`).
- **`{"remove": [токены], "mode": "no_entries" | "close_all"}`** — токен ДОЛЖЕН сопоставляться с участниками контура: короткое имя контракта, тикер акции или код семейства, если в составе ровно один контракт этого семейства. Без `mode` ДОЛЖЕН применяться `no_entries`. Токен не из состава ДОЛЖЕН отклоняться `422`, состав не меняется.

Принятая команда ДОЛЖНА записывать изменение в таблицу `contour_members` базы `core.sqlite3` одной транзакцией и поднимать поколение контура один раз. Ответ — `202` с поколением и состоянием контура.

Повторы и переходы:

- **Повтор без изменений.** Если команда ничего не меняет — добавляется уже активный инструмент, повторно убирается с тем же режимом — ответ ДОЛЖЕН быть `200` с прежним поколением.
- **`close_all` поверх `no_entries`** у убираемого инструмента ДОЛЖЕН приниматься.
- **`no_entries` поверх `close_all`** ДОЛЖЕН отклоняться `409 MODE_CONFLICT`.
- **`add` убираемого инструмента** ДОЛЖЕН возвращать его в активный состав.

Остальные ответы:

- `409 NOT_RUNNING` — процесс контура не работает;
- `409 STOPPING` — контур выполняет остановку;
- `400` — неверное тело;
- `404` — неизвестный `id`;
- `202` без поколения — разрешение не уложилось в 60 секунд, итог виден в `GET`.

Запуск контура (`POST /api/v1/contours`) ДОЛЖЕН заменять желаемый состав составом запуска. Каждая команда состава ДОЛЖНА записываться в журнал команд.

#### Scenario: Добавить газ на ходу
- **GIVEN** эмуляция торгует SBER, поколение 1
- **WHEN** приходит `POST /api/v1/contours/emulation/instruments` с `{"add": ["NG"]}`
- **THEN** ответ `202` с поколением 2, в `contour_members` NG-12.26 `active` с карточкой контракта, SBER продолжает торговать

#### Scenario: Убрать Сбер без режима
- **WHEN** приходит `{"remove": ["SBER"]}`
- **THEN** SBER становится `removed` с режимом `no_entries`, ответ `202`

#### Scenario: Отклонённое добавление
- **WHEN** приходит `{"add": ["NG", "AFLT"]}`, а у AFLT нет привязок
- **THEN** ответ `422` называет AFLT, NG не добавляется, поколение не меняется

#### Scenario: Убрать то, чего нет
- **WHEN** приходит `{"remove": ["GAZP"]}`, а GAZP нет в составе
- **THEN** ответ `422`, состав не меняется

#### Scenario: Состав во время остановки контура
- **GIVEN** контур выполняет остановку `no_entries`
- **WHEN** приходит `{"add": ["NG"]}`
- **THEN** ответ `409 STOPPING`, состав не меняется

#### Scenario: Вернуть доживающий инструмент
- **GIVEN** SBER убран с `no_entries` и доживает позицию
- **WHEN** приходит `{"add": ["SBER"]}`
- **THEN** ответ `202` с новым поколением, SBER снова `active`
