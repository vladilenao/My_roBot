## MODIFIED Requirements

### Requirement: Включение локального API
Нормативный уровень: MUST.
Локальный HTTP API робота ДОЛЖЕН быть включён по умолчанию (`[market_data] export_enabled = true`) и запускаться в режиме эмуляции сразу после раннего сбора рыночных данных, до выбора инструментов, если в окружении задан хотя бы один из ключей: `MARKET_DATA_EXPORT_TOKEN` (экспорт и отчёт кластерного фильтра) или `ROBOT_CONTROL_TOKEN` (управление запуском). Маршруты, ключ которых не задан, ДОЛЖНЫ отвечать `401`. Без обоих ключей API НЕ ДОЛЖЕН запускаться, а робот ДОЛЖЕН продолжать работу. Для каждого незаданного ключа робот ДОЛЖЕН сообщать в консоли и логе, какая часть API недоступна; значения ключей НЕ ДОЛЖНЫ печататься. В историческом режиме API НЕ ДОЛЖЕН запускаться.

#### Scenario: Токен не задан
- **WHEN** `export_enabled = true`, а `MARKET_DATA_EXPORT_TOKEN` и `ROBOT_CONTROL_TOKEN` пусты
- **THEN** API не запускается, робот работает, в консоли — «Локальный API не запущен: в .env не задан MARKET_DATA_EXPORT_TOKEN» и сообщение о недоступном управлении

#### Scenario: Токен задан
- **WHEN** `MARKET_DATA_EXPORT_TOKEN` задан
- **THEN** `GET /docs` показывает Swagger UI по `docs/api/openapi.yaml`, а `GET /api/v1/clusters/report` с этим токеном отвечает 200

#### Scenario: Задан только ключ управления
- **WHEN** задан `ROBOT_CONTROL_TOKEN`, а `MARKET_DATA_EXPORT_TOKEN` пуст
- **THEN** API запускается, маршруты управления работают, экспорт и отчёт кластерного фильтра отвечают `401`, а в консоли — что экспорт недоступен без `MARKET_DATA_EXPORT_TOKEN`

#### Scenario: API доступен до выбора инструментов
- **WHEN** робот в режиме эмуляции ждёт выбора инструментов или команды запуска
- **THEN** `GET /docs` и маршруты с заданным ключом уже отвечают

### Requirement: Отчёт кластерного фильтра за день или период
Нормативный уровень: MUST.
Локальный HTTP-сервер робота ДОЛЖЕН отдавать `GET /api/v1/clusters/report` по контракту тега `Кластеры` в `docs/api/openapi.yaml`, с той же авторизацией и тем же выключателем, что экспорт рыночных данных. Параметры: `date` (обязательный, последний день периода) и `period` (длина в календарных днях, по умолчанию 1, от 1 до 366). Период — МСК-даты закрытия бара сигнала с `date − period + 1` по `date` включительно.

Ответ (`application/hal+json`) ДОЛЖЕН содержать:
- `period`, режим фильтра (`mixed`, если у привязок в периоде режимы различались), время формирования, горизонты 15 и 60 минут;
- группы по вердикту с числом сигналов, числом ставших сделкой, их чистым итогом, числом прибыльных и убыточных, статистикой движения цены по каждому горизонту (число наступивших, среднее, медиана, доля движений в сторону сигнала);
- `veto_effect` по вердиктам `veto_strong` и `veto`: сколько сделок убрал бы запрет, сколько из них прибыльных и убыточных, их итоги и чистый эффект (минус итог убранных сделок);
- список всех сигналов периода по возрастанию времени с вердиктом, причиной, тем же текстом, что в консоли, сделкой (или `null`) и движением цены по горизонтам со статусом `pending`, `final` или `no_data`;
- `_links.self`, `_links.previous` (период той же длины перед ним) и `_links.next` (после него), если следующий период не целиком в будущем.

Сигналы периода ДОЛЖНЫ браться из трасс `filter.cluster`, сделки — по `signal_id`, движение цены — `s · ln(close_at(T + h) / close_at(T)) · 10 000` б.п. по 1m свечам локального журнала. Отчёт НЕ ДОЛЖЕН менять состояние робота.

#### Scenario: Отчёт за день
- **WHEN** `GET /api/v1/clusters/report?date=2026-10-15` и в этот день был теневой `veto` по BR-11.26 SELL, ставший сделкой с итогом −1 455,94 ₽
- **THEN** группа `veto` содержит 1 сигнал и 1 сделку с итогом −1 455,94 ₽, `veto_effect.net_effect` = +1 455,94 ₽, список содержит этот сигнал с движением −39,11 б.п. через 15 минут и −74,27 б.п. через 60 минут

#### Scenario: Период из нескольких дней
- **WHEN** `date=2026-11-05&period=22`
- **THEN** отчёт охватывает 15.10–05.11, `_links.previous` ведёт на `date=2026-10-14&period=22`

#### Scenario: Горизонт не наступил
- **WHEN** сигнал закрылся 20 минут назад
- **THEN** у него движение через 15 минут `final`, через 60 минут `pending`, в статистике горизонта 60 минут он не учитывается

#### Scenario: Сигналов нет
- **WHEN** за период нет трасс `filter.cluster`
- **THEN** ответ 200 с пустыми группами и списком, а не 404

#### Scenario: Неверный период
- **WHEN** `period=0` или `date` позже сегодняшнего дня
- **THEN** ответ 400 с кодом ошибки и причиной

#### Scenario: Без токена
- **WHEN** запрос без заголовка авторизации
- **THEN** ответ 401
