## MODIFIED Requirements

### Requirement: Версионированный внешний контракт
Нормативный уровень: MUST. My Robot ДОЛЖЕН предоставлять версионированный
HTTP API `/api/v1/market-data`, отдавать OpenAPI 3.0.3 контракт по
`GET /openapi.yaml` и предоставлять Swagger UI по `GET /docs`.
Контракт ДОЛЖЕН описывать все внешние запросы, ответы, авторизацию,
ошибки и примеры подключения потребителя. API ДОЛЖЕН сообщать постоянный
`producer_id` локальной базы и доступный диапазон курсора.

Контракт ДОЛЖЕН быть единым для всех HTTP-сервисов робота: файл
`docs/api/openapi.yaml`, по одному тегу на раздел (`Навигация`, `Ядро`,
`Эмуляция`, `История`, `Рыночные данные`, `Кластеры`, `Служебное`). `GET /openapi.yaml` ДОЛЖЕН отдавать именно этот файл.
Отдельные файлы контрактов HTTP-сервисов робота НЕ ДОЛЖНЫ создаваться.
Каждая схема ключа (`ExportToken`, `ControlToken`) ДОЛЖНА быть описана в
контракте отдельно, а маршрут ДОЛЖЕН ссылаться только на свою схему.

#### Scenario: Потребитель начинает подключение
- **WHEN** Historical Broker API Emulator запрашивает `GET /source`
- **THEN** он получает идентификатор производителя и допустимый диапазон курсора для последующих запросов

#### Scenario: Один контракт на все сервисы
- **WHEN** пользователь открывает `GET /docs`
- **THEN** Swagger UI показывает экспорт рыночных данных, отчёт кластерного фильтра, ядро, эмуляцию и историю из `docs/api/openapi.yaml`

#### Scenario: Ключ управления в Swagger
- **WHEN** пользователь открывает в Swagger UI маршрут `PUT /api/v1/emulation/target`
- **THEN** маршрут требует схему `ControlToken`, а не `ExportToken`

### Requirement: Внутренние потребители ленты
Нормативный уровень: MUST. Торговые контуры робота ДОЛЖНЫ читать ленту `changes` и подтверждать курсор через то же хранилище и те же правила, что внешние потребители: монотонное подтверждение, `CursorExpired` раньше `min_after_id`, `ProducerMismatch` при смене производителя. Контуры ДОЛЖНЫ делать это напрямую через рыночную базу, без HTTP. Курсоры контуров ДОЛЖНЫ удерживать очистку ленты так же, как курсоры внешних потребителей.

Идентификаторы с префиксом `contour-` ДОЛЖНЫ быть зарезервированы за контурами. Подтверждение через HTTP API с таким идентификатором ДОЛЖНО отклоняться ошибкой валидации. Внешний контракт `/changes` и состав изменений НЕ ДОЛЖНЫ меняться. Описание `consumer_id` в Swagger (`docs/api/openapi.yaml`) ДОЛЖНО называть зарезервированный префикс.

#### Scenario: Очистку держит курсор контура
- **GIVEN** внешний потребитель подтвердил 5000, а `contour-emulation` подтвердил 4200
- **WHEN** запускается очистка ленты старше `changes_retention_days`
- **THEN** изменения после 4200 не удаляются

#### Scenario: Внешний клиент занимает имя контура
- **WHEN** клиент вызывает `PUT /api/v1/market-data/consumers/contour-emulation/checkpoint`
- **THEN** API отвечает ошибкой валидации идентификатора, курсор контура не меняется
