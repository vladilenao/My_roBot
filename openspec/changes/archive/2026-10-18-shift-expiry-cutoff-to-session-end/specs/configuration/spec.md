## MODIFIED Requirements

### Requirement: Горизонт блокировки экспирации фьючерсов
Нормативный уровень: MUST.
Система ДОЛЖНА читать неотрицательное целое значение `contract_expiry_block_days` из секции `[trading]` файла `robot.toml` (или вшитого дефолта `default.toml`) — количество календарных суток до момента экспирации фьючерсного контракта, в течение которых вход в сделку запрещён, а существующие сделки закрываются. При отсутствии ключа применяется дефолт `2`. Система ДОЛЖНА также читать из `[trading]` неотрицательное целое `contract_expiry_close_before_end_min` — запас в минутах до конца последней торговой сессии, на который сдвигается рубеж экспирации из перерыва (futures-rollover, «Эффективный рубеж экспирации»); при отсутствии ключа применяется дефолт `20`, boolean, отрицательное или нецелое значение ДОЛЖНО завершать загрузку `ConfigError` с указанием файла и ключа. Недопустимое значение (отрицательное, нецелое, нечисловое) ДОЛЖНО завершать загрузку конфигурации `ConfigError` с указанием файла и ключа.

#### Scenario: Дефолтное значение
- **WHEN** ключ `contract_expiry_block_days` отсутствует в конфигурации
- **THEN** применяется порог `2` календарных суток

#### Scenario: Переопределение порога
- **WHEN** в секции `[trading]` задан `contract_expiry_block_days = 3`
- **THEN** порог блокировки и закрытия составляет `3` календарных суток

#### Scenario: Недопустимое значение
- **WHEN** ключ `contract_expiry_block_days` задан отрицательным числом или нецелым значением
- **THEN** загрузка конфигурации завершается `ConfigError` с указанием файла и ключа

#### Scenario: Запас до конца сессии по умолчанию
- **WHEN** ключ `contract_expiry_close_before_end_min` отсутствует
- **THEN** рубеж экспирации из перерыва сдвигается на конец последней сессии минус 20 минут

#### Scenario: Недопустимый запас
- **WHEN** `contract_expiry_close_before_end_min` задан отрицательным, дробным или boolean
- **THEN** загрузка конфигурации завершается `ConfigError` с указанием файла и ключа
