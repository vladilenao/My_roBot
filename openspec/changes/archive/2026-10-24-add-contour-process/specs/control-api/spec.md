## MODIFIED Requirements

### Requirement: Состояние контура
Нормативный уровень: MUST. `GET /api/v1/contours` с ключом управления ДОЛЖЕН возвращать список контуров процесса. В режиме эмуляции в списке ДОЛЖЕН быть ровно один контур с `id` и `kind`, равными `emulation`, и полями: состояние (`waiting_command`, `starting`, `running`, `stopped`, `failed`), источник запуска (`cli`, `menu`, `api`), выбранные контракты коротким именем с днями до экспирации, время запуска, эквивалентная команда, если последняя команда отклонена — её отказы, а также процесс контура: `pid` (пока процесс жив) и `exit_code` (после завершения). Состояние `starting` ДОЛЖНО держаться с запуска процесса до первого подтверждения курсора `contour-emulation`, затем — `running`. `stopped` — процесс завершился с кодом 0 по команде остановки, `failed` — с другим кодом или не запустился. Ответ НЕ ДОЛЖЕН содержать сделки, баланс и секреты.

#### Scenario: Торговля запущена параметрами
- **WHEN** робот запущен с `--mode emulation --instruments NG`, контур подтвердил курсор, а затем приходит `GET /api/v1/contours`
- **THEN** контур `emulation` в состоянии `running` с источником `cli`, контрактом NG и `pid` процесса контура

#### Scenario: Последняя команда отклонена
- **WHEN** команда запуска получила `422`, а затем приходит `GET /api/v1/contours`
- **THEN** контур в состоянии `waiting_command` и содержит отказы последней команды

#### Scenario: Процесс контура упал
- **WHEN** процесс контура завершился с кодом 1, а затем приходит `GET /api/v1/contours`
- **THEN** контур в состоянии `failed`, `pid` — `null`, `exit_code` — 1
