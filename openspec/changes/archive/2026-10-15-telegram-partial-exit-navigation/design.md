## Context

Кнопки корневой карточки Telegram хранятся в `telegram_delivery.sqlite3`, таблица `stages(namespace, trade_id, role, message_id)` с ключом `(namespace, trade_id, role)`: на одну роль — одна кнопка, новая запись той же роли заменяет `message_id`. Порядок кнопок — порядок первой записи роли (`rowid`).

Этап регистрируется в двух местах:

| Место | Что делает | Что пропускает |
|---|---|---|
| `TelegramChannel._deliver` (`src/notifier/telegram.py`) | после подтверждённого поста вызывает `add_stage`, если `event_role` — `ЦЕЛЬN`, `СТОП` или `Итог` | роль «Частичный выход» |
| `event_navigation` (`src/notifier/telegram_navigation.py`) | сохраняет роли поста в `operation_navigation` до HTTP | та же проверка — «Частичный выход» не сохраняется |
| `register_confirmed` / `descriptor` (`--telegram-retry`) | берёт роли из сохранённой навигации; заголовки распознаёт только у постов без неё (база v2) | пост с навигацией `{"roles": []}` |

Роль поста определяет `event_role` (`src/notifier/telegram_templates.py`): по исполнению с ключом `visual["event_key"]` в `visual["fills"]`, `REDUCE` → «Частичный выход». Терминальное исполнение (остаток 0, фаза `CLOSED`) всегда получает роль `Итог`.

Запись исполнения в визуальном снимке (`lifecycle_snapshot` в `src/trade_management/notification.py`) содержит `key`, `time`, `role`, `side`, `quantity`, `price`. Причина команды хранится в журнале (`outbox.payload_json` → `reason`) и в снимок не попадает. Русские подписи причин есть только в `src/trade_journal/export.py` (`REASON_LABELS`).

Наблюдение 15.10.2026, сделка `future-ed-ma:EDZ6:1h:2026-10-15T09:00:00:BUY`: `stages` = `{СТОП: 792}`, пост 793 «Частичный выход · подтверждено» сохранён с навигацией без ролей, последняя правка корня (операция 79) содержит одну кнопку `СТОП` → 792.

## Goals / Non-Goals

**Goals:**
- Корневая карточка ведёт на последний частичный выход отдельной кнопкой.
- Одно правило ролей навигации для доставки и восстановления.
- Пост частичного выхода объясняет причину по-русски.
- Карточку ED-12.26 можно исправить командой восстановления без повторной публикации.

**Non-Goals:**
- Кнопка на каждый частичный выход.
- Новые причины, новые подписи или изменение правил выхода профилей.
- Автоматическая правка клавиатур уже отправленных карточек при запуске.

## Decisions

### D1. Одна функция ролей навигации

Список ролей поста вычисляет только `event_navigation(event)`. `TelegramChannel._deliver` перестаёт повторять проверку `role.startswith("ЦЕЛЬ") or role in {...}` и регистрирует этапы по `event_navigation(event)["roles"]` — той же навигации, что уже сохранена в операцию до HTTP. Так доставка и восстановление не расходятся.

Допустимые роли этапа: `ЦЕЛЬN`, `СТОП`, `Частичный выход`, `Итог`. Для терминального исполнения по цели по-прежнему добавляется `ЦЕЛЬN` вместе с `Итог`.

*Альтернатива:* добавить «Частичный выход» в оба места отдельно. Отклонена: два списка уже один раз разошлись бы при следующем изменении.

### D2. Последний частичный выход

Роль одна — `Частичный выход`; `add_stage` заменяет `message_id`, кнопка ведёт на последний подтверждённый пост частичного выхода. Это повторяет поведение `СТОП` (последний перенос).

*Альтернатива:* нумерованные `Выход 1`, `Выход 2`, … Отклонена: профиль MA-облака снимает по одному контракту на каждом подходящем баре, и сделка на 10 контрактов дала бы до 9 кнопок. Все выходы и так перечислены в краткой истории корня.

Неполное исполнение заявки `REDUCE` (несколько execution) даёт несколько постов; кнопка ведёт на последний.

### D3. Причина в снимке и в посте

`lifecycle_snapshot` добавляет записи исполнения необязательное поле `reason` — значение `reason` команды из `outbox.payload_json` по `orders.command_id`, если оно есть. Схема снимка (`visual_schema`, `docs/notification/visual-snapshot.json`) получает необязательное текстовое поле `fills[].reason`; версия снимка остаётся `1`. Сохранённые снимки без поля проходят схему.

Русские подписи причин переносятся из `src/trade_journal/export.py` в общий модуль (например, `src/trade_journal/reasons.py`); журнал и Telegram импортируют один словарь. Набор подписей не меняется.

Шаблон поста частичного выхода добавляет строку `Причина: <подпись>` после строки «Продано: …». Причина без подписи в словаре или отсутствующая причина строку не порождает: сырой код (`ma10-or-cloud-partial-exit`) пользователю не показывается.

### D4. Восстановление для уже доставленных постов

`register_confirmed` дополняет роли, полученные из `descriptor`: если подтверждённый `sendPhoto`/`sendMessage` с ключом `…:post` имеет второй строкой заголовок `<b>Частичный выход · подтверждено</b>`, а роли `Частичный выход` в навигации нет, роль добавляется. Это известный сохранённый формат заголовка, что разрешено требованием «Восстановление кнопок доставленных сообщений». Сохранённая навигация не перезаписывается.

Порядок постов в `register_confirmed` — порядок операций, поэтому последний подтверждённый пост частичного выхода окажется в `stages`.

Восстановление ED-12.26 после внедрения:

```bash
python run.py --telegram-retry
```

с выбором подтверждённой публикации этой сделки; команда правит только клавиатуру через `editMessageReplyMarkup`.

## Risks / Trade-offs

- **Порядок кнопок.** Кнопка `Частичный выход` встаёт в порядке первой записи роли: у ED-12.26 — после `СТОП`. Сортировка кнопок не меняется.
- **Длина клавиатуры.** Плюс одна кнопка; по три в ряд (`markup`) карточка с тремя целями, стопом, частичным выходом и итогом занимает два ряда.
- **Неточность в истории.** До этого изменения уже отправленные карточки других сделок остаются без кнопки, пока не запущено восстановление; автоматической правки нет (Non-goal).
