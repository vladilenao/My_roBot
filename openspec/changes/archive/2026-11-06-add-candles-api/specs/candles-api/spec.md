## ADDED Requirements

### Requirement: Ряды свечей
Нормативный уровень: MUST. `GET /api/v1/candles` ДОЛЖЕН отдавать список рядов свечей, которые хранит рыночная база ядра: по одному элементу на пару «инструмент × таймфрейм» из состава базы любого происхождения, включая пары, которые больше не нужны (`previous`). Элемент ДОЛЖЕН содержать:

- `instrument` — короткое имя контракта или тикер акции;
- `instrument_type` — тип инструмента из состава базы;
- `timeframe` — таймфрейм ряда;
- `status` — `active` для пар текущего состава (`selected`, `obligation`) и `retired` для прошлых;
- `first_open_time` и `last_open_time` — время открытия первой и последней завершённой свечи, `null`, если завершённых свечей нет;
- `last_close` — цена закрытия последней завершённой свечи десятичной строкой или `null`;
- `readiness` — состояние готовности живой пары (`READY`, `GAP_HOLD`, …) или `null`, если пара не живая;
- `_links.self` — адрес свечей ряда.

Необязательный параметр `instrument` ДОЛЖЕН оставлять ряды одного инструмента по тем же правилам имени, что в требовании «Имя инструмента»; неизвестное имя — пустой список. Ряды ДОЛЖНЫ идти по инструменту, затем по длительности таймфрейма. Биржевой тикер контракта и `instrument_uid` НЕ ДОЛЖНЫ появляться в ответе.

#### Scenario: Ряды торгуемого контракта
- **GIVEN** в составе базы пары NG-12.26 `1m` и `15m` (`selected`) с готовностью `READY` и пара NG-11.26 `15m` (`previous`)
- **WHEN** приходит `GET /api/v1/candles?instrument=NG-12.26`
- **THEN** ответ `200` с двумя рядами NG-12.26 — `1m`, затем `15m` — со `status: active`, `readiness: READY` и ссылками `/api/v1/candles/NG-12.26/1m` и `/api/v1/candles/NG-12.26/15m`

#### Scenario: Прошлая пара
- **WHEN** приходит `GET /api/v1/candles` без параметров
- **THEN** в списке есть ряд NG-11.26 `15m` со `status: retired` и `readiness: null`

### Requirement: Свечи ряда за окно
Нормативный уровень: MUST. `GET /api/v1/candles/{instrument}/{timeframe}` ДОЛЖЕН отдавать свечи одного ряда, время открытия которых попадает в окно `[from, to)`. Параметры:

- `from` — начало окна, момент ISO 8601 с зоной; по умолчанию не ограничено;
- `to` — конец окна, не входит в окно; по умолчанию — текущий момент;
- `limit` — 1…5000, по умолчанию 500.

Ответ ДОЛЖЕН содержать последние `limit` свечей окна (ближайшие к `to`) по возрастанию времени открытия. Свеча — `open_time` (UTC), `open`, `high`, `low`, `close` десятичными строками, `volume` в лотах и `complete`. Ответ ДОЛЖЕН содержать `instrument`, `instrument_type`, `timeframe`, фактические `from` и `to` запроса и `_links`: `self`, `series` (список рядов этого инструмента) и `earlier` — только если в ряду есть свечи раньше первой отданной. `earlier` ДОЛЖЕН вести на тот же ряд с `to`, равным времени открытия первой отданной свечи, и тем же `limit`.

`from` не раньше `to`, момент без зоны или не в формате ISO 8601, `limit` вне диапазона и таймфрейм не из родных таймфреймов брокера (`1m`, `5m`, `15m`, `30m`, `1h`, `4h`, `1d`, `1w`, `1M`) ДОЛЖНЫ отклоняться `400 INVALID_REQUEST`.

#### Scenario: Последние свечи
- **GIVEN** в ряду NG-12.26 `15m` 2000 завершённых свечей
- **WHEN** приходит `GET /api/v1/candles/NG-12.26/15m`
- **THEN** ответ `200` с 500 последними свечами по возрастанию времени и ссылкой `earlier` на `/api/v1/candles/NG-12.26/15m?to=<время первой из 500>&limit=500`

#### Scenario: Листание до начала ряда
- **GIVEN** в ряду 700 свечей, UI получил последние 500
- **WHEN** UI переходит по `_links.earlier`
- **THEN** ответ содержит 200 первых свечей ряда, стыка без пропуска и повтора, ссылки `earlier` нет

#### Scenario: Окно без свечей
- **WHEN** окно `[from, to)` приходится на выходные без свечей
- **THEN** ответ `200` с пустым `candles`; ссылка `earlier` есть, если раньше `from` в ряду есть свечи

#### Scenario: Неверное окно
- **WHEN** приходит запрос с `from=2026-10-30T10:00:00Z&to=2026-10-30T09:00:00Z`
- **THEN** ответ `400` с `code = INVALID_REQUEST`

### Requirement: Незавершённая свеча
Нормативный уровень: MUST. Ответ ДОЛЖЕН включать не больше одной незавершённой свечи — последнюю строку ряда, если она незавершённая и открыта позже последней завершённой, с `complete: false`. Незавершённые строки внутри ряда, за которыми есть более поздние свечи, НЕ ДОЛЖНЫ отдаваться.

#### Scenario: Предварительной свечи нет
- **GIVEN** последняя строка ряда NG-12.26 `15m` — завершённая свеча 11:45
- **WHEN** UI запрашивает свечи с `to` по умолчанию
- **THEN** последняя свеча ответа — 11:45 с `complete: true`

#### Scenario: Свеча в процессе
- **GIVEN** последняя завершённая свеча `1m` — 12:13, в ряду есть предварительная 12:14
- **WHEN** UI запрашивает свечи `1m`
- **THEN** последняя свеча ответа — 12:14 с `complete: false`

#### Scenario: Брошенная предварительная свеча
- **GIVEN** в ряду предварительная свеча 10:05, за которой есть завершённые 10:06 и позже
- **THEN** свеча 10:05 в ответе отсутствует

### Requirement: Имя инструмента
Нормативный уровень: MUST. Имя инструмента в адресе и в параметре `instrument` ДОЛЖНО разрешаться по составу рыночной базы любого происхождения без учёта регистра: короткое имя контракта (`NG-12.26`) или тикер акции (`SBER`). В ответе имя ДОЛЖНО быть каноническим, как в составе базы. Биржевой тикер контракта и код семейства НЕ ДОЛЖНЫ приниматься.

На имя, которое не разрешилось, и на таймфрейм, которого у инструмента нет в составе базы, ответ ДОЛЖЕН быть `404 NOT_FOUND` с полем `suggestions` — списком подходящих коротких имён или имеющихся таймфреймов:

- биржевой тикер контракта — короткое имя этого контракта;
- код семейства — короткие имена хранимых контрактов семейства: сначала контракты текущего состава по возрастанию экспирации, затем прошлые — новые первыми;
- отсутствующий таймфрейм — таймфреймы инструмента в составе базы;
- неизвестное имя — пустой список.

Биржевой тикер НЕ ДОЛЖЕН появляться в `detail`, `suggestions` и любом другом поле ответа.

#### Scenario: Регистр
- **WHEN** приходит `GET /api/v1/candles/ng-12.26/15m`
- **THEN** ответ `200` с `instrument: NG-12.26`

#### Scenario: Код семейства
- **GIVEN** в составе базы контракты NG-11.26 и NG-12.26
- **WHEN** приходит `GET /api/v1/candles/NG/15m`
- **THEN** ответ `404` с `code = NOT_FOUND`, `detail` «Код семейства не принимается — укажите контракт» и `suggestions: ["NG-12.26", "NG-11.26"]`

#### Scenario: Биржевой тикер
- **WHEN** приходит `GET /api/v1/candles/NGZ6/15m`
- **THEN** ответ `404` с `suggestions: ["NG-12.26"]`, строки `NGZ6` в ответе нет

#### Scenario: Нет таймфрейма
- **GIVEN** у NG-12.26 в составе базы только `1m` и `15m`
- **WHEN** приходит `GET /api/v1/candles/NG-12.26/4h`
- **THEN** ответ `404` с `suggestions: ["1m", "15m"]`

### Requirement: Чтение свечей без влияния на ядро
Нормативный уровень: MUST. Ресурсы `/api/v1/candles…` ДОЛЖНЫ только читать рыночную базу ядра. Они НЕ ДОЛЖНЫ запрашивать брокера, записывать в базу, менять курсоры, покрытие, готовность пар и ленту экспорта `changes`, а также собирать свечи одного таймфрейма из другого. Пока ядро не открыло рыночную базу, ответ ДОЛЖЕН быть `503 MARKET_DATA_NOT_READY`.

#### Scenario: База не тронута
- **GIVEN** сняты курсоры, покрытие и последний `change_id` рыночной базы
- **WHEN** приходят сто запросов списка рядов и свечей
- **THEN** курсоры, покрытие и последний `change_id` не изменились, запросов к брокеру не было

#### Scenario: Ядро ещё не открыло базу
- **GIVEN** робот стартовал, ядро ещё не открыло рыночную базу
- **WHEN** приходит `GET /api/v1/candles/NG-12.26/15m` с ключом управления
- **THEN** ответ `503` в `application/problem+json` с `code = MARKET_DATA_NOT_READY` и подсказкой смотреть `GET /api/v1/core`
