## MODIFIED Requirements

### Requirement: Явная конфигурация управления сделками
Нормативный уровень: MUST.
Каждая привязка ДОЛЖНА иметь уникальный глобально непустой `id`, `name`, `management`, опциональные `filter` (basic_levels), `tf` (существующий каскад) и целый `priority` (0). Профили в `[trade_management.profiles.<имя>]` ДОЛЖНЫ ссылаться на один из четырёх типов и содержать валидируемые параметры стопов, целей, доборов и выхода. Профиль ДОЛЖЕН принимать параметры геометрии защитного стопа: `min_stop_atr`, `min_stop_ticks`, `stop_beyond_bar` и `max_stop_atr`. Значения геометрии ДОЛЖНЫ быть неотрицательными числами, `max_stop_atr` при заданном `min_stop_atr` ДОЛЖЕН быть не меньше `min_stop_atr`, а `min_stop_ticks` ДОЛЖЕН быть целым неотрицательным числом шагов цены. Профиль без явной геометрии ДОЛЖЕН получать действующие значения по умолчанию. Неизвестные ключи/имена, несовместимые ориентиры, повторные ID, нечисловые/нефинитные уровни, отрицательные отступы, некорректные доли или периоды ДОЛЖНЫ отклоняться до торгового цикла с указанием файла и ключа. Привязки с различным management разрешены при одинаковой стратегии, фильтре и ТФ.

Система ДОЛЖНА принимать минимальный риск сделки в процентах бюджета (`min_trade_risk_pct`): значение ДОЛЖНО быть неотрицательным числом, не превышающим лимит риска сделки; при отсутствии ключа применяется дефолт `0`, означающий отсутствие нижней границы. Неизвестный ключ геометрии, не поддерживаемый профилем, ДОЛЖЕН отклоняться с указанием файла и ключа, а не игнорироваться. Отсутствие поддерживаемых ключей геометрии не является неизвестным ключом и ДОЛЖНО приводить к применению дефолтов.

Круговые расходы ДОЛЖНЫ задаваться конфигурацией (`commission`, `slippage`) и ДОЛЖНЫ быть неотрицательными числами. Значения по умолчанию в поставляемой конфигурации ДОЛЖНЫ быть положительными: нулевые расходы допустимы только как явно выбранное значение пользователя, а расчёт безубытка, плановой доходности и отношения прибыли к риску на нулевых расходах не является поведением по умолчанию.

#### Scenario: Два профиля одной стратегии
- **WHEN** заданы две привязки macd_rsi_stoch на 15m с разными id и management
- **THEN** они создают независимые торговые планы и могут разделять расчёт входных сигналов

#### Scenario: Несовместимая формация
- **WHEN** pattern_targets назначен стратегии без заявленной поддержки ориентиров формации
- **THEN** загрузка завершается ConfigError до отправки заявок

#### Scenario: Профиль без геометрии стопа
- **WHEN** в `[trade_management.profiles.levels_rr]` не заданы `min_stop_atr`, `min_stop_ticks`, `stop_beyond_bar` и `max_stop_atr`
- **THEN** профиль загружается с действующими значениями геометрии по умолчанию

#### Scenario: Потолок волатильности ниже пола
- **WHEN** у профиля заданы `min_stop_atr = 3` и `max_stop_atr = 2`
- **THEN** загрузка завершается ConfigError с указанием файла и ключа `max_stop_atr`

#### Scenario: Дробное число шагов
- **WHEN** у профиля задан `min_stop_ticks = 2.5`
- **THEN** загрузка завершается ConfigError с указанием файла и ключа `min_stop_ticks`

#### Scenario: Минимальный риск больше лимита риска
- **WHEN** задан `min_trade_risk_pct = 5` при лимите риска сделки `risk_pct = 2`
- **THEN** загрузка завершается ConfigError с указанием файла и ключа `min_trade_risk_pct`

#### Scenario: Нулевые расходы по умолчанию запрещены
- **WHEN** конфигурация не задаёт `commission` и `slippage`
- **THEN** применяются положительные значения по умолчанию, а безубыток и плановые доходности считаются с расходами

#### Scenario: Отрицательные расходы
- **WHEN** задано `commission = -1.0`
- **THEN** загрузка завершается ConfigError с указанием файла и ключа `commission`
