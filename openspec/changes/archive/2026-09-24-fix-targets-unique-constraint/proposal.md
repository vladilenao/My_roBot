## Why

Вторая сделка в журнале не допускается: колонка `target_id` таблицы `targets` объявлена глобальным первичным ключом, а профили управления генерируют одинаковые короткие ярлыки `tp-1`/`tp-2` для каждой сделки. При открытии следующей сделки вставка целей падает с `UNIQUE constraint failed: targets.target_id`, допуск обрабатывается как исключение и в консоль уходит англоязычный текст ошибки. В БД физически может существовать только одна сделка — баг блокирует работу робота после первого входа.

## What Changes

- **Корень**: уникальность цели в `targets` становится составной `(trade_id, target_id)` вместо глобального `target_id PRIMARY KEY`; значения id целей не меняются.
- **Миграция схемы V6→V7** (`SCHEMA_VERSION = 7`): пересоздание таблицы `targets` с тем же порядком колонок и переносом существующих данных. Живая БД пользователя с одной сделкой мигрирует без потерь.
- **Русское сообщение об ошибке БД**: при `sqlite3.IntegrityError` в допуске сигнала причина `admission-error` получает описание «Ошибка на уровне БД: нарушение целостности данных»; полный traceback сохраняется в логах.
- **Тесты**: одновременное открытие двух сделок на разных связках; миграция v6→v7 с сохранением данных; русский текст ошибки БД.
- **Документация**: обновить `docs/database.md` (версия схемы 7, составной ключ).

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `trade-journal`: уникальность целей ограничивается рамками сделки — разные сделки могут использовать одинаковые короткие текстовые id целей (`tp-1`, `tp-2`).
- `trade-management`: причина недопуска `admission-error` для нарушения целостности БД имеет человекочитаемое русское описание.

## Impact

- `src/trade_journal/schema.py`: `SCHEMA_VERSION`, новый `MIGRATE_V6_TO_V7_SQL`, ветка `version == 6` в `initialize_schema`, изменение `CREATE TABLE targets`.
- `src/trade_management/manager.py`: except-ветка допуска — обработка `sqlite3.IntegrityError`.
- `docs/database.md`: версия схемы и описание `targets`.
- Тесты: миграция и сосуществование сделок (`tests/integration/`), русское сообщение (`tests/unit/trade_management/test_manager.py`).
- Существующие БД версии 6 (в т.ч. у пользователя) мигрируют; данные сделок, позиций и целей не теряются.
