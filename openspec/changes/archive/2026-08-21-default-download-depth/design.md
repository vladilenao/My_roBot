# Дизайн: дефолтная глубина скачивания = 300

## Context

`tools/download_snapshot_data.py` считает глубину как `calculate_depth(SIGNAL_WINDOW) = min(max(SIGNAL_WINDOW × 4, WARMUP_RESERVE=50), HARD_LIMIT=300)` → фактически всегда 50. Эталонные фикстуры в репозитории (коммит `2cb87aa`) скачаны на границе потолка 300 часов. См. proposal.md — Why.

## Goals / Non-Goals

**Goals:**
- Дефолтная глубина запроса = `HARD_LIMIT` (300) — воспроизводимость зафиксированных фикстур штатным скриптом.
- Убрать мёртвую сложность: формулу и зависимость глубины от конфига.

**Non-Goals:**
- CLI-флаг переопределения глубины (отклонено пользователем).
- Изменение потолка 300, пост-обрезки, guard'а и механизма эталонов.

## Decisions

- **D1. Константа вместо функции.** `calculate_depth()` и `WARMUP_RESERVE` удаляются; глубина = `HARD_LIMIT`. Альтернатива «дефолт 300 + флаг --depth» отклонена решением пользователя.
- **D2. `SIGNAL_WINDOW` остаётся импортированным.** Он по-прежнему нужен для `compute_expected_signals(df, SIGNAL_WINDOW)`; отвязана только глубина запроса.
- **D3. Guard сохраняется.** `len(df) > HARD_LIMIT → SystemExit` и `tail(limit)` не меняются: потолок остаётся неприкосновенным инвариантом.

## Risks / Trade-offs

- [Запрос 300 часов при каждом скачивании] → объём ограничен потолком ≤300 свечей на кейс; это и есть целевое поведение.
- [Повторное скачивание обновит существующие NG_1h/BR_1h свежими барами] → diff фикстур ревьюится коммитом; эталоны регенерируются тем же запуском скрипта.

## Migration Plan

Правка одного модуля; после неё — перекачка обоих кейсов штатным скриптом, полный pytest, коммит. Откат — revert коммита.
