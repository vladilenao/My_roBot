## ADDED Requirements

### Requirement: Решение-трейс остаётся в транзакции решения
Нормативный уровень: MUST.
Запись решения-трейса (расчёта допуска) ДОЛЖНА выполняться в той же транзакции SQLite, что и запись самого решения, и ДОЛЖНА завершаться вместе с ней. Решение-трейс ДОЛЖЕН НЕ публиковаться через шину событий и ДОЛЖЕН НЕ доставляться подписчикам: доставка не гарантирует атомарность, а аудит решения без полной записи бесполезен.

По той же причине обработка события исполнения, применение post-fill проверок и обновление проекций журнала ДОЛЖНЫ оставаться прямыми вызовами, а не доставкой подписчикам.

#### Scenario: Трейс атомарен с решением
- **WHEN** расчёт допуска завершается отказом по лимиту риска
- **THEN** запись решения-трейса присутствует в той же транзакции, что и запись отказа, и обе откатываются вместе

#### Scenario: Трейс не идёт через шину
- **WHEN** выполняется расчёт допуска
- **THEN** событие о расчёте не публикуется в шину событий

#### Scenario: Проверки после исполнения не через шину
- **WHEN** исполнение применено редьюсером
- **THEN** post-fill проверки выполняются прямым вызовой менеджера до любой доставки подписчикам

### Requirement: Сырой тикер не попадает в проекции журнала
Нормативный уровень: MUST.
Колонка контракта в `trade_event.csv`, `trade_summary.csv` и связанных пользовательских проекциях ДОЛЖНА содержать короткое имя контракта из карты `instrument_names`. Если для биржевого тикера короткое имя неизвестно, ДОЛЖНА выводиться фраза «контракт не указан»; биржевой тикер (`NGV6`/`BRV6`) как замена контракта ДОЛЖЕН НЕ использоваться. Сырой тикер ДОЛЖЕН оставаться только внутри `trade_id` во внутренних идентификаторах.

Передача карты имён в журнал ДОЛЖНА объединяться с ранее сохранённой картой: запуск робота с подмножеством инструментов ДОЛЖЕН НЕ обесценивать короткие имена контрактов, записанных предыдущими запусками.

#### Scenario: Неизвестное имя не превращается в тикер
- **WHEN** в `instrument_names` нет короткого имени для биржевого тикера
- **THEN** колонка контракта в `trade_event.csv` и `trade_summary.csv` содержит «контракт не указан», а не биржевой тикер

#### Scenario: Известное имя сохраняется при запуске с подмножеством инструментов
- **WHEN** для `NGV6` ранее сохранено имя `NG-10.26`, а текущий запуск передал только имя другого контракта
- **THEN** в проекциях журнала контракт по `NGV6` остаётся `NG-10.26`
