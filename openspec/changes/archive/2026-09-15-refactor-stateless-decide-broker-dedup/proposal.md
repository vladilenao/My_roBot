# Статeless decide + дедупликация входа в брокере

## Why

Сейчас одна стратегия на паре `(имя, таймфрейм)` живёт одним инстансом, а `decide()` у `ma_cloud_rsi_macd` — **с внутренним состоянием** (pending-сигналы, счётчики контрактов). Если инструменту назначить одну и ту же стратегию **дважды на одном ТФ с разными профилями фильтрации**, оба вызова `decide()` за тик приходят в общий инстанс: первый «съедает» состояние, второй видит HOLD. Именно так появилось расхождение сигналов на SI (5m, `raw` + `triple_screen`) между чистой и дублирующей привязкой. Сейчас физически невозможно сравнивать «один инструмент, один ТФ, разные фильтры» — ровно тот сценарий, который нужен для валидации фильтров.

Второй пробел: если оба фильтра на одном тике пропустят входящий сигнал, исполнение получит **два идентичных входа** в одну позицию.

## What Changes

- **MA Cloud RSI MACD становится «чистой»**: `decide(ta)` детерминированно восстанавливает своё внутреннее состояние реплеем из полной истории `ta`; повторные вызовы на одном инстансе с одинаковым `ta` дают одинаковый `Decision` (идемпотентность). Утечка состояния между привязками исключается самим дизайном.
- **`expected_events()`** переиспользует тот же реплей — snapshot-эталоны остаются валидными без перегенерации.
- **Контракт стратегий уточняется**: общий инстанс стратегии на паре `(имя, ТФ)` безопасен независимо от числа привязок; решение детерминировано накопительной историей; эквивалентность гарантируется для полной истории и префиксов от её начала, но не для произвольных обрезанных чанков.
- **Дедупликация входа в брокерском слое исполнения**: за один сигнальный бар допускается не более одного входящего ордера на пару (инструмент, таймфрейм); повторные входящие сигналы с тем же баром отклоняются с причиной `duplicate`.
- **Тесты**: идемпотентность `decide()`, сценарий «два профиля на одном ТФ» (обе привязки видят одинаковое решение), дедупликация в брокере (два прошедших фильтр входа → один ордер).

### Modified Capabilities
- `strategy-contract` — «Дубли стратегии с разными профилями» больше не полагается на разделяемый stateful инстанс: общий инстанс безопасен, т.к. `decide()` детерминирован историей. Сценарий «Эквивалентность чанка и полной истории» уточняется: равны полная история и префиксы от начала; произвольный чанк — вне контракта.
- `strategy/ma-cloud-rsi-macd` — добавляется требование детерминизма/идемпотентности `decide()` (реплей состояния из истории) и единого реплей-пути для `expected_events()`.
- `execution` — добавляется требование дедупликации входящих сигналов: не более одного входа на (инструмент, таймфрейм) за сигнальный бар; дубликаты отклоняются с причиной.

## Impact

- `src/strategies/ma_cloud_rsi_macd_strategy.py` — `decide()`/`expected_events()`/`_check_exit`/`_check_scale_in` переводятся на явный объект состояния и реплей из истории.
- `src/bot/trading_bot.py` — ключ кэша `(имя, ТФ)` сохраняется; разделяемый инстанс теперь безопасен, дополнительных правок анализа не требуется.
- Брокер исполнения — `src/broker/*` (`JournalBroker`) и `src/execution/port.py` (`BrokerExecutionPort`/адаптер) уже содержат торговое исполнение; дедупликация добавляется в этот слой. **Примечание**: на текущей ветке исходники брокера отсутствуют (только следы в `__pycache__`); реализация живёт на ветке `feature/deal-note` — при реализации потребуется перенести/объединить брокерский слой.
- `tests/unit/strategies/test_ma_cloud_rsi_macd.py` — ~13 тестов, инжектирующих приватное состояние, переписываются на шов «явление State» либо на историю, ведущую к нужному состоянию.
- `tests/snapshot/*` — эталоны `*_expected_signals.csv` **не перегенерируются**; они служат регрессионной сеткой рефакторинга.
- Новые тесты: `TestDecideIdempotence`, сценарий «два профиля на одном ТФ», `TestBrokerEntryDedup`.
