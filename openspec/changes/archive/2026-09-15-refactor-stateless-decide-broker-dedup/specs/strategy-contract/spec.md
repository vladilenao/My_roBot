# Контракт стратегий

## MODIFIED Requirements

### Requirement: Контракт Strategy
Каждая стратегия ДОЛЖНА (MUST) реализовать контракт: атрибуты `NAME` (уникальный идентификатор — ключ реестра и имя файла эталона) и `STRATEGY_WINDOW` (собственное окно агрегации); методы `compute(df)` — боевой расчёт сигнальных колонок поверх DataFrame свечей, `decide(ta)` — решение на последней свече, возвращающее `Decision` (`SignalType`, цена), `expected_events(ta)` — события BUY/SELL за всю историю для эталона snapshot-тестов, `required_history()` — минимальная глубина истории (окно + прогрев индикаторов стратегии). Стратегия ДОЛЖНА принимать `StrategyConfig` через конструктор. Конфиг ОБЯЗАТЕЛЕН — fallback на дефолты запрещён. Потребители ДОЛЖНЫ работать со стратегиями только через этот контракт.

`decide(ta)` ДОЛЖЕН получать накопительную историю: полный фрейм до текущей (последней) свечи, где `len(ta) - 1` — абсолютная позиция этой свечи, либо префикс этого фрейма от начала истории. Решение стратегии с внутренним состоянием (pending-сигналы, окна входа, счётчики контрактов) ДОЛЖНО быть детерминировано историей: одинаковый накопительный фрейм ДОЛЖЕН давать одинаковое решение независимо от числа привязок и инстансов, разделяющих одну пару (стратегия, таймфрейм); повторный вызов `decide(ta)` с тем же `ta` НЕ ДОЛЖЕН менять результат. Внутреннее состояние ДОЛЖНО восстанавливаться из переданной истории, а не переноситься между вызовами. Передача произвольного обрезанного чанка (не префикса от начала истории) — вне контракта: результат такого вызова не гарантируется. `expected_events(ta)` ДОЛЖЕН воспроизводить ту же семантику вызова `decide`, что и боевой цикл, покрывая весь объём `ta` накопительно, и НЕ ДОЛЖЕН менять состояние инстанса, для которого вызывается.

#### Scenario: Единый интерфейс для любой стратегии
- **WHEN** движок обрабатывает очередную стратегию из реестра
- **THEN** используются только методы контракта без проверок типа конкретной стратегии

#### Scenario: Окно принадлежит стратегии
- **WHEN** у стратегии задан `STRATEGY_WINDOW` через `StrategyConfig`
- **THEN** агрегация и `required_history()` рассчитываются от этого значения

#### Scenario: Стратегия принимает StrategyConfig
- **WHEN** создаётся `MacdRsiStochStrategy(config)`
- **THEN** параметры индикаторов и окно берутся из `config`, а не из хардкода

#### Scenario: Config обязателен
- **WHEN** создаётся `MacdRsiStochStrategy()` без параметров
- **THEN** выбрасывается `TypeError` (отсутствует обязательный аргумент config)

#### Scenario: Накопительная история для decide
- **WHEN** вызывается `decide(ta)` для стратегии с внутренним состоянием (например, `ma_cloud_rsi_macd`)
- **THEN** `bar_idx = len(ta) - 1` интерпретируется как абсолютная позиция; окно входа отсчитывается от неё

#### Scenario: Идемпотентность общего инстанса
- **WHEN** инстанс стратегии вызывается несколько раз за тик с одним и тем же накопительным `ta` (например, двумя привязками одного таймфрейма с разными профилями фильтрации)
- **THEN** каждый вызов возвращает одинаковый `Decision`; состояние «не съедается» и не переносится между вызовами

#### Scenario: Эквивалентность чанка и полной истории
- **WHEN** стратегия с внутренним состоянием вызывается с префиксом фрейма от начала истории до той же свечи и с полной историей
- **THEN** результат решения не отличается (окно отсчитывается от абсолютной позиции без сдвига)
- **AND** произвольный обрезанный чанк (не префикс от начала) находится вне контракта: результат такого вызова не гарантируется

### Requirement: Привязка инструментов к стратегиям
Конфигурация ДОЛЖНА (MUST) предоставлять два словаря привязок «многие ко многим»:
- `SHARE_STRATEGIES` — точный тикер нефьючерсного инструмента → список привязок;
- `FUTURE_STRATEGIES` — двухбуквенный код базового актива в верхнем регистре → список привязок; запись действует на любой контракт этого актива.

Привязка ДОЛЖНА содержать имя стратегии, профиль фильтрации (по умолчанию `"basic_levels"`) и таймфрейм (каскад: `tf` инлайн-записи → `timeframe` тикера → глобальный `TIMEFRAME`). Включение или выключение стратегии на инструменте ДОЛЖНО выполняться правкой конфигурации без изменения кода стратегий. Дублирование имени стратегии внутри одного инструмента ДОПУСТИМО при различных профилях фильтрации или различных таймфреймах; идентичность привязки — кортеж (инструмент, стратегия, профиль, таймфрейм). Имена стратегий и имена профилей фильтрации ДОЛЖНЫ валидироваться против соответствующих реестров до старта основного цикла; неизвестное имя ДОЛЖНО вызывать ошибку с перечнем неизвестных и доступных имён.

#### Scenario: Несколько стратегий на тикере
- **WHEN** инструменту назначены две стратегии и данные загружены
- **THEN** обе стратегии обрабатывают одни и те же свечи независимо друг от друга

#### Scenario: Фьючерсная привязка действует на любой контракт актива
- **WHEN** в `FUTURE_STRATEGIES` есть запись `"NG"`
- **THEN** любой контракт базового актива NG получает назначенные ей привязки без дополнительной настройки

#### Scenario: Тикер без привязки пропускается
- **WHEN** тикер отсутствует в словаре своего класса инструментов или его список пуст
- **THEN** запрос данных для него не выполняется, в лог пишется запись о пропуске

#### Scenario: Невалидная привязка останавливает запуск
- **WHEN** в любом из словарей `SHARE_STRATEGIES` или `FUTURE_STRATEGIES` указано имя незарегистрированной стратегии
- **THEN** выбрасывается ошибка с перечнем неизвестных и доступных имён; основной цикл не запускается

#### Scenario: Неизвестный профиль фильтрации останавливает запуск
- **WHEN** в любой привязке указано имя незарегистрированного профиля фильтрации
- **THEN** выбрасывается ошибка с перечнем неизвестных и доступных профилей; основной цикл не запускается

#### Scenario: Дубли стратегии с разными профилями
- **WHEN** инструменту назначена одна и та же стратегия дважды на одном таймфрейме с разными профилями фильтрации
- **THEN** обе привязки обрабатываются в цикле как независимые задачи, разделяющие инстанс стратегии; разделение инстанса безопасно — решение каждой привязки детерминировано накопительной историей и не зависит от других привязок

#### Scenario: Дубли стратегии на разных таймфреймах — разные инстансы
- **WHEN** инструменту назначена одна и та же стратегия на двух таймфреймах (например, `15m` и `1h`)
- **THEN** каждая привязка обрабатывается отдельным инстансом стратегии; внутреннее состояние (pending-сигналы, счётчики) между таймфреймами не смешивается
