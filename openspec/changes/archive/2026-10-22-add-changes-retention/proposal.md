## Why

Каждая запись или исправление свечи и каждое изменение состояния покрытия добавляют строку в таблицу `changes` базы `market-data.sqlite3`. Это лента для `GET /api/v1/market-data/changes`: Historical Broker API Emulator забирает по ней новое после своего курсора. Строки из ленты никогда не удаляются.

На копии рабочей базы от 19.10.2026 в ленте 1,39 млн строк за 8 дней (с 11.10 по 19.10), это 503 МБ из 1,34 ГБ файла, примерно 60 МБ в сутки. Таблица `consumer_checkpoints` пуста: ни один потребитель ни разу не подтвердил чтение. Сейчас лента копится впустую, а в будущей схеме «ядро + торговые узлы» её начнут читать узлы, и без правила хранения она станет главной причиной роста базы.

Механизм для удержанного диапазона в контракте уже есть: `GET /source` отдаёт `min_after_id`, курсор старше него получает `410 CURSOR_EXPIRED`, а эмулятор при `min_after_id > 0` отмечает импорт неполным. Не хватает самого удаления.

## What Changes

- Новая фоновая полоса хранения ленты в живом режиме. Она удаляет из начала ленты изменения старше `[market_data] changes_retention_days` суток (по умолчанию 7, `0` выключает), не дальше наименьшего подтверждённого курсора зарегистрированных потребителей ленты `/changes`.
- Удаление идёт порциями короткими транзакциями. Вместе с каждой порцией в той же транзакции поднимается `min_after_id` до последнего удалённого `change_id`.
- `max_change_id` в `GET /source` не опускается ниже `min_after_id`, даже если лента целиком очищена. Подтверждение потребителя после очистки остаётся корректным.
- Подтверждения ленты расписаний (`trading-schedules:*`) очистку ленты `/changes` не удерживают. Лента расписаний не меняется.
- Журнал: итог прохода очистки (сколько удалено, новый `min_after_id`) и потребитель, который удерживает очистку, с его отставанием.
- Файл базы автоматически не сжимается (`VACUUM` не запускается). Освобождённые страницы переиспользуются новыми записями.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `market-data-export`: правило хранения ленты `/changes` с удержанием по подтверждениям потребителей и подъёмом `min_after_id`.

## Impact

- `src/data/market_store.py`: `prune_changes`, `max_change_id` не ниже `min_after_id`.
- `src/data/lanes.py`: полоса `ChangesRetentionLane`.
- `src/data/ingestion_settings.py`: `changes_retention_days`.
- `run.py`: полоса хранения среди полос раннего сбора данных.
- `docs/market-data/live-ingestion.md`, `docs/openapi.yaml`: новый параметр и смысл `min_after_id`.
- Исторический режим не затронут: он не запускает полосы.
