## Context

См. proposal.md — Why. Механизм отображения времени с учётом смещения уже реализован в change `display-bar-time-local-tz` (`DecisionFormatter(tz_offset_hours)`, проводка через `get_notifier()`); данная правка лишь меняет конфигурационный дефолт `BAR_TIME_TZ_OFFSET_HOURS с 0 на 3 в src/config.py.

## Goals / Non-Goals

**Goals:**
- Чтобы по умолчанию бот показывал время бара в МСК (UTC+3).

**Non-Goals:**
- Не менять механизм форматирования и внутреннее UTC-значение `bar_time`.
- Не вводить чтение из `.env` (выбрано простое значение-дефолт; пользователь всегда в МСК).

## Decisions

### D1: Дефолт константы = 3 (МСК)
Установить `BAR_TIME_TZ_OFFSET_HOURS = 3` в `src/config.py`. Это одна строка; механизм уже использует её через `get_notifier()`, поэтому изменений в `src/notifier` не требуется.

Альтернативы:
- `os.getenv("BAR_TIME_TZ_OFFSET_HOURS", 3)` — гибче, но добавляет конфигурационный поверхностный слой без реальной потребности. Отклонено, пользователь всегда в МСК.
- Оставить `0` и править только `.env` — не работало, т.к. `os.getenv` для константы не было. Отклонено.

## Risks / Trade-offs

- [Значение жёсткое (не настраивается через env)] → Если понадобится другой пояс — однострочная правка константы. Приемлемо.
- [Конфликт с уже записанным сценарием «Нулевое смещение сохраняет UTC» в спеках] → Сценарий описывает поведение при `offset=0`, а не дефолт конфига; spec не меняется (skip_specs).

## Migration Plan

Правка уже применена в `src/config.py:40` (`= 3`). Для вступления в силу достаточно перезапустить бота (текущий процесс `run.py` читает код при старте). Rollback — вернуть значение `0`.
