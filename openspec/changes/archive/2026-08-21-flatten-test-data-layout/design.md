# Design: Плоская структура тестовых данных

## Context

Инфраструктура snapshot-тестов уже работает (смена `snapshot-tests` архивирована): скрипт скачивания, replay-тест, эталоны. Мотивация — см. proposal.md (Why). Текущее состояние: `tests/data/macd_rsi_stoch/NG_1h/{candles.csv, expected_signals.csv}`, тест сканирует подпапки своей стратегии, download-скрипт пишет в `tests/data/<strategy>/<case>/`.

Ограничения:
- Формула глубины глобальная (`SIGNAL_WINDOW` из `src.config`), потолок 300 — разрыв между стратегиями по требованиям к истории пока невозможен.
- Кейс один (`NG_1h`), миграция одноразовая и тривиальная.
- Главные спеки обеих capabilities только что синхронизированы со старой структурой — при архивации этой смены дельты MODIFIED их обновят.

## Goals / Non-Goals

**Goals:**
- Кейс = пара (инструмент, таймфрейм); шаринг свечей между стратегиями.
- Имя стратегии — только в имени файла эталона, без префиксов.
- Однообразие: правило наименования зафиксировано в спеках и контексте проекта.

**Non-Goals:**
- Механизмы нескольких `candles.csv` на кейс (суффиксы, маппинги) — не заводим; потолок 300 ограничивает проблему, при необходимости кейс перекачивается целиком.
- Изменение форматов CSV, логики расчёта сигналов, рабочего кода `src/**`.
- Внедрение готовых snapshot-фреймворков (syrupy и т.п.).

## Decisions

### D1. Связь «тест ↔ данные» — точное имя файла
Стратегия ищет `glob("data/*/<точное_имя>_expected_signals.csv")`: имя файла строится f-строкой из константы стратегии, а не wildcard-суффиксом. Это исключает коллизию имён-префиксов («macd_rsi_stoch» vs «rsi_stoch»). Альтернатива (скан всех CSV с парсингом имени) отклонена — избыточная логика там, где достаточно точного совпадения.

### D2. Один candles.csv на кейс, глубина — по самой голодной стратегии
Свечи общие; глубина выбирается при скачивании под все стратегии кейса (по умолчанию глобальная формула). Если будущей стратегии нужно больше истории — перезапуск download для этого кейса + штатная регенерация эталонов `--update-snapshots`. EMA-память индикаторов может слегка сдвинуть значения при удлинении истории — это легитимный повод для осознанной перегенерации, а не проблема. Альтернатива (разрешить суффиксированные файлы свечей) отложена как YAGNI.

### D3. Миграция = перенос + переименование, без обратной совместимости
`mv tests/data/macd_rsi_stoch/NG_1h tests/data/NG_1h` + rename эталона в `macd_rsi_stoch_expected_signals.csv`. Старая структура не поддерживается вовсе (кейс один, внешних потребителей нет). Прогон pytest после миграции — проверка эквивалентности (эталон не меняется, меняется только путь).

### D4. Скрипт скачивания: стратегия уходит в имя эталона
Параметр `--strategy` сохраняется (нужен для имени эталона), но перестаёт участвовать в пути. Кейс задаётся `--case` или дефолтом `<тикер>_<таймфрейм>`. Повторный запуск той же команды перезаписывает свой эталон и общий `candles.csv`, не трогая чужие эталоны кейса.

### D5. Правило фиксируется дважды: контракт + память проекта
Дельты MODIFIED обновят главные спеки при архивации (поведенческий контракт). Дополнительно короткий блок `context:` в `openspec/config.yaml` — чтобы правило попадало в поле зрения при создании любых будущих артефактов. Альтернатива (только спеки) отклонена: спеки читаются реже, чем контекст, а цель пользователя — именно однообразие вперёд.

## Risks / Trade-offs

- [Тихая опечатка в имени эталона делает кейс невидимым] → риск равен старому (кейс в чужой папке тоже был невидим); частично гасится сценарием «Изоляция стратегий» и ревью diff'а при добавлении кейса.
- [Чужой эталон случайно удалён/перезаписан скриптом] → скрипт пишет только файл своей стратегии и candles.csv; git diff виден до коммита.
- [Расхождение черновиков главных спек с дельтами при архивации] → синк дельт закрывает; пути в спеках обновятся за один прогон archive.

## Migration Plan

Аддитивно-переименовательная миграция внутри `tests/`: один `mv` + один rename + правка путей в двух файлах кода. Рабочий код и CI отсутствуют — риска простоя нет. Откат = обратный rename/mv.
