## Context

Полосы данных ядра (`MarketDataPoller`) — отдельные потоки: `live-market-data` (`IngestionWorker.step()`) и `market-data-<имя>` для `evidence`, `completeness`, `calendar`, `retention`. Каждый поток крутит цикл «шаг → пауза». Если шаг бросил исключение, цикл журналирует его и продолжает работу. Если шаг не вернулся, цикл молчит. Сводку «Полосы данных: запросы за минуту…» пишет `_log_status`, и вызывается он из цикла живой полосы. Поэтому 01.11 сводка пропала ровно тогда, когда завис этот поток.

## Goals / Non-Goals

**Goals:**
- Шаг полосы, который не вернулся за порог, виден в журнале, в консоли ядра и в `GET /api/v1/core`.
- В журнале есть стек зависшего потока, по нему можно найти причину.
- Сводка полос выходит, даже когда любая полоса зависла.

**Non-Goals:**
- Прерывать зависший поток, запускать замену или перезапускать ядро. Python-поток нельзя безопасно прервать, а замена при «оживании» старого потока даёт две живые полосы над одним владельцем. Решение владельца 02.11: только тревога, рестарт делает владелец.
- Уведомление в Telegram.
- Исправление самой причины зависания: она неизвестна, её ищем по стеку.

## Decisions

1. **Учёт шагов — в цикле полосы, не в самой полосе.** `_run_lane` и `_run_live_worker` обрамляют `step()` вызовами `watchdog.begin(name)` / `watchdog.end(name)` (через `try/finally`). Сами полосы и `IngestionWorker` не меняются. Пауза между шагами шагом не считается: длинный простой полосы полноты (`COMPLETENESS_IDLE`) тревогу не вызывает.
2. **Сторож — отдельный поток `market-data-watchdog`**, просыпается раз в `min(30 с, порог/4)`. Для каждой полосы, у которой текущий шаг идёт дольше порога, он один раз за этот шаг пишет WARNING и строку в консоль ядра. Когда шаг завершится, сторож пишет INFO «полоса … снова работает, шаг длился N с». Повторных тревог за один и тот же шаг нет.
3. **Стек.** `sys._current_frames()[ident]` → `traceback.format_stack`. Это только файлы, строки и исходный код, локальные переменные в стек не попадают. Текст стека проходит обычный форматтер журнала с маскированием секретов. В консоль уходит только короткая строка без стека.
4. **Сводка полос переезжает в сторож.** `_log_status` вызывается из потока сторожа с прежним периодом `lane_status_log_interval_secs`. В конец строки добавляются зависшие полосы: «зависли: live с 07:50:02». Без зависших строка не меняется, только ставится в журнал другим потоком.
5. **Снимок для API.** `watchdog.snapshot()` возвращает для каждой известной полосы `state` (`ok` или `stalled`), `step_started_at` (UTC, ISO с `Z`, или `null` между шагами) и `last_step_at` (время последнего завершённого шага или `null`). `LiveCore.core_snapshot` кладёт его в `lanes`. До `ready` и без независимых полос там пустой объект.
6. **Порог** — `market_data.lane_stall_timeout_secs`, по умолчанию 300 с. Это больше любого законного шага: прогрев с `wait=True` ждёт квоту не дольше минуты на чанк, RPC — 30 с. Значение должно быть конечным и положительным.

## Risks / Trade-offs

- [Законно долгий шаг (прогрев большого окна чанками) превысит порог] → в журнале будет WARNING и потом INFO «снова работает», работа не меняется. Если такое увидим, порог поднимается в конфиге.
- [`sys._current_frames` — служебный API CPython] → в сборке PyInstaller это тот же CPython 3.13. Если кадра потока нет, пишется тревога без стека.
- [Сторож сам может упасть] → его цикл ловит исключения шага проверки и продолжает работу, как остальные полосы.
