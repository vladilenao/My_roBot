## ADDED Requirements

### Requirement: Раздельная сборка ядра и торгового контура
Нормативный уровень: MUST. Сборка запуска ДОЛЖНА состоять из двух объектов. Ядро (в эмуляции) владеет рыночной базой, арбитром лимитов, календарём, кэшем свечей и планировщиком тиков, ранним сбором и полосами, приёмом свечей и потоком, локальным API, кластерным потоком и обработчиком паттернов. Торговый контур владеет каналами уведомлений и шиной событий, кластерным вердиктом, торговой частью (TradeManager, исполнение, журнал), оркестратором и отчётом исторического прогона.

Контур ДОЛЖЕН получать рыночные данные только через порт рыночных служб. В эмуляции порт реализует ядро, в историческом прогоне — историческая служба данных с эмулятором и виртуальными часами. Контур НЕ ДОЛЖЕН зависеть от того, какая реализация порта ему передана.

Потребности контура (инструменты исполнения, их алиасы, обязательства незавершённых сделок, запросы истории для сопровождения, нижние границы исполнения) ДОЛЖНЫ передаваться службам объектом потребностей при запуске и после каждого тика. Объект потребностей ДОЛЖЕН собираться главным потоком из финансовой базы контура. Службы НЕ ДОЛЖНЫ читать финансовую базу контура сами и НЕ ДОЛЖНЫ записывать свои объекты в торговую часть контура.

Значения, которые различаются между контурами (вид контура, каталог состояния, часы и сессия прогона, каналы уведомлений, выбранные инструменты, источник данных), ДОЛЖНЫ передаваться контуру объектом настроек. Модули ядра и исторической службы НЕ ДОЛЖНЫ импортировать модули контура.

Разделение НЕ ДОЛЖНО менять поведение: вопросы и сообщения консоли, порядок запуска (ранний сбор, локальный API, выбор инструментов, торговая часть, приём, оркестратор), порядок остановки (обработчик паттернов, приём и полосы, кластерный поток, локальный API, отчёт истории, каналы), сделки и отчёты остаются прежними.

#### Scenario: Исторический прогон до и после разделения
- **WHEN** один и тот же исторический диапазон с теми же инструментами прогоняется до и после разделения сборки
- **THEN** журнал сделок и отчёт прогона совпадают

#### Scenario: Контур с исторической службой
- **WHEN** контур собирается для исторического прогона
- **THEN** он получает данные от исторической службы, служба не запускает полосы, приём, поток, локальный API и обработчик паттернов

#### Scenario: Обязательства после тика
- **GIVEN** в эмуляции открыта сделка по NG с сопровождением на 1h
- **WHEN** завершается тик
- **THEN** контур собирает объект потребностей из своей финансовой базы и передаёт его ядру, а ядро обновляет обязательства, не обращаясь к финансовой базе

#### Scenario: Направление зависимостей
- **WHEN** проверяются импорты модулей сборки
- **THEN** модули ядра и исторической службы не импортируют модуль контура, а контур обращается к данным только через порт рыночных служб

#### Scenario: Порядок запуска в эмуляции сохраняется
- **WHEN** эмуляция запускается командой API после ожидания
- **THEN** ранний сбор и локальный API стартуют до выбора инструментов, а торговая часть, приём и оркестратор — после, в прежнем порядке
