# Тестовые данные: скачивание и хранение

## Purpose

Обеспечивает воспроизводимый набор компактных исторических данных (свечей) для snapshot-тестов торговых сигналов: однократное скачивание из Invest API с жёстким лимитом глубины истории, статическое хранение фикстур в репозитории и зафиксированное тестовое окружение.

## ADDED Requirements

### Requirement: Скрипт скачивания тестовых данных
Система ДОЛЖНА предоставлять отдельный скрипт (вне pytest-прогона) для однократного скачивания свечей и записи их в файл фикстур. Скрипт ДОЛЖЕН принимать параметры: тикер, тип инструмента, таймфрейм и целевую стратегию/кейс.

#### Scenario: Скачивание фикстуры Природный газ 1h
- **WHEN** скрипт запущен для тикера NG (тип future), таймфрейм 1h, стратегия с папкой кейса `NG_1h`
- **THEN** свечи записываются в `tests/data/<strategy_name>/NG_1h/candles.csv`

### Requirement: Жёсткий лимит глубины истории
Запрос к API ДОЛЖЕН ограничивать глубину истории так, чтобы объём скачанных данных не превышал 300 свечей на один тест-кейс. Глубина ДОЛЖНА рассчитываться автоматически как `SIGNAL_WINDOW × 4` из `src.config` с абсолютным потолком 300 свечей. Граница `from_` ДОЛЖНА вычисляться явно как `end − (глубина × длительность таймфрейма)`; диапазон по умолчанию `load_candles` (30 дней) НЕ ДОЛЖЕН использоваться.

#### Scenario: Расчёт глубины из конфигурации
- **WHEN** `SIGNAL_WINDOW` импортирован из `src.config`
- **THEN** глубина = `max(SIGNAL_WINDOW × 4, фиксированный запас прогрева индикаторов)`, но не более 300

#### Scenario: Часовой таймфрейм, потолок 300
- **WHEN** расчётная глубина превышает 300 свечей
- **THEN** запрашиваются последние 300 свечей; полный доступный период истории не запрашивается

#### Scenario: Запрет дефолтного диапазона
- **WHEN** скрипт формирует запрос
- **THEN** `start_date` и `end_date` передаются в загрузчик явно; значение по умолчанию (30 дней ≈ 720 часовых свечей) не применяется

### Requirement: Пост-обрезка после загрузки
После загрузки DataFrame ДОЛЖЕН обрезаться до последних `limit` строк (`tail(limit)`) независимо от фактического числа полученных свечей.

#### Scenario: Защитная обрезка
- **WHEN** загружено больше `limit` свечей
- **THEN** сохраняются только последние `limit` строк

#### Scenario: Меньше лимита
- **WHEN** API вернул меньше `limit` свечей (торговые сессии, праздники)
- **THEN** возвращаются все полученные строки без дополнения

### Requirement: Структура хранения фикстур
Фикстуры ДОЛЖНЫ храниться по пути `tests/data/<strategy_name>/<case>/candles.csv`, где `<case>` кодирует инструмент и таймфрейм (например `NG_1h`). Структура ДОЛЖНА поддерживать произвольное число стратегий и кейсов без правки кода тестов.

#### Scenario: Добавление нового кейса
- **WHEN** создана новая папка `tests/data/<strategy_name>/BTC_15m/` с корректными файлами
- **THEN** кейс подхватывается тестами автоматически при следующем прогоне

### Requirement: Формат файла фикстур
Файл `candles.csv` ДОЛЖЕН содержать столбцы `datetime,open,high,low,close,volume`, идентичные выводу `load_candles`. `datetime` ДОЛЖЕН храниться в ISO-формате без часового пояса; цены — с точностью, достаточной для обратимого чтения float.

#### Scenario: Совместимость с load_candles
- **WHEN** `candles.csv` прочитан через `pd.read_csv`
- **THEN** DataFrame структурно идентичен результату `load_candles` (столбцы, порядок строк)

### Requirement: Зафиксированное тестовое окружение
Версии pandas, pandas-ta-classic, numba и pytest ДОЛЖНЫ быть жёстко зафиксированы в отдельном файле `requirements-dev.txt` по фактически установленным в проекте версиям.

#### Scenario: Воспроизводимость на другой машине
- **WHEN** тестовое окружение разворачивается из `requirements-dev.txt`
- **THEN** версии библиотек совпадают с версиями, для которых сгенерированы эталоны

### Requirement: Изоляция тестов от сети
Snapshot-тесты НЕ ДОЛЖНЫ выполнять сетевых вызовов; единственный источник данных — статические файлы. Сеть разрешена только скрипту скачивания.

#### Scenario: Запуск без токена
- **WHEN** pytest выполняется на машине без `TINKOFF_TOKEN`
- **THEN** snapshot-тесты проходят, используя только локальные файлы
