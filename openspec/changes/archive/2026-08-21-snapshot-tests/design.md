# Design: Snapshot-тесты торговых сигналов

## Context

Расчётный конвейер (`src/indicators/calculator.py` → `src/signals/generator.py`) детерминирован и зависит только от входного DataFrame, `SIGNAL_WINDOW` из `src/config.py` и версий pandas/pandas-ta-classic. Существующие тесты в `tests/` — юнит-тесты логики на синтетических данных; сквозной проверки «свечи → сигналы» нет. Версии pandas-ta-classic/numba в `requirements.txt` не запинены. Мотивация — см. proposal.md (Why).

Ограничения из исследования:
- `load_candles(start_date=None)` тянет 30 дней ≈ 720 часовых свечей — превышает лимит 300; скрипт скачивания обязан передавать даты явно.
- Прогрев индикаторов: MACD(12,26,9) ≈ 35 бар до первых валидных значений; сигналы используют `shift(1)`.
- Цены приходят как `units + nano/1e9` (float); `datetime` после `tz_localize(None)`.

## Goals / Non-Goals

**Goals:**
- Два контура: сетевой скрипт скачивания (однократно, вручную) и полностью offline pytest-прогон.
- Структура, готовая к N стратегиям без правки кода тестов.
- Детерминизм: результат зависит только от фикстуры + боевого кода + запиненных версий.
- Осознанная регенерация эталонов через Git diff.

**Non-Goals:**
- Бэктестинг доходности, симуляция сделок, P&L (сторонние библиотеки запрещены, задача не ставилась).
- Изменение рабочего кода `src/**` и `run.py`.
- CI-настройка (вне рамок этой смены).
- Автоматическое обновление эталонов по расписанию — только явный флаг.

## Decisions

### D1. Два контура: сеть изолирована в скрипте
Скачивание живёт в `tools/download_snapshot_data.py` (запуск вручную), pytest физически не имеет доступа к сети — тест читает только CSV. Альтернатива (фикстуры, качающие данные при первом прогоне с кэшированием) отклонена: скрытая сетевая зависимость ломает воспроизводимость и провоцирует случайное превышение лимита API.

### D2. Раскладка папок под стратегии
```
tests/
├── strategies/
│   └── test_macd_rsi_stoch.py      ← один файл = одна стратегия
└── data/
    └── macd_rsi_stoch/             ← имя стратегии = имя файла теста
        └── NG_1h/                  ← кейс: инструмент_таймфрейм
            ├── candles.csv         ← вход, ≤300 свечей
            └── expected_signals.csv← эталон событий BUY/SELL
```
Связь «файл теста ↔ папка данных» по имени стратегии: тест сам сканирует свою папку. Альтернатива (реестр кейсов в YAML/константе) отклонена — лишний файл синхронизации, именно от него уходим.

Первая стратегия получает имя **`macd_rsi_stoch`** (по составу индикаторов MACD + RSI + Stochastic): `tests/strategies/test_macd_rsi_stoch.py` + `tests/data/macd_rsi_stoch/`.

### D3. Формула глубины истории
`depth = min(max(SIGNAL_WINDOW × 4, WARMUP_RESERVE), 300)`, где `WARMUP_RESERVE` — константа запаса на прогрев самого долгого индикатора (MACD ≈ 35 бар → резерв 50 бар). При `SIGNAL_WINDOW=5`: `max(20, 50) = 50` свечей минимум, потолок 300. Скрипт передаёт в загрузчик явные `start_date = end − depth × длительность ТФ` и делает пост-обрезку `tail(depth)`. Двойная защита: лимит на уровне запроса + guard на уровне данных (страховка от смены таймфрейма без пересчёта окна). Альтернатива «фиксированные 300 всегда» отклонена пользователем — глубина должна следовать за конфигом, потолок 300 неприкосновенен.

### D4. Форматы файлов
- `candles.csv`: столбцы `datetime,open,high,low,close,volume` — зеркало вывода `load_candles`; datetime ISO без tz; цены полной float-точностью (без усекающего `float_format`) для обратимого round-trip.
- `expected_signals.csv`: `datetime,signal,price,macd_sum,rsi_sum,stoch_sum`; только строки консенсуса (все три суммы строго одного знака → BUY/SELL); HOLD не пишется (~95% строк — шум). Диагностические суммы позволяют при падении отличить «сломалась агрегация» от «сломалось решение». Альтернатива JSON отклонена: CSV читается `pd.read_csv` в одну строку и диффается git'ом построчно.

### D5. Регенерация через флаг pytest
Кастомная опция `--update-snapshots` регистрируется в `conftest.py` (`pytest_addoption`); тест проверяет флаг: сверка либо перезапись `expected_signals.csv` текущим поведением конвейера. Изменение стратегии = diff эталона в git, ревьюится человеком. Альтернатива (отдельный regenerate-скрипт) отклонена пользователем — флаг держит механизм внутри стандартного прогона pytest.

### D6. Динамическая параметризация
Тест стратегии собирает список кейсов сканом `tests/data/<strategy_name>/*/` на этапе коллекции (`pytest_generate_tests` или параметризация списком папок из фикстуры). Имя подпапки = id кейса. Новый инструмент = новая папка с двумя CSV, ноль правок кода. Пустая папка → ноль кейсов, прогон не падает.

### D7. Агрегация повторяет семантику get_last_signals
Бегунок `rolling(SIGNAL_WINDOW).sum()` по столбцам `macd_signal/rsi_signal/stoch_signal` воспроизводит `.iloc[-window:].sum()` для каждой позиции истории (продакшн считает так только на последней свече цикла; replay обобщает на всю историю). Окно берётся импортом из `src.config`, не хардкодом. Первые строки NaN-региона индикаторов исключаются из сравнения.

### D8. Пин окружения
`requirements-dev.txt` фиксирует фактически установленные версии pandas, pandas-ta-classic, numba, pytest (`pip freeze` выборочно). Эталон валиден только для этих версий; обновление библиотеки = осознанная перегенерация эталона. Основной `requirements.txt` не трогаем.

## Risks / Trade-offs

- [Дрейф версий библиотек меняет значения индикаторов] → пин в requirements-dev.txt + snapshot падает при любом расхождении; обновление только с осознанной перегенерацией.
- [--update-snapshots маскирует реальный баг, если нажать не глядя] → правило: флаг только после просмотра обычного падения; git diff эталона обязателен к ревью.
- [Пустой эталон (нет консенсусных свечей в окне)] → валидный кейс: тест сверяет пустые множества и проходит; регрессия появится, когда события возникнут неожиданно.
- [Торговые сессии/праздники дают меньше свечей, чем запрошено] → допустимо: тест работает с фактическим числом строк ≥ порога прогрева; post-guard `tail(limit)` не дополняет данные.
- [Float-погрешность цен при round-trip CSV] → сравнение `assert_frame_equal(check_exact=False, rtol≈1e-9)`; запись полной точностью.
- [Расхождение черновых главных спек с финальными решениями] → при архивации дельты синхронизируют `openspec/specs/{test-data,snapshot-testing}`; черновые расхождения (пути tests/snapshots/**, отсутствие --update-snapshots) будут устранены синком.

## Migration Plan

Рабочий код не меняется — миграция не требуется. Новые пути добавляются аддитивно: `tests/strategies/`, `tests/data/`, `tools/download_snapshot_data.py`, `requirements-dev.txt`. Откат = удаление новых файлов. Черновые главные спеки приводятся к финальному виду синком дельт при архивации смены.
