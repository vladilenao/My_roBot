## Purpose

Интерактивный ввод и валидация торговых инструментов при старте приложения. Пользователь выбирает тип инструментов (акции или фьючерсы), затем видит список доступных тикеров и может выбрать несколько за раз. Процесс выбора можно повторить для добавления инструментов другого типа.

## ADDED Requirements

### Requirement: Выбор типа инструментов
- Система ДОЛЖНА при старте предлагать пользователю выбор между акциями (индекс РТС) и фьючерсами.

#### Scenario: Пользователь выбирает акции
- **WHEN** пользователь вводит `1` на этапе выбора типа
- **THEN** система отображает список тикеров акций индекса РТС

#### Scenario: Пользователь выбирает фьючерсы
- **WHEN** пользователь вводит `2` на этапе выбора типа
- **THEN** система загружает список фьючерсов через API и отображает все контракты баз RTS, BR, Si, SBRF, ED, NG, GOLD, SILV с экспирацией в ближайшие 6 месяцев

#### Scenario: Неверный выбор типа
- **WHEN** пользователь вводит значение, отличное от `1` или `2`
- **THEN** система запрашивает повторный ввод с указанием допустимых вариантов

### Requirement: Отображение списка акций
- Система ДОЛЖНА отображать статический список тикеров акций индекса РТС: SBER, GAZP, LKOH, GMKN, ROSN, NVTK, YDEX, TCSG, VTBR, MTSS, PHOR, ALRS, MOEX, PLZL, TATN.

#### Scenario: Нумерация списка
- **WHEN** система отображает список акций
- **THEN** каждый тикер пронумерован начиная с 1

### Requirement: Динамическая загрузка фьючерсов
- Система ДОЛЖНА загружать список фьючерсов через API `client.instruments.futures()`.
- Система ДОЛЖНА включать все контракты с экспирацией в ближайшие 6 месяцев (183 дня) для баз: RTS, BR, Si, SBRF, ED, NG, GOLD, SILV.
- Система ДОЛЖНА исключать контракты с суффиксом «микро» или «мини» в названии.
- Система ДОЛЖНА отображать все доступные контракты, а не только ближайший по экспирации.
- Система ДОЛЖНА отображать фьючерсы в формате `BASE (Русское описание) — ИмяКонтракта` (например, `NG (Природный газ) — NG-9.26`).
- Система ДОЛЖНА использовать единый формат отображения фьючерсов во всех контекстах: список выбора, текущий список, сообщения анализа.
- Система ДОЛЖНА сортировать фьючерсы сначала по типу базового актива (в порядке FUTURES_BASES), затем по дате экспирации от ближайшей к дальней внутри каждого типа.

#### Scenario: Фьючерсы успешно загружены
- **WHEN** пользователь выбрал пункт `2` и API вернул список фьючерсов
- **THEN** система отображает пронумерованный список, сгруппированный по базовому активу и отсортированный по дате экспирации внутри каждого типа

#### Scenario: Единый формат отображения
- **WHEN** система отображает фьючерс с тикером `NGU6` и именем `NG-9.26 Природный газ`
- **THEN** отображается `NG (Природный газ) — NG-9.26` во всех контекстах

#### Scenario: Фьючерсов с экспирацией в ближайшие 6 месяцев нет
- **WHEN** API не вернул подходящих фьючерсов
- **THEN** система выводит сообщение «Нет фьючерсов с экспирацией в ближайшие 6 месяцев»

#### Scenario: Ошибка загрузки фьючерсов
- **WHEN** при загрузке фьючерсов через API произошла ошибка
- **THEN** система выводит сообщение об ошибке и позволяет продолжить выбор

### Requirement: Множественный выбор инструментов
- Пользователь ДОЛЖЕН иметь возможность выбрать несколько инструментов за один ввод, указав номера через запятую.

#### Scenario: Выбор по номерам
- **WHEN** пользователь вводит `1,3,5`
- **THEN** система выбирает инструменты под номерами 1, 3 и 5 из списка

#### Scenario: Выбор по тикерам
- **WHEN** пользователь вводит `SBER,GAZP`
- **THEN** система выбирает инструменты с указанными тикерами

#### Scenario: Смешанный выбор
- **WHEN** пользователь вводит `1,SBER,5`
- **THEN** система выбирает инструмент под номером 1, тикер SBER и инструмент под номером 5

#### Scenario: Пустой ввод
- **WHEN** пользователь вводит пустую строку на этапе выбора инструментов
- **THEN** система считает это пропуском и не добавляет инструментов

#### Scenario: Номер вне диапазона
- **WHEN** пользователь указывает номер, который выходит за пределы списка
- **THEN** система выводит предупреждение и пропускает этот номер

### Requirement: Валидация инструментов через API
- Каждый выбранный инструмент ДОЛЖЕН быть проверен через `find_working_instrument`.

#### Scenario: Инструмент валиден
- **WHEN** тикер найден и имеет свечные данные
- **THEN** инструмент добавляется в список и выводится `✓`

#### Scenario: Инструмент не найден
- **WHEN** `find_working_instrument` выбрасывает `ValueError`
- **THEN** система выводит `✗` с описанием ошибки и не добавляет инструмент

#### Scenario: Ошибка API
- **WHEN** при проверке возникает неожиданное исключение
- **THEN** система выводит `✗` с описанием ошибки API

### Requirement: Дедупликация инструментов
- Система ДОЛЖНА исключать повторное добавление одного и того же тикера в итоговый список.

#### Scenario: Пользователь выбирает один и тот же тикер дважды
- **WHEN** пользователь выбирает инструмент, который уже есть в списке
- **THEN** дубликат не добавляется, в списке остаётся только один экземпляр

#### Scenario: Дедупликация после каждого раунда
- **WHEN** завершается раунд выбора инструментов
- **THEN** список инструментов проверяется на дубликаты и очищается от них

### Requirement: Возможность добавления инструментов
- После каждого раунда выбора система ДОЛЖНА спрашивать, хочет ли пользователь добавить ещё инструменты.

#### Scenario: Пользователь хочет добавить ещё
- **WHEN** пользователь отвечает `да` (или `д`, `y`, `yes`)
- **THEN** система возвращает к выбору типа инструментов

#### Scenario: Пользователь завершает выбор
- **WHEN** пользователь отвечает `нет` (или `n`, `no`)
- **THEN** система завершает процесс выбора

#### Scenario: Неверный ответ на вопрос о добавлении
- **WHEN** пользователь вводит значение, отличное от допустимых
- **THEN** система запрашивает повторный ввод

### Requirement: Минимум один инструмент
- Система ДОЛЖНА потребовать выбор как минимум одного валидного инструмента перед запуском основного цикла.

#### Scenario: Все инструменты невалидны
- **WHEN** после завершения выбора список инструментов пуст
- **THEN** система выводит сообщение и начинает процесс выбора заново

### Requirement: Возврат списка инструментов
- Функция выбора инструментов ДОЛЖНА возвращать список кортежей `(display_name, ticker, instrument_type)`.
- `display_name` ДОЛЖЕН содержать человекочитаемое имя инструмента (для акций — тикер, для фьючерсов — формат `BASE (Описание) — Контракт`).

#### Scenario: Возвращаемый формат для акций
- **WHEN** пользователь выбрал `SBER share`
- **THEN** функция возвращает `[("SBER", "SBER", "share")]`

#### Scenario: Возвращаемый формат для фьючерсов
- **WHEN** пользователь выбрал фьючерс `NGU6` с именем `NG-9.26 Природный газ`
- **THEN** функция возвращает `[("NG (Природный газ) — NG-9.26", "NGU6", "future")]`

### Requirement: Использование контекстного менеджера API
- Функция выбора инструментов ДОЛЖНА использовать `client_context()` как контекстный менеджер (`with`) для доступа к API.

#### Scenario: Клиент закрывается после завершения выбора
- **WHEN** пользователь завершает ввод инструментов
- **THEN** контекстный менеджер клиента корректно закрывается
