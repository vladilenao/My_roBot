## ADDED Requirements

### Requirement: Секреты не попадают в лог
Нормативный уровень: MUST.
Файл лога НЕ ДОЛЖЕН содержать значения секретов: токенов брокера, Telegram-бота и API экспорта, паролей, а также секретного адреса прокси Telegram (`CLOUDFLARE_URL`) и его хоста. Маскирование ДОЛЖНО применяться к готовой строке записи — сообщению, аргументам и traceback — для записей любых логгеров, включая сторонние библиотеки. Вместо секрета ДОЛЖНО выводиться `[скрыто]`.

Значения секретов ДОЛЖНЫ передаваться в настройку логирования из `.env`/переменных окружения при запуске. Токен Telegram-бота в формате `<цифры>:<строка>` и значение `Bearer …` ДОЛЖНЫ скрываться и без переданного значения. Пустые значения и значения короче 8 символов НЕ ДОЛЖНЫ маскироваться, чтобы не искажать обычный текст. Маскирование НЕ ДОЛЖНО менять строки без секретов, уровни логгеров, формат строки и ротацию.

#### Scenario: Адрес запроса Telegram от urllib3
- **WHEN** `urllib3.connectionpool` на уровне DEBUG пишет хост прокси и путь `/bot<токен>/sendMessage`
- **THEN** в файле лога есть `/bot[скрыто]/sendMessage`, нет ни токена, ни хоста прокси

#### Scenario: Секрет в traceback
- **WHEN** исключение с текстом `Authorization: Bearer <токен брокера>` записано через `log.exception`
- **THEN** в файле лога вместо токена `[скрыто]`, остальной traceback сохранён

#### Scenario: Токен без регистрации
- **WHEN** в лог попадает токен Telegram-бота, значение которого не передано в настройку
- **THEN** токен скрыт по формату

#### Scenario: Обычный текст
- **WHEN** строка лога содержит время свечи, цену и короткое значение, совпадающее с секретом короче 8 символов
- **THEN** строка записывается без изменений
