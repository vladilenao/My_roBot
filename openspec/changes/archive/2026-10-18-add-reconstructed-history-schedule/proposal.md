## Why

Исторический прогон BR за 2025-03-10 — 2025-09-10 (каталог `HIST/20261017T220225-…`) прошёл без расписания торгов ни на одну дату (`schedule_resource_unavailable`). Сессионная защита внутридневных сделок (`add-intraday-session-guard`) без расписания запрещает вход, поэтому все 910 сигналов `future-br-macd` (845) и `future-br-ma` (65) получили `session-schedule-unknown`. Торговали только часовые `future-br-harmonic` и `future-br-flat`, а отчёт показал лишь список из 141 даты без расписания и не сказал, что половина стратегий не участвовала.

Брокер не отдаёт расписание прошедших дат, а робот записывает его только с 2026-10-13. Эмулятор теперь хранит для прошедших дат **восстановленное** расписание: окна по версии правил, торговые и неторговые даты по барам. Он отдаёт его тем же `GET /api/v1/trading-schedules` с пометкой `provenance: "reconstructed"` и `rules_version`, а привязки прошлых контрактов — с `binding_provenance`. Подтверждённые дни из ленты робота всегда главнее. Задача эмулятора: `docs/emulator-reconstructed-schedules.md` в репозитории «Historical Broker API Emulator». Все 650 восстановленных дней (`forts_futures_weekend/1`, 2025-01-01 — 2026-10-12) проходят разбор робота, и версия совпадает.

Робот должен принять такие дни для сессионной защиты в историческом прогоне. При этом их нельзя смешивать с подтверждённым расписанием там, где расписание служит доказательством (плановое отсутствие свечей, проверка границ), и прогон должен заметно сообщать, какие стратегии не смогли торговать и почему.

## What Changes

- **Происхождение дня расписания.** Робот читает у дня `provenance` и `rules_version`, а у привязки — `binding_provenance`, хранит их в расписании снимка прогона и передаёт в разобранный день календаря. День без поля — подтверждённый (старый эмулятор). Неизвестное значение отвергается с диагностикой.
- **Восстановленный день — не доказательство.** По умолчанию календарь отдаёт только подтверждённые дни. Ожидание свечей, сверка покрытия (`scheduled_closed`), проверка правых границ и представление графиков работают как сейчас. Восстановленные дни видит только сессионная защита: она запрашивает их явно.
- **Сессионная защита в истории** применяет восстановленный день так же, как подтверждённый. Трасса `session.intraday` (версия алгоритма `2`) показывает происхождение дня и версию правил.
- **Выключатель** `[historical.schedule].use_reconstructed` (по умолчанию `true`) — для сравнительных прогонов без восстановленного расписания.
- **Предупреждение на старте.** После закрепления снимка прогон один раз загружает расписание цепочки инструментов на весь диапазон. Если сессионная защита включена, а у части дат расписания нет, в консоль и лог выводится предупреждение с числом дат и затронутыми внутридневными привязками. Прогон не останавливается.
- **Отчёт прогона:**
  - дни расписания по происхождению (подтверждено / восстановлено), версии правил и происхождение привязок;
  - даты без расписания диапазонами, а не списком;
  - новый раздел «Сигналы и недопуски по стратегиям»: по каждой привязке — сигналы, сделки и недопуски по причинам;
  - предупреждение, если стратегия не открыла ни одной сделки, а большинство её сигналов отклонено из-за неизвестного расписания.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `trading-calendar`: происхождение дня расписания; восстановленный день не служит доказательством.
- `historical-mode`: расписание прогона с происхождением дней, предварительная загрузка и предупреждение, раздел недопусков по стратегиям в отчёте.
- `trade-management`: сессионная защита по восстановленному расписанию в историческом прогоне, происхождение дня в трассе.
- `configuration`: секция `[historical.schedule]`.

## Impact

- Код:
  - `src/market_calendar/service.py`: `EmulatorScheduleSource`, `SnapshotScheduleStore`, `MarketCalendar` (вид календаря, `usage`);
  - `src/market_calendar/core.py`: `CalendarDay`;
  - `src/data/market_store.py`: `StoredScheduleDay` — поля со значениями по умолчанию, схема БД не меняется;
  - `run.py`: `_session_calendar_provider`, предварительная загрузка;
  - `src/trade_management/session_guard.py` и `manager.py`: трасса;
  - `src/history/report.py`;
  - `src/config_loader.py`, `src/config.py`, `default.toml`.
- Данные: схемы `trades.sqlite3` и `market-data.sqlite3` не меняются. Восстановленные дни живут только в непостоянном расписании снимка и в `market-data.sqlite3` не попадают.
- Live не меняется: брокер отдаёт только подтверждённые дни.
- Зависимость: изменение `add-intraday-session-guard` и эмулятор с восстановленным расписанием. Со старым эмулятором поведение прежнее.

Non-goals:
- генерация и хранение восстановленного расписания (сделано в эмуляторе);
- использование восстановленных дней для статистики разрывов и доказательства отсутствия свечей;
- cutoff перехода контракта в торговых днях (отдельное изменение);
- остановка прогона без расписания.
