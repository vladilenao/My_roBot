## Why

Сегодня робот нельзя запустить без человека за консолью: режим, даты истории и инструменты спрашиваются через `input()`. Даже `--no-prompt` пропускает только вопрос о режиме, а инструменты всё равно выбираются в меню. Хочется другого: робот стартует, сразу греет свечи и ждёт команды, а торговлю нужными контрактами запускает запрос к API. Это первый этап перехода к ядру и торговым контурам (`docs/architecture/core-contours.md`, П1).

## What Changes

- **Запуск эмуляции командой API.** С `--mode emulation --wait-command` (или пунктом меню) робот запускается, поднимает рыночные данные и ждёт. `POST /api/v1/contours` с телом `{"kind": "emulation", "instruments": [...]}` проверяет инструменты и запускает торговлю ими. `GET /api/v1/contours` показывает, ждёт ли робот команды, запускается или торгует и какими контрактами.
- **Ключ управления.** Новый секрет `ROBOT_CONTROL_TOKEN` (схема `ControlToken` в Swagger) отдельно от экспортного: ключ эмулятора истории не может запускать торговлю. Ключ принимается только в заголовке, сервер проверяет `Host`.
- **Сервер поднимается раньше.** Локальный API стартует сразу после раннего сбора данных, до выбора инструментов, если задан хотя бы один из ключей. Раньше он стартовал после выбора и только с экспортным ключом.
- **Параметры командной строки:** `--mode emulation | history`, `--from`, `--to`, `--pause`, `--instruments`, `--wait-command`. Ошибка в параметрах — причина и код `2`, без вопросов и без торговли.
- **Единые правила инструментов** для командной строки, меню и API. Принимаются тикер акции, код семейства и контракт, по умолчанию `all` — все инструменты с привязками в `robot.toml`. Инструмент без привязок отклоняется. Для семейства в эмуляции выбирается ближайший контракт, до экспирации которого больше `contract_expiry_block_days` суток. В истории семейство, как и сейчас, означает автоматическую цепочку.
- **Сегодняшний «боевой» режим называется эмуляцией**, как в целевой архитектуре. Пункт меню «Боевая торговля (реальный брокер…)» вводил в заблуждение.
- **Меню остаётся** и только собирает те же параметры. В начале любого запуска робот печатает и пишет в журнал эквивалентную команду.
- **BREAKING**: `--no-prompt` становится полностью неинтерактивным: это `--mode emulation` со всеми инструментами из привязок, если не задан `--instruments`.
- **Swagger** (`docs/openapi.yaml`): тег `Contours`, маршруты `GET` и `POST /api/v1/contours`, схема `ControlToken`, примеры успешного запуска, отказа и повторного запуска.

## Capabilities

### New Capabilities

- `control-api`: управление запуском торгового контура через локальный API: ожидание команды, запуск эмуляции, состояние, доступ по ключу управления.

### Modified Capabilities

- `historical-mode`: режим и диапазон задаются параметрами запуска; меню — способ собрать те же параметры.
- `orchestration`: точка входа получает параметры из командной строки, меню или команды API; разрешение инструментов идёт после раннего сбора данных через тот же арбитр.
- `instruments`: инструменты из параметров запуска и привязок конфигурации, правило выбора контракта для семейства.
- `cluster-report`: локальный API запускается до выбора инструментов и при заданном хотя бы одном ключе.
- `market-data-export`: единый контракт `docs/openapi.yaml` получает тег `Contours`.

## Impact

- `run.py`: разбор аргументов, `main`, `ask_mode`, `ask_history_range`, `_run_live`, `_run_history`, `_launch`, `_start_local_api` (раньше и с двумя ключами), `secrets` у `setup_logging`.
- Новый модуль параметров запуска и разрешения инструментов `src/bot/launch.py`.
- `src/data/export_api.py`: маршруты `/api/v1/contours`, проверка ключа управления и `Host`.
- `src/config.py`: `ROBOT_CONTROL_TOKEN`.
- `src/instruments/selector.py`: список активных фьючерсов с моментом экспирации; меню сохраняет проверку по ходу выбора, после неё — фильтр привязок.
- Документация: `docs/openapi.yaml`, `README.txt`, `docs/architecture/core-contours.md`, `CHANGELOG.md`.
- Торговля, стратегии, журнал и рыночные данные не меняются.
