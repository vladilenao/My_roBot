## ADDED Requirements

### Requirement: Параметры торгового календаря
Нормативный уровень: MUST. Конфигурация ДОЛЖНА поддерживать необязательные параметры секции `market_data`:
- `schedule_refresh_interval_secs` — период обновления расписания;
- `schedule_max_age_secs` — предел возраста наблюдения относительно начала торговой даты для применимости в боевом режиме;
- `schedule_horizon_days` — горизонт дат вперёд;
- `calendar_evidence` — разрешение календарного доказательства планового отсутствия свечи.

Значения ДОЛЖНЫ быть конечными и положительными, с проверкой типа; `calendar_evidence` — логическое. Отсутствие ключей ДОЛЖНО сохранять приём старых конфигов с документированным инженерным профилем, без изменения торговых настроек, риска и окна актуальности решения. Числа профиля НЕ ДОЛЖНЫ выдаваться за гарантию брокера. Эффективные значения ДОЛЖНЫ быть наблюдаемы в диагностике.

При `calendar_evidence=false`:
- система НЕ ДОЛЖНА выдавать календарное доказательство планового отсутствия свечи;
- сокращение свечных запросов НЕ ДОЛЖНО применяться;
- фаза, следующее событие, источник и версия расписания ДОЛЖНЫ продолжать отображаться;
- сохранённые расписания и доказательства НЕ ДОЛЖНЫ удаляться.

Исторический режим НЕ ДОЛЖЕН применять предел возраста к расписанию снимка.

#### Scenario: Старый конфиг
- **WHEN** параметры календаря отсутствуют
- **THEN** конфиг принимается, используется документированный профиль, эффективные значения отображаются в диагностике

#### Scenario: Недопустимое значение
- **WHEN** `schedule_max_age_secs` отрицателен, нечисловой или нефинитен
- **THEN** запуск отклоняется с именем проблемного ключа

#### Scenario: Откат календарных доказательств
- **WHEN** задано `calendar_evidence=false`
- **THEN** интервалы без свечи не разрешаются календарём и свечные запросы не сокращаются, а фаза и следующее событие продолжают публиковаться

### Requirement: Задержка публикации по таймфрейму
Нормативный уровень: MUST. Конфигурация ДОЛЖНА поддерживать необязательное отображение `market_data.candle_publication_timeout_by_tf`, уточняющее допустимую задержку публикации свечи для отдельных таймфреймов. Для ТФ без уточнения ДОЛЖЕН применяться базовый `market_data.candle_publication_timeout_secs`. Ключи отображения ДОЛЖНЫ быть поддерживаемыми таймфреймами, значения — конечными положительными. Уточнение НЕ ДОЛЖНО наследоваться от `tick.timeout_secs` и НЕ ДОЛЖНО расширять окно актуальности торгового решения.

#### Scenario: Уточнение для дневного ТФ
- **WHEN** базовая задержка равна 65 с, а для `1d` задано 900 с
- **THEN** срок публикации дневной свечи — закрытие плюс 900 с, у остальных ТФ — плюс 65 с

#### Scenario: Неизвестный таймфрейм в уточнении
- **WHEN** отображение содержит ключ, не являющийся поддерживаемым таймфреймом
- **THEN** конфигурация отклоняется с именем ключа и таймфрейма
