## ADDED Requirements

### Requirement: Историческая календарная политика перехода
Нормативный уровень: MUST.
Система ДОЛЖНА принимать опциональную секцию `[historical.rollover]` с `policy = "calendar"` и таблицы `[historical.rollover.families.<семейство>]` с `lead_days`. Отсутствующая политика ДОЛЖНА означать calendar; отсутствие горизонта семейства ДОЛЖНО означать наследование `[trading] contract_expiry_block_days`, включая его действующий дефолт 2. `lead_days` ДОЛЖЕН быть целым неотрицательным числом, не boolean, и не меньше эффективного contract_expiry_block_days. N ДОЛЖЕН означать календарные сутки по 24 часа, а не торговые сессии.

Система ДОЛЖНА поддерживать существующие семейства RTS, BR, Si, SBRF, ED, NG, GOLD, SILV с нечувствительными к регистру ключами. Неизвестная политика, семейство, ключ, дубли после нормализации, неправильный тип или слишком малый горизонт ДОЛЖНЫ отклоняться с ConfigError, файлом и ключом. Настройки ДОЛЖНЫ применяться только к автоматическому историческому выбору; боевой и фиксированный режимы сохраняют действующую защиту экспирации.

#### Scenario: Старый конфиг без новой секции
- **WHEN** новая секция отсутствует, contract_expiry_block_days равен 2
- **THEN** автоматическая история использует calendar и N=2 для всех выбранных семейств

#### Scenario: Переход раньше для одного семейства
- **WHEN** общий порог равен 2, для BR задан lead_days=3, для NG ничего не задано
- **THEN** BR переходит за 3 календарных суток, NG за 2

#### Scenario: Защита не ослабляется
- **WHEN** общий порог равен 2, а семейство задаёт lead_days=1
- **THEN** конфигурация отвергается с указанием конфликтующего ключа

#### Scenario: Неверные параметры
- **WHEN** policy неизвестен, lead_days дробный/отрицательный/boolean либо присутствует неизвестный ключ
- **THEN** загрузка завершается ConfigError без молчаливой подстановки дефолта

#### Scenario: Дубли ключей семейства
- **WHEN** указаны таблицы NG и ng
- **THEN** загрузка отвергает дубли после нормализации

#### Scenario: Настройки не включают боевой переход
- **WHEN** конфиг содержит корректные настройки исторического перехода, выбран боевой режим
- **THEN** выбор конкретного контракта и его действующая защита экспирации сохраняются
