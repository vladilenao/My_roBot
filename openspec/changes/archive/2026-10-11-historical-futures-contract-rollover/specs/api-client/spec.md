## ADDED Requirements

### Requirement: Исторический каталог для календарной цепочки
Нормативный уровень: MUST.
Система ДОЛЖНА получать исторические, включая уже истёкшие относительно системной даты, контракты из источника выбранного прогона без боевого токена. Для автоматического выбора карточка ДОЛЖНА предоставлять стабильную идентичность, короткое имя, однозначное семейство и разновидность, начало обращения и экспирацию. При наличии последней торговли и начала поставочных обязательств система ДОЛЖНА сохранять их. Даты ДОЛЖНЫ нормализоваться в UTC из достоверных моментов с часовым поясом; пропущенные, ошибочные или только календарные даты НЕ ДОЛЖНЫ превращаться в вымышленные моменты.

Известные обозначения семейства ДОЛЖНЫ разрешаться однозначно без переименования существующих привязок стратегий. Мини/микро и контракты иной спецификации НЕ ДОЛЖНЫ попадать в стандартную цепочку. Отсутствие обязательных полей или экономических метаданных нужного контракта ДОЛЖНО блокировать автоматическую предпроверку с перечнем проблем; фиксированный режим сохраняет своё действующее поведение отсутствующих полей.

#### Scenario: Истёкший сегодня контракт
- **WHEN** каталог содержит контракт, истёкший относительно системной даты, но нужный на историческом диапазоне
- **THEN** он доступен календарному планированию и не отфильтровывается как сегодняшний expired

#### Scenario: Нет даты начала обращения
- **WHEN** нужная карточка содержит экспирацию, но не достоверный first_trade_date
- **THEN** автоматический прогон отклоняется с конкретной причиной, начало обращения не выводится из названия или первой импортированной свечи

#### Scenario: Часовой пояс границы
- **WHEN** последняя торговля задана как `2026-09-25T15:00:00+03:00`
- **THEN** план использует `2026-09-25T12:00:00Z`

#### Scenario: Дата без времени
- **WHEN** обязательная дата содержит только календарное число без достоверного момента
- **THEN** автоматическая предпроверка сообщает недостаточность даты, не назначая произвольное время сессии

#### Scenario: Разные названия семейства
- **WHEN** исторический стандартный контракт РТС имеет биржевой код семейства RI
- **THEN** он разрешается в пользовательское семейство RTS и использует прежние привязки этого семейства

### Requirement: Зафиксированный каталог одного прогона
Нормативный уровень: MUST.
Автоматический исторический прогон ДОЛЖЕН использовать одну неизменяемую копию нормализованного каталога, полученную после синхронизации источника до планирования, предпроверки и торговли. Карточки, используемые параметры и идентификатор содержимого ДОЛЖНЫ сохраняться в каталоге прогона. Повтор после сдвига начала ДОЛЖЕН использовать тот же каталог и тот же закреплённый снимок свечей; новый прогон ДОЛЖЕН получать новую копию каталога. Локальная фиксация каталога НЕ ДОЛЖНА объявляться доказательством исторической доступности каждой версии экономических параметров.

#### Scenario: Каталог изменился во время прогона
- **WHEN** источник изменяет карточку после начала автоматического прогона
- **THEN** текущая цепочка и её расчёт продолжают использовать сохранённую копию

#### Scenario: Повтор предпроверки со сдвигом
- **WHEN** предпроверка сдвинула начало и прогон собирается повторно
- **THEN** участки пересчитываются на исходном каталоге и снимке, каталог не перечитывается

#### Scenario: Следующий независимый прогон
- **WHEN** пользователь запускает новый прогон
- **THEN** каталог фиксируется заново, его идентификатор записывается в новый результат
