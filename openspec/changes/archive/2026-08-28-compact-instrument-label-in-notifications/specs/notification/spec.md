## MODIFIED Requirements

### Requirement: Иерархия нотификаторов
Пакет `src/notifier` ДОЛЖЕН предоставлять абстрактный класс `AbstractNotifier`: метод `notify(message)` — абстрактный, принимает только готовый текст сообщения; метод `notify_decision(decision, instrument_label="")` — конкретный, форматирует решение через внедрённый форматтер и доставляет результат через `notify`. Форматтер ДОЛЖЕН внедряться через конструктор нотификатора; по умолчанию используется `DecisionFormatter`. Создание экземпляра `AbstractNotifier` и наследника без реализации `notify` ДОЛЖНО завершаться ошибкой. Форматтер ДОЛЖЕН выдавать компактную однострочную строку вида `● <инструмент> (<таймфрейм>) HH:MM | <стратегия> ➜ <сигнал>`, где `<инструмент>` — краткое имя инструмента (`instrument_label`), `<таймфрейм>` — таймфрейм, заданный форматтеру при конструировании, `HH:MM` — время последнего бара (поле `bar_time` решения), `<стратегия>` — имя стратегии; при отсутствии `bar_time` или имени стратегии их блоки в строке ДОЛЖНЫ опускаться, при отсутствии заданного таймфрейма опускается блок `(<таймфрейм>)`.

#### Scenario: Мостик от решения к доставке
- **WHEN** вызывается `notify_decision` с решением BUY, кратким именем инструмента «NG-10.26», таймфреймом форматтера `1h`, именем стратегии `macd_rsi_stoch` и `bar_time` 22:00
- **THEN** нотификатор доставляет отформатированное решение текстом `● NG-10.26 (1h) 22:00 | macd_rsi_stoch ➜ 🟢 ПОКУПКА (BUY) — Цена: X` единственным вызовом `notify`

#### Scenario: Абстрактный класс нельзя инстанцировать
- **WHEN** выполняется попытка создания экземпляра `AbstractNotifier`
- **THEN** выбрасывается ошибка (класс абстрактный)

#### Scenario: Наследник обязан реализовать notify
- **WHEN** создаётся наследник без переопределения `notify`
- **THEN** создание экземпляра завершается ошибкой

#### Scenario: Подмена форматтера
- **WHEN** в конструктор нотификатора передан альтернативный форматтер
- **THEN** `notify_decision` форматирует решение им, а не `DecisionFormatter` по умолчанию

### Requirement: Компактный формат сигналов
`DecisionFormatter` ДОЛЖЕН оформлять каждое решение одной строкой. Для BUY — `🟢 ПОКУПКА (BUY) — Цена: X`; для SELL — `🔴 ПРОДАЖА (SELL) — Цена: X`; для HOLD — `⏳ Нет сигнала.` без цены. Строка ДОЛЖНА начинаться с маркера `● `; за маркером ДОЛЖЕН следовать `<инструмент>`, к которому через один пробел добавляется блок таймфрейма `(<таймфрейм>)` при наличии заданного форматтеру таймфрейма; блок времени бара `HH:MM` и блок стратегии `| <имя>` включаются только при наличии соответствующих значений.

Значение `bar_time` решения ДОЛЖНО представлять момент ЗАКРЫТИЯ свечи последнего бара, а не момент её начала: момент начала бара в tz-naive UTC, сложенный с длительностью периода таймфрейма. Блок времени `HH:MM` ДОЛЖЕН отображать `bar_time` в локальном часовом поясе пользователя: к значению применяется сконфигурированное смещение от UTC, заданное в часах. При нулевом смещении выводится UTC-время закрытия без изменений.

#### Scenario: Покупка
- **WHEN** решение имеет тип BUY, цену X, время закрытия бара 22:00, стратегию `macd_rsi_stoch`, а таймфрейм форматтера `1h`
- **THEN** сообщение равно `● <инструмент> (1h) 22:00 | macd_rsi_stoch ➜ 🟢 ПОКУПКА (BUY) — Цена: X`

#### Scenario: Продажа
- **WHEN** решение имеет тип SELL, цену X, время закрытия бара 22:00, стратегию `macd_rsi_stoch`, а таймфрейм форматтера `1h`
- **THEN** сообщение равно `● <инструмент> (1h) 22:00 | macd_rsi_stoch ➜ 🔴 ПРОДАЖА (SELL) — Цена: X`

#### Scenario: Нет сигнала
- **WHEN** решение имеет тип HOLD
- **THEN** сообщение содержит `⏳ Нет сигнала.` и не содержит цены

#### Scenario: Нет времени бара
- **WHEN** решение не имеет `bar_time`
- **THEN** блок времени в строке опускается (нет `HH:MM`)

#### Scenario: Нет имени стратегии
- **WHEN** решение не имеет имени стратегии
- **THEN** блок `| <имя>` в строке опускается

#### Scenario: Нет таймфрейма
- **WHEN** форматтеру не задан таймфрейм
- **THEN** блок `(<таймфрейм>)` в строке опускается, маркер `● ` и `<инструмент>` выводятся без него

#### Scenario: Время в локальном поясе
- **WHEN** смещение часового пояса задано, например `+3` часа, а `bar_time` равен `06:00` UTC (момент закрытия свечи)
- **THEN** в сообщении блок времени выводится как `09:00` (к значению закрытия прибавлено смещение)

#### Scenario: Нулевое смещение сохраняет UTC
- **WHEN** смещение часового пояса равно `0`, а `bar_time` равен `06:00` UTC (момент закрытия свечи)
- **THEN** блок времени выводится как `06:00` (UTC-время закрытия без изменений)
