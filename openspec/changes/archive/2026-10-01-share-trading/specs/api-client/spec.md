## ADDED Requirements

### Requirement: Загрузка метаданных акций
Нормативный уровень: MUST.
Система ДОЛЖНА загружать торговые метаданные акций отдельным вызовом каталога акций `client.instruments.shares()` с фильтрацией по выбранным тикерам. Для каждой акции метаданные ДОЛЖНЫ содержать: `price_step` — минимальный шаг цены из `min_price_increment`; `step_cost` — `price_step × lot`, то есть цену одного лота в рублях; `go_buy` и `go_sell` — 0, поскольку у акции нет гарантийного обеспечения; `expiration_date` — `None`, поскольку акция не экспирируется. Отношение `step_cost / price_step` ДОЛЖНО равняться размеру лота в акциях и ДОЛЖНО использоваться как цена одного контракта при расчёте риска и прибыли.

Акции с нулевым шагом цены или нулевым размером лота ДОЛЖНЫ исключаться из карты метаданных с предупреждением: из них нельзя достоверно вычислить ни риск, ни прибыль.

#### Scenario: Цена лота вычислена из каталога
- **WHEN** в каталоге акций есть `SBER` с минимальным шагом цены 0.01 ₽ и лотом 100 акций
- **THEN** метаданные содержат `price_step` = 0.01 и `step_cost` = 1.0, а `step_cost / price_step` = 100

#### Scenario: У акции нет ГО и даты экспирации
- **WHEN** загружены метаданные акции
- **THEN** `go_buy` и `go_sell` равны 0, а `expiration_date` равен `None`

#### Scenario: Вызывается каталог акций
- **WHEN** загружаются метаданные акций
- **THEN** вызывается `client.instruments.shares()`, а не `client.instruments.futures()`

#### Scenario: Запрошены только выбранные акции
- **WHEN** выбраны акции `SBER` и `GAZP`
- **THEN** в карту метаданных попадают только `SBER` и `GAZP`

#### Scenario: Акция без лота исключается
- **WHEN** в каталоге акция `SBER` имеет нулевой размер лота
- **THEN** акция не попадает в карту метаданных, в лог пишется предупреждение

### Requirement: Единая карта метаданных выбранных инструментов
Нормативный уровень: MUST.
При старте торговли система ДОЛЖНА собирать метаданные всех выбранных инструментов в одну карту: фьючерсы — из каталога фьючерсов, акции — из каталога акций. Источник данных ДОЛЖЕН соответствовать режиму запуска: в историческом режиме — клиент провайдера истории, в боевом — клиент по токену. Отсутствие метаданных для части выбранных инструментов ДОЛЖНО логироваться с перечислением тикеров и ДОЛЖНО приводить к отказу допуска только по этим инструментам. Сбой загрузки метаданных одного типа инструментов (например, недоступен каталог акций) НЕ ДОЛЖЕН отменять уже загруженные метаданные другого типа.

#### Scenario: Акции и фьючерсы в одной карте
- **WHEN** выбраны фьючерс `NGV6` и акция `SBER`
- **THEN** карта метаданных содержит оба тикера, и сигнал по акции проходит входной допуск

#### Scenario: В историческом режиме используется провайдер истории
- **WHEN** бот запущен в историческом режиме и загружает метаданные акций
- **THEN** запрос выполняется через клиент провайдера истории, а не по боевому токену

#### Scenario: Каталог акций недоступен
- **WHEN** загрузка метаданных акций завершилась ошибкой, а метаданные фьючерсов загрузились
- **THEN** карта содержит фьючерс, акции остаются без метаданных, а вход по акции отклоняется с кодом `no-contract-metadata`

#### Scenario: Перечислены инструменты без метаданных
- **WHEN** метаданные не найдены для части выбранных инструментов
- **THEN** в лог пишется предупреждение с перечислением тикеров, не имеющих метаданных
