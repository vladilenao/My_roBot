## MODIFIED Requirements

### Requirement: Иерархия нотификаторов
Пакет `src/notifier` ДОЛЖЕН предоставлять абстрактный класс `AbstractNotifier`: метод `notify(message)` — абстрактный, принимает только готовый текст сообщения; метод `notify_decision(decision, instrument_label="")` — конкретный, форматирует решение через внедрённый форматтер и доставляет результат через `notify`. Форматтер ДОЛЖЕН внедряться через конструктор нотификатора; по умолчанию используется `DecisionFormatter`. Создание экземпляра `AbstractNotifier` и наследника без реализации `notify` ДОЛЖНО завершаться ошибкой. Форматтер ДОЛЖЕН выдавать компактную однострочную строку вида `● <инструмент> HH:MM | <стратегия> ➜ <сигнал>`, где `HH:MM` — время последнего бара (поле `bar_time` решения), `<стратегия>` — имя стратегии; при отсутствии `bar_time` или имени стратегии их блоки в строке ДОЛЖНЫ опускаться.

#### Scenario: Мостик от решения к доставке
- **WHEN** вызывается `notify_decision` с решением BUY и label «NG-10.26 (1h)», именем стратегии `macd_rsi_stoch` и `bar_time` 22:00
- **THEN** нотификатор доставляет отформатированное решение текстом `● NG-10.26 (1h) 22:00 | macd_rsi_stoch ➜ 🟢 ПОКУПКА (BUY) — Цена: X` единственным вызовом `notify`

#### Scenario: Абстрактный класс нельзя инстанцировать
- **WHEN** выполняется попытка создания экземпляра `AbstractNotifier`
- **THEN** выбрасывается ошибка (класс абстрактный)

#### Scenario: Наследник обязан реализовать notify
- **WHEN** создаётся наследник без переопределения `notify`
- **THEN** создание экземпляра завершается ошибкой

#### Scenario: Подмена форматтера
- **WHEN** в конструктор нотификатора передан альтернативный форматтер
- **THEN** `notify_decision` форматирует решение им, а не `DecisionFormatter` по умолчанию

### Requirement: Компактный формат сигналов
`DecisionFormatter` ДОЛЖЕН оформлять каждое решение одной строкой. Для BUY — `🟢 ПОКУПКА (BUY) — Цена: X`; для SELL — `🔴 ПРОДАЖА (SELL) — Цена: X`; для HOLD — `⏳ Нет сигнала.` без цены. Строка ДОЛЖНА начинаться с маркера `● `; блок времени бара `HH:MM` и блок стратегии `| <имя>` включаются только при наличии соответствующих значений.

#### Scenario: Покупка
- **WHEN** решение имеет тип BUY, цену X, время бара 22:00 и стратегию `macd_rsi_stoch`
- **THEN** сообщение равно `● <label> 22:00 | macd_rsi_stoch ➜ 🟢 ПОКУПКА (BUY) — Цена: X`

#### Scenario: Продажа
- **WHEN** решение имеет тип SELL, цену X, время бара 22:00 и стратегию `macd_rsi_stoch`
- **THEN** сообщение равно `● <label> 22:00 | macd_rsi_stoch ➜ 🔴 ПРОДАЖА (SELL) — Цена: X`

#### Scenario: Нет сигнала
- **WHEN** решение имеет тип HOLD
- **THEN** сообщение содержит `⏳ Нет сигнала.` и не содержит цены

#### Scenario: Нет времени бара
- **WHEN** решение не имеет `bar_time`
- **THEN** блок времени в строке опускается (нет `HH:MM`)

#### Scenario: Нет имени стратегии
- **WHEN** решение не имеет имени стратегии
- **THEN** блок `| <имя>` в строке опускается
