## Context

Консольная лента собирается шаблоном `src/notifier/templates/console_view.py`:

- `when(event, tz_offset_hours, now)` даёт `HH:MM` заголовка. Для `market_data_status` и событий без `bar_time` время переводится в UTC+3 жёстко; для событий с `bar_time` к наивному UTC прибавляется `tz_offset_hours` (из `config.BAR_TIME_TZ_OFFSET_HOURS = 3`).
- `status_row` собирает строку пары группы состояний. Единственное время, которое она форматирует сама, — `expected_bar` через `_bar_clock(..., tz_offset_hours)`. Всё остальное приходит готовым текстом в `reason`.
- Тихая сводка тика в `ConsoleChannel._finish_tick` уже жёстко по Москве.

Текст `reason` для `market_data_status` собирает `LiveAnalysis` (`src/bot/live_analysis.py`):

| Состояние | Текст сейчас | Время в тексте |
|---|---|---|
| барьер 1m (`_execution_barrier`) | `Удержано: базовая 1m не подтверждена до {close−1m:%d.%m.%Y %H:%M} UTC` | наивный UTC + суффикс |
| `INTEGRITY_HOLD` | `Удержано: изменена уже исполненная минута {incident.open_time}` | сырое значение |
| `CONFLICT_HOLD` | `Удержано: расхождение версий свечи, идёт согласующая проверка` | — |
| `GAP_HOLD`, `parked` | `Пропуск {lower}–{upper} не восстановлен; следующая проверка {next_retry_at}` | ISO UTC |
| `GAP_HOLD` | `Восстановление пропуска {lower}–{upper}` | ISO UTC |
| `RECONCILING` | `Согласование потока с историей` | — |
| `BOOTSTRAPPING` + ошибка | `Прогрев: {history_error}` | текст исключения |

К фразе удержания может добавляться `; расписание неизвестно`. Барьер также записывается в `states[key].reason` из цикла причинной обработки (строка с `barrier = self._execution_barrier(...)`).

`market_data_status` рендерит и Telegram (`telegram_templates.render`): `reason` выводится как есть, даты — функцией `dated` с подписью пояса по смещению.

Повтор одинакового состояния ограничивают два места: `StatusCadence.due` (подпись `session, data_state, reason, coverage_complete`) и `ConsoleChannel` (15 минут по `(data_state, reason)`).

## Goals / Non-Goals

**Goals:**
- Любое время, которое видит пользователь в консольной ленте, — московское и в одной короткой записи.
- Фразу с временем собирает шаблон канала из структурированных моментов; каждый канал применяет своё правило пояса.
- Поведение удержаний, их длительность и периодичность сообщений не меняются.

**Non-Goals:**
- Ширина и перенос консольных строк.
- Отчёт исторического прогона, файлы логов, журнал сделок, правила Telegram.
- Разбор произвольного текста исключений (`Прогрев: …`, ошибки загрузки) на моменты.

## Decisions

### D1. Консоль фиксирует UTC+3, смещение — настройка других каналов

Шаблон консоли перестаёт принимать смещение: все моменты переводятся в `timezone(timedelta(hours=3))` (MOEX и FORTS живут по МСК без летнего времени — см. `src/market_calendar/intervals.py`). `ConsoleChannel` и `render`/`render_status_group` теряют параметр `tz_offset_hours`; фабрика (`src/notifier/factory.py`) перестаёт его передавать в консоль, Telegram получает его как раньше.

Наивный момент трактуется как UTC (правило всего проекта), aware — переводится из своего пояса.

**Альтернатива.** Оставить смещение и в консоли, просто вывести через него и моменты причин. Сейчас результат тот же (смещение `3`), но правило консоли осталось бы двойным: заголовок по смещению, время публикации — по Москве. Владелец просил московское время для всей ленты, поэтому один фиксированный пояс проще и честнее.

### D2. Одна функция короткой записи момента

`clock(moment, anchor)` в `console_view.py`:

- `moment` и `anchor` переводятся в UTC+3;
- тот же день, что `anchor`, — `HH:MM`;
- тот же год — `DD.MM HH:MM`;
- иначе — `DD.MM.YYYY HH:MM`.

`anchor` — момент заголовка блока (`bar_time` или `observed_at`/время публикации). Для строк группы состояний якорь — заголовок группы, то есть `observed_at` первого события. `_bar_clock` для `expected_bar` заменяется той же функцией. Пояс не подписывается: в консоли он один.

### D3. Поле `hold` в `market_data_status`

Новое необязательное поле события (добавляется в `_OPTIONAL` схемы и в `Event.market_data_status`):

| `kind` | Поля | Источник |
|---|---|---|
| `execution_barrier` | `through` — момент закрытия бара, до которого не доказан 1m-префикс | `close` из `_execution_barrier` |
| `integrity` | `minute` — открытие изменённой исполненной минуты | `incident.open_time` |
| `conflict` | — | `CONFLICT_HOLD` |
| `gap` | `lower`, `upper`; при `parked` — ещё `next_retry_at` | `ingestion.gap` |
| `reconciling` | — | `RECONCILING` |

Все моменты — tz-aware UTC (`datetime`), чтобы шаблоны не гадали о поясе строк. Неразборчивое значение (`None`, пустая строка) остаётся `None`, и шаблон пишет фразу без времени, как сейчас при пустом `open_time`.

`LivePairState` получает поле `hold: dict | None`; `_hold_reason` превращается в `_hold(...) -> dict | None`, `_execution_barrier` возвращает `dict | None`. `reason` удержания больше не содержит: при удержании без иной причины `reason` пуст, при неизвестном расписании остаётся `Применимое торговое расписание неизвестно`. `Прогрев: {history_error}` остаётся текстом в `reason` — это текст исключения, не момент.

Проверка «есть ли что показать» (`status_label`, `ConsoleChannel._handle_status` для `current`/`waiting_bar` без причины) учитывает `hold` наравне с `reason`, иначе удержание при пустом `reason` станет невидимым.

### D4. Фразы удержания собирает шаблон канала

Консоль (`status_row`) строит фразу из `hold` и якоря группы:

- `execution_barrier` → `Удержано: базовая 1m не подтверждена до {clock(through)}`;
- `integrity` → `Удержано: изменена уже исполненная минута {clock(minute)}`;
- `conflict` → `Удержано: расхождение версий свечи, идёт согласующая проверка`;
- `gap` → `Восстановление пропуска {clock(lower)}–{clock(upper)}` или `Пропуск {…}–{…} не восстановлен; следующая проверка {clock(next_retry_at)}`;
- `reconciling` → `Согласование потока с историей`.

При одновременном `reason` о неизвестном расписании добавляется `; расписание неизвестно`, как сейчас.

Telegram строит те же фразы, но моменты выводит своей функцией `dated` (полная дата и подпись пояса по смещению). Общий словарь фраз — маленькая функция в `src/notifier/templates/`, принимающая форматтер момента; оба канала вызывают её со своим форматтером.

### D5. Граница барьера — время закрытия

Сейчас текст показывает открытие последней минуты (`close − 1m`, `07:59`), а заголовок блока и все `bar_time` проекта — время закрытия (`08:00` → `11:00`). Фраза «не подтверждена до 11:00» с границей по закрытию совпадает с заголовком и читается однозначно: префикс должен быть доказан до момента закрытия бара. Сама проверка `execution_ready(instrument, close − 1m)` не меняется — меняется только момент, который кладётся в `hold.through`.

### D6. Повтор и группировка

`StatusCadence.due` и ключ повтора `ConsoleChannel` включают `hold` (как кортеж `kind` и моментов) рядом с `reason`. Это сохраняет нынешнее поведение: сейчас любой сдвиг времени удержания меняет текст `reason` и считается сменой причины.

## Risks / Trade-offs

- [Внешний читатель фразы удержания из `reason`] → в репозитории таких нет, кроме теста `test_live_causal_processing.py`, который переписывается на `hold`. Telegram получает фразу из `hold`.
- [Буквальные эталоны консоли с временем бара] → сейчас смещение `3`, поэтому заголовки эталонов не меняются; меняются только тесты, которые передавали смещение `0` или иное ради проверки смещения в консоли.
- [Строка без времени при неразборчивом моменте] → лучше, чем выдуманное время; поведение совпадает с нынешним для пустого `open_time`.

## Migration Plan

Сохранённых событий `market_data_status` нет (они не пишутся в базы), поэтому миграция не нужна. Откат — возврат коммита.
