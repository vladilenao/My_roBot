## ADDED Requirements

### Requirement: Контур следит за пульсом ядра
Нормативный уровень: MUST. Процесс торгового контура ДОЛЖЕН отдельным потоком раз в `[contours] heartbeat_secs` читать пульс ядра из `core.sqlite3` только на чтение.

- **Связь потеряна.** Удара нет дольше `[contours] heartbeat_timeout_secs` (по умолчанию 30 с), строки пульса нет или база не читается — связь `lost`. На ближайшей границе тика контур ДОЛЖЕН включить запрет входов `core-lost`.
- **Связь вернулась.** При свежем ударе той же версии связь ДОЛЖНА вернуться в `ok`, запрет ДОЛЖЕН сниматься на ближайшей границе тика. Ударить может как прежнее, так и новое ядро.
- **Ядро остановлено штатно.** При состоянии пульса `stopped` контур ДОЛЖЕН остановиться после текущего тика, как по строке `stop`.
- **Ядро другой версии.** При свежем ударе ядра другой версии контур ДОЛЖЕН остановиться после текущего тика.
- **Ожидание.** Без пульса контур ДОЛЖЕН ждать без ограничения срока и сопровождать открытые сделки по свечам, которые получает.
- **Журнал.** Переходы связи ДОЛЖНЫ записываться в журнал контура: время последнего удара, без значений из `.env`.
- **Снимок.** Состояние связи (`core_link`) ДОЛЖНО попадать в `status.json`.

#### Scenario: Ядро убито
- **GIVEN** контур торгует NG и SBER, `heartbeat_timeout_secs = 30`
- **WHEN** процесс ядра завершён `kill -9`
- **THEN** контур продолжает работать. Через 30 секунд без удара связь `lost`, новые входы отклоняются с причиной `core-lost`, открытая позиция NG сопровождается

#### Scenario: Новое ядро подхватило контур
- **GIVEN** связь контура `lost`
- **WHEN** стартует ядро той же версии и пишет первый удар
- **THEN** на следующей проверке связь `ok`, запрет `core-lost` снят на ближайшей границе тика

#### Scenario: Пришло ядро другой версии
- **GIVEN** контур версии 7.1.0 без связи с ядром
- **WHEN** стартует ядро 7.2.0 и пишет удар
- **THEN** контур доделывает тик, фиксирует журнал и курсор и завершается с кодом 0

### Requirement: Признак жизни контура
Нормативный уровень: MUST. Процесс торгового контура ДОЛЖЕН раз в `heartbeat_secs` обновлять поле `alive_at` в своём `status.json`, в том числе между тиками и без связи с ядром. Запись ДОЛЖНА идти под тем же замком, что запись снимка после тика. При завершении процесса контур ДОЛЖЕН записать `exited_at` и причину выхода (`exit_reason`). Причина — текст без секретов: «команда ядра», «ядро остановлено», «ядро другой версии», «Ctrl+C», «остановка командой ядра». Аварийный выход ДОЛЖЕН оставлять `exited_at` незаписанным.

#### Scenario: Контур ждёт между тиками
- **GIVEN** рынок закрыт, тиков нет
- **WHEN** проходит 15 секунд
- **THEN** `alive_at` в `status.json` обновлён не менее двух раз, `last_tick_at` не изменился

#### Scenario: Штатный выход
- **WHEN** контур завершается по пульсу `stopped`
- **THEN** `status.json` содержит `exited_at` и `exit_reason = "ядро остановлено"`

## MODIFIED Requirements

### Requirement: Жизнь процесса контура
Нормативный уровень: MUST. Ядро ДОЛЖНО держать открытым stdin процесса контура, который оно запустило. Строка `stop` ДОЛЖНА останавливать контур после текущего тика с commit журнала и подтверждением курсора. Конец потока stdin НЕ ДОЛЖЕН останавливать контур. Он ДОЛЖЕН лишь записываться в журнал: о смерти ядра контур судит по пульсу. Ctrl+C ДОЛЖЕН останавливать контур так же, как `stop`.

При своей остановке ядро ДОЛЖНО:

1. записать пульс `stopped`;
2. отправить `stop` своему процессу;
3. ждать завершения контура до 30 секунд;
4. только потом завершить процесс принудительно.

Подхваченный процесс ядро ДОЛЖНО останавливать так же, без stdin. Остановка ядра НЕ ДОЛЖНА менять желаемое состояние контура.

Если процесс контура завершился сам с кодом не 0, ядро ДОЛЖНО:
- записать ошибку в журнал и консоль;
- показать состояние `failed` с кодом выхода;
- НЕ перезапускать контур до следующего старта ядра.

#### Scenario: Штатная остановка
- **WHEN** пользователь нажимает Ctrl+C в консоли робота во время тика контура
- **THEN** контур доделывает тик, фиксирует журнал и курсор и завершается с кодом 0, ядро ждёт его и останавливает свои службы, желаемое «работает» в `core.sqlite3` сохраняется

#### Scenario: Ядро завершилось
- **GIVEN** контур торгует
- **WHEN** процесс ядра завершается аварийно
- **THEN** контур видит конец stdin и продолжает работу, дальнейшее определяет пульс ядра

#### Scenario: Контур упал
- **WHEN** процесс контура завершается с кодом 1
- **THEN** ядро продолжает приём данных, `GET /api/v1/contours` показывает `failed` с `exit_code` 1, торговля сама не перезапускается

### Requirement: Снимок состояния контура для ядра
Нормативный уровень: MUST. После каждого тика и при завершении процесс контура ДОЛЖЕН атомарно записывать в свою папку `status.json`: временный файл и переименование. Состав файла:

- `schema_version`;
- `contour_id`;
- фактическое состояние;
- применённое поколение и режим остановки;
- число открытых позиций и неисполненных входов;
- время последнего тика;
- версия и `pid` процесса;
- `alive_at`, `core_link`, а после выхода — `exited_at` и `exit_reason`;
- время записи.

Файл НЕ ДОЛЖЕН содержать сделки, цены, баланс и секреты. Ядро ДОЛЖНО читать файл для ответа API и для решения о подхвате и автоподъёме при своём старте. Отсутствующий или повреждённый файл НЕ ДОЛЖЕН считаться ошибкой ядра: при старте это означает, что живой контур не подтверждён.

#### Scenario: Снимок после тика
- **WHEN** контур завершил тик с одной открытой позицией
- **THEN** `status.json` содержит `open_positions = 1`, применённое поколение и время этого тика

#### Scenario: Битый снимок
- **WHEN** `status.json` повреждён, а приходит `GET /api/v1/contours`
- **THEN** ответ `200`, поле `actual` равно `null`, остальное состояние показано
