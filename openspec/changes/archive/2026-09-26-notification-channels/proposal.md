## Why

Нотификации устроены как один канал с общим форматтером: `DecisionFormatter` создаётся один раз и внедряется в нотификатор, поэтому разные каналы физически не могут иметь разное представление одного события. Требование `configuration/spec.md:43` прямо запрещало список каналов, что делало невозможным разделение объёма для консоли (отладка) и Telegram (канал сигналов для пользователя).

Консоль в `default.toml` имеет 17 привязок — решения идут на каждый закрытый бар, и все они нужны для отладки. Telegram — канал сигналов для пользователя: если не вошли в сделку, его внимание засорять не нужно. При этом доставка в Telegram синхронная (блокирует торговый поток) и ошибки пишутся в stdout вместо `bot_debug.log`.

## What Changes

- **BREAKING (паттерн):** разводка по каналам строится строго на **Observer (GoF) + Publish/Subscribe (POSA)**. Издатель не знает подписчиков, подписчик фильтрует по типу, доставка неблокирующая. Общий форматтер запрещён, шаблон принадлежит каналу.
- **BREAKING (конфигурация):** `[notifier] channel` → `[notifier] channels` (список, минимум один). Старый ключ принимается как список из одного канала с предупреждением, одновременное указание отвергается. Секреты — только в `.env`.
- **BREAKING (контракт):** `AbstractNotifier` → порт `Channel` с `supported_types` и методом обработки события. Форматтеры переезжают в шаблоны каналов. Методы `notify_*` остаются тонким слоем перевода в типизированные события.
- NEW: пакет `src/events/` — `EventType`, `Event`, `EventBus` (шина не зависит от торговой предметной области).
- NEW: каталог из 19 типов событий с разделением по каналам. Telegram получает только `signal`, `trade_opened`, `stop_hit`, `target_hit`, `trade_closed`. Отказы, недопуски, отмены, служебные — только консоль.
- Разделение `decision` (этап стратегии, до допуска) и `signal` (после допуска, с планом) — рекомендация публикуется только при успешном допуске.
- Торговые события публикуются после коммита SQLite (исключает фантомные уведомления). Доставка Telegram — через очередь и один рабочий поток, с разбиением по 4096, обработкой 429, записью ошибок в `bot_debug.log`.

## Capabilities

### Modified Capabilities
- `notification`: переход на Observer + Pub/Sub, порт `Channel`, каталог типов событий, принадлежность шаблона каналу, публикация после коммита, неблокирующая доставка с изоляцией ошибок.
- `configuration`: список каналов вместо единственного, совместимость со старым ключом `channel`, экспорт `NOTIFIER_CHANNELS`.
