## ADDED Requirements

### Requirement: Возобновление адресного исполнения после блокировки данными
Нормативный уровень: MUST. В текущем режиме симуляция адресных команд ДОЛЖНА обрабатывать доказанно доступные минуты без зависимости от legacy CSV-журнала. После разрешения пропуска она ДОЛЖНА продолжать с долговечной границы исполнения по порядку; при повторном чтении минуты количество, комиссии и финансовый результат НЕ ДОЛЖНЫ применяться дважды. Если данных для текущей переоценки открытой позиции нет из-за остановленного исполнения, риск новых увеличений ДОЛЖЕН оставаться неизвестным до обработки нужных минут, а старые сигналы НЕ ДОЛЖНЫ превращаться в новые входы.

Исключение симулятора до надёжной фиксации событий НЕ ДОЛЖНО продвигать границу исполнения или разрешать дальнейшие бары по этому инструменту в том же непроверенном состоянии. Незавершённый пакет событий ДОЛЖЕН быть повторён с прежней идентичностью, если его безопасный повтор возможен; иначе исполнение ДОЛЖНО возобновляться из долговечного состояния после восстановления, без молчаливого пропуска минуты.

#### Scenario: Адресный симулятор без CSV-журнала
- **WHEN** адресный симулятор создан без legacy CSV-журнала и получает закрытый бар для открытой позиции
- **THEN** бар обрабатывается через адресные события без ошибки обращения к отсутствующему журналу

#### Scenario: Пробел разрешён после перезапуска
- **WHEN** после перезапуска минуту между сохранённой границей и текущими свечами удалось доказанно разрешить
- **THEN** последующие свечи обрабатываются по порядку один раз, позиция получает актуальную переоценку после догоняющей обработки, а старые сигналы не создают входов задним числом

#### Scenario: Исключение до фиксации минуты
- **WHEN** симулятор прервал обработку минуты до надёжной фиксации её событий
- **THEN** курсор остаётся перед этой минутой, последующие минуты не исполняются из частично изменённого состояния, а восстановление не удваивает уже подтверждённые финансовые факты
