## Why

В день с задержкой публикации свечей робот молчит часами, хотя бары рано или поздно
появляются. 2026-09-21 на v4.1.0 за сессию прошло всего два тика (08:56 bootstrap и
09:02:05): бары закрывались в 09:15, 09:30 и далее, но публиковались с задержкой
70–120+ с, превышающей окно ожидания (65 с). Бары, пришедшие после истечения окна,
навсегда выпадали из кандидатов — на следующем тике множество пересечённых границ
пересчитывается заново, и пропущенный бар больше не опрашивается. Дополнительно
защитный ТФ `1m` гейтил цикл жёстким AND по всем загруженным инструментам: один
отстающий/неликвидный инструмент (NG/BR с редкими барами) держал гейт закрытым.
Временный фикс `timeout_secs = 300` закрывает симптом, но не устраняет потерю баров
при отставании больше окна и хрупкость гейта.

## What Changes

- **Догон поздно опубликованных баров**: пройденная в прошлом тике граница, для
  которой свежий бар не опубликован в окне, остаётся кандидатом на следующем тике и
  повторно опрашивается в пределах горизонта догона (несколько интервалов), пока
  бар не появится. Пропущенный бар теряется только за пределами горизонта.
- **Терпимость готовности к отстающим инструментам**: признак «свежий закрытый бар
  ТФ» считается на уровне пары (инструмент, ТФ); отстающие пары не блокируют
  обработку готовых. Защитный гейт `1m` учитывает только инструменты с фактической
  активностью за недавнее окно и не «замирает» из-за одного неликвидного
  инструмента.
- **Плавная восстановительная загрузка**: стартовые/восстановительные загрузки
  (включая валидацию инструментов при выборе) выстраиваются в очередь с тем же
  минимальным интервалом перезагрузки, чтобы догон после простоя не выжигал лимит
  API и не падал в `RESOURCE_EXHAUSTED`.
- Внешне для пользователя поведение не меняется: анализ выполняется по каждому
  свежему закрытому бару; дополнительно поздно пришедшие бары теперь обрабатываются
  в пределах горизонта догона вместо беззвучной потери.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `timing`: ожидание публикации бара не теряет границы, чей бар не появился в окне
  ожидания: такие границы повторно опрашиваются на последующих тиках в пределах
  горизонта догона.
- `data-cache`: готовность пары (инструмент, ТФ) не блокируется отстающими парами
  того же ТФ; дозагрузка допускает догон баров, не опубликованных в прошлые окна
  ожидания; стартовые и восстановительные загрузки троттлятся минимальным интервалом
  перезагрузки.
- `instruments`: валидация инструментов при выборе выполняется с паузой (не чаще
  минимального интервала перезагрузки) и приостанавливается при исчерпании лимита
  API до сброса лимита.

## Impact

- Код: `src/scheduler/timing.py` (`wait_until_bar_published`, множество кандидатов и
  горизонт догона), `src/data/cache.py` (`has_fresh_closed_bar`, готовность по
  паре, троттлинг восстановительной загрузки), `src/instruments/selector.py`
  (троттлинг валидации), `src/bot/trading_bot.py` (обработка поздних готовых баров,
  гейт защитного тика), `src/config.py`/`robot.toml` (горизонт догона, допуск
  свежести для защитного ТФ).
- Инфраструктура: остаётся релизный временный фикс `tick.timeout_secs = 300`; после
  внедрения догона окно ожидания можно вернуть к короткому значению (65 с) без риска
  потерять бары.
- Тесты: `tests/unit/` — догон позднего бара по границе/горизонту, потеря только за
  горизонтом, готовность пары при отстающем соседе, защитный гейт с неликвидным
  инструментом, троттлинг восстановительной загрузки.
