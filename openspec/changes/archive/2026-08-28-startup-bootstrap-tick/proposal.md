## Why

При запуске бот ждёт ближайшей календарной границы закрытия свечи и только потом выполняет первый тик. Запустив бота в 9:58 с таймфреймом 1h, пользователь получает первое сообщение в 10:00 — про свечу 9:00–10:00 (в терминах «по моменту закрытия» — «свеча на 10:00»). Ожидание пользователя иное: первый тик должен выполняться сразу при запуске и анализировать последнюю уже закрытую свечу 8:00–9:00 («свеча на 9:00»). Дополнительно сообщения показывают время бара как момент НАЧАЛА свечи, тогда как пользователь мыслит категорией момента ЗАКРЫТИЯ — уведомления должны показывать время закрытия свечи.

## What Changes

- Первый тик при запуске выполняется немедленно, без ожидания ближайшей границы закрытия; анализирует последнюю закрытую свечу и доставляет по ней решение.
- Bootstrap-ожидание: если запуск приходится точно на границу и свежий закрытый бар ещё не опубликован (задержка публикации Tinkoff), первый тик ограниченно ожидает появления свежего закрытого бара (тот же таймаут, что в штатном цикле), прежде чем обработать данные; если бар так и не появился — обрабатывает с имеющимися данными.
- Сообщения уведомлений: блок времени `HH:MM` показывает момент ЗАКРЫТИЯ свечи (`bar_time + период таймфрейма`, затем сдвиг пояса), а не момент начала.
- Поведение последующих тиков не меняется: они по-прежнему выравниваются по границе закрытия свечи, решения принимаются только по закрытым свечам.

## Capabilities

### New Capabilities

Нет новых capability.

### Modified Capabilities
- `orchestration`: Добавляется bootstrap-фаза первого тика при запуске — немедленная обработка последней закрытой свечи с ограниченным ожиданием свежего закрытого бара; последующие тики остаются выровненными по границе закрытия.
- `notification`: Блок времени `HH:MM` в сообщении отображает момент закрытия свечи (`bar_time + период`) вместо момента начала.

## Impact

- `src/bot/trading_bot.py` — `_loop()` / `_tick()`: bootstrap-тик при запуске.
- `src/data/cache.py` — косвенно: первичное наполнение кадров и дозагрузка на старте (дальнейшие детали в design).
- `src/notifier/base.py` — `DecisionFormatter`: время закрытия свечи; потребуется знание периода таймфрейма.
- `src/scheduler/timing.py` — возможна новая операция ограниченного ожидания свежего бара без ожидания границы (либо реализация в оркестраторе).
- `src/config.py` — возможно, параметр периода таймфрейма для форматтера.
- Тесты: `tests/unit/bot/test_trading_bot.py`, `tests/unit/notifier/test_formatter.py`, при необходимости `tests/unit/scheduler/test_timing.py`.
