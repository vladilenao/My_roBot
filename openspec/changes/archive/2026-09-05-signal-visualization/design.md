## Context

См. proposal.md. Пилот — `macd_rsi_stoch`, чей дизайн согласован с пользователем на едином прототипе (классические бары, зоны осцилляторов, пунктиры окна анализа, горизонтальный текст справа). Данные: `BR_1h`/`NG_1h` содержат и BUY, и SELL события. Индикаторы `macd_rsi_stoch`: MACD (12/26/9), RSI (14), Stochastic (14/3/3) — колонки в `ta` после `compute()`.

## Goals / Non-Goals

**Goals**
- Утилита `tools/visualize_signals.py`, генерирующая SVG-картинки BUY/SELL для любой стратегии через реестр.
- Отрисовка по согласованному дизайну и встраивание картинок в спек по root-relative пути.
- Smoke-тест генератора на существующих фикстурах.

**Non-Goals**
- Визуализация для flat_triangle и harmonic_abcd — последующие изменения (конфиг панелей заложен, но панели этих стратегий не реализуем в этом change).
- Интерактивные графики, HTML, PNG-бинарники; только SVG.
- Изменение кода бота (`src/`) — картинки это документирующий инструмент.

## Decisions

- **D1. SVG + root-relative путь.** Изображения — векторизация, рендерятся на GitHub/в IDE; ссылка `/openspec/assets/signals/<файл>` не зависит от глубины дерева и переживает перенос дельты в main-спек (проверено в прототипе spec-image-demo: data-URI выживает, относительный путь ломается; root-relative — альтернатива без раздувания спека на ~100 КБ base64).
- **D2. Окно рисования** — 40 свечей до входа, 8 после (ровно как в одобренном прототипе). Окно анализа «тонким пунктиром» = `ei − STRATEGY_WINDOW` (для macd_rsi_stoch `ei − 4`), жирный пунктир — на `ei`.
- **D3. Панели через конфиг.** `PANEL_CONFIG[strategy] = [правила панелей]`: каждая панель описывает колонки, зоны, подписи, текстовый генератор. В этом change реализуем только `macd_rsi_stoch` (price/MACD/RSI/Stoch), но скелет расширяем.
- **D4. Описания по событиям, не по суммам.** Справа от панели — человекочитаемые события индикаторов за окно стратегии (получены из `ta[<инд>_signal]` на последних `STRATEGY_WINDOW` барах) + текущие значения. Суммарные «перевесы» (macd_sum и т.п.) в тексте не показываем — прототип показал, что они неочевидны.
- **D5. matplotlib только в dev-зависимостях.** `requirements-dev.txt`; в run-time `src/` matplotlib не импортируется.
- **D6. Точный поиск событий.** Первое BUY/SELL берётся из `expected_signals.csv` кейса (фиксированный порядок — как в helper). Бар входа = индекс даты события в `ta`.

## Risks / Trade-offs

- Root-relative путь рендерится GitHub-приложением; в некоторых локальных просмотрщиках markdown может не работать без веб-окружения — выбираем GitHub/IDE как эталон.
- SVG от matplotlib содержит текстовые подписи кириллицей — нужно убедиться, что шрифт с поддержкой кириллицы доступен (`DejaVu Sans` в matplotlib есть).
- Описание для каждой стратегии индивидуально — объём кода растёт с числом панелей; ограничиваем пилотом.

## Migration Plan

1. Создать `tools/visualize_signals.py` (кли, reестр стратегий, PANEL_CONFIG, рендер).
2. Сгенерировать `openspec/assets/signals/macd_rsi_stoch_BUY.svg` и `_SELL.svg`.
3. Добавить `matplotlib` в `requirements-dev.txt`.
4. Добавить `tests/snapshot/test_visualization.py`.
5. `openspec validate`, `pytest`.
6. Sync дельты в main-спек с root-relative ссылками, archive.

Откат: удалить утилиту, тест, `openspec/assets/signals/` и main-спек; вернуть `requirements-dev.txt`.
