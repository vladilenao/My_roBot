## MODIFIED Requirements

### Requirement: Неизменяемый вход тика и разделение курсоров
Нормативный уровень: MUST. Торговый тик ДОЛЖЕН читать согласованный неизменяемый срез версий входных свечей; конкурентная коррекция НЕ ДОЛЖНА менять OHLC уже начатого исполнения. Получение, непрерывное разрешение, анализ и исполнение ДОЛЖНЫ иметь разные границы. Input-revision ссылки начатого/обработанного пакета ДОЛЖНЫ сохраняться в рыночном состоянии для безопасного продолжения после сбоя, без миграции финансовой истины в рыночный кэш. Исполнительный cursor продвигается только после существующего durable commit; receipt или warmup его не меняют.

Отметки исполнения ДОЛЖНЫ храниться под идентификатором торгового контура: закрепление входа, граница обработки и курсор анализа привязки. Контур ДОЛЖЕН записывать в рыночную базу только эти свои отметки. Запись отметки без идентификатора контура ДОЛЖНА отклоняться. Отметки одного контура НЕ ДОЛЖНЫ сдвигать отметки другого. При миграции базы существующие отметки ДОЛЖНЫ перейти контуру `emulation` в одной транзакции.

#### Scenario: Исправление во время тика
- **WHEN** новая версия пришла между чтением среза и commit финансовых фактов
- **THEN** начатый пакет сохраняет выбранную версию, исправление учитывается отдельно и не создаёт второе исполнение этой минуты

#### Scenario: Рестарт после финансового commit
- **WHEN** финансовая обработка минуты завершена, а market-marker ещё не записан
- **THEN** сверка использует сохранённый input-reference контура и существующую durable границу сделки, не проигрывает исправленную минуту заново

#### Scenario: Миграция существующих отметок
- **GIVEN** база до изменения содержит `processed_through` 10:15 для NG 1m, закрепление входа 10:16 и курсор анализа привязки `ng-1h-abcd`
- **WHEN** робот новой версии открывает базу
- **THEN** все три отметки принадлежат контуру `emulation` с теми же значениями, эмуляция продолжает с 10:16 без повторного исполнения

#### Scenario: Запись отметки без контура
- **WHEN** код ядра вызывает запись границы обработки без идентификатора контура
- **THEN** запись отклоняется ошибкой, база не меняется

## ADDED Requirements

### Requirement: Кэш контура только читает рыночные данные
Нормативный уровень: MUST. Кэш свечей торгового контура (ведомый кэш) НЕ ДОЛЖЕН записывать свечи, состояния интервалов, курсоры получения и разрешения, готовность пар и факты удержания. Решение «интервал закрыт по применимому расписанию» ведомый кэш ДОЛЖЕН вычислять по тем же правилам, что ядро, но НЕ ДОЛЖЕН сохранять его в базу. Готовность пары (`pair_status`) ведомый кэш ДОЛЖЕН собирать из опубликованной ядром готовности, курсоров, фактов удержания и границ обработки своего контура. Набор полей ДОЛЖЕН совпадать с ответом кэша ядра.

#### Scenario: Пробел в закрытые часы
- **GIVEN** у интервала 19:00 нет свечи, состояние `pending`, а по расписанию биржа закрыта
- **WHEN** ведомый кэш проверяет покрытие кадра
- **THEN** интервал считается закрытым по расписанию, а в базе по-прежнему `pending`, пока его не разрешит ядро

#### Scenario: Готовность пары из базы
- **GIVEN** ядро опубликовало для NG 1m состояние `READY`, транспорт `stream` и границу запуска 09:58
- **WHEN** контур спрашивает `pair_status` этой пары
- **THEN** ответ содержит те же состояние, транспорт и границу, что ответ кэша ядра, а граница обработки взята из отметок контура
