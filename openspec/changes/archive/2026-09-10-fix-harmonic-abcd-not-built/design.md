## Context

См. proposal.md — Why: `harmonic_abcd` объявлена в привязках (`config.py` → `SHARE_STRATEGIES`/`FUTURE_STRATEGIES`), но отсутствует в `_strategy_map()` в `run.py`. Кэш стратегий оркестратора (`TradingBot._strategy_cache`) строится только из `strategy_map` (trading_bot.py:183-191), а `_analyze` берёт имена для обработки из привязок инструмента (trading_bot.py:141). Рассинхрон двух источников правды даёт `cache.get(name) is None` → предупреждение «не построена» на каждый тик.

Существующий fail-fast (`TradingBot._validate`, trading_bot.py:174-179) вызывает `validate_assignments`, который сверяет имена с **реестром** стратегий (`src.strategies.registry`), а не с `strategy_map`. Реестр знает `harmonic_abcd` (auto-discovery), поэтому проверка проходила, хотя стратегия не строилась.

## Goals / Non-Goals

**Goals:**
- Восстановить работу `harmonic_abcd` в штатной сборке (`run.py`).
- Сделать рассинхрон «привязки ↛ strategy_map» стартовой ошибкой, а не бесконечным warning на каждый тик.
- Сохранить существующий контракт `strategy_map` (имя → конфиг) как единственный источник построимости стратегий.

**Non-Goals:**
- Не меняем поведение и контракты стратегий (`harmonic_abcd`, `macd_rsi_stoch`, `flat_triangle`).
- Не меняем механику реестра (`validate_assignments` против реестра остаётся).
- Не выпиливаем защитное предупреждение «не построена» из `_analyze` — оно остаётся как дефензивная ветка.

## Decisions

**D1: Проверять согласованность привязок с `strategy_map` в `TradingBot._validate()`.**
`_validate` — уже существующая fail-fast точка (вызывается до цикла из `run()`). После `validate_assignments` добавляется проверка: каждое имя из значений `_share_strategies` и `_future_strategies` обязано быть ключом `_strategy_map`. Отсутствующие имена собираются и выбрасывается `ValueError` с их перечислением.

*Почему здесь, а не в `run.py`:* растроение уже существующего слоя fail-fast; проверка работает и для тестов/других точек входа, которые конструируют `TradingBot` напрямую (tests/unit/bot/test_trading_bot.py). `run.py` — лишь один из потребителей.

*Альтернатива (отклонена):* проверять только в `run.py`. Закрывает конкретный баг, но не дыру: любой будущий потребитель `TradingBot` повторит рассинхрон. Проверка живёт рядом с предметом рассинхрона (карта vs привязки).

**D2: Фикс в `run.py` — добавить `harmonic_abcd` в `_strategy_map()`.** Импорт `DEFAULT_CONFIG` из `src.strategies.harmonic_abcd_strategy`, добавление в словарь. Это соответствует уже принятому паттерну других стратегий (импорт DEFAULT_CONFIG, no hardcode логики).

**D3: Использовать `strategy_map` как источник «построимости».**
Кэш строится из `strategy_map`; наличие ключа = стратегия будет построена. Если ключ есть, но `get_strategy` упадёт (имя не зарегистрировано), это уже ловится при форсировании кэша в `_validate` (`_ = self._strategy_cache`). Дыр (незарегистрированное имя в карте) закрыта существующим кодом; новая проверка закрывает обратную пару (имя в привязке, но не в карте).

*Альтернатива (рассмотрена, не выбрана в этом скоупе):* полностью убрать ручную `_strategy_map()` и выводить карту автоматически из привязок через реестр (каждый `DEFAULT_CONFIG` стратегии). Устраняет класс бага целиком, но меняет контракт `TradingBot(strategy_map=...)` и дизайн карты имя→конфиг (потенциально нужна для будущих параметров стратегий). Отложено — см. Open Questions.

## Risks / Trade-offs

- [Новая проверка может сломать существующие тесты/точки входа с рассинхроненными fixture] → Mitigation: задача в tasks.md на аудит всех вызовов `TradingBot(...)` в тестах; в реальном коде запуск валиден только против `run.py`.
- [Защитное предупреждение «не построена» остаётся недостижимым при штатном запуске → ложное ощущение «мёртвого кода»] → Mitigation: признано осмысленным как дефензивная ветка (прямой вызов `_analyze`, ручные кейсы); не увеличивает стоимость кода.

## Migration Plan

- Развёртывание: правки атомарны в одном коммите (`run.py` + `trading_bot.py` + тесты). Обратной совместимости не ломают: при согласованных данных поведение не меняется, добавляется только стартовая проверка.
- Откат: revert коммита; при повторном запуске старый код вернёт warning «не построена» для `harmonic_abcd`, статус-кво.

## Open Questions

- Надо ли со временем убрать ручную `_strategy_map()` и выводить построимость автоматически из реестра (D1-альтернатива)? Не влияет на этот фикс; решение безопасно отложить до появления реальных параметров стратегий, требующих не-дефолтный конфиг.
