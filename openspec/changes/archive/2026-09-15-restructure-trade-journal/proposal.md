# Реструктуризация журнала сделок: лента исполнений + карточки позиций

## Why

Текущий журнал сделок — один плоский CSV, где строка-событие несёт 23 колонки сразу под заявку, вход, выход и снимок: статус `FILLED` перегружен (помечаются и вход, и закрытие), поэтому тип операции приходится угадывать по заполненности колонок, а «мёртвые» пустые ячейки делают файл нечитаемым. По нему невозможно проследить всю жизнь позиции (вход → добор → частичные тейки → выход). Там же нарушается пользовательский формат: контракт пишется сырым тикером (`NGV6` вместо `NG-10.26`), времена — в UTC (консоль показывает МСК).

## What Changes

- **BREAKING**: плоский `trade_journal.csv` заменяется двухфайловой моделью:
  - `journal.csv` — append-only лента исполнений и снимков (`ВХОД`, `ДОБОР`, `ТЕЙК`, `ВЫХОД`, `СНИМОК`, `ОТМЕНА`) — источник истины для восстановления состояния при перезапуске;
  - `positions.csv` — производная карточка позиций: одна строка = вся жизнь позиции (вход, добор, тейки, выход, накопленные PnL/комиссия/ГО), пересчитывается из `journal.csv`, без пустых ячеек.
- В журнале тип операции становится явной колонкой; статус `FILLED` теряет двойной смысл — «исполнена» остаётся характеристикой заявки, а вход/выход различаются типом записи, а не заполненностью колонок.
- Строки одной позиции линкуются по `position_id` — от входа через доборы/частичные тейки до закрытия.
- Пользовательский формат журнала: контракт ВСЕГДА коротким именем (`NG-10.26`), времена — МСК (совпадают с консолью), отсутствуют системно-пустые колонки.
- Структура готова к доборам и частичным тейкам (структуры поддерживают, даже если движок пока не генерирует такие операции).

## Capabilities

### New Capabilities
- `trade-journal`: структура и семантика журнала сделок — append-only лента исполнений/снимков, производные карточки позиций, типы операций (ВХОД/ДОБОР/ТЕЙК/ВЫХОД/СНИМОК/ОТМЕНА), восстановление состояния из ленты при перезапуске, линковка по `position_id`, пользовательский формат (короткое имя контракта, время МСК, без пустых колонок).

### Modified Capabilities
- `configuration`: секция `[trading]` дополняется опцией `positions_file` (имя файла карточек позиций; по умолчанию производное от `journal_file`). Текущий контракт `journal_file` сохраняется для ленты исполнений.

## Impact

- `src/trade_journal/journal.py` — новая структура: писатель ленты, пересчёт карточек позиций, реплей состояния из `journal.csv`; `JournalEvent`/`RestoredOrder`/`RestoredPosition` пересобираются под новые типы операций и колонки.
- `src/broker/journal_broker.py` — построение строк журнала по новым типам операций; снимок клиринга → `СНИМОК`; имя контракта в записях — короткое имя (`NG-10.26`), не сырой тикер.
- `src/broker/exec_adapter.py`, `src/execution/port.py` — проброс короткого имени контракта в пользовательские сообщения и журнал (внутренние ключи остаются на тикере).
- `src/config.py`, `src/config_loader.py` — опция `positions_file`.
- Существующий `trade_journal.csv` содержит повреждённую склеенную строку; в рамках изменения — очистка/миграция.
- Тесты: `tests/unit/trade_journal`, `tests/unit/broker`, `tests/integration/test_trading_simulation.py` переписываются под новую структуру; добавляются тесты на карточки позиций и линковку жизни позиции.
