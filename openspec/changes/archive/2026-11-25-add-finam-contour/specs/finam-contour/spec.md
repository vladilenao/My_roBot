## ADDED Requirements

### Requirement: Контур «Счёт Финам» отдельным процессом
Нормативный уровень: MUST. Контур на брокере `finam` вида «счёт» на брокере Финам ДОЛЖЕН работать процессом `run.py --contour finam`, который запускает ядро. Каталог — `data/contours/finam/`, состав файлов — как у «Счёта». Контур ДОЛЖЕН работать одновременно с `account` и `sandbox`, их поведение не меняется.

В этой версии адаптер Финама не умеет заявки, и контур ДОЛЖЕН работать только на чтение:

- НЕ ДОЛЖЕН ставить и снимать заявки и стоп-заявки;
- НЕ ДОЛЖЕН читать свечи и заявлять спрос в ленте ядра;
- НЕ ДОЛЖЕН строить торговую часть.

Карточки контура ДОЛЖНЫ уходить в канал Финама с меткой «СЧЁТ ФИНАМ».

#### Scenario: Три контура на брокере
- **GIVEN** работают контуры `account` и `sandbox`
- **WHEN** ядро запускает контур `finam`
- **THEN** работает процесс `run.py --contour finam`, его лог, `status.json` и `broker.sqlite3` лежат в `data/contours/finam/`, процессы `account` и `sandbox` работают дальше

#### Scenario: Только чтение
- **WHEN** контур `finam` проходит любое число шагов
- **THEN** в вызовах API Финама нет `PlaceOrder`, `CancelOrder` и `PlaceSLTPOrder`

### Requirement: Транспорт Финама
Нормативный уровень: MUST. Адаптер Финама ДОЛЖЕН работать с Finam Trade API по gRPC на `api.finam.ru:443` через свой транспорт на заглушках `src/finam/proto`. Адаптер НЕ ДОЛЖЕН импортировать код разведки `src.finam` (кроме `src.finam.proto`), `src.broker_contour.tinvest`, `src.sandbox` и `t_tech`. Ошибка вызова ДОЛЖНА становиться ошибкой вызова брокера с кодом gRPC и текстом Финама в одну строку. Объект исключения не логируется.

#### Scenario: Граница адаптера
- **WHEN** тест разбирает импорты модулей `src/broker_contour/finam/`
- **THEN** среди них нет `src.finam` кроме `src.finam.proto`, нет `src.broker_contour.tinvest`, `src.sandbox` и `t_tech`

### Requirement: JWT Финама — один источник
Нормативный уровень: MUST. JWT ДОЛЖЕН хранить один объект адаптера. Он получает JWT `Auth` по `FINAM_SECRET_TOKEN` при входе, затем — стримом `SubscribeJwtRenewal`. Каждый JWT ДОЛЖЕН регистрироваться секретом лога до того, как станет текущим. Если стрим оборвался, его ДОЛЖНО переоткрыть с паузой 5, 10, 30, 60 с. Пока стрима нет, а текущему JWT больше 10 минут, перед вызовом ДОЛЖЕН выполняться `Auth`. Вызовы `AuthService` и стрим обновления ДОЛЖНЫ идти без заголовка `authorization`.

#### Scenario: Смена JWT
- **GIVEN** стрим обновления прислал новый JWT
- **WHEN** контур делает следующий вызов
- **THEN** вызов идёт с новым JWT, и ни один JWT не встречается в логе, `status.json`, событиях канала и ответах API

#### Scenario: Обрыв стрима обновления
- **GIVEN** стрим `SubscribeJwtRenewal` закрылся с ошибкой, текущему JWT 11 минут
- **WHEN** контур делает вызов до переподписки
- **THEN** перед вызовом выполнен `Auth`, вызов идёт с новым JWT, стрим переоткрыт после паузы

### Requirement: Лимит запросов Финама
Нормативный уровень: MUST. На `RESOURCE_EXHAUSTED` транспорт ДОЛЖЕН прочитать `GetUsageMetrics`, взять `reset_time` квоты вызванного метода и повторить вызов через 1 с после него, но не позже чем через 65 с. Повторов — не больше двух. Квоты нет или `GetUsageMetrics` не ответил — пауза 60 с. Повторы исчерпаны — ошибка вызова `RESOURCE_EXHAUSTED`. Других повторов по лимиту в адаптере НЕ ДОЛЖНО быть.

#### Scenario: Повтор после сброса квоты
- **GIVEN** `GetAccount` ответил `RESOURCE_EXHAUSTED`, квота `GetAccount` сбрасывается через 12 с
- **WHEN** адаптер читает счёт
- **THEN** через 13 с `GetAccount` вызывается снова, и снимок прочитан

### Requirement: Окно обслуживания Финама
Нормативный уровень: MUST. Недоступность API Финама (`UNAVAILABLE`, `DEADLINE_EXCEEDED`, отказ `Auth`) с 05:00 до 06:15 МСК ДОЛЖНА давать `BrokerOutage`. Вне окна — обычная ошибка вызова.

#### Scenario: Сверка в окне
- **GIVEN** 05:30 МСК, API Финама недоступен
- **WHEN** наступает сверка
- **THEN** сверка пропущена без тревоги, `account_link` — `maintenance`, счётчик пропусков не растёт

#### Scenario: Недоступность вне окна
- **GIVEN** 12:00 МСК, API Финама недоступен три сверки подряд
- **WHEN** проходит третья сверка
- **THEN** в канал Финама уходит тревога «Счёт недоступен: три сверки подряд пропущены.»

### Requirement: Допуск контура «Счёт Финам»
Нормативный уровень: MUST. Допуск ДОЛЖЕН идти по порядку:

1. без сети — `FINAM_SECRET_TOKEN`, `FINAM_ACCOUNT_ID`, бот и канал Финама;
2. `TokenDetails`: счёт токена ровно один, и это `FINAM_ACCOUNT_ID`; права — `read_only` при `readonly`, иначе `full_access`;
3. факты: квоты из `GetUsageMetrics`;
4. отпечаток `broker = finam` в `data/contours/finam/broker.sqlite3`;
5. снимок счёта.

Отказ на шагах 2–5 ДОЛЖЕН уходить тревогой в канал Финама. Номера счетов из `TokenDetails` ДОЛЖНЫ регистрироваться секретами до проверки; в причине — только последние четыре символа. Факты ДОЛЖНЫ содержать `access_level`, `limits` (квоты методов контура в минуту) и `warnings`, без полей, которых Финам не сообщает.

#### Scenario: Токен видит два счёта
- **GIVEN** в `TokenDetails` два счёта
- **WHEN** контур `finam` стартует
- **THEN** процесс выходит с кодом 2, в канал Финама уходит тревога с числом счетов и их последними четырьмя символами, полных номеров нет нигде

#### Scenario: Номер не совпал
- **GIVEN** токен видит один счёт, а `FINAM_ACCOUNT_ID` задаёт другой
- **WHEN** контур `finam` стартует
- **THEN** процесс выходит с кодом 2, причина «Токен видит счёт …XXXX, а FINAM_ACCOUNT_ID задаёт другой»

#### Scenario: Чужой отпечаток
- **GIVEN** в `data/contours/finam/broker.sqlite3` отпечаток другого счёта
- **WHEN** контур `finam` стартует
- **THEN** процесс выходит с кодом 2, тревога называет последние четыре символа записанного счёта

### Requirement: Снимок счёта Финама
Нормативный уровень: MUST. Снимок ДОЛЖЕН строиться из `GetAccount` и `GetOrders`:

- деньги — сумма строк `cash` в RUB; у пустого счёта `cash` нет — 0;
- ликвидный портфель — `equity`; нет — `null`;
- позиции — строки `positions` с `quantity ≠ 0`; лоты фьючерса — `quantity`, лоты акции — `quantity` ÷ лот карточки ядра; нецелое число лотов — снимок противоречив, как у «Счёта»;
- заявки — активные биржевые заявки; стоп-заявки — активные `ORDER_TYPE_STOP` и `ORDER_TYPE_STOP_LIMIT`;
- `names` — UID карточки ядра → короткое имя; символ без карточки — «инструмент не указан» и в `names` не входит.

#### Scenario: Результат сделки второй строкой
- **GIVEN** `cash` — RUB 30000 и RUB −8,21, позиция NG с `quantity` 0
- **WHEN** контур читает счёт
- **THEN** `capital.rub` — 29991.79, позиций нет

#### Scenario: Пустой счёт
- **GIVEN** `GetAccount` без `equity`, `cash` и позиций
- **WHEN** контур читает счёт
- **THEN** `capital.rub` — 0.00, `capital.liquid_portfolio` — `null`, позиций, заявок и стоп-заявок нет

### Requirement: Инструменты Финама
Нормативный уровень: MUST. Соответствие инструмента ДОЛЖНО строиться по карточке ядра из `InstrumentCatalog`, переданного адаптеру точкой сборки. `symbol` — из `Assets` по биржевому тикеру карточки: не архивный, на RTSX у фьючерса и MISX у акции. Шаг цены Финама (`min_step / 10^decimals`) ДОЛЖЕН совпадать с шагом карточки. Лот ДОЛЖЕН совпадать с лотом карточки: у фьючерса — `trade_lot_size`, у акции — `lot_size`. Расхождение — ошибка соответствия с коротким именем и полем. ГО ДОЛЖНО читаться из `GetAssetParams` при каждом запросе, без кэша.

#### Scenario: Фьючерс на RTSX
- **GIVEN** в `Assets` тикер контракта Si есть на RTSX и на другой площадке
- **WHEN** адаптер ищет `symbol` для карточки Si
- **THEN** выбран `symbol` на RTSX, шаг и лот совпали

#### Scenario: Шаг не совпал
- **GIVEN** у Финама шаг инструмента 0.01, в карточке ядра 0.001
- **WHEN** адаптер ищет `symbol`
- **THEN** ошибка соответствия называет короткое имя и «шаг»

#### Scenario: ГО плавает
- **GIVEN** `GetAssetParams` ответил 7 390 ₽, затем 8 637 ₽
- **WHEN** адаптер дважды читает ГО
- **THEN** второе чтение — 8 637 ₽

### Requirement: Секреты контура «Счёт Финам»
Нормативный уровень: MUST. `FINAM_SECRET_TOKEN`, `FINAM_ACCOUNT_ID`, токен бота Финама, каждый JWT и каждый номер счёта из `TokenDetails` ДОЛЖНЫ заменяться на `[скрыто]` в логе. Их НЕ ДОЛЖНО быть в `status.json`, `broker.sqlite3`, событиях канала и ответах API. Номер счёта для человека — последние четыре символа.

#### Scenario: Секреты нигде
- **GIVEN** контур прошёл допуск и сменил JWT
- **WHEN** тест читает лог, `status.json`, события канала и ответы `/api/v1/finam/*`
- **THEN** ни секрета, ни номера счёта, ни одного JWT в них нет
