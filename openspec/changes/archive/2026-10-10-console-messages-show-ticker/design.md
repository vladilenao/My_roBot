## Context

См. `proposal.md — Why`. Внутренний `order_id` сейчас попадает в консольный текст
в двух шаблонах (`src/notifier/templates/deal.py`): `order_accepted` печатает
`(id=<order_id>)`, а `trade_cancelled` печатает `Заявка <order_id> …`. Для отмены по
таймауту входа событие приходит не от брокера напрямую, а через
`execution_observer` (`run.py:publish_execution`), где `order_id` не заполняется —
отсюда `None`.

Консоль использует только текстовые шаблоны `src/notifier/templates/*`; Telegram
имеет собственные HTML-шаблоны (`telegram_templates.py`), куда `order_id` не
выводится, поэтому изменение консоли их не затрагивает.

## Goals / Non-Goals

**Goals:**
- Консольные сообщения о заявке показывают короткое имя инструмента.
- Внутренний `order_id` не выводится в пользовательский текст ни в одном из
  издателей `trade_cancelled`/`order_accepted`.

**Non-Goals:**
- Не менять формат Telegram-карточек и CSV-журнала.
- Не убирать `order_id` из структурированного payload события (нужен для
  корреляции и дедупликации delivery).
- Не менять сами торговые решения/исполнение.

## Decisions

**Источник текста — шаблон канала, а не издатель.** Формат консольной строки
меняется только в `deal.py`; издатели лишь обязаны передать в событие
`instrument`. Альтернатива «собирать строку в брокере» отклонена: она нарушает
требование «События исполнителя структурированы: текст формируется шаблоном
канала».

**`instrument` обязателен для `trade_cancelled`.** Путь через
`execution_observer` уже передаёт `instrument` (`run.py:515`). Прямые издатели
брокера (`cancel_order`, `_expire_order`) сейчас передают только `order_id`,
поэтому в их `_publish_event` добавляется `instrument=self._display(order.ticker)`.
`_display` уже отдаёт короткое имя либо заглушку `контракт не указан` — совпадает
с требованием spec.

**Фолбэк на пустой инструмент.** Если по какой-то причине `instrument` пуст,
консоль выведет `Заявка  отменена`; полагаемся на то, что все издатели
гарантируют `_display`-заглушку. Альтернатива — скрывать инструмент при пустом
значении — даёт нечитаемую строку, поэтому отклонена.

**Формулировки.** Сохраняется причину в скобках и отдельная фраза для TTL
(`истекла по TTL`) — как в текущем `deal.py`, меняется только подставляемое
значение (`instrument` вместо `order_id`). Формат `order_accepted` теряет хвост
`(id=…)` и остаётся в прежнем виде до него.

## Risks / Trade-offs

- [Изменение текста может задеть snapshot-тесты консоли] → полный прогон
  `pytest`; релевантных snapshot-эталонов с этими строками нет (в snapshot-данных
  встречается только CSV-формулировка `Заявка принята: …`, которая принадлежит
  `trade-journal`, а не `notification`).
- [Прямые издатели брокера могут не иметь `ticker` при восстановлении] →
  используется существующий `_display`, который уже покрывает неизвестное имя
  заглушкой.
- [Пользователь привык видеть `id`] → принцип «внутренние id в текст не
  попадают» и явное решение пользователя убрать идентификатор из текста.

## Migration Plan

Регрессии контракта нет: `order_id` остаётся в payload и в delivery-корреляции.
Откат — обратное изменение шаблонов и добавленного `instrument`; данные/journal
не мигрируют.
