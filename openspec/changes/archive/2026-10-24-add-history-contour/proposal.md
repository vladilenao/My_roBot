## Why

Этап П7 документа «Ядро и контуры робота» (`docs/architecture/core-contours.md`).
После П6 эмуляция живёт контуром ядра, а история — по-старому:

- прогон запускается отдельным процессом робота из командной строки
  (`--mode history --from --to --pause`) или пунктом 2 меню;
- ядро о прогонах не знает: нельзя поставить прогон, пока робот торгует
  эмуляцией, нельзя посмотреть очередь и итог через API;
- при старте робот спрашивает режим, хотя управлять им уже можно по API.

Есть и обратная зависимость. API управления — тот же сервер, что экспорт
рыночных данных. Он поднимается только после того, как ядро открыло
рыночную базу и запустило полосы брокера. Если старт ядра не удался (нет
токена брокера, сбой базы), API нет, и роботом нельзя управлять. Истории
ядро не нужно: свечи она берёт у эмулятора данных.

Критерий этапа из документа 1: история параллельно с эмуляцией.

Решения владельца (24.10):

- **При запуске робот ничего не спрашивает.** Ни меню, ни параметров
  режима: робот запущен и ждёт команд API. Эмуляция —
  `POST /api/v1/contours` с `kind = emulation`, история — та же команда с
  `kind = history`. История — обычный вид контура в `/api/v1/contours`.
- **API не зависит от ядра.** История запускается, даже если ядро не
  стартовало. Ядро после сбоя пробует стартовать снова.
- **Один конфиг.** Инструмент, названный и в истории, и в эмуляции,
  торгуется по одним и тем же привязкам `robot.toml`. Эмуляция получает
  свежие свечи из ядра, исторический контур — исторические свечи из
  эмулятора данных (Historical Broker API).
- **Прогоны гаснут вместе с роботом.** Ctrl+C останавливает идущие прогоны
  с отчётом, очередь отменяется; после рестарта ничего не возобновляется.
- **Сверку импорта делает робот**, по одному прогону за раз, и передаёт
  номер снимка процессу прогона.
- **Инструменты и данные проверяются в процессе прогона.** `POST` проверяет
  только форму запроса и привязки, отвечает сразу.

## What Changes

- **Старт робота.**
  - Без вопросов и без параметров.
  - Сразу после блокировки и журнала поднимается API управления. Ему не
    нужны рыночная база и брокер, он не зависит от `export_enabled` и
    `independent_lanes`.
  - Затем стартует ядро: рыночная база, арбитр, календарь, полосы.
  - Без `ROBOT_CONTROL_TOKEN` или при занятом порте API робот не
    запускается: код `2` и причина.
- **Ядро повторяет старт.** Сбой старта ядра не останавливает робота:
  - причина пишется в консоль, журнал и `GET /api/v1/core`;
  - повтор через 30 с, паузы растут вдвое до 5 мин;
  - без `TINKOFF_TOKEN` повтора нет, ядро в `failed`;
  - пока ядро не готово, `POST /api/v1/contours` отвечает
    `409 CORE_NOT_READY`, маршруты экспорта — `503`;
  - автоподъём эмуляции (П6) ждёт готовности ядра.
- **`POST /api/v1/contours`** `{"kind": "history", "from", "to", "pause",
  "instruments"}` ставит прогон в очередь и сразу отвечает `202` с `id`
  вида `history-20261024-101500`. Поле `instruments` —
  те же токены, что у эмуляции; без него — `all`. Ошибки формы — `400`,
  токены без привязок и конфликт семейства с контрактом — `422`.
- **Очередь прогонов.** Одновременно идут не больше
  `[contours] max_history_runs` (2) прогонов, остальные ждут в порядке
  поступления. Перед стартом каждого робот сверяет импорт в эмуляторе
  (`POST /api/v1/market-import/sync`), сверки идут по одной. Если ядро не
  готово, сверка не проходит, и прогон идёт без снимка, как сегодня.
- **Процесс прогона** — тот же бинарник с `--contour history <id>`.
  Папка `data/contours/history/20261024-101500/`: `launch.json`, журнал сделок,
  `bot_debug.log`, `console.log`, `status.json`, `report.txt`,
  `report.json`. Внутри — прежний путь истории: выбор контрактов,
  предпроверка, повтор при сдвиге начала, тики, отчёт.
- **Состояние прогонов.**
  - `GET /api/v1/contours` — эмуляция, прогоны в очереди и в работе, 20
    последних завершённых, `limits`; фильтры `?kind=`, `?limit=`;
  - `GET /api/v1/contours/{id}` — один прогон: состояние, ход по
    рыночному времени, итог из `report.json`;
  - `GET /api/v1/contours/{id}/log?tail=200` — строки лога;
  - `POST /api/v1/contours/{id}/stop` — тело может быть пустым; из
    очереди убирает, идущий прогон останавливает после тика с отчётом;
  - `POST /api/v1/contours/{id}/instruments` для прогона —
    `409 NOT_SUPPORTED`.

  Журнал прогонов — таблица `history_runs` в `core.sqlite3`.
- **Командная строка.** Уходят `--mode`, `--instruments`, `--wait-command`,
  `--no-prompt`, `--from`, `--to`, `--pause` и меню. Любой из них даёт
  код `2` с подсказкой про `POST /api/v1/contours`.
  Остаются служебные: `--contour`, `--version`, `--config-smoke`,
  `--telegram-*`.
- **Эквивалентная команда** в состоянии контура — тело
  `POST /api/v1/contours` с выбранными контрактами, а не строка
  параметров.
- **`GET /api/v1/core`** — новые поля `state` (`starting`, `ready`,
  `retrying`, `failed`), `error`, `attempts`, `next_retry_at`.
- **Конфиг:** `[contours] max_history_runs = 2`.
- **Swagger** (`docs/openapi.yaml`): тег `History`, маршруты, схемы, поля
  ядра; версия `1.8.0-proposal`.

Вне этапа:

- удаление кода интерактивного выбора (`src/instruments/selector.py`) и
  его требований в `instruments`: робот его больше не вызывает,
  чистка — отдельным change;
- автоматическая очистка старых папок прогонов;
- перенос старых прогонов из `HIST/` в `data/contours/history/`;
- возобновление прерванного прогона и очереди после рестарта;
- уведомления Telegram из истории: история, как и прежде, молчит.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `control-api`:
  - робот всегда ждёт команд, API поднимается до ядра;
  - ядро повторяет старт, `CORE_NOT_READY`, поля состояния ядра;
  - прогон истории — вид контура `history` в `/api/v1/contours`: запуск,
    очередь, состояние в списке контуров, стоп и лог;
  - автоподъём без явного запуска из командной строки;
  - эквивалентная команда — тело запроса API.
- `historical-mode`:
  - выбор режима при старте уходит;
  - исторический контур отдельным процессом;
  - изоляция состояния: папка прогона в `data/contours/history/`;
  - сверку импорта выполняет робот перед стартом прогона.
- `orchestration` — точка входа, порядок старта и данные до выбора
  инструментов без меню и параметров.
- `instruments` — инструменты только из команд API.
- `configuration` — `[contours] max_history_runs`.

## Impact

- **Код:**
  - `run.py`: старт без параметров, API до ядра, повтор старта ядра,
    `--contour history`;
  - `src/bot/launch.py`: разбор параметров, эквивалентная команда;
  - новый `src/assembly/history_runs.py`: очередь, журнал, надзор за
    прогонами;
  - `src/assembly/core.py`: старт ядра с повтором, API отдельно от
    рыночной базы;
  - `src/assembly/core_state.py`: таблица `history_runs`;
  - `src/assembly/process.py`: процесс прогона с выводом в `console.log`;
  - `src/data/export_api.py`, `src/bot/launch_control.py`: маршруты,
    экспорт без базы — `503`;
  - `src/config.py`, `src/config_loader.py`, `default.toml`.
- **Данные:** таблица `history_runs` (`CREATE TABLE IF NOT EXISTS`), папка
  `data/contours/history/`. Миграции не нужны.
- **Поведение:**
  - запуск с любыми прежними параметрами режима завершается кодом `2`
    с подсказкой;
  - без `ROBOT_CONTROL_TOKEN` робот не запускается;
  - после обновления эмуляция поднимается автоподъёмом по желаемому из
    `core.sqlite3`, если перед остановкой работала.
