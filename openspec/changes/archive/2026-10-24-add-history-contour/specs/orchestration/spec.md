## MODIFIED Requirements

### Requirement: Точка входа
Нормативный уровень: MUST. Система ДОЛЖНА предоставлять run.py, который запускается без параметров, получает параметры запуска командой локального API, разрешает по ним инструменты, собирает зависимости и запускает TradingBot.run() в процессе контура. Порядок старта и повтор старта ядра задаёт спецификация `control-api`. Параметры запуска ДОЛЖНЫ быть одним объектом, не зависящим от консоли: режим, границы и пауза истории, список токенов инструментов. Интерактивный выбор инструментов НЕ ДОЛЖЕН вызываться. Разрешение инструментов, сборка и запуск ДОЛЖНЫ выполняться главным потоком при любом источнике параметров. В текущем режиме run.py ДОЛЖЕН также собрать выбранный ingestion-транспорт и его readiness-порт; TradingBot, стратегии и финансовые компоненты НЕ ДОЛЖНЫ знать gRPC-подписку или читать сеть для торгового тика. Общие стратегии, профили, риск, исполнение и журналы сохраняются; source/clock/state-directory и необязательный live-ingestion различаются по режимам. Исторический провайдер НЕ ДОЛЖЕН реализовывать фиктивный stream ради общего интерфейса.

#### Scenario: Запуск через run.py
- **WHEN** выполняется python run.py
- **THEN** вопросов в консоли нет, поднимается API управления, затем ядро; инструменты приходят командой API

#### Scenario: Запуск через меню
- **WHEN** выполняется python run.py с прежним параметром режима
- **THEN** меню не показывается, процесс печатает подсказку про команды API и завершается с кодом `2`

#### Scenario: Запуск командой API
- **WHEN** робот запущен и получил команду запуска эмуляции
- **THEN** главный поток разрешает инструменты из команды, собирает зависимости и запускает процесс контура

#### Scenario: Сборка боевого режима
- **WHEN** выбран текущий режим данных (эмуляция, прежний боевой режим)
- **THEN** собираются выбранный live-ingestion и прежний JournalBroker либо NotifyOnly; реальный exchange-executor не создаётся

#### Scenario: Сборка исторического режима
- **WHEN** принят прогон `POST /api/v1/contours` с `kind = history`
- **THEN** процесс прогона использует прежние исторический source/virtual clock и общие торговые компоненты без запуска stream, папка состояния — папка прогона

### Requirement: Обслуживание рыночных данных до выбора инструментов
Нормативный уровень: MUST. Сразу после подъёма API управления ядро ДОЛЖНО создать рыночное хранилище, арбитр лимитов, календарь и владельца входа и запустить полосы календаря, доказательств и полноты. Неудачная попытка ДОЛЖНА повторяться по требованию «Повтор старта ядра» спецификации `control-api`. Это ДОЛЖНО происходить до разрешения инструментов и загрузки контрактов. Ожидание команды API ДОЛЖНО занимать место прежнего интерактивного выбора. Граница запуска ДОЛЖНА фиксироваться моментом старта процесса, а не моментом создания торговых компонентов.

До выбора инструментов полосы ДОЛЖНЫ работать по сохранённому составу прошлого запуска и парам незавершённых сделок. Снимок незавершённых сделок и их границ ДОЛЖЕН читаться главным потоком из финансовой базы. Запросы разрешения инструментов команды API и загрузки контрактов ДОЛЖНЫ проходить через тот же арбитр лимитов с приоритетом интерактивной полосы.

После выбора состав ДОЛЖЕН сохраняться и обновляться. Пары, не выбранные и не связанные с незавершённой сделкой, ДОЛЖНЫ исключаться из очередей полос без удаления их данных. Пара — это инструмент и таймфрейм: пара сохранённого состава, чей таймфрейм после регистрации потребностей не запросили ни стратегии и фильтры выбранных привязок, ни сопровождение незавершённых сделок, ДОЛЖНА исключаться так же, даже если инструмент выбран или по нему есть незавершённая сделка. Обязательство сделки ДОЛЖНО удерживать только таймфреймы, которые запрашивает её сопровождение. Исключённая пара ДОЛЖНА пересохраняться в составе как прошлая и ДОЛЖНА возвращаться в обслуживание, если её позже запросит потребность. Затем ДОЛЖНЫ стартовать живая полоса и поток. Ожидание первого торгового шага ДОЛЖНО по-прежнему зависеть только от прогрева выбранных пар и подключения потока, а не от завершения полосы полноты.

Ожидание первого торгового шага ДОЛЖНО быть ограничено настраиваемым таймаутом. По его истечении стартовый обзор ДОЛЖЕН выполняться с неготовыми парами и причиной неготовности, их прогрев ДОЛЖЕН продолжаться в фоне, а журнал ДОЛЖЕН перечислять пары, которых ждал старт. Процесс исторического прогона НЕ ДОЛЖЕН запускать полосы и ранний сбор данных.

#### Scenario: Пользователь выбирает инструменты
- **WHEN** после запуска робота команда запуска эмуляции приходит через четыре минуты
- **THEN** полосы календаря, доказательств и полноты в это время уже работают по сохранённому составу и незавершённым сделкам

#### Scenario: Запуск с параметрами
- **WHEN** приходит команда запуска эмуляции с NG и SBER
- **THEN** полосы уже работают, а проверка NG и SBER у источника идёт через арбитр с приоритетом интерактивной полосы

#### Scenario: Робот ждёт команду API
- **WHEN** робот запущен и команда запуска пришла через час
- **THEN** весь этот час полосы календаря, доказательств и полноты работают по сохранённому составу и незавершённым сделкам

#### Scenario: Первый запуск без сохранённого состава
- **WHEN** сохранённого состава нет и незавершённых сделок нет
- **THEN** полоса календаря и ранний сбор не выполняют запросов по парам до выбора, а после выбора работают по выбранному составу

#### Scenario: Запросы выбора и полноты одновременно
- **WHEN** выбор инструментов проверяет инструменты у источника, а полоса полноты догружает свечи
- **THEN** оба проходят через арбитр; выбор не получает ограничение источника из-за неучтённых запросов полноты

#### Scenario: Граница запуска
- **WHEN** процесс стартовал в 17:23:47, а торговые компоненты собраны в 17:27
- **THEN** граница запуска — 17:23, минуты 17:23–17:26 проверяются строго и восстанавливаются полосами

#### Scenario: Таймфрейм убран из конфигурации при открытой сделке
- **GIVEN** по PHOR открыта сделка с планом на 1h, а в сохранённом составе есть PHOR 15m с происхождением обязательства
- **WHEN** в конфигурации 15m-стратегии PHOR заменены на 4h и робот перезапущен
- **THEN** после регистрации потребностей PHOR 15m снимается с обслуживания и сохраняется как прошлая, PHOR 1h и 1m остаются, и стартовый обзор выходит после прогрева оставшихся пар

#### Scenario: Снятая пара снова нужна
- **WHEN** пара сохранённого состава снята как незапрошенная, а позже её таймфрейм запросила потребность прогрева
- **THEN** пара снова регистрируется, прогревается и обслуживается обычным путём

#### Scenario: Прогрев не уложился в таймаут
- **WHEN** одна выбранная пара не прогрелась за таймаут ожидания старта
- **THEN** стартовый обзор выходит с причиной неготовности этой пары, готовые пары анализируются, журнал называет неготовую пару, а её прогрев продолжается

#### Scenario: Исторический прогон
- **WHEN** идёт процесс исторического прогона
- **THEN** ранний сбор и полосы в нём не запускаются, порядок исторической сборки не меняется

### Requirement: Контур эмуляции отдельным процессом
Нормативный уровень: MUST. В эмуляции после выбора инструментов (`POST /api/v1/contours` или автоподъём) ядро ДОЛЖНО запускать торговый контур отдельным процессом тем же исполняемым файлом со служебным флагом `--contour emulation`. Процесс контура НЕ ДОЛЖЕН держать объектов ядра: данные — из рыночной базы, состав и карточки контрактов — из файла запуска, кластерные события — из `cluster-events.sqlite3` только на чтение. Процесс ДОЛЖЕН брать блокировку `data/contours/emulation/robot.pid` и писать технический журнал в `data/contours/emulation/bot_debug.log` с маскированием тех же секретов, что ядро. Вывод консоли процесса ДОЛЖЕН идти в консоль ядра. Одновременно ДОЛЖЕН работать не больше одного процесса контура эмуляции.

#### Scenario: Запуск командой API
- **GIVEN** робот запущен и ядро готово
- **WHEN** приходит `POST /api/v1/contours` с инструментами NG и SBER
- **THEN** ядро пишет файл запуска, запускает процесс `--contour emulation`, блоки СИГНАЛ и ПЛАН контура печатаются в той же консоли

#### Scenario: Второй процесс контура
- **GIVEN** процесс контура эмуляции уже работает
- **WHEN** второй процесс запускается с `--contour emulation`
- **THEN** он не получает блокировку и завершается с сообщением, торговля первого не меняется

#### Scenario: История не меняется
- **WHEN** принят прогон `POST /api/v1/contours` с `kind = history`
- **THEN** прогон идёт отдельным процессом `--contour history <id>` на исторической службе данных, процесс контура эмуляции не запускается и не меняется
