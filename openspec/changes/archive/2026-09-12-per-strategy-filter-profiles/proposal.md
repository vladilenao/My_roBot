# Proposal: Профили фильтрации и каскадная привязка стратегий

## Why

Сейчас фильтрация сигналов едина для всех пар «тикер × стратегия»: `SignalFilter` (`src/decision/filter.py`) жёстко зашит — блокировка против тренда, без вариантов. Нельзя ни отключить контекстные фильтры для скальперской стратегии, ни усилить их для консервативной. Вторая боль — «слепые алерты»: сообщение вида `[NG] 🚀 ПОКУПАТЬ! Цена: X` не сообщает, по каким правилам фильтрации принято решение, а отклонение сигнала фильтром вообще неотличимо от отсутствия сигнала. Конфигурация привязок — плоские списки имён стратегий — не имеет точек расширения под точечные параметры.

## What Changes

- **BREAKING: Каскадная привязка в `robot.toml`.** Секции `[strategies.share]`/`[strategies.future]` превращаются в таблицы тикеров: `[strategies.share.SBER]` с ключом `strategies` — гибридным массивом, где элемент — строка (`"flat_triangle"`) или инлайн-таблица (`{ name = "macd_rsi_stoch", filter = "raw" }`). Отсутствующий `filter` прозрачно падает на профиль по умолчанию `"basic_levels"` (идиома Null Object). Дубликаты имени стратегии внутри тикера легальны, если различаются профилем. Строгая валидация `config_loader` сохраняется: неизвестные ключи (включая `timeframe`/`tf` — см. Non-Goals), неизвестные имена стратегий и профилей → `ConfigError` с перечнем допустимых значений.
- **Профили фильтрации с фабричным методом.** `SignalFilter` становится фасадом: `apply(decision, ctx, profile_name)` внутри конструирует конкретный фильтр по имени профиля. Профили этого чейнджа: `raw` — Null Object, пропускает всё без изменений; `basic_levels` — дефолт, текущее поведение (блок против тренда + обогащение trend-полей), что делает миграцию существующих привязок бесшовной. Новый профиль = новый класс + регистрация в фабрике, главный цикл не меняется; жёсткие многошаговые профили — отдельными чейнджами поверх этой точки расширения.
- **Обогащённый шаблон нотификаций.** Сообщение: `● {ticker} ({timeframe}) {time} | {strategy} [{filter_profile}] ➜ {status}`. Отклонение фильтром — явный статус `❌ Отклонено фильтром.` вместо молчаливого HOLD: оркестратор различает «HOLD стратегии» и «HOLD от фильтра» сравнением решения до/после фильтра; контракт `Decision` не меняется. Таймфрейм в шаблоне — глобальный `TIMEFRAME` (мульти-ТФ — вне скоупа).
- **Non-Goals (отложено):** мульти-таймфреймный ритм планировщика, `timeframe` на уровне тикера, `tf` на уровне стратегии, ключ `data_cache` по `(инструмент, tf)` — отдельный чейндж после проработки риска мульти-ТФ; цветовая эмодзи-индикация профилей — fast-follow после стабилизации шаблона.

## Capabilities

### New Capabilities

(нет — все изменения ложатся в существующие capability)

### Modified Capabilities

- `configuration`: структура привязок «инструмент → стратегии» — таблицы тикеров с гибридным массивом; `SHARE_STRATEGIES`/`FUTURE_STRATEGIES` отдают развёрнутые привязки (имя стратегии + профиль фильтра); каскад профиля по умолчанию; валидация имён профилей.
- `signal-filter`: пост-фильтр получает профили фильтрации и фабричный метод выбора по имени; профили `raw` / `basic_levels`.
- `strategy-contract`: требование «Привязка инструментов к стратегиям» — привязка несёт профиль фильтра, дубликаты имени стратегии с разными профилями легальны; требование «Формирование уведомлений отдельным классом» — форматтер получает контекст задачи (стратегия, профиль, признак отклонения фильтром) параметрами вызова.
- `notification`: наблюдаемый шаблон сообщения — тикер, ТФ, время, стратегия, профиль фильтра, статус; новый статус отклонения фильтром.

## Impact

- **Код:** `src/config_loader.py` (парсер гибридного массива, валидация профилей), `src/config.py` (типы привязок), `src/decision/filter.py` (фасад + фабрика), новый подпакет `src/decision/filters/` (классы профилей), `src/bot/trading_bot.py` (per-assignment профиль, вычисление «отклонено фильтром»), `src/notifier/base.py` (шаблон `DecisionFormatter`, параметры вызова; `ConsoleNotifier`/`TelegramNotifier` — делегируют, без логики).
- **Конфигурация:** `default.toml` и `robot.toml` — новая схема секций `strategies.*` (миграция одношаговая: массивы имён → таблицы тикеров).
- **Тесты:** unit-тесты форматтера/фильтра/конфига — синхронное обновление ожиданий; snapshot-раннер стратегий не затрагивается (фильтр — пост-обработка).
- **Specs:** `configuration`, `signal-filter`, `strategy-contract`, `notification` — MODIFIED.
- **Выпуск:** BREAKING формат конфигурации → SemVer MAJOR (`2.0.0`), секция в CHANGELOG с инструкцией миграции `robot.toml`.
