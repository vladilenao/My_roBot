## MODIFIED Requirements

### Requirement: Использование контекстного менеджера клиента
- Клиент ДОЛЖЕН получаться из источника данных прогона, а не создаваться напрямую, и ДОЛЖЕН использоваться в форме контекстного менеджера (`with ... as client:`) для доступа к API.
- Форма вызовов методов клиента ДОЛЖНА быть одинаковой для боевого и исторического источников: загрузчик ДОЛЖЕН работать через тот же контракт запроса и разбора ответа.

#### Scenario: Клиент автоматически закрывается
- **WHEN** загрузка завершается (успешно или с ошибкой)
- **THEN** контекстный менеджер клиента корректно закрывается

#### Scenario: Источник подменён без изменения кода загрузчика
- **WHEN** прогон выполняется на историческом источнике
- **THEN** загрузчик запрашивает свечи через тот же контракт вызовов, что и в боевом режиме, без отдельной ветки кода

### Requirement: Диапазон дат по умолчанию
- Если `start_date=None`, используется `now() - timedelta(days=30)`.
- Если `end_date=None`, используется `now()`.
- Значение `now()` ДОЛЖНО браться из источника рыночного времени прогона, а не из системных часов: в историческом прогоне границы по умолчанию отсчитываются от текущего рыночного момента.

#### Scenario: Дефолтный диапазон
- **WHEN** обе даты `None`
- **THEN** загружаются свечи за последние 30 дней

#### Scenario: Дефолтный диапазон в историческом прогоне
- **WHEN** обе даты `None`, а рыночное время прогона равно `2023-05-10 12:00`
- **THEN** запрашиваются свечи с `2023-04-10 12:00` по `2023-05-10 12:00`, а не до текущей системной даты
