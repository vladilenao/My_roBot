## MODIFIED Requirements

### Requirement: Дозагрузка только новых баров
Кэш ДОЛЖЕН определять появление новой закрытой свечи и при необходимости дозагружать только новые бары поверх имеющихся, а не пересобирать весь срез.

Перезагрузка данных ДОЛЖНА допускать повторные попытки, чтобы дождаться появления свежего закрытого бара текущей закрытой минуты, который из-за задержки публикации может быть временно недоступен. Повторные принудительные дозагрузки ДОЛЖНЫ выполняться с паузой не чаще сконфигурированного минимального интервала перезагрузки данных (`data_refresh_min_interval`): между принудительными дозагрузками проверки готовности выполняются по кэшу без обращения к API. Принудительная дозагрузка ДОЛЖНА запрашивать только свежие бары с ограниченным окном дозагрузки (не перезапрашивая накопленную историю). Повторные попытки ДОЛЖНЫ ограничиваться таймаутом, после которого перезагрузка прекращается и кэш отдаёт имеющиеся данные.

В историческом режиме повторные принудительные дозагрузки ДОЛЖНЫ отключаться: данные прошлого периода публикуются без задержки, поэтому отсутствие бара на текущем рыночном моменте означает конец доступных данных, а не задержку публикации. Кэш ДОЛЖЕН сигнализировать конец доступных данных и ДОЛЖЕН учитывать количество пропущенных баров внутри диапазона.

#### Scenario: Появился новый бар
- **WHEN** граница таймфрейма пройдена и появился новый закрытый бар
- **THEN** выполняется дозагрузка новых баров и кэш обновляется

#### Scenario: Бара ещё нет
- **WHEN** новая закрытая свеча ещё не появилась
- **THEN** кэш не перезагружается, данные не меняются

#### Scenario: Свежий бар появляется после повторных попыток
- **WHEN** на первой попытке после границы свежего закрытого бара в данных ещё нет, но он появляется после малой паузы
- **THEN** кэш повторно дозагружает данные, свежий закрытый бар фиксируется и кэш обновляется

#### Scenario: Таймаут ожидания бара
- **WHEN** свежий закрытый бар не появляется в течение ограниченного таймаута повторных попыток
- **THEN** перезагрузка прекращается и кэш отдаёт имеющиеся (закэшированные) данные, не блокируясь бесконечно

#### Scenario: Форс-дозагрузка не чаще минимального интервала
- **WHEN** ожидается появление свежего закрытого бара, но интервал с последней принудительной дозагрузки меньше `data_refresh_min_interval`
- **THEN** API не вызывается; готовность проверяется по закэшированным данным

#### Scenario: Ограниченное окно дозагрузки
- **WHEN** выполняется принудительная дозагрузка свежих баров
- **THEN** запрашиваются только свежие бары в пределах окна дозагрузки (bounded backfill), накопленная история повторно не запрашивается

#### Scenario: Конец данных в историческом режиме
- **WHEN** в историческом прогоне на текущем рыночном моменте свежий закрытый бар отсутствует
- **THEN** повторные попытки перезагрузки не выполняются, кэш сигнализирует конец доступных данных и возвращает накопленные бары

#### Scenario: Учёт пропущенных баров
- **WHEN** внутри диапазона отсутствует ожидаемый бар
- **THEN** кэш увеличивает счётчик пропусков, и значение доступно для отчёта прогона

## ADDED Requirements

### Requirement: Учёт конца данных по рыночным тикам
Проверки конца доступных данных ДОЛЖНЫ агрегироваться по рыночному тику, а не
выполняться отдельно для каждого таймфрейма. Один рыночный тик ДОЛЖЕН давать
ровно одну запись в счётчике последовательных тиков без прогресса, независимо от
того, сколько таймфреймов обновлялось на этом тике.

Таймфрейм, у которого на текущем рыночном моменте закрытый бар ещё не ожидается
(старший таймфрейм внутри интервала между его границами), ДОЛЖЕН исключаться из
расчёта тика без прогресса. Тик, на котором ни у одного таймфрейма не ожидается
закрытый бар, ДОЛЖЕН игнорироваться и не учитываться ни в одном счётчике.

Счётчик ДОЛЖЕН сбрасываться при появлении любого нового закрытого бара, поэтому
наличие прогресса по одному таймфрейму ДОЛЖЕНО отменять сигнал конца данных,
поднятый остальными таймфреймами на том же тике.

#### Scenario: Старшие таймфреймы не завершают прогон
- **WHEN** в тик приходят проверки таймфреймов `15m`, `1m`, `1h`, `5m`, у которых
  закрытые бары уже опубликованы, и только у `1m` появился новый закрытый бар
- **THEN** тик учитывается как тик с прогрессом, конец доступных данных не
  сигнализируется

#### Scenario: Тик без ожидаемого бара игнорируется
- **WHEN** на рыночном моменте не истекла граница закрытия ни для одного
  таймфрейма, поэтому ожидаемых закрытых баров нет
- **THEN** счётчик тиков без прогресса не увеличивается и конец доступных данных
  не сигнализируется

#### Scenario: Пропуск считается один раз за тик
- **WHEN** на одном тике ожидаемый закрытый бар отсутствует у нескольких
  таймфреймов
- **THEN** счётчик тиков без прогресса увеличивается ровно на единицу

#### Scenario: Повторная проверка одного таймфрейма не удваивает счётчик
- **WHEN** один и тот же таймфрейм проверяется на тике повторно
- **THEN** таймфрейм учитывается в ожидаемых барах тика один раз

#### Scenario: Конец данных по-прежнему объявляется
- **WHEN** ни у одного таймфрейма не появилось нового закрытого бара несколько
  рыночных тиков подряд
- **THEN** кэш сигнализирует конец доступных данных
