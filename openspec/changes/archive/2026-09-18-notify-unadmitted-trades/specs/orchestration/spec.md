## MODIFIED Requirements

### Requirement: Доставка уведомления о недопуске кандидата
В торговом режиме система ДОЛЖНА доставлять через порт исполнения в нотификатор уведомление о недопуске: когда результат допуска кандидата содержит причины недопуска, по каждой причине ДОЛЖНО быть доставлено одно сообщение о недопуске с контекстом задачи (инструмент, таймфрейм, стратегия, профиль) и человекочитаемым описанием причины. Недопуск из-за решения HOLD («Нет сигнала») уведомлением о недопуске НЕ сопровождается: для HOLD доставляется обычное сообщение об отсутствии сигнала. Уведомление о недопуске НЕ должно дублировать и НЕ должно подавлять обычное уведомление о самом сигнале.

#### Scenario: Недопущенные кандидаты уведомляются
- **WHEN** торговый режим активен, по активной паре «инструмент × стратегия» менеджер допуска вернул BUY-сигнал с причиной недопуска (например, `zero-quantity`)
- **THEN** через порт исполнения доставляется сообщение о недопуске с маркером `⛔`, контекстом задачи и текстом причины; обычное уведомление о решении BUY тоже доставляется

#### Scenario: HOLD не считается недопуском
- **WHEN** стратегия вернула HOLD (нет сигнала)
- **THEN** уведомление о недопуске не доставляется; доставляется только обычное сообщение `⏳ Нет сигнала.`

#### Scenario: Допущенный сигнал без уведомления о недопуске
- **WHEN** кандидат успешно допущен (менеджер вернул действия без причин)
- **THEN** уведомление о недопуске не доставляется, действия исполняются как обычно

#### Scenario: Множественные причины
- **WHEN** результат допуска содержит несколько причин недопуска
- **THEN** доставляется по одному сообщению о недопуске на каждую причину
