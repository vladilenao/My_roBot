# Design: readable-journal-export

## Context

См. proposal.md. Проекции `journal.csv`/`positions.csv` строятся в `src/trade_journal/export.py` из SQLite-журнала (source of truth) атомарной заменой temp-файла. Сейчас в CSV попадают внутренние сущности (тикер, ID событий/команд/заявок, ревизия, UTC). Данные для читаемого выхода уже есть в базе: `trades` (сторона, фаза, created_at/updated_at), `positions` (количество, средняя цена, PnL, комиссия), `orders` (action_type, объём, цена), `fills` (цены/время исполнений), `events` (payload с причиной), `protection` (подтверждённый/ожидающий стоп), `reservations` (фактический риск входа). Короткое имя контракта берётся из селектора инструментов через карту тикер→имя — она уже прокидывается в брокер (`broker.set_names`), в экспорт ещё нет.

## Goals / Non-Goals

**Goals**
- Пользовательские CSV читаемы без базы: короткие имена, МСК, русские фразы событий, только применимые колонки, без внутренних ID.
- Карточка позиции несёт практический смысл: стоп, цена/время/причина выхода, фактический риск, ГО.
- Версия экспорта остаётся внутренним состоянием БД, из CSV уходит.
- Минимальное вмешательство: схема SQLite не меняется, восстановление состояния по-прежнему идёт из БД.

**Non-Goals**
- Не вводим новые события (например, отдельные записи «Изменение стопа») — лента отображает уже существующие исполнения/подтверждения.
- Не добавляем в CSV риск/ГО «макс» из агрегата нескольких резервов — карточка несёт фактический риск входа и маржинальные требования контракта.
- Не переводим аудит (`AuditExporter`) на человекочитаемый формат — он остаётся техническим.

## Decisions

1. **Новые колонки вместо переименования старых.** Лента и карточка полностью переопределяются под читаемый набор (`JOURNAL_COLUMNS`/`POSITIONS_COLUMNS` + русские `JOURNAL_HEADERS`/`POSITIONS_HEADERS`). Альтернатива (добавить колонки к прежним) сохраняла бы машиные ID — отвергнуто, противоречит цели.
2. **Короткое имя контракта через карту, а не парсинг тикера.** Тикер `BRV6` не позволяет вывести `BR-10.26` без справочника. Карта тикер→короткое имя уже строится в `run.py` (`_instrument_names`) и используется брокером; добавляется зеркальный `Storage.set_names()` → `CsvExporter.set_names()`. Фолбэк при отсутствии карты — тикер (для тестовых/автономных сред), в боевом `run.py` карта всегда передаётся.
3. **События — комбинация `event_type` + `action_type` + payload.** Фраза строится из machine-статуса (ACK/FILL/REJECT/…) и действия заявки (OPEN/ADD/TARGET/STOP/CLOSE/REDUCE) на русском. Альтернатива — отдельное поле «тип» таблицей соответствий — дала бы тоже самое, но дублировала бы информацию.
4. **Парсинг стратегии и ТФ из `trade_id` (signal_id)** вида `macd_rsi_stoch:5m:…` — первый и второй сегмент. Без новой колонки в БД и без внесения резолвера привязок в экспорт. Для старых ID без структуры выводится сам ID фолбэком.
5. **Выход агрегируется из `fills`.** Средняя цена выхода — взвешенная по объёму по закрывающим исполнениям (REDUCE/CLOSE/TARGET/STOP), время — последнее из них, причина — из payload последнего закрывающего события. Альтернатива — хранить поля выхода в `positions` — потребовала бы миграции схемы (не делаем).
6. **Фактический риск — из `reservations` по первому ордеру входа** (`original_risk_amount`), ГО — маржинальные параметры контракта из метаданных. Деньги округляются до копеек (`_money`), время — в МСК (`_msk`).
7. **Смена схемы колонок = новая версия проекции.** `_is_current_projection` сравнивает заголовки; при первом экспорте новой версии прежние файлы автоматически сохраняются копией `.legacy.<timestamp>` (механизм уже был).

## Risks / Trade-offs

- [Причина выхода берётся из последнего закрывающего события] → Mitigation: порядок по `event_seq DESC`, первая запись на позицию; при отсутствии события поле пустое (допустимо для открытых позиций).
- [Парсинг `trade_id` хрупок для нестандартных ID] → Mitigation: tolerant-парсинг, при несогласованном формате выводится исходное значение, экспорт не ломает.
- [Смена заголовков меняет формат файлов, открытых в сторонних таблицах] → Mitigation: атомарная замена + `.legacy.`-копия, ошибки записи не роняют БД (поведение уже тестируется).
- [Урезается колонка «ГО (покупка/продажа)» для фьючерсов без метаданных] → Mitigation: пустое значение; в боевом режиме метаданные контрактов всегда загружаются.

## Migration Plan

Развёртывание: перезапуск робота — `run.py` передаст карту имён в экспорт; первый экспорт новой версии сохранит прежние CSV копиями `.legacy.<timestamp>` и запишет читаемые. Откат: возврат к прежнему коду экспорта; SQLite не менялась, полное восстановление состояния идёт из БД без потери данных.
