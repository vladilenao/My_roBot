## MODIFIED Requirements

### Requirement: Уведомление при новой закрытой свече
Система ДОЛЖНА доставлять уведомление о решении только на тике с новой закрытой свечей. На пустом тике (свеча не закрылась) compute/decide НЕ ДОЛЖНЫ вызываться, уведомления НЕ ДОЛЖНЫ доставляться, heartbeat НЕ ДОЛЖЕН отправляться. Обработка включает: получение MarketContext (через MarketContextCache), вычисление индикаторов, фильтрацию сигнала, расчёт SL/TP и доставку решения.

#### Scenario: Новая свеча — полная обработка
- **WHEN** появилась новая закрытая свеча
- **THEN** выполняется полный pipeline: MarketContext → compute → decide → signal filter → risk manager → delivery

#### Scenario: Пустой тик — тишина
- **WHEN** новая закрытая свеча не появилась
- **THEN** compute/decide не вызываются, уведомления не доставляются, heartbeat не отправляется, _process не вызывается

#### Scenario: Контекст вычисляется на инструмент, а не на стратегию
- **WHEN** инструменту назначены 3 стратегии
- **THEN** MarketContext вычисляется 1 раз для инструмента и передаётся во все стратегии

### Requirement: Конвейер по каждой паре «инструмент × стратегия»
На каждом тике (при новой закрытой свече) для каждого инструмента: получить MarketContext из кэша → для каждой назначенной стратегии из реестра: рассчитать сигналы (`compute`) → принять решение (`decide`) → применить фильтр тренда → рассчитать SL/TP → передать решение в порт исполнения → доставить уведомление. Нотификатор и порт исполнения ДОЛЖНЫ создаваться один раз до входа в цикл.

#### Scenario: Нормальная итерация
- **WHEN** данные доступны и появилась новая свеча
- **THEN** полный конвейер выполняется для каждой пары «инструмент × назначенная стратегия»; решение доставляется единственным вызовом порта исполнения

#### Scenario: Единственный экземпляр нотификатора
- **WHEN** оркестратор запускается
- **THEN** нотификатор создаётся один раз до цикла и переиспользуется для всех инструментов и стратегий
