## MODIFIED Requirements

### Requirement: Отмена запланированного входа при близкой экспирации
Нормативный уровень: MUST.
Система ДОЛЖНА отменять команду `CancelEntry` незаполненный вход в фазе `ENTRY_PENDING` по фьючерсному контракту, до экспирации которого осталось не более настроенного количества календарных суток, с причиной `contract-expiring`. Решение ДОЛЖНА приниматься на каждом цикле сопровождения из статичной даты экспирации контракта и текущего времени. Для контрактов без даты экспирации (акции) отмена по этому правилу НЕ выполняется. Дата экспирации ДОЛЖНА использоваться та, что получена у источника данных для конкретного контракта; подмена её константой (в том числе пустым значением или текущей датой) ДОЛЖНА приводить к тому, что отмена по экспирации не выполняется вовсе, а не к ложной отмене входа.

#### Scenario: Отмена ожидающего входа
- **WHEN** по фьючерсному контракту с горизонтом до экспирации в пределах настроенного порога имеется незаполненный вход `ENTRY_PENDING`
- **THEN** вход отменяется командой `CancelEntry` с причиной `contract-expiring`, новая заявка по нему не создаётся

#### Scenario: Незаполненный вход вне порога не отменяется
- **WHEN** до экспирации фьючерсного контракта осталось больше настроенного количества календарных суток
- **THEN** ожидающий вход `ENTRY_PENDING` продолжает ожидать исполнения без отмены по экспирации

#### Scenario: Реальная дата экспирации из источника учитывается
- **WHEN** у источника данных запрошен фьючерсный контракт, дата экспирации которого приведена в виде даты и времени с часовым поясом, и до неё менее порога
- **THEN** дата приводится к naive-UTC и по ней выполняется отмена входа с причиной `contract-expiring`

#### Scenario: Отсутствие даты экспирации не считается истечением
- **WHEN** источник данных не отдал дату экспирации контракта
- **THEN** отмена входа по экспирации не выполняется, а пустое значение не интерпретируется как текущая дата
