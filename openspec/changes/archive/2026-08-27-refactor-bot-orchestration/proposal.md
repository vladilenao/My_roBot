# Proposal: Рефакторинг оркестрации робота (TradingBot)

## Why

`run_bot` в `src/scheduler/runner.py` — «божественная функция»: весь сценарий (валидация, выбор стратегий, загрузка данных, анализ, уведомление, пауза, обработка ошибок) свален в 80 строк с вложенными циклами и try/except. Чтобы понять работу робота — надо читать всё. Кроме того, сценарий неграмотен с точки зрения трейдера: итерация идёт по фиксированной паузе `SLEEP_SECONDS`, а не по закрытию свечи; решения принимаются по живой (незавершённой) свече; каждый цикл — полный пересчёт индикаторов с нуля по всей истории; одинаковые сигналы дублируются; сбои логируются только в консоль без алерта трейдеру.

Цель — превратить main-класс в читаемый сценарий, где каждый пункт словесного описания соответствует вызову отдельного метода, и заложить архитектурную заглушку (ExecutionPort) для будущего развития бота до торгового (сейчас это бот сигналов).

## What Changes

- **BREAKING** Переместить оркестрацию из `src/scheduler/runner.py:run_bot` в новый класс `TradingBot` в `src/bot/trading_bot.py`. `src/scheduler/runner.py` удаляется.
- Ввести класс `TradingBot`, файл которого читается как сценарий: метод на каждый пункт (запуск → цикл → данные → анализ → решение → уведомление).
- Точка входа `run.py` переходит с `run_bot(instruments)` на `TradingBot(...).run()`.
- **Ввести выравнивание итерации по закрытию свечи таймфрейма** (`CandleScheduler` в `src/scheduler/timing.py`): робот просыпается в момент закрытия текущей свечи, а не ждёт фиксированную `SLEEP_SECONDS` паузу.
- **Решения принимаются только по закрытым (готовым) свечам** — `decide` никогда не видит живую свечу.
- **Инкрементальный пересчёт данных** (`MarketDataCache` в `src/data/cache.py`): кэш свечей, дозагрузка только новых баров и пересчёт индикаторов один раз на тик, а не полный пересбор каждый проход.
- **Защита от дублирования сигналов** — уведомление об изменении состояния решения (фронт сигнала), а не о каждом проходе.
- **Устойчивость и диагностика** — при сбое тика алерт трейдеру через нотификатор (не только лог в консоль); добавлены сердцебиение/диагностика.
- Ввести `Instrument`-модель (dataclass) вместо голых кортежей и единую нормализацию.
- **BREAKING** Ввести слой `ExecutionPort` (`src/execution/port.py`) — абстракция «куда отправляем решение»; сейчас реализуется `NotifyOnlyExecutionPort` (уведомление), заготовка под будущее торговое исполнение.

## Capabilities

### New Capabilities
- `execution`: выходной слой принятых решений. Абстрактный `ExecutionPort` + конкретный `NotifyOnlyExecutionPort` (уведомление). Точка расширения для будущего торгового исполнения (ордера, позиции) без изменения контура сигналов.
- `timing`: планировщик итерации по границе закрытия свечи таймфрейма (`CandleScheduler`) — расчёт «когда закрывается текущая свеча», пауза до границы, fallback-пауза при сбое, предоставление рыночного времени.
- `data-cache`: `MarketDataCache` — кэш истории свечей, дозагрузка только новых баров, предоставление стратегиям только закрытых свечей.

### Modified Capabilities
- `orchestration`: преобразование «божественной функции» `run_bot` в класс-оркестратор `TradingBot`; замена фиксированной паузы на выравнивание по закрытию свечи; принятие решений только по готовым свечам; инкрементальный пересчёт; защита от дублей; алерт трейдеру при сбое; смена точки входа `run.py`; поддерживаемые форматы инструментов нормализуются в `Instrument`.
- `data-loading`: добавление инкрементального режима — загрузчик/кэш способен догружать только новые бары поверх кэша, а не всегда полный срез; критерий «свеча готова» по границе таймфрейма.

## Impact

- **Code**: создаются `src/bot/`, `src/execution/`, `src/data/cache.py`, `src/scheduler/timing.py`, `src/instruments/model.py`; удаляется `src/scheduler/runner.py`; `run.py` переписывается.
- **Breaking API**: импорт `from src.scheduler.runner import run_bot` исчезает (при необходимости — тонкий реэкспорт на время миграции, но не является целью).
- **Tests**: `tests/unit/scheduler/test_runner.py` (12 тестов) удаляется вместе с `runner.py`; добавляются `tests/unit/bot/`, `tests/unit/execution/`, `tests/unit/scheduler/test_timing.py`, `tests/unit/data/test_cache.py`. Снэпшот-тесты стратегий (`tests/snapshot/`) не затрагиваются — сигнальный слой не меняется.
- **Dependencies**: новых внешних зависимостей не требуется.
- **Behavior**: ритм работы меняется с «пауза N секунд» на «выравнивание по закрытию свечи»; уведомления приходят при смене сигнала; ошибки тика попадают трейдеру.
