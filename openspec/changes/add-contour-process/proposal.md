## Why

Этап П3.2 документа «Ядро и контуры робота» (`docs/architecture/core-contours.md`).
После П3.1 контур эмуляции уже берёт свечи из ленты ядра и пишет отметки
исполнения под своим ключом, но живёт в одном процессе с ядром. С ядром его
связывают пять вызовов внутри процесса:

| Связь | Сейчас |
| --- | --- |
| Спрос пар и глубины истории | `_CoreLink.request_history` / `touch` → кэш ядра |
| Обязательства сделок | `core.update_obligations(...)` после каждого тика |
| Состав, карточки контрактов | контур сам ходит к брокеру через арбитр ядра |
| Кластерный вердикт | `core.cluster_gate(...)` — хранилище и кэш ядра |
| Календарь, часы, арбитр квот | общие объекты ядра |

Пока эти вызовы есть, контур нельзя ни запустить отдельно, ни перезапустить
без ядра, а следующие этапы (команды управления, состав на ходу,
восстановление после рестарта) опираются именно на отдельный процесс.

## What Changes

- **Контур эмуляции — отдельный процесс.** После выбора инструментов (меню,
  `--instruments` или `POST /api/v1/contours`) ядро запускает процесс контура
  тем же исполняемым файлом со служебным флагом `--contour emulation`.
  Исторический прогон не меняется: он по-прежнему в одном процессе.
- **Файл запуска.** Ядро пишет `data/contours/emulation/launch.json`: вид
  контура, выбранные инструменты, карточки контрактов, имя переменной канала
  Telegram, pid ядра, `schema_version`. Контур в брокера не ходит вообще —
  все квоты остаются у арбитра ядра. В П4 файл заменит `core.sqlite3`.
- **Потребности — строками в рыночной базе.** Контур пишет под своим
  `contour_id` таблицы `contour_demand` (пары и глубина истории) и
  `contour_obligations` (границы исполнения незавершённых сделок). Ядро
  опрашивает их и применяет так же, как вызовы П3.1. Это тот же приём, что
  отметки исполнения в П3.1: контур пишет только свои строки.
- **Жизнь процесса.** Ядро держит процессу контура канал stdin: строка
  `stop` — штатная остановка после текущего тика, конец потока — ядро
  завершилось, контур доделывает тик, фиксирует журнал и выходит. Ядро при
  своей остановке шлёт `stop`, ждёт 30 секунд и только потом завершает процесс
  принудительно. Одинаково работает на macOS и Windows.
- **Папка контура.** `data/contours/emulation/`: `trades.sqlite3`,
  `trade_event.csv`, `trade_summary.csv`, `trade_decision_trace.log`,
  `telegram_delivery.sqlite3`, `bot_debug.log`, `robot.pid`, `launch.json`.
  Ядро остаётся в `data/` со своими `market-data.sqlite3`,
  `cluster-events.sqlite3`, `bot_debug.log`, `robot.pid`.
- **Переезд журнала.** При первом запуске новой версии ядро один раз копирует
  журнал эмуляции из `data/` в папку контура (SQLite — через backup) и
  оставляет исходные файлы для отката на прежнюю версию.
- **Вывод контура** идёт в ту же консоль, что ядро (процесс наследует вывод);
  свой технический журнал — `data/contours/emulation/bot_debug.log`.
- **Канал Telegram из конфига.** `[contours.emulation] telegram_channel_env`
  — имя переменной `.env` с id канала (по умолчанию `TELEGRAM_CHANNEL_ID`).
- **Кластеры.** Читатель Redis остаётся в ядре; контур открывает
  `cluster-events.sqlite3` только на чтение и считает вердикт по своему кэшу.
  Отчёт `GET /api/v1/clusters/report` читает журнал из папки контура.
- **Состояние в API.** `GET /api/v1/contours` добавляет процесс контура:
  `pid`, `exit_code` и состояния `stopped` / `failed`. Swagger
  (`docs/openapi.yaml`) обновлён в этом изменении.
- **Удаляется** переключатель `[contours] market_feed` и путь контура на
  памяти ядра.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `orchestration` — контур эмуляции отдельным процессом, файл запуска,
  потребности строками в рыночной базе, жизнь процесса; удалён переключатель
  `market_feed`.
- `live-market-data` — ядро применяет потребности контуров из рыночной базы.
- `control-api` — состояние процесса контура в `GET /api/v1/contours`.
- `configuration` — `[contours.emulation] telegram_channel_env`, удалён
  `[contours] market_feed`.
- `trade-journal` — журнал эмуляции в папке контура и его разовый переезд.

## Impact

- Код: `run.py` (вход `--contour`, запуск процесса из ядра), `src/assembly/`
  (новый `process.py` — запуск и надзор, `feed.py` — служба ленты без ядра в
  памяти, правки `core.py`, `contour.py`), `src/data/market_store.py`
  (таблицы `contour_demand`, `contour_obligations`, версия схемы),
  `src/data/ingestion.py` (обязательства всех контуров), `src/bot/launch_control.py`
  (состояние процесса), `src/clusters/store.py` (чтение без записи),
  `src/config*.py`, `src/notifier/factory.py` (канал контура).
- Данные: новая папка `data/contours/emulation/`; копия журнала эмуляции;
  версия схемы `market-data.sqlite3` растёт на одну.
- Сборка: `run.spec` без изменений — процесс контура запускается тем же
  исполняемым файлом.
- Документы: `docs/architecture/core-contours.md` (файл запуска, канал stdin,
  П3.2 ✓), `docs/openapi.yaml`.

Non-goals: `core.sqlite3`, поколения, команды остановки и повторного запуска
через API (П4); состав привязок на ходу (П5); автоподъём контура и подхват
живого процесса после рестарта ядра (П6); история отдельным контуром (П7);
свой Telegram у ядра; удержание целостности отдельно по каждому контуру.
