## ADDED Requirements

### Requirement: Отчёт «Песочница против эмуляции»
Нормативный уровень: MUST. API управления ДОЛЖЕН отдавать `GET /api/v1/sandbox/comparison`. Это сравнение сделок песочницы и эмуляции по одним и тем же сигналам, только чтение журналов сделок обоих контуров (`trades.sqlite3` в папке каждого контура).

Ресурс ДОЛЖЕН требовать ключ управления и проверять `Host`, как остальные маршруты контура. Ошибки ДОЛЖНЫ отдаваться в `application/problem+json`.

Ответ ДОЛЖЕН строиться и тогда, когда процессы контуров не запущены. Нет файла журнала или таблиц в нём — контур считается без сделок, ответ `200`.

Ответ ДОЛЖЕН содержать:
- `currency: "RUB"`;
- `as_of`;
- `period` (`name`, `from`, `to`);
- `summary`, `items`, `earlier`;
- `_links.self`.

Деньги, цены и R — десятичные строки, время — UTC ISO 8601. Биржевые тикеры и `trade_id` журнала наружу НЕ ДОЛЖНЫ выходить. Инструмент — короткое имя, сделка — непрозрачный `id`, как в `…/trades`.

Параметры:
- `period` (`day`, `week`, `month`, `all`) либо `from` и `to` — по правилам `…/performance`, по умолчанию `day`;
- `binding`, `instrument` — фильтры;
- `limit` — от 1 до 1000, по умолчанию 200.

Неизвестный параметр, неверный период, `limit` вне диапазона и неизвестная привязка в `binding` ДОЛЖНЫ отклоняться `400 INVALID_REQUEST`.

#### Scenario: Контуры остановлены
- **GIVEN** процессы эмуляции и песочницы не запущены, в журналах есть сделки за день
- **WHEN** приходит `GET /api/v1/sandbox/comparison`
- **THEN** ответ `200` с парами из журналов

#### Scenario: Журнала песочницы нет
- **GIVEN** `data/contours/sandbox/trades.sqlite3` не существует
- **WHEN** приходит `GET /api/v1/sandbox/comparison?period=week`
- **THEN** ответ `200`, `items` пуст, все числа `summary` нулевые

#### Scenario: Неверный лимит
- **WHEN** приходит `GET /api/v1/sandbox/comparison?limit=0`
- **THEN** ответ `400` с `code = INVALID_REQUEST`

### Requirement: Сделки и сигналы отчёта
Нормативный уровень: MUST. В отчёт ДОЛЖНЫ входить сигналы привязок текущего состава песочницы и привязок, по которым у песочницы есть сделки за период. Сигналы привязок, которых в песочнице нет и не было, НЕ ДОЛЖНЫ входить.

Сделка отчёта — строка журнала сделок с хотя бы одним исполнением входа, открытая или закрытая. Сделка, отклонённая или снятая без исполнений входа, НЕ ДОЛЖНА быть стороной пары: она даёт причину по требованию «Причина сделки без пары».

Элемент входит в период по времени сигнала — `created_at` сделки. Ключ сигнала — `signal_id` сделки.

#### Scenario: Эмуляция торгует шире
- **GIVEN** в составе песочницы одна привязка `future-si-ma-raw`, эмуляция за день сделала сделки по 12 привязкам
- **WHEN** приходит `GET /api/v1/sandbox/comparison`
- **THEN** в `items` только сигналы `future-si-ma-raw`

#### Scenario: Отказ брокера — не сторона пары
- **GIVEN** у песочницы сделка по сигналу в фазе `REJECTED` без исполнений, у эмуляции по тому же сигналу закрытая сделка
- **WHEN** приходит отчёт
- **THEN** элемент — `emulation_only`, у песочницы стороны нет, причина — отказ брокера

### Requirement: Пара и её расхождения
Нормативный уровень: MUST. Сделки двух контуров с одинаковым ключом сигнала ДОЛЖНЫ отдаваться одним элементом `kind: "pair"`.

`signal` элемента: `binding`, `instrument`, `timeframe`, `side` (`long` или `short`), `at`.

Сторона (`emulation`, `sandbox`):
- `id`;
- `state` (`open` или `closed`);
- `entry` — `at` первого входа, `price` средняя, `lots` наибольший объём;
- `exit` — `at` последнего выхода, `price` средняя, `kind`, `code`, `label` по требованию «Вид выхода» ресурсов торговли; `null`, если сделка открыта;
- `net`, `net_per_lot` (нетто / наибольший объём), `result_r`, `fees`, `fees_source`.

У открытой сделки `net` — реализованное с учётом комиссий, без переоценки.

`diffs` — список расхождений, у каждого `code`, `label`, `value`:

| `code` | Когда | `value` |
|---|---|---|
| `entry_price` | средние входа отличаются на 1 шаг цены и больше | разница в шагах со знаком стороны: плюс — песочница хуже |
| `entry_time` | первые входы разошлись больше чем на 60 секунд | секунды: песочница − эмуляция |
| `lots` | наибольший объём разный | `{emulation, sandbox}` |
| `exit_kind` | обе закрыты, вид выхода разный | `{emulation, sandbox}` |
| `exit_price` | обе закрыты, вид одинаковый, средние выхода отличаются на 1 шаг и больше | разница в шагах со знаком стороны: плюс — песочница хуже |
| `exit_time` | обе закрыты, последние выходы разошлись больше чем на 60 секунд | секунды: песочница − эмуляция |
| `closed_one_side` | одна сторона закрыта, другая открыта | контур закрытой стороны |

Шаг цены ДОЛЖЕН браться из сделки песочницы, при его отсутствии — из сделки эмуляции. Шага нет у обеих — ценовые коды не считаются, у элемента `steps_unknown: true`. Пара без расхождений ДОЛЖНА иметь пустой `diffs`.

#### Scenario: Вход хуже на два шага
- **GIVEN** сигнал на покупку Si с шагом 1, эмуляция вошла по 92 410, песочница — по 92 412, на 20 секунд позже
- **WHEN** приходит отчёт
- **THEN** у пары `diffs` содержит `entry_price` со значением `2`, а `entry_time` нет

#### Scenario: Стоп у брокера против стопа по минуте
- **GIVEN** обе стороны закрыты стопом, песочница — у брокера по 92 300 в 10:14:37, эмуляция — по закрытой минуте по 92 296 в 10:15:00, шаг 1, сделка на покупку
- **WHEN** приходит отчёт
- **THEN** `diffs` содержит `exit_price` со значением `-4` (песочница лучше), `exit_kind` нет

#### Scenario: Разный вид выхода
- **GIVEN** эмуляция вышла по цели, песочница — стопом у брокера
- **WHEN** приходит отчёт
- **THEN** `diffs` содержит `exit_kind` с `{emulation: "target", sandbox: "stop"}`, `exit_price` не считается

#### Scenario: Разные лоты
- **GIVEN** эмуляция вошла 3 лотами, песочница — 1 лотом, нетто +900 и +290
- **WHEN** приходит отчёт
- **THEN** `diffs` содержит `lots`, `net_per_lot` — `"300"` и `"290"`

### Requirement: Причина сделки без пары
Нормативный уровень: MUST. Сделка только в одном контуре ДОЛЖНА отдаваться элементом `emulation_only` или `sandbox_only` со стороной этого контура и `missing_reason`: `contour` (контур без сделки), `code`, `label`.

Причина ДОЛЖНА искаться в журнале контура без сделки по тому же ключу сигнала, по порядку:

1. последний отказ решения по сигналу (`calculations`, `outcome = REJECTED`) — его код причины и подпись;
2. сделка без исполнений входа в фазе `REJECTED` или `CANCELLED` — причина её последнего исполнения;
3. иначе `not-seen` — «сигнала в контуре не было».

#### Scenario: Запрет входа в песочнице
- **GIVEN** эмуляция вошла по сигналу, в журнале песочницы по нему отказ `contour-stopping`
- **WHEN** приходит отчёт
- **THEN** элемент `emulation_only`, `missing_reason = {contour: "sandbox", code: "contour-stopping", label: …}`

#### Scenario: Лимит входа не исполнился
- **GIVEN** у песочницы сделка по сигналу снята без исполнений, последнее исполнение — отмена лимита входа
- **WHEN** приходит отчёт
- **THEN** у элемента `emulation_only` код причины — код этой отмены

#### Scenario: Привязки нет в эмуляции
- **GIVEN** у песочницы сделка по привязке, инструмента которой нет в составе эмуляции
- **WHEN** приходит отчёт
- **THEN** элемент `sandbox_only` с `code = not-seen`

### Requirement: Сводка и порядок элементов отчёта
Нормативный уровень: MUST. `items` ДОЛЖНЫ идти новыми сверху по времени сигнала, не больше `limit`. `earlier = true`, если за периодом с фильтрами остались элементы.

`summary` ДОЛЖНА считаться по всем элементам периода с фильтрами без учёта `limit`:
- `pairs`, `emulation_only`, `sandbox_only` — числа элементов;
- `missing_reasons` — список `{contour, code, label, count}`;
- `diffs` — число пар по каждому коду расхождения;
- `entry_steps`, `exit_steps` — `{count, mean, max_abs}` по парам, где отклонение посчитано; `null`, если таких нет;
- `paired_result` — по парам, закрытым с обеих сторон: `count` и у каждой стороны сумма `result_r` и сумма `net_per_lot`;
- `sandbox_fees` — число исполнений сделок песочницы отчёта с комиссией брокера (`broker`) и с оценкой (`estimated`).

#### Scenario: Сводка недели
- **GIVEN** за неделю 14 пар, из них 3 с `exit_kind`, 2 сделки только в эмуляции по отказу `risk-budget` и одна только в песочнице `not-seen`
- **WHEN** приходит `GET /api/v1/sandbox/comparison?period=week&limit=5`
- **THEN** в `items` 5 элементов, `earlier = true`, `summary.pairs = 14`, `summary.diffs.exit_kind = 3`, в `missing_reasons` две строки с числами 2 и 1

#### Scenario: Сводка по инструменту
- **WHEN** приходит `GET /api/v1/sandbox/comparison?instrument=Si`
- **THEN** и `items`, и `summary` считаются только по Si

### Requirement: Чтение журналов не мешает контурам
Нормативный уровень: MUST. Ядро ДОЛЖНО открывать журналы сделок контуров только на чтение, каждый — одной транзакцией на ответ, и НЕ ДОЛЖНО писать в них. Запрос отчёта НЕ ДОЛЖЕН задерживать запись контура дольше одной транзакции чтения.

#### Scenario: Контур пишет во время отчёта
- **GIVEN** песочница проводит исполнение
- **WHEN** приходит `GET /api/v1/sandbox/comparison`
- **THEN** ответ строится по согласованному снимку журнала, контур не получает ошибку блокировки
