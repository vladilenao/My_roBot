## Context

- **Свечи для графика** уже отдаёт `GET /api/v1/candles/{instrument}/{timeframe}` (`add-candles-api`, `src/bot/candles_view.py`). Окно `[from, to)`, последние `limit` свечей, `_links.earlier`, незавершённая свеча только последней. Читается рыночная база ядра, `MarketDataStore.candle_window`.
- **Индикаторы** — frozen-dataclass'ы `src/strategies/indicators/*` (`ma`, `bb`, `rsi`, `macd`, `stochastic`). `compute(df)` добавляет колонки на копии кадра, `warmup` — глубина прогрева. Колонки pandas_ta приводятся к нижнему регистру: `macd_12_26_9`, `macdh_12_26_9`, `macds_12_26_9`, `stochk_14_3_3`, `bbl_20_2.0` и т. п.
- **Набор индикаторов стратегии** — `DEFAULT_CONFIG.indicators` её модуля. Ядро собирает конфигурации в `_strategy_map()` (`src/assembly/contour.py`). У `harmonic_abcd` индикаторов нет.
- **Привязка** (`Assignment`): `id`, `strategy`, `timeframe`, `management`, `filter_profile`. Её `id` уже есть в ответах API: `MemberBinding` у эмуляции, `BindingMember` и `BindingCard` у песочницы.
- **Глубина живого анализа.** `LiveAnalysis._calculate` (`src/bot/live_analysis.py`) берёт `frame.tail(binding_requirements(...)[tf])` и считает на нём `strategy.compute()`. `binding_requirements` (`src/history/warmup.py`) — максимум из `required_history()` стратегии, прогрева сопровождения, `ema_long` тренда (50), `adx_period × 2` и `fractal_bars`. У `macd_rsi_stoch` и `ma_cloud_rsi_macd` на NG 15m это 50 свечей.
- **Сервер** — `ThreadingHTTPServer` в процессе ядра. Там же идут живые полосы данных. Тяжёлый расчёт на pandas в потоке запроса делит GIL с живым анализом.
- **Потребитель** — `CandleChart` UI (Lightweight Charts 5.2.1): панели `addSeries(…, paneIndex)`, уровни `createPriceLine`, опрос раз в 5 с.

## Goals / Non-Goals

**Goals:**

- Отдать UI ряды индикаторов стратегии привязки на тех же свечах, что `/api/v1/candles…`, с синхронным листанием.
- По умолчанию — ровно те значения, на которых стратегия принимала решения.
- Описание отрисовки от робота: UI не держит своей таблицы «какой индикатор в какой панели».
- Ноль влияния на торговлю: расчёт не задерживает живой анализ заметно для его сроков.

**Non-Goals:**

- Свой набор индикаторов и периодов (`set=rsi(14),…`) — следующее изменение, решение владельца 06.11.
- Сигналы индикаторов (`rsi_signal`, `macd_signal`, …) точками на графике — позже, отдельным переключателем.
- Индикаторы фильтра `triple_screen` на старших таймфреймах, уровни `basic_levels`, контекст тренда.
- Фигуры `harmonic_abcd` (точки A, B, C, D) и треугольники `flat_triangle`.
- Изменение глубины расчёта стратегий. Расхождение режимов — факт, который график показывает, а не исправляет.
- Индикаторы прогонов истории — их свечи живут у эмулятора данных.

## Decisions

### 1. Адрес: под рядом свечей

`GET /api/v1/candles/{instrument}/{timeframe}/indicators?binding=<id>`

| Вариант | За | Против |
|---|---|---|
| **Под рядом свечей** | то же имя, таймфрейм, окно и листание; одна логика разбора; рядом с данными, на которых считается | адрес длиннее |
| `/api/v1/bindings/{id}/chart` | ресурс привязки | ресурса привязок нет; инструмент и таймфрейм всё равно параметры |
| Индикаторы полем в ответе свечей | один запрос | ломает простой ресурс свечей; свечи без привязки не имеют смысла индикаторов |

Выбран первый. Доступ, `Host`, формат ошибок и разрешение имени — общие с `/api/v1/candles…`: требования `control-api` уже покрывают маршруты `/api/v1/candles…`.

### 2. Режимы расчёта и глубина

Проба на `tests/snapshot/data/NG_15m` (1732 свечи, последние 500 точек):

| Колонка | `strategy` (хвост 50) против `continuous` |
|---|---|
| `sma_fast`, `sma_slow`, `stochk_14_3_3`, `stochd_14_3_3` | совпадают точно — окно конечное и короче хвоста |
| `rsi` (RMA, период 14) | до 4,1 пункта |
| `macd_12_26_9` | до 0,00492 при типичном 0,00518 |
| `macds_12_26_9` | до 0,00726 при типичном 0,00494 |

EMA-26 и сигнальная EMA-9 на 50 свечах ещё не забыли точку старта, поэтому MACD стратегии и «классический» MACD — разные линии. Обе нужны: первая объясняет решения, вторая — привычная картинка.

- **`mode=strategy`** (по умолчанию). Точка свечи `t` равна последней строке `compute()` всех индикаторов стратегии на кадре из `depth` свечей ряда, последняя из которых — `t`. `depth = binding_requirements(binding, …)[binding.timeframe]`, те же профили сопровождения и параметры фильтра, что у живого анализа. Свеча, перед которой в ряду меньше `depth − 1` свечей, получает `null`: стратегия на ней не считала.
- **`mode=continuous`.** Один `compute()` на кадре из окна и 300 свечей перед ним (или с начала ряда). Остаток точки старта после 300 свечей: EMA-26 ≈ (25/27)³⁰⁰ ≈ 10⁻¹⁰, RMA-14 ≈ (13/14)³⁰⁰ ≈ 2·10⁻¹⁰ — меньше точности цены. `null` — где прогрев индикатора не набран с начала ряда.

Ответ содержит `mode` и `depth` (у `continuous` — `null`). UI подписывает режим в легенде.

### 3. Привязка и таймфрейм

- `binding` обязателен: из него стратегия, её конфигурация и глубина. Поиск — среди привязок текущей конфигурации `[strategies.*]` по `id` без учёта регистра. Привязка не обязана торговать этим инструментом: график «как стратегия увидела бы NG» имеет смысл и для привязки SBER.
- Таймфрейм графика — любой хранимый для инструмента, как у свечей (решение владельца 06.11). Ответ несёт `binding.timeframe` и `binding_timeframe: true|false`. На чужом таймфрейме режим `strategy` берёт ту же `depth` — «как стратегия увидела бы на этом таймфрейме». UI показывает пометку «не таймфрейм стратегии».
- Стратегия без индикаторов — `200` с пустым `indicators`.

### 4. Описание отрисовки — у индикатора

Новое свойство `chart` у `Indicator` возвращает `IndicatorChart` (`src/strategies/indicators/chart.py`):

```python
IndicatorChart(
    key="macd", title="MACD 12/26/9", params={"fast": 12, "slow": 26, "signal": 9},
    pane="separate", levels=(0.0,),
    lines=(ChartLine("macd", "macd_12_26_9", "line"),
           ChartLine("signal", "macds_12_26_9", "line"),
           ChartLine("histogram", "macdh_12_26_9", "histogram")),
)
```

| Индикатор | `pane` | Линии | Уровни |
|---|---|---|---|
| `MaCloudIndicator` | `price` | `fast`, `slow`; `fill: between` | — |
| `BollingerBandsIndicator` | `price` | `upper`, `middle`, `lower` | — |
| `RsiIndicator` | `separate` | `rsi` | 30, 50, 70 |
| `MacdIndicator` | `separate` | `macd`, `signal`, `histogram` | 0 |
| `StochasticIndicator` | `separate` | `k`, `d` | 20, 80 |

- Имя колонки — из тех же параметров, что строят её в `compute()`. Тест сверяет описание с фактическими колонками результата, иначе переименование pandas_ta прошло бы молча.
- Цвета — дело UI (`theme/chart.ts`), робот отдаёт только роли линий.
- Почему у индикатора, а не таблицей в `indicators_view`: новый индикатор без описания не пройдёт тест, а таблица в API устареет незаметно.

### 5. Формат ответа

```json
{
  "instrument": "NG-12.26", "instrument_type": "future", "timeframe": "15m",
  "binding": {"id": "future-ng-macd", "strategy": "macd_rsi_stoch", "timeframe": "15m"},
  "binding_timeframe": true,
  "mode": "strategy", "depth": 50,
  "from": null, "to": "2026-11-06T09:14:05Z",
  "times": ["2026-11-06T08:30:00Z", "2026-11-06T08:45:00Z", "2026-11-06T09:00:00Z"],
  "last_complete": false,
  "indicators": [
    {"key": "rsi", "title": "RSI 14", "params": {"period": 14}, "pane": "separate", "levels": [30, 50, 70],
     "lines": [{"name": "rsi", "kind": "line", "values": [54.21, 55.02, 53.87]}]}
  ],
  "_links": {"self": {"href": "…"}, "candles": {"href": "/api/v1/candles/NG-12.26/15m?limit=3"},
             "earlier": {"href": "…/indicators?binding=future-ng-macd&mode=strategy&to=2026-11-06T08:30:00Z&limit=3"}}
}
```

- `times` — моменты открытия ровно тех свечей, что отдал бы `/api/v1/candles…` с теми же `from`, `to`, `limit`. Значения линий выровнены по `times`. Это компактнее массива объектов на каждую точку, и UI сопоставляет свечи по индексу.
- Значения — числа JSON, округлённые до 8 значащих цифр, `NaN` → `null`. Не десятичные строки: индикатор не деньги и не цена сделки.
- `last_complete: false` — последняя точка посчитана с незавершённой свечой и изменится.
- `_links.candles` — свечи того же окна, `_links.earlier` — по тому же правилу, что у свечей, с теми же `binding` и `mode`.

### 6. Окно, листание, незавершённая свеча

- `from`, `to`, `limit` — как у свечей. `limit` 1…1000, по умолчанию 500: верхняя граница ниже, чем у свечей (5000), из-за цены расчёта, см. решение 7.
- Свечи окна читаются тем же `candle_window`. Ещё `depth − 1` (режим `strategy`) или 300 (`continuous`) завершённых свечей до первой читаются в той же транзакции. Расчёт — вне блокировки хранилища.
- Незавершённая свеча — по правилам свечей: только последняя и позже последней завершённой. Режим `strategy` считает её точку на хвосте, который она завершает. Живая стратегия так не делает, она ждёт закрытия. Поэтому точка помечена `last_complete: false`.

### 7. Нагрузка и кэш

Цена режима `strategy` — один `compute()` на точку. На пробе 500 точек — 2,8 с (`ma_cloud_rsi_macd`) и 4,1 с (`macd_rsi_stoch`). `continuous` — один `compute()` на ответ, десятки миллисекунд.

- **Кэш точек.** Точка завершённой свечи в режиме `strategy` не меняется. Кэш в памяти ядра по ключу `(binding.id, отпечаток конфигурации стратегии, depth, instrument_uid, timeframe, open_time)`, LRU на 100 000 точек (~30 МБ). Опрос раз в 5 с считает одну-две новые точки. Листание назад считает только новое окно. Отпечаток — `repr` кортежа индикаторов: смена параметров в коде даёт новый ключ.
- **Один расчёт за раз.** `threading.Lock` на расчёт. Второй запрос ждёт. Два открытых графика не удваивают нагрузку на GIL.
- **Свечи без расчёта при ожидании.** Свечи UI запрашивает отдельно, они не стоят в очереди за индикаторами.
- **Процесс-работник — не сейчас.** Вынос расчёта в отдельный процесс снял бы спор за GIL полностью, но добавил бы пул процессов в собранный PyInstaller бинарник. Сначала замер (ручная проверка 6.4). Если холодный запрос заметно сдвигает живой анализ — отдельное изменение.

### 8. Ошибки

| Случай | Ответ |
|---|---|
| нет `binding`, неверный `mode`, окно, `limit` вне 1…1000 | `400 INVALID_REQUEST` |
| неизвестная привязка | `404 NOT_FOUND`, `suggestions` — `id` привязок конфигурации для этого инструмента (акция — по тикеру, фьючерс — по семейству), иначе пустой список |
| имя инструмента, таймфрейм | как у свечей: `404` с `suggestions` |
| база не открыта | `503 MARKET_DATA_NOT_READY` |
| индикатор упал на данных | `500` с `detail` без данных кадра; в журнал — тип исключения, привязка, инструмент коротким именем, таймфрейм |

Новых кодов ошибок нет.

### 9. Ссылки у привязок

`MemberBinding` (эмуляция) и `BindingMember` (песочница) получают `_links.indicators` — адрес индикаторов привязки на её таймфрейме для инструмента участника. UI строит график «как видела стратегия» по ссылке, не зная правил адреса. У `BindingCard` каталога ссылки нет: там инструмент — код семейства, а не контракт.

### 10. Версия контракта

Действующий `docs/api/openapi.yaml` — 2.6.0. Черновик — 2.7.0. Изменение только добавляет операцию, схемы и необязательное поле `_links` у двух схем привязки: прежние клиенты не ломаются.

## Risks / Trade-offs

- **[Холодный график 3–4 с]** Первое открытие ряда в режиме `strategy` ждёт расчёта 500 точек. → Кэш, UI показывает свечи сразу, а индикаторы — по готовности. Прогрев кэша при старте не делаем: неизвестно, какие графики откроют.
- **[GIL]** Расчёт в процессе ядра замедляет живой анализ, пока идёт. → Один расчёт за раз, замер в ручной проверке. Если влияние заметно — процесс-работник отдельным изменением.
- **[Два MACD]** Владелец увидит, что MACD стратегии на 50 свечах не похож на MACD в терминале. Это верно и полезно, но может удивить. → Переключатель режима в UI с подписью, раздел в `docs/api/README.md`.
- **[Глубина изменится]** Если поменяется `binding_requirements` или профиль сопровождения, точки в кэше со старой `depth` не используются: `depth` в ключе.
- **[Кадр живого анализа шире ряда базы]** Живой анализ получает кадр из кэша данных контура, график — из рыночной базы ядра. Расхождение возможно, если кэш контура отстаёт или содержит свечи, которых нет в базе. → Тест сверяет точки с `LiveAnalysis._calculate` на одном кадре. Ручная проверка 6.2 сверяет последнюю точку с журналом решений.

## Open Questions

1. Режим по умолчанию в UI: `strategy` (как видела стратегия) или `continuous` (привычная картинка) с переключателем на `strategy`? Контракт по умолчанию — `strategy`.
2. Нужна ли отдельная проверка глубины стратегий? MACD на 50 свечах — особенность текущей логики, а не графика. Менять её — отдельное изменение с бэктестом.
