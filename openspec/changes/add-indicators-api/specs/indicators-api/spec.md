## ADDED Requirements

### Requirement: Ряды индикаторов привязки
Нормативный уровень: MUST. `GET /api/v1/candles/{instrument}/{timeframe}/indicators` ДОЛЖЕН отдавать значения индикаторов стратегии привязки на свечах одного ряда рыночной базы ядра. Обязательный параметр `binding` — `id` привязки из текущей конфигурации `[strategies.*]` без учёта регистра. Набор индикаторов и их параметры ДОЛЖНЫ быть теми же, с которыми стратегия привязки работает в контурах.

Ответ ДОЛЖЕН содержать:

- `instrument`, `instrument_type`, `timeframe` — как у ресурса свечей;
- `binding` — `id`, `strategy` и `timeframe` привязки;
- `binding_timeframe` — `true`, если таймфрейм ряда совпадает с таймфреймом привязки;
- `mode` и `depth` — режим расчёта и глубина хвоста (`null` для `continuous`);
- `from`, `to` — фактическое окно запроса;
- `times` — моменты открытия свечей окна по возрастанию;
- `last_complete` — `false`, если последняя точка посчитана с незавершённой свечой;
- `indicators` — по элементу на индикатор стратегии в порядке её конфигурации: `key`, `title`, `params`, `pane`, `levels` и `lines`; у линии `name`, `kind` и `values` — числа, выровненные по `times`, `null` там, где значения нет;
- `_links`: `self`, `candles` — свечи того же окна, `earlier` — по правилу ресурса свечей.

Стратегия без индикаторов ДОЛЖНА давать `200` с пустым `indicators`. Биржевой тикер и `instrument_uid` НЕ ДОЛЖНЫ появляться в ответе.

#### Scenario: Индикаторы стратегии привязки
- **GIVEN** привязка `future-ng-macd` стратегии `macd_rsi_stoch` на `15m`, в ряду NG-12.26 `15m` 2000 завершённых свечей
- **WHEN** приходит `GET /api/v1/candles/NG-12.26/15m/indicators?binding=future-ng-macd`
- **THEN** ответ `200`: 500 моментов в `times`; в `indicators` по порядку MACD 12/26/9, RSI 14 и стохастик 14/3/3, у каждой линии 500 значений; `binding_timeframe: true`, `mode: strategy`

#### Scenario: Стратегия без индикаторов
- **GIVEN** привязка стратегии `harmonic_abcd`
- **WHEN** приходят индикаторы этой привязки
- **THEN** ответ `200` с `times` окна и пустым `indicators`

#### Scenario: Привязка другого инструмента
- **GIVEN** привязка `share-sber-ma` торгует SBER
- **WHEN** приходит `GET /api/v1/candles/NG-12.26/15m/indicators?binding=share-sber-ma`
- **THEN** ответ `200` с индикаторами `ma_cloud_rsi_macd` на свечах NG-12.26

### Requirement: Режим расчёта как у стратегии
Нормативный уровень: MUST. Параметр `mode` ДОЛЖЕН принимать `strategy` (по умолчанию) и `continuous`.

В режиме `strategy` значение в точке свечи `t` ДОЛЖНО быть равно последней строке `compute()` индикаторов стратегии на кадре из последних min(`depth`, число свечей ряда до `t` включительно) свечей ряда, последняя из которых — `t`. `depth` ДОЛЖНА быть глубиной расчёта, на которой живой анализ считает стратегию этой привязки на её таймфрейме: max(минимум допуска, `[robot] analysis_depth`). Минимум допуска — `binding_requirements` привязки на её таймфрейме. Если в ряду до свечи включительно меньше свечей, чем минимум допуска, значения ДОЛЖНЫ быть `null`.

В режиме `continuous` значения ДОЛЖНЫ считаться одним `compute()` на кадре из свечей окна и не менее 300 свечей перед ним (или с начала ряда, если их меньше); `depth` в ответе — `null`.

#### Scenario: Совпадение с живым анализом
- **GIVEN** ряд NG-12.26 `15m`, привязка `future-ng-macd`, `analysis_depth = 150`
- **WHEN** приходят индикаторы в режиме `strategy`
- **THEN** `depth: 150`, у каждой точки значения MACD, сигнальной линии, гистограммы, RSI и стохастика совпадают с последней строкой `compute()` стратегии на тех же 150 свечах до относительной погрешности 10⁻⁹

#### Scenario: Глубина из конфигурации
- **GIVEN** `[robot] analysis_depth = 80`, минимум допуска привязки `future-ng-macd` на `15m` — 50
- **WHEN** приходят индикаторы этой привязки в режиме `strategy`
- **THEN** `depth: 80`, точки посчитаны на хвостах из 80 свечей

#### Scenario: Начало ряда
- **GIVEN** в ряду 30 свечей, минимум допуска привязки 50
- **WHEN** приходят индикаторы в режиме `strategy`
- **THEN** у всех 30 точек значения `null`

#### Scenario: Молодой ряд короче глубины
- **GIVEN** в ряду 100 свечей, минимум допуска привязки 50, глубина 150
- **WHEN** приходят индикаторы в режиме `strategy`
- **THEN** у первых 49 точек значения `null`; точка 50-й свечи и следующие посчитаны на всех свечах ряда до них включительно

#### Scenario: Классический расчёт
- **WHEN** приходит запрос с `mode=continuous`
- **THEN** значения совпадают с `compute()` индикаторов на всём ряде до относительной погрешности 10⁻⁶, `depth: null`

#### Scenario: Неверный режим
- **WHEN** приходит запрос с `mode=fast`
- **THEN** ответ `400` с `code = INVALID_REQUEST`

### Requirement: Окно индикаторов совпадает с окном свечей
Нормативный уровень: MUST. Параметры `from`, `to` ДОЛЖНЫ значить то же, что у `GET /api/v1/candles/{instrument}/{timeframe}`. `limit` ДОЛЖЕН быть от 1 до 1000, по умолчанию 500. `times` ДОЛЖЕН совпадать с `open_time` свечей, которые ресурс свечей отдал бы с теми же `from`, `to` и `limit`, включая правило незавершённой свечи. `_links.earlier` ДОЛЖЕН вести на тот же ряд, ту же привязку и тот же режим с `to`, равным первому моменту `times`, и тем же `limit` — только если в ряду есть свечи раньше. Окно, неверное для ресурса свечей, и `limit` вне 1…1000 ДОЛЖНЫ отклоняться `400 INVALID_REQUEST`.

#### Scenario: Синхронное листание
- **GIVEN** UI получил свечи и индикаторы NG-12.26 `15m` без параметров
- **WHEN** UI переходит по `_links.earlier` свечей и по `_links.earlier` индикаторов
- **THEN** `times` индикаторов совпадает с `open_time` свечей нового окна поэлементно

#### Scenario: Незавершённая свеча
- **GIVEN** последняя строка ряда `1m` — незавершённая свеча 12:14 после завершённой 12:13
- **WHEN** приходят индикаторы `1m`
- **THEN** последний момент `times` — 12:14, `last_complete: false`

#### Scenario: Предел окна
- **WHEN** приходит запрос с `limit=1001`
- **THEN** ответ `400` с `code = INVALID_REQUEST`

### Requirement: Таймфрейм графика не таймфрейм привязки
Нормативный уровень: MUST. Ресурс ДОЛЖЕН принимать любой таймфрейм, который хранится у инструмента в рыночной базе, а не только таймфрейм привязки. При несовпадении `binding_timeframe` ДОЛЖЕН быть `false`, а режим `strategy` ДОЛЖЕН брать те же `depth` и минимум допуска, что на таймфрейме привязки.

#### Scenario: Старший таймфрейм
- **GIVEN** привязка `future-ng-macd` на `15m` с глубиной 150, у NG-12.26 хранится ряд `1h`
- **WHEN** приходит `GET /api/v1/candles/NG-12.26/1h/indicators?binding=future-ng-macd`
- **THEN** ответ `200` с `binding.timeframe: 15m`, `binding_timeframe: false`, `depth: 150`

### Requirement: Ошибки ресурса индикаторов
Нормативный уровень: MUST. Ошибки ДОЛЖНЫ идти в формате ошибок API управления:

- нет `binding` — `400 INVALID_REQUEST`;
- привязки с таким `id` нет в конфигурации — `404 NOT_FOUND` с `suggestions`: `id` привязок конфигурации для этого инструмента по правилам подбора торговли (акция — по тикеру, фьючерс — по семейству, затем по коду), иначе пустой список;
- имя инструмента и таймфрейм — по правилам ресурса свечей, с теми же `suggestions`;
- рыночная база не открыта — `503 MARKET_DATA_NOT_READY`;
- исключение при расчёте — `500` без данных кадра в `detail`. В журнал ДОЛЖНЫ попадать только тип исключения, `id` привязки, короткое имя инструмента и таймфрейм.

#### Scenario: Неизвестная привязка
- **GIVEN** у семейства NG в конфигурации привязки `future-ng-macd` и `future-ng-ma`
- **WHEN** приходит `GET /api/v1/candles/NG-12.26/15m/indicators?binding=ng-macd`
- **THEN** ответ `404` с `code = NOT_FOUND` и `suggestions: ["future-ng-macd", "future-ng-ma"]`

#### Scenario: Без привязки
- **WHEN** приходит `GET /api/v1/candles/NG-12.26/15m/indicators`
- **THEN** ответ `400` с `code = INVALID_REQUEST`

#### Scenario: Ключ экспорта
- **WHEN** запрос индикаторов приходит с ключом `MARKET_DATA_EXPORT_TOKEN`
- **THEN** ответ `401` с `code = UNAUTHORIZED` в `application/problem+json`

### Requirement: Расчёт индикаторов не мешает ядру
Нормативный уровень: MUST. Ресурс ДОЛЖЕН только читать рыночную базу: без запросов к брокеру, записей в базу, изменений курсоров, покрытия, готовности пар и ленты `changes`. Свечи окна и прогрева ДОЛЖНЫ читаться одной транзакцией, расчёт — вне блокировки хранилища. Одновременно ДОЛЖЕН идти не больше одного расчёта индикаторов, остальные запросы ждут. Точки завершённых свечей режима `strategy` ДОЛЖНЫ кэшироваться в памяти по привязке, конфигурации стратегии, минимуму допуска, глубине, ряду и времени свечи с ограничением размера кэша. Точка незавершённой свечи НЕ ДОЛЖНА кэшироваться.

#### Scenario: Повторный запрос из кэша
- **GIVEN** индикаторы NG-12.26 `15m` привязки `future-ng-macd` уже запрошены
- **WHEN** через 5 с приходит тот же запрос, в ряду появилась одна новая завершённая свеча
- **THEN** считается одна новая точка, остальные берутся из кэша, значения совпадают с первым ответом

#### Scenario: База не тронута
- **GIVEN** сняты курсоры, покрытие и последний `change_id` рыночной базы
- **WHEN** приходят двадцать запросов индикаторов в обоих режимах
- **THEN** курсоры, покрытие и последний `change_id` не изменились, запросов к брокеру не было

#### Scenario: Два запроса одновременно
- **WHEN** два запроса индикаторов разных рядов приходят одновременно
- **THEN** расчёты идут друг за другом, оба ответа `200`
