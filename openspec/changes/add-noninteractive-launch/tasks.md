## 3. Ожидание и команда API

- [x] 3.1 `src/config.py`: `ROBOT_CONTROL_TOKEN` из окружения; `run.py`: ключ в `secrets` у `setup_logging`.
- [x] 3.2 `_start_local_api` в эмуляции сразу после `_start_early_market_data`, до выбора инструментов; запуск при хотя бы одном ключе; сообщение о каждом незаданном ключе без значения ключа.
- [x] 3.3 `src/data/export_api.py`: раздельные ключи `ExportToken` и `ControlToken` по маршрутам; проверка `Host` (`127.0.0.1`, `localhost`, `[::1]` с портом сервера) для маршрутов управления; без заголовков CORS.
- [x] 3.4 Состояние контура в памяти процесса (потокобезопасно): `waiting_command`, `starting`, `running`, источник, контракты, время, команда, отказы последней команды.
- [x] 3.5 `GET /api/v1/contours` и `POST /api/v1/contours` по контракту `docs/openapi.yaml`: разбор тела (`400`), очередь к главному потоку, ожидание ответа до 60 секунд (`201`/`422`, иначе `202` с `Location`), `409` при уже запущенной торговле.
- [x] 3.6 Главный поток при `--wait-command` ждёт команду на месте интерактивного выбора, печатает адрес команды; после `422` продолжает ждать; после успеха разрешённый набор идёт в обычную сборку.
- [x] 3.7 Без `ROBOT_CONTROL_TOKEN` запуск с `--wait-command` завершается с кодом `2` до ожидания.

## 4. Меню и точка входа

- [x] 4.1 `ask_mode`: «Эмуляция (живые данные, симулятор исполнения)» и «Историческая торговля»; для эмуляции — «Инструменты: выбрать сейчас — 1, ждать команду API — 2»; меню собирает `LaunchRequest`.
- [x] 4.2 Меню сохраняет проверку по ходу выбора; после выбора — фильтр привязок с `✗` и возвратом к выбору при пустом итоге; итог меню превращается в `Chosen` для эквивалентной команды и состояния API.
- [x] 4.3 `run.py`: `main` получает `LaunchRequest` из разбора или меню; `_run_live` и `_run_history` передают его в `_launch`; `_launch` разрешает инструменты или ждёт команду вместо вызова `select_instruments`.
- [x] 4.4 Повтор прогона истории при сдвиге начала передаёт уже разрешённую выборку без повторного разрешения и вопросов.
