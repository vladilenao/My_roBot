## ADDED Requirements

### Requirement: Предварительная проверка прогона истории
Нормативный уровень: MUST. `POST /api/v1/history/preflight` с телом `POST /api/v1/history` (`from`, `to`, `pause`, `instruments`) ДОЛЖЕН проверять прогон так, как его проверит процесс прогона перед стартом, и НЕ ДОЛЖЕН ставить прогон в очередь, создавать папку прогона или писать файлы прогона. `pause` ДОЛЖЕН приниматься по правилам постановки и НЕ ДОЛЖЕН влиять на итог.

**Шаги проверки** — те же, что у постановки и процесса прогона:

1. форма тела и привязки инструментов — как у `POST /api/v1/history`, с теми же ответами `400` и `422 INSTRUMENTS_REJECTED`;
2. сверка импорта эмулятора данных — по требованию «Сверка импорта перед историческим прогоном»; сверка проверки и сверка очереди прогонов НЕ ДОЛЖНЫ идти одновременно;
3. разрешение инструментов у эмулятора на начало диапазона;
4. контрактная цепочка семейств, расписание участков и предпроверка данных — пары «инструмент × таймфрейм» связок и `1m`, прогрев, начало и правая граница. Процесс прогона и проверка ДОЛЖНЫ выполнять этот шаг одной и той же функцией. Если предпроверка сдвинула начало на первую доступную свечу, проверка ДОЛЖНА один раз повторить шаг 4 с новым началом, как повторяет процесс прогона.

**Ответ `200`** — итог проверки:

- `ok` — прогон с этим телом на тех же данных пройдёт предпроверку;
- `start`, `end` — диапазон, с которым начнётся торговля, с учётом сдвига начала;
- `market_data_sync` — `status` и `snapshot_generation` сверки импорта;
- `pairs` — проверенные пары: `instrument` (тикер акции или короткое имя контракта), `instrument_type`, `timeframe`, `segment` (участок цепочки `{from, to}`, у фиксированного инструмента — `null`), `found` (первый и последний найденные бары `{from, to}` или `null`) и `ok` пары;
- `problems` — проблемы предпроверки тем же текстом, что процесс прогона пишет в `console.log`;
- `notes` — заметки предпроверки: сдвиг начала, наблюдаемое покрытие, расписание;
- `rejections` — инструменты, которые не разрешились у эмулятора (`instrument`, `reason`);
- `reason` — причина, с которой настоящий прогон завершится в `failed`, или `null` при `ok`;
- `bindings` — связки, которые будут торговать, по требованию «Связки прогона истории»;
- `_links.history`, а при `ok` — действие `start` с телом запроса для `POST /api/v1/history`.

Если эмулятор данных недоступен или не ответил, ответ ДОЛЖЕН быть `503` с кодом `SOURCE_UNAVAILABLE` и причиной без адреса эмулятора, а не `500`. Ответ НЕ ДОЛЖЕН содержать секреты и адрес эмулятора данных.

#### Scenario: Проверка находит ту же причину, что прогон
- **GIVEN** у NG в эмуляторе нет минутных свечей в конце диапазона 01.06.2026—20.06.2026
- **WHEN** приходит `POST /api/v1/history/preflight` с `{"from": "2026-06-01 00:00", "to": "2026-06-20 00:00", "instruments": ["BR", "NG"]}`
- **THEN** ответ `200`, `ok = false`, в `problems` — та же строка про NG, что в `console.log` прогона с этим телом, `reason` совпадает с `reason` упавшего прогона, а `GET /api/v1/history` не показывает нового прогона

#### Scenario: Проверка пройдена
- **WHEN** приходит проверка прогона SBER на диапазоне, покрытом свечами с прогревом
- **THEN** ответ `200`, `ok = true`, `problems` пуст, у каждой пары SBER `ok = true` и `found`, `bindings` — привязки SBER из `robot.toml`, `_actions` содержит `start`

#### Scenario: Сдвиг начала
- **GIVEN** начало диапазона приходится на выходной, первая минутная свеча — в понедельник 10:00
- **WHEN** приходит проверка
- **THEN** `start` — понедельник 10:00, в `notes` — сдвиг начала, итог — по повторной проверке с новым началом

#### Scenario: Отказ привязок
- **WHEN** приходит проверка с `"instruments": ["NG", "AFLT"]`, а у AFLT нет привязок
- **THEN** ответ `422 INSTRUMENTS_REJECTED` называет AFLT, к эмулятору проверка не обращается

#### Scenario: Контракт не найден у эмулятора
- **WHEN** приходит проверка с `"instruments": ["NG-03.20"]`, а такого контракта нет среди контрактов эмулятора на начало прогона
- **THEN** ответ `200`, `ok = false`, `rejections` называет NG-03.20, `reason` — та же причина, что у прогона

#### Scenario: Эмулятор недоступен
- **GIVEN** эмулятор данных не запущен
- **WHEN** приходит проверка
- **THEN** ответ `503` с кодом `SOURCE_UNAVAILABLE` и причиной «эмулятор недоступен», очередь прогонов не меняется

### Requirement: Связки прогона истории
Нормативный уровень: MUST. Связка прогона — привязка `[strategies.*]`, по которой торгует инструмент прогона: `id`, `instrument` (тикер акции, короткое имя фиксированного контракта или код семейства автоматической цепочки), `strategy`, `timeframe`, `filter`, `management`. Подбор ДОЛЖЕН совпадать с торговлей: акция — по тикеру, фьючерс — по семейству, а если по семейству привязок нет — по его коду.

- `HistoryRun` ДОЛЖЕН нести `bindings` — связки, разрешённые при постановке, сохранённые в `history_runs`. Изменение конфигурации после постановки НЕ ДОЛЖНО менять `bindings` прогона. У прогона, принятого прежней версией, `bindings` — `null`.
- Процесс прогона ДОЛЖЕН записать в `report.json` связки, по которым он торговал. `HistoryReport` ДОЛЖЕН отдавать их в `bindings`; у отчёта прежней версии — `null`.
- Проверка `POST /api/v1/history/preflight` ДОЛЖНА отдавать в `bindings` связки разрешённых инструментов.

#### Scenario: Состав прогона после смены конфигурации
- **GIVEN** прогон NG принят, когда у NG была одна привязка `future-ng-macd`
- **WHEN** в конфигурацию добавили вторую привязку NG и пришёл `GET /api/v1/history/{id}`
- **THEN** `bindings` прогона — только `future-ng-macd`

#### Scenario: Прогон прежней версии
- **GIVEN** в `history_runs` прогон без связок, отчёт прогона без поля `bindings`
- **WHEN** приходят `GET /api/v1/history/{id}` и `GET /api/v1/history/{id}/report`
- **THEN** ответы `200`, `bindings` — `null`
