## Why

В UI робота диалог «Новый прогон» показывает проверку данных и блок «Будут торговать N связок». Сейчас UI может только угадать, откажет ли робот: `POST /api/v1/history` до ответа проверяет лишь форму и привязки, а выбор контрактов у эмулятора и предпроверку данных (`run_preflight` / `run_chain_preflight`) делает процесс прогона уже после постановки. Прогон падает в `failed` с причиной «данные не прошли предварительную проверку», и пользователь узнаёт об этом после ожидания в очереди.

Кроме того, по прогону не видно, по каким связкам он шёл: состав прогона — это токены запроса, а привязки берутся из `[strategies.*]` текущей конфигурации. Если конфигурация потом поменялась, восстановить состав старого прогона нельзя.

## What Changes

- **R1 — предварительная проверка без постановки в очередь.** Новый маршрут `POST /api/v1/history/preflight` с тем же телом, что `POST /api/v1/history` (`pause` допускается и не влияет). Робот:
  - проверяет форму и привязки так же, как постановка (`400`, `422 INSTRUMENTS_REJECTED`);
  - сверяет импорт эмулятора данных (по одной сверке с очередью прогонов) и разрешает инструменты у эмулятора;
  - строит контрактную цепочку, загружает расписание и выполняет ту же предпроверку данных, что процесс прогона перед стартом (одна общая функция для обоих путей), включая один повтор после сдвига начала;
  - ничего не ставит в очередь, не создаёт папку прогона и не пишет файлов.
  
  Ответ `200` — `HistoryPreflight`: итог `ok`, действующее начало (с учётом сдвига), проверенные пары (инструмент или контракт цепочки, таймфрейм, участок, найденный диапазон, итог пары), проблемы и заметки тем же текстом, что в `console.log` прогона, отказы разрешения у эмулятора, `reason` — какой будет причина `failed` у настоящего прогона, и `bindings` — связки, которые будут торговать. Эмулятор недоступен — `503 SOURCE_UNAVAILABLE` с понятной причиной, а не `500`.
- **R2 — состав прогона.** `bindings` (`id`, `instrument`, `strategy`, `timeframe`, `filter`, `management`):
  - в `HistoryRun` — связки, разрешённые при постановке, хранятся в `history_runs` (новая колонка `bindings_json`); у прогонов прежней версии — `null`;
  - в `report.json` и `HistoryReport` — связки, по которым процесс прогона действительно торговал; у отчётов прежней версии — `null`.
- **Swagger** `docs/api/openapi.yaml` — 2.13.0: маршрут, схемы `HistoryPreflight`, `HistoryPreflightPair`, `HistoryBinding`, код ошибки `SOURCE_UNAVAILABLE`; изменения только добавляют.

Выбор отдельных связок прогона (R3) и отдельный каталог привязок (R4) — не в этом изменении.

## Capabilities

### Modified Capabilities

- `control-api` — новые требования «Предварительная проверка прогона истории» и «Связки прогона истории».

## Impact

- `run.py` — проверка данных вынесена из `_launch` в общую функцию; функция проверки запроса для API передаётся очереди.
- `src/assembly/history_runs.py` — `HistoryRuns.preflight`, связки при постановке и в итоге, общий замок сверки импорта.
- `src/assembly/core_state.py` — колонка `bindings_json` в `history_runs` (миграция без потери строк).
- `src/history/preflight.py` — структурированные проверенные пары в `PreflightReport`.
- `src/history/bindings.py` (новый) — связки прогона по токенам и по выбору инструментов.
- `src/history/report.py`, `src/assembly/contour.py` — `bindings` в `report.json`.
- `src/data/export_api.py`, `src/bot/control_views.py` — маршрут и код ошибки.
- `docs/api/openapi.yaml`, `docs/api/README.md`, `CHANGELOG.md`; тесты истории и API.
- UI — отдельно, в репозитории `UI`.
