## MODIFIED Requirements

### Requirement: Ленивое вычисление контекста
Нормативный уровень: MUST.
Кэш ДОЛЖЕН вычислять MarketContext только при первом запросе для пары (инструмент, таймфрейм) или при обнаружении новой закрытой свечи её таймфрейма. Повторные запросы на том же тике ДОЛЖНЫ возвращать кэшированный результат без пересчёта. Контексты разных таймфреймов одного инструмента ДОЛЖНЫ вычисляться и храниться независимо.

Тик ДОЛЖЕН передавать фильтрам входа и сопровождению ленивый контекст таймфрейма: запрос к кэшу и расчёт тренда и S/R выполняются при первом чтении поля (`trend`, `sr_levels`, `current_price`), а результат запоминается до конца тика. Таймфрейм, контекст которого на тике никто не прочитал, НЕ ДОЛЖЕН вызывать расчёт. Текстовое представление ленивого контекста НЕ ДОЛЖНО вызывать расчёт.

#### Scenario: Первый запрос
- **WHEN** для пары (инструмент, таймфрейм) ещё не вычислялся контекст и его поле прочитано
- **THEN** выполняется полный расчёт (trend + S/R) и результат сохраняется в кэш

#### Scenario: Повторный запрос на том же тике
- **WHEN** для пары (инструмент, таймфрейм) контекст уже вычислен и свеча не изменилась
- **THEN** расчёт не выполняется, возвращается кэшированный результат

#### Scenario: Новая свеча
- **WHEN** последняя свеча в DataFrame пары (инструмент, таймфрейм) отличается от той, по которой был вычислен контекст
- **THEN** контекст пересчитывается и кэш обновляется

#### Scenario: Контексты разных ТФ не смешиваются
- **WHEN** для одного инструмента запрошены контексты `15m` и `1h`
- **THEN** каждый вычисляется на кадре своего таймфрейма и хранится отдельно

#### Scenario: Контекст никто не читает
- **WHEN** на защитном таймфрейме `1m` нет стратегий, фильтров и сопровождения, читающих контекст
- **THEN** тренд и уровни S/R для `1m` на этом тике не вычисляются
