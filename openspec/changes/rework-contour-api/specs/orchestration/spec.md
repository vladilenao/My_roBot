## MODIFIED Requirements

### Requirement: Точка входа
Нормативный уровень: MUST. Система ДОЛЖНА предоставлять run.py, который запускается без параметров, получает параметры запуска командой локального API, разрешает по ним инструменты, собирает зависимости и запускает TradingBot.run() в процессе контура. Порядок старта и повтор старта ядра задаёт спецификация `control-api`. Параметры запуска ДОЛЖНЫ быть одним объектом, не зависящим от консоли: режим, границы и пауза истории, список токенов инструментов. Интерактивный выбор инструментов НЕ ДОЛЖЕН вызываться. Разрешение инструментов, сборка и запуск ДОЛЖНЫ выполняться главным потоком при любом источнике параметров. В текущем режиме run.py ДОЛЖЕН также собрать выбранный ingestion-транспорт и его readiness-порт; TradingBot, стратегии и финансовые компоненты НЕ ДОЛЖНЫ знать gRPC-подписку или читать сеть для торгового тика. Общие стратегии, профили, риск, исполнение и журналы сохраняются; source/clock/state-directory и необязательный live-ingestion различаются по режимам. Исторический провайдер НЕ ДОЛЖЕН реализовывать фиктивный stream ради общего интерфейса.

#### Scenario: Запуск через run.py
- **WHEN** выполняется python run.py
- **THEN** вопросов в консоли нет, поднимается API управления, затем ядро; инструменты приходят командой API

#### Scenario: Запуск через меню
- **WHEN** выполняется python run.py с прежним параметром режима
- **THEN** меню не показывается, процесс печатает подсказку про команды API и завершается с кодом `2`

#### Scenario: Запуск командой API
- **WHEN** робот запущен и получил команду запуска эмуляции
- **THEN** главный поток разрешает инструменты из команды, собирает зависимости и запускает процесс контура

#### Scenario: Сборка боевого режима
- **WHEN** выбран текущий режим данных (эмуляция, прежний боевой режим)
- **THEN** собираются выбранный live-ingestion и прежний JournalBroker либо NotifyOnly; реальный exchange-executor не создаётся

#### Scenario: Сборка исторического режима
- **WHEN** принят прогон `POST /api/v1/history`
- **THEN** процесс прогона использует прежние исторический source/virtual clock и общие торговые компоненты без запуска stream, папка состояния — папка прогона

### Requirement: Контур эмуляции отдельным процессом
Нормативный уровень: MUST. В эмуляции после выбора инструментов (`PUT /api/v1/emulation/target` с `mode = on` или автоподъём) ядро ДОЛЖНО запускать торговый контур отдельным процессом тем же исполняемым файлом со служебным флагом `--contour emulation`. Процесс контура НЕ ДОЛЖЕН держать объектов ядра: данные — из рыночной базы, состав и карточки контрактов — из файла запуска, кластерные события — из `cluster-events.sqlite3` только на чтение. Процесс ДОЛЖЕН брать блокировку `data/contours/emulation/robot.pid` и писать технический журнал в `data/contours/emulation/bot_debug.log` с маскированием тех же секретов, что ядро. Вывод консоли процесса ДОЛЖЕН идти в консоль ядра. Одновременно ДОЛЖЕН работать не больше одного процесса контура эмуляции.

#### Scenario: Запуск командой API
- **GIVEN** робот запущен и ядро готово
- **WHEN** приходит `PUT /api/v1/emulation/target` с инструментами NG-12.26 и SBER
- **THEN** ядро пишет файл запуска, запускает процесс `--contour emulation`, блоки СИГНАЛ и ПЛАН контура печатаются в той же консоли

#### Scenario: Второй процесс контура
- **GIVEN** процесс контура эмуляции уже работает
- **WHEN** второй процесс запускается с `--contour emulation`
- **THEN** он не получает блокировку и завершается с сообщением, торговля первого не меняется

#### Scenario: История не меняется
- **WHEN** принят прогон `POST /api/v1/history`
- **THEN** прогон идёт отдельным процессом `--contour history <id>` на исторической службе данных, процесс контура эмуляции не запускается и не меняется

### Requirement: Жизнь процесса контура
Нормативный уровень: MUST. Ядро ДОЛЖНО держать открытым stdin процесса контура, который оно запустило. Строка `stop` ДОЛЖНА останавливать контур после текущего тика с commit журнала и подтверждением курсора. Конец потока stdin НЕ ДОЛЖЕН останавливать контур. Он ДОЛЖЕН лишь записываться в журнал: о смерти ядра контур судит по пульсу. Ctrl+C ДОЛЖЕН останавливать контур так же, как `stop`.

При своей остановке ядро ДОЛЖНО:

1. записать пульс `stopped`;
2. отправить `stop` своему процессу;
3. ждать завершения контура до 30 секунд;
4. только потом завершить процесс принудительно.

Подхваченный процесс ядро ДОЛЖНО останавливать так же, без stdin. Остановка ядра НЕ ДОЛЖНА менять желаемое состояние контура.

Если процесс контура завершился сам с кодом не 0, ядро ДОЛЖНО:
- записать ошибку в журнал и консоль;
- показать состояние `failed` с кодом выхода;
- НЕ перезапускать контур до следующего старта ядра.

#### Scenario: Штатная остановка
- **WHEN** пользователь нажимает Ctrl+C в консоли робота во время тика контура
- **THEN** контур доделывает тик, фиксирует журнал и курсор и завершается с кодом 0, ядро ждёт его и останавливает свои службы, желаемое «работает» в `core.sqlite3` сохраняется

#### Scenario: Ядро завершилось
- **GIVEN** контур торгует
- **WHEN** процесс ядра завершается аварийно
- **THEN** контур видит конец stdin и продолжает работу, дальнейшее определяет пульс ядра

#### Scenario: Контур упал
- **WHEN** процесс контура завершается с кодом 1
- **THEN** ядро продолжает приём данных, `GET /api/v1/emulation` показывает `failed` с `process.exit_code` 1, торговля сама не перезапускается

### Requirement: Снимок состояния контура для ядра
Нормативный уровень: MUST. После каждого тика и при завершении процесс контура ДОЛЖЕН атомарно записывать в свою папку `status.json`: временный файл и переименование. Состав файла:

- `schema_version`;
- `contour_id`;
- фактическое состояние;
- применённое поколение и режим остановки;
- число открытых позиций и неисполненных входов;
- время последнего тика;
- версия и `pid` процесса;
- `alive_at`, `core_link`, а после выхода — `exited_at` и `exit_reason`;
- время записи.

Файл НЕ ДОЛЖЕН содержать сделки, цены, баланс и секреты. Ядро ДОЛЖНО читать файл для ответа API и для решения о подхвате и автоподъёме при своём старте. Отсутствующий или повреждённый файл НЕ ДОЛЖЕН считаться ошибкой ядра: при старте это означает, что живой контур не подтверждён.

#### Scenario: Снимок после тика
- **WHEN** контур завершил тик с одной открытой позицией
- **THEN** `status.json` содержит `open_positions = 1`, применённое поколение и время этого тика

#### Scenario: Битый снимок
- **WHEN** `status.json` повреждён, а приходит `GET /api/v1/emulation`
- **THEN** ответ `200`, поле `current` равно `null`, остальное состояние показано
