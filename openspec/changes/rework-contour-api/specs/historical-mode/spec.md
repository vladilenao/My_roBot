## MODIFIED Requirements

### Requirement: Выбор режима при старте
Нормативный уровень: MUST. При старте робот НЕ ДОЛЖЕН предлагать выбор режима и НЕ ДОЛЖЕН задавать вопросов: ни меню, ни параметров режима. Робот запускается без параметров и ждёт команд API (спецификация `control-api`):

- эмуляция (торговля на живых данных с симулятором исполнения, прежде — «боевой» режим) — `PUT /api/v1/emulation/target` с `mode = on` или автоподъём по целевому состоянию;
- историческая торговля — `POST /api/v1/history`.

Историческая торговля НЕ ДОЛЖНА зависеть от готовности ядра: прогон принимается и идёт, пока ядро стартует, повторяет старт или не стартовало.

Параметры `--mode`, `--instruments`, `--wait-command`, `--no-prompt`, `--from`, `--to` и `--pause` ДОЛЖНЫ отклоняться: процесс печатает, что робот запускается без параметров, называет оба маршрута API и завершается с кодом `2` без запуска торговли.

#### Scenario: Выбран боевой режим
- **WHEN** пользователь запускает робота без параметров
- **THEN** вопросов о режиме и инструментах нет, консоль печатает адрес API, эмуляция запускается командой `PUT /api/v1/emulation/target` или автоподъёмом

#### Scenario: Выбран исторический режим
- **WHEN** пользователь хочет исторический прогон
- **THEN** он отправляет `POST /api/v1/history` работающему роботу; консоль о диапазоне не спрашивает

#### Scenario: История параметрами без вопросов
- **WHEN** робот запущен с `--mode history --from "2026-09-01 10:00" --to "2026-09-08 10:00" --pause 0`
- **THEN** печатается, что робот запускается без параметров, а история — командой `POST /api/v1/history`; процесс завершается с кодом `2`, прогон не начинается

#### Scenario: Ошибка в параметрах
- **WHEN** робот запущен с `--from "2026-09-01 10:00"`
- **THEN** печатается та же подсказка, процесс завершается с кодом `2`

#### Scenario: Запуск без вопросов по старому флагу
- **WHEN** робот запущен с `--no-prompt`
- **THEN** печатается, что флаг больше не нужен и робот запускается без параметров; процесс завершается с кодом `2`

#### Scenario: Повтор запуска из меню
- **WHEN** пользователь скопировал эквивалентную команду из консоли или из состояния контура
- **THEN** это тело `PUT /api/v1/emulation/target`, и запрос с ним запускает эмуляцию с теми же контрактами

#### Scenario: История без готового ядра
- **GIVEN** старт ядра упал и ждёт повтора
- **WHEN** приходит `POST /api/v1/history`
- **THEN** прогон ставится в очередь и идёт по свечам эмулятора данных

### Requirement: Исторический контур отдельным процессом
Нормативный уровень: MUST. Каждый исторический прогон ДОЛЖЕН идти отдельным процессом того же исполняемого файла с `--contour history <id>`. Процесс запускает робот из очереди прогонов (спецификация `control-api`).

Процесс ДОЛЖЕН:

1. занять блокировку `robot.pid` папки прогона;
2. вести `bot_debug.log` по настройкам `[historical.logging]`, с маскированием секретов, как другие процессы робота;
3. прочитать `launch.json`: диапазон, паузу, токены инструментов, итог сверки импорта и номер снимка;
4. пройти прежний путь истории:
   - выбор контрактов у эмулятора данных;
   - контрактная цепочка и расписание прогона;
   - предпроверка покрытия;
   - тики;
   - отчёт `report.txt` и `report.json`;
5. вести `status.json`: фаза (`checking`, `running`, `finishing`), диапазон с учётом сдвига начала, рыночное время, число тиков, отказы инструментов, признак жизни, итог выхода.

Если предпроверка сдвинула начало на первую доступную свечу, процесс ДОЛЖЕН собрать прогон заново в той же папке. Файлы журнала и выбора прошлой попытки удаляются; `launch.json`, `status.json`, логи и `robot.pid` остаются. Повтор ровно один, на том же снимке.

Коды выхода:

- `0` — отчёт записан;
- `2` — прогон отклонён до первого тика;
- другой — сбой. Отчёт при сбое пишется, как прежде.

Процесс НЕ ДОЛЖЕН читать ленту ядра и обращаться к брокеру. Уведомления НЕ ДОЛЖНЫ отправляться.

#### Scenario: Прогон тем же путём
- **GIVEN** прежний `--mode history` на диапазоне, инструментах и снимке дал набор сделок
- **WHEN** тот же диапазон и инструменты запущены командой `POST /api/v1/history` на том же снимке
- **THEN** процесс прогона даёт те же сделки и тот же итог `report.json`, кроме времени запуска и пути папки

#### Scenario: Сдвиг начала
- **GIVEN** первая доступная свеча позже начала диапазона
- **WHEN** предпроверка сдвигает начало
- **THEN** прогон собирается заново в той же папке, `status.json` показывает новое начало, журнал содержит только сделки второй попытки
