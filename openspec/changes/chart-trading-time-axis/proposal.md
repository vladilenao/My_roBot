## Why

На графиках сделок в Telegram регулярно видны «дыры» — широкие пустые полосы между свечами. 15.10.2026 все три графика плана LKOH 15m показали пустоту с 00:00 до 06:45 МСК.

- **Данные целые.** В `market-data.sqlite3` у LKOH 15m свечи 14.10 идут без пропусков до 23:45 МСК, 15.10 начинаются с 06:45 МСК. Все интервалы между ними в `interval_coverage` размечены `scheduled_closed` с доказательством `applicable_trading_schedule:moex_mrng_evng_e_wknd_dlr:2026-10-15:…` — биржа была закрыта по расписанию.
- **Дыру рисует график.** `render_png` ставит свечи по календарному времени (`dates.date2num`), поэтому ночь, выходные и клиринг занимают на оси столько же места, сколько торговое время. Каждый утренний график с хвостом вчерашней сессии получает пустую полосу на большую часть ширины.
- **Пометка неполноты врёт.** `market_snapshot` считает разрывом любые две несоседние свечи (`gaps`), включая обычную ночь. Пометка «Ограниченное окно / неполная история» поэтому стоит почти на каждом графике и перестаёт отличать настоящий пропуск данных от закрытой биржи.
- **Почему «снова».** Прежние изменения (`history-data-gaps`, `reliable-live-candle-ingestion`, `fix-live-execution-gap-recovery`) чинили настоящие пропуски свечей в данных. Неторговое время график не учитывал никогда.

Решение владельца 15.10.2026: ось по номерам свечей (как в торговых терминалах) и классификация разрывов по торговому календарю через уже существующую разметку `interval_coverage`; интервалы, для которых календаря нет, подписываются «расписание недоступно», а не «пропуск данных».

## What Changes

- **Ось по свечам.** Свечи графика стоят подряд по порядковому номеру в окне; неторговое время места на оси не занимает. Подписи оси берутся из времени самих свечей в поясе пользователя, смена дня отмечается тонким разделителем с датой. Исполнения, шаги стопа и начало линии стопа ставятся на свечу, в которую попадает их момент; момент внутри разрыва — на границу разрыва.
- **Разрывы классифицируются в снимке.** Визуальный снимок получает необязательный список `market.breaks`: для каждого разрыва между соседними свечами окна — его границы, число отсутствующих интервалов сетки и вид:
  - `closed` — биржа закрыта по расписанию (`scheduled_closed`): ночь, выходные, клиринг;
  - `no_trade` — интервал разрешён без свечи (`confirmed_no_trade`, `source_absent`);
  - `missing` — интервал не разрешён, а расписание на этот момент известно: настоящий пропуск данных;
  - `schedule_unavailable` — интервал не разрешён и расписания на этот момент нет.
- **Источник правды — слой рыночных данных.** Вид разрыва вычисляется кэшем по долговечным состояниям `interval_coverage` и календарю того же reconciler, по которому робот решает, ждать ли свечу. Чтение пакетное, без сети и без записи; снимок и renderer базу не читают.
- **Честная пометка.** На графике `missing` отмечается заметной меткой «пропуск», `schedule_unavailable` — нейтральным разделителем «расписание недоступно»; `closed` и `no_trade` меток не получают. Подпись под графиком перечисляет только то, что есть: ограниченное окно, число пропусков, число разрывов без расписания, неполную историю исполнений. Флаг `market.gaps` становится истинным только при `missing` или `schedule_unavailable`.
- **Совместимость.** Версия снимка остаётся `1`, поле `breaks` необязательное. Снимок без `breaks` (сохранённый до изменения) рисуется на оси по свечам, а его разрывы считаются `schedule_unavailable`: сведений о причине у него нет.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `telegram-trade-cards`: требование «Графики плана сопровождения и итога» — ось по свечам вместо календарного времени, виды разрывов и их отображение, точная подпись о неполноте.
- `data-cache`: новое требование «Классификация разрывов окна для представления» — кэш отдаёт вид каждого разрыва окна по долговечному покрытию и календарю, без сети и записи.

## Impact

- Код: `src/notifier/telegram_chart.py` (`build_scene`, `render_png`), `src/events/visual.py` (`market_snapshot`, `visual_schema`), `src/data/cache.py` (новый метод классификации), `src/data/reconciliation.py` (чтение покрытия календарём без записи), `src/bot/trading_bot.py` (передача классификатора в `remember_market` и `signal_snapshot`), `src/trade_management/manager.py` и `src/trade_management/notification.py` (проброс параметра).
- Документация: `docs/notification/visual-snapshot.json`, `docs/notification/telegram-cards.md`.
- Тесты: `tests/snapshot/test_telegram_visuals.py` и его данные (новые сценарии с ночью, выходными, пропуском и разрывом без расписания), unit-тесты классификатора кэша и `market_snapshot`.
- Схемы `trades.sqlite3`, `market-data.sqlite3` и `telegram_delivery.sqlite3` не меняются. Торговые решения, готовность данных и `coverage_for` не меняются.
- Риск: внешний потребитель, проверяющий снимок старой JSON-схемой со строгим `additionalProperties`, отвергнет снимок с `breaks`. Известных внешних потребителей нет; схема в `docs/` обновляется вместе с кодом.

Non-goals: заполнение пропусков данных, изменение загрузки или восстановления свечей, загрузка расписаний задним числом для периода до 13.10.2026, перерисовка уже отправленных в Telegram графиков.
