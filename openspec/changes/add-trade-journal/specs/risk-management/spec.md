## ADDED Requirements

### Requirement: Расчёт размера позиции из риск-бюджета
Система ДОЛЖНА рассчитывать количество контрактов для входа из риск-бюджета: `риск_руб = |вход − стоп| / шаг_цены × стоимость_шага × количество`. Количество ДОЛЖНО вычисляться целым с округлением вниз и минимумом 1, где риск-бюджет равен `текущий_баланс × max_risk_pct`. Если расчётное количество равно 0, входной сигнал НЕ допускается в исполнение. Расчёт ДОЛЖЕН учитывать метаданные контракта (шаг цены, стоимость шага) и размерность для нефьючерсных инструментов.

#### Scenario: Позиция из бюджета
- **WHEN** баланс 100000, `max_risk_pct = 2.0`, |вход − стоп| = 1000, шаг цены = 10, стоимость шага = 100
- **THEN** риск_руб = |вход − стоп| × (стоимость_шага / шаг_цены) = 1000 × 10 = 10000 на контракт; количество = floor(2000 / 10000) = 0 → сигнал не допускается; при риск 2000 и стоимости контракта 500 количество = 4

#### Scenario: Минимальное количество
- **WHEN** расчёт даёт количество меньше 1
- **THEN** если результат округления вниз равен 0, вход отклоняется; в противном случае применяется минимум в 1 контракт

### Requirement: Снимок риск-сметы в решении
Система ДОЛЖНА при входе фиксировать в решении риск-смету: задействованный процент риска (`risk_pct` — снимок конфигурации на момент сделки), величину риска в рублях (`risk_rub`), цену входа и стопа, количество. Эти значения используются дневником и портфелем; при изменении `max_risk_pct` между запусками применяется значение, действовавшее на момент сделки.

#### Scenario: Снимок зафиксирован
- **WHEN** решение входа проходит риск-менеджмент
- **THEN** решение содержит `risk_pct`, `risk_rub`, `entry_price`, `stop_price` и количество, которые затем попадают в запись дневника
