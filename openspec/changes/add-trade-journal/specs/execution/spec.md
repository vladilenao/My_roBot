## MODIFIED Requirements

### Requirement: Абстрактный порт исполнения
Система ДОЛЖНА предоставлять абстрактный интерфейс `ExecutionPort` с методом `execute(decision, instrument, ...)`, принимающим решение (`Decision`), инструмент и контекст привязки (профиль фильтрации, таймфрейм) и возвращающим результат исполнения: для торговых действий — идентификатор заявки и её статус, для HOLD/отклонённых решений — признак «нет сделки». Интерфейс НЕ ДОЛЖЕН зависеть от конкретного нотификатора или биржевого клиента.

#### Scenario: Вызов порта
- **WHEN** оркестратор принимает торговое решение по инструменту
- **THEN** вызывается `execute(decision, instrument, ...)` единственного активного порта исполнения

#### Scenario: Результат исполнения
- **WHEN** `execute` завершился для торгового действия
- **THEN** возвращён идентификатор заявки и её статус (либо признак «нет сделки» для HOLD/отклонённых решений)

## ADDED Requirements

### Requirement: Исполнение через брокерский слой
Система ДОЛЖНА предоставлять реализацию порта исполнения на базе брокерского слоя, портфеля и дневника сделок: торговые действия (`entry`, `scale_in`, `partial`, `full`) направляются брокеру, портфель обновляется по событиям исполнения, дневник дописывается. Реализация `NotifyOnlyExecutionPort` ДОЛЖНА оставаться доступной как режим без торговли (только уведомления).

#### Scenario: Решение уходит в брокер
- **WHEN** решение `entry` передано брокерной реализации порта
- **THEN** создаётся лимитная заявка, портфель фиксирует потенциальный риск, дневник дополняется записями

#### Scenario: Режим только уведомлений
- **WHEN** активна реализация `NotifyOnlyExecutionPort`
- **THEN** торговые действия не создаются, решения доставляются как уведомления

### Requirement: Уведомления о событиях сделок
Система ДОЛЖНА через нотификатор доставлять трейдеру значимые события сделок: подача заявки, исполнение входа/добора, частичный и полный выход, отмена заявки с причиной, отметка превышения риска, клиринговый снимок. Тексты ДОЛЖНЫ формироваться форматтером решений (`DecisionFormatter`) на основе решений и контекста события.

#### Scenario: Уведомление об исполнении входа
- **WHEN** заявка на вход исполнилась
- **THEN** трейдеру доставляется уведомление с инструментом, ценой входа, количеством и меткой позиции

#### Scenario: Уведомление об отмене
- **WHEN** заявка отменена по причине (TTL, клиринг, превышение лимита риска)
- **THEN** трейдеру доставляется уведомление с причиной отмены
