## Why

Комиссии Т-Инвест владельца не устраивают: решено подключить Финам вторым реальным брокером. План — отдельный контур `finam` из того же кода, что «Счёт»: свечи и анализ остаются у ядра на Т-Инвест, Финам только исполняет. Этапы: Ф0 — разведка (этот change), Ф1 — порт брокера из `TInvestApi`, Ф2 — контур `finam` только на чтение, Ф3 — заявки и стопы, Ф4 — предохранители и перенос привязок, Ф5 — выпуск.

Документация Finam Trade API 2.24.0 оставляет открытыми вопросы, от которых зависит адаптер. Разведка песочницы Т-Инвест (add-sandbox-probe) в своё время нашла неочевидное: цены фьючерса в рублях, а не в пунктах, временный номер заявки в первом событии стрима, особое поведение ключа повтора. У Финама надо выяснить то же самое до проектирования Ф1–Ф3:

- а) пускает ли API к демо-счёту — тогда демо станет стендом для Ф3;
- б) формат `symbol` фьючерса и акции, как его получить по нашему имени, совпадают ли лот и шаг цены с карточкой Т-Инвест;
- в) в чём цены фьючерса в заявках, сделках и позициях (пункты или рубли), в чём `quantity` (штуки или лоты);
- г) `client_order_id`: повтор после приёма и после ошибки, поиск заявки после обрыва, видимость исполненных и снятых заявок после рестарта и на другой день;
- д) стоп-заявка: жизнь `GOOD_TILL_CANCEL` через ночь и выходные, статусы, связь с порождённой биржевой заявкой;
- е) комиссия в `Trades` и `Transactions` и её привязка к сделке;
- ж) JWT: срок жизни, `SubscribeJwtRenewal`, судьба открытых стримов при истечении;
- з) лимиты запросов, ответ при превышении, `GetUsageMetrics`;
- и) вечерняя сессия и торги выходного дня, границы цен, аналог `GetMaxLots` и ГО;
- к) что брать капиталом счёта из `GetAccount`.

## What Changes

- Новая команда `python -m src.finam <действие>` своим процессом, отдельно от робота: не нужен запущенный робот, базы робота не открываются.
- Действия только на чтение: `account` (токен, счёт, заявки, сделки, транзакции, инструменты, котировки, расписание, лимиты), `probe-jwt` (жизнь JWT и стримов), `probe-limits` (ответ при превышении лимита).
- Действия с заявками, запускает только владелец: `probe` (лимитная заявка далеко от рынка, повтор ключа, поиск, снятие, стримы), `probe-stops` (стоп-заявка далеко от рынка, при `--keep` оставляется на ночь), `cleanup` (снять только заявки разведки).
- Отдельное действие `probe-trigger` — срабатывание стопа с настоящей сделкой в 1 лот и закрытием позиции. Запускается только с вводом подтверждения в консоли; на реальном счёте дополнительно требует флаг `--real`.
- Каждый вызов пишется в `responses.jsonl`, итог — в `report.md` в `data/finam/<действие>-ГГГГММДД-ЧЧММСС/`, лог — `data/finam/finam.log`. Коды выхода 0/1/2.
- Подключение — gRPC-заглушки, сгенерированные из официальных proto Finam Trade API 2.24.0 и положенные в репозиторий; новых зависимостей нет.
- Новые секреты `FINAM_SECRET_TOKEN`, `FINAM_ACCOUNT_ID` и необязательные `FINAM_DEMO_SECRET_TOKEN`, `FINAM_DEMO_ACCOUNT_ID` маскируются в логе, как и каждый полученный JWT. Номер счёта показывается только последними четырьмя символами.
- Итог разведки — раздел «Факты разведки» в `design.md` этого change с ответами на а–к.

## Capabilities

### New Capabilities

- `finam-probe`: команда разведки Finam Trade API — чтение счёта и справочников, пробные заявки и стоп-заявки, срабатывание стопа по подтверждению, JWT и лимиты.

### Modified Capabilities

Нет. Робот, его API (`docs/api/openapi.yaml`), контуры и базы не меняются.

## Impact

- Новый пакет `src/finam/`: шлюз gRPC, записи, разрешение имён, действия, `__main__`; `src/finam/proto/` — сгенерированные заглушки с версией proto.
- `tools/finam_proto.py` — перегенерация заглушек из checkout официального репозитория.
- `src/config.py`: переменные `FINAM_*`; `run.py`: секреты в `_SECRETS`.
- Тесты `tests/unit/finam/` на фейковых заглушках, без сети.
- Каталог `data/finam/` — уже в `.gitignore` вместе с `data/`.
- Дистрибутив не меняется: команда запускается из исходников, `run.py` пакет `src.finam` не импортирует.
