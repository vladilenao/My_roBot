# Дефолтная глубина скачивания = потолок 300

## Why

Формула глубины скачивания (`max(SIGNAL_WINDOW × 4, 50)` → 50) не позволяет скрипту воспроизвести зафиксированные в репозитории эталонные фикстуры: коммит `2cb87aa` содержит NG_1h на 187 свечей, скачанный разово на границе 300 часов вручную. Повторный запуск скрипта с формулой затирает глубокие фикстуры короткими (39 свечей), что обесценивает непустые эталоны.

## What Changes

- **BREAKING** Дефолтная глубина запроса скрипта скачивания становится равной абсолютному потолку — 300 свечей — и больше не зависит от `SIGNAL_WINDOW` из `src.config`.
- Формула `SIGNAL_WINDOW × 4` с запасом прогрева удаляется из кода скрипта и из требования спеки.
- Жёсткий потолок ≤300 свечей, пост-обрезка `tail(limit)`, явные границы запроса и guard от превышения сохраняются без изменений.

## Impact

- Код: `tools/download_snapshot_data.py` — константа глубины вместо `calculate_depth`; докстринг. Импорт `SIGNAL_WINDOW` остаётся (нужен для расчёта эталона).
- Спеки: главное требование глубины в `test-data` меняет формулировку (синхронизация при архивации).
- Фикстуры: повторное скачивание NG_1h и BR_1h с новым дефолтом обновит их до полной доступной глубины (~187/188+ свечей); diff ревьюится коммитом.
