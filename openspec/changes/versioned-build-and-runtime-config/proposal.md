## Why

Робот распространяется как готовая сборка (PyInstaller-бинарник), но версионирования и правил выпуска нет: бинарник называется анонимно `run`, номера версии в коде нет, CHANGELOG отсутствует, а конфигурация (таймфрейм, инструменты, стратегии) зашита в код и не настраивается получателем без пересборки. Нужно превратить «запускаемый скрипт» в распространяемый продукт: версия в имени, журнал изменений, настраиваемый внешний конфиг рядом с исполняемым файлом.

## What Changes

- **Версионирование (SemVer `MAJOR.MINOR.PATCH`)**: `__version__` в новом `src/__init__.py` вместе с комментарием-правилами нумерации. Версия печатается в лог при старте робота. Правила: `MAJOR` — меняется поведение сигналов / ломается конфиг; `MINOR` — новое обратно совместимое; `PATCH` — багфиксы без изменения сигналов.
- **CHANGELOG.md** (формат Keep a Changelog) в корне: правки копятся под `## Unreleased`, при выпуске секция получает номер и дату. Заполняется руками, тезисно, «письмом тому, кто запустит робота».
- **Имя бинарника `robot-vX.Y.Z`**: сборка PyInstaller с подстановкой версии (`pyinstaller --name "robot-v<версия>" run.spec`). Сборка руками, без скриптов.
- **Файл изменений `robot-vX.Y.Z.txt` рядом с бинарником**: тезисы секции текущей версии из CHANGELOG, копируется вручную при сборке.
- **Внешний конфиг `robot.toml`**: все параметры из `src/config.py` (таймфрейм, паузы, fallback-инструменты, канал уведомлений, `SHARE_STRATEGIES`/`FUTURE_STRATEGIES`). Ищется **в папке исполняемого файла** (`dirname(sys.executable)`), а не в текущей рабочей папке; при отсутствии файла используются дефолты, **вшитые в сборку** (`default.toml` через `sys._MEIPASS`).
- **Переезд конфига для dev**: в режиме разработки (`python run.py`) параметры читаются из `robot.toml` в корне проекта, секреты — как сейчас из `.env`.
- **Секреты отдельно**: `TINKOFF_TOKEN`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHANNEL_ID` остаются в `.env` рядом (и/или в переменных окружения); **`BREAKING` для процесса раздачи** — `.env` не входит в сборку, получатель создаёт свой.
- **Готовый конфиг `robot.toml`** распространяется рядом с исполняемым файлом (без токенов — токены только в `.env`).

## Capabilities

### New Capabilities
- `release`: поведение «продукт-сборка» — правила SemVer, наличие `__version__`, версия в логе при старте, имя бинарника `robot-vX.Y.Z`, текстовый файл `robot-vX.Y.Z.txt` с тезисами изменений рядом с бинарником, роль CHANGELOG.md.

### Modified Capabilities
- `configuration`: источник параметров меняется — настройки загружаются из внешнего `robot.toml` (для сборки — из папки исполняемого файла, для dev — из корня проекта) с fallback на вшитые в сборку дефолты; токены по-прежнему из `.env`/переменных окружения; `TIMEFRAMES` остаётся константой кода.

## Impact

- Создаются: `src/__init__.py`, `CHANGELOG.md`, вшиваемый в сборку `default.toml`; рабочий `robot.toml` подготавливается рядом с собранным бинарником.
- Правятся: `src/config.py` (резолвинг папки приложения, чтение TOML с fallback, разделение параметров и секретов), `run.spec` (добавление `default.toml` в `datas`), `run.py` (лог версии).
- Тесты: unit на резолвинг конфига (внешний файл / вшитый дефолт / отсутствие) и на правила чтения секретов (`tests/unit/`).
- Внешние зависимости: добавление только стандартного `tomllib` (Python 3.11+) для чтения TOML — без новых библиотек.
- Раздача: `robot-vX.Y.Z` + `robot-vX.Y.Z.txt` + `robot.toml` (без `.env`).
