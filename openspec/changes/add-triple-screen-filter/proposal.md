## Why

Робот решает по сигналам базовых стратегий без агрегации направления тренда на
старших таймфреймах. Профиль фильтрации `basic_levels` проверяет только локальный
тренд в контексте рабочего ТФ и не блокирует входы против глобального движения.
Это приводит к сигналам «против прилива»: ловля ножа на M5 при падении на H4 и
аналогичные потери. Методика Александра Элдера «Triple Screen» решает это
детерминированной трёхэкранной лестницей — тренд на старшем ТФ, коррекция на
среднем, вход на рабочем — и полностью укладывается в «цикл закрытой свечи» робота.

## What Changes

- **Новый профиль фильтрации `triple_screen`** в реестре `src/decision/filters/`
  (фабричный выбор через фасад `SignalFilter`, как у `basic_levels`/`raw`):
  - Экран 1 (старший ТФ, направление тренда) — наклон гистограммы
    MACD(12,26,9): `Hist[t] > Hist[t-1]` разрешает Lоng, `Hist[t] < Hist[t-1]`
    разрешает Short; встречное направление блокируется.
  - Экран 2 (средний ТФ, коррекция) — Stochastic(14,3,3), линия `%K`:
    `%K[t] < 20` даёт откат BUY, `%K[t] > 80` — откат SELL.
  - Экран 3 (рабочий ТФ) — входящий `SignalType` базовой стратегии пропускается
    в `risk_manager` только при прохождении экранов 1 и 2 одновременно.
- **Иерархия таймфреймов по множителю Элдера (дефолт 5)**:
  `TF_int` = ближайший стандартный ТФ строго больше `TF_work × 5`;
  `TF_htf` = ближайший стандартный ТФ строго больше `TF_int × 5`
  (например M5 → M30 → H4).
- **Расширение контракта фильтров**: `apply()` фасада получает `instrument` и
  `timeframe` привязки (для данных-зависимых фильтров вроде `triple_screen`);
  `basic_levels`/`raw` не меняют поведения.
- **Доступ к данным старших ТФ по требованию**: старшие ТФ загружаются
  определённо выровненными к закрытию рабочей свечи (`close <= close_work`),
  без look-ahead bias. Сетки неактивных ТФ создаются on-demand и **не** влияют
  на ритм пробуждения цикла.
- **Конфигурация**: новая секция `[strategies.filter.triple_screen]` в
  `robot.toml` (множитель, `fast`/`slow`/`signal` MACD, `k`/`d`/`smooth_k` и
  пороги `%K`); поддержка таймфреймов `30m` и `4h` в слое таймфреймов робота.
- Поведение при нехватке истории старших ТФ (холодный старт) — окно расчёта
  расширяется на предыдущую торговую сессию; при невозможности расчёта даже с ней —
  сигнал отклоняется (HOLD) с диагностикой в `bot_debug.log`. Невалидная иерархия
  (выход за рамки доступных ТФ) — `ConfigError` при загрузке конфигурации.

## Capabilities

### New Capabilities

- нет

### Modified Capabilities

- `signal-filter`: новый профиль `triple_screen`; контракт `apply()` расширяется
  `instrument`/`timeframe`; правила пропуска/блокировки по экранам 1-2.
- `configuration`: секция `[strategies.filter.triple_screen]` (множитель ТФ,
  параметры MACD/Stochastic, пороги `%K`); новые таймфреймы `30m`/`4h`;
  валидация недопустимой иерархии ТФ.
- `data-cache`: получение выровненных по времени закрытия рабочей свечи кадров
  старших ТФ по требованию (порядок количества баров для холодного старта).
- `timing`: сетки неактивных ТФ резолвятся on-demand для потребителей данных,
  но исключены из множества пробуждения цикла.

## Impact

- `src/decision/filter.py` — фасад; сигнатура `apply` + `profile_name` резолв.
- `src/decision/filters/` — новый `triple_screen.py`, реестр `PROFILES`.
- `src/decision/filters/base.py` — протокол `ProfileFilter` (опциональные
  `instrument`/`timeframe`).
- `src/bot/trading_bot.py` — передача `instrument`/`tf` в `signal_filter.apply()`.
- `run.py` — композиция зависимостей фильтра (data-провайдер, конфиг) через
  конструктор.
- `src/config.py`, `src/config_loader.py` — `TIMEFRAMES` (+`30m`,`4h`), новая
  секция конфига и её валидация.
- `src/scheduler/timing.py` — `_PERIODS` (+`30m`,`4h`), on-demand сетки без
  влияния на ритм; `src/data/cache.py` — доступ к кадрам старших ТФ.
- Не влияет на: сигналы базовых стратегий, уведомления (сохранится «Отклонено
  фильтром»), порт исполнения, каскад привязок.
