## Why

`_launch` в `run.py` — одна функция на двести строк, в которой перемешаны рыночные данные, локальный API, выбор инструментов, торговая часть, оркестратор и отчёт истории. Приём данных сам читает финансовую базу торговой части, торговый цикл сам отправляет свечи в обработчик паттернов, а всё вместе живёт в одном процессе на общих объектах. Пока это так, торговый контур нельзя вынести в отдельный процесс (П3) и нельзя дать ядру управлять им по API (П4). Это этап П2 из `docs/architecture/core-contours.md`: разрезать сборку на ядро и торговый контур внутри одного процесса, не меняя поведения.

## What Changes

- Новый пакет `src/assembly/`:
  - `services.py` — порт рыночных служб `MarketServices`, через который контур получает данные, и объект потребностей контура `ContourDemand`;
  - `core.py` — `LiveCore`: рыночная база, арбитр, календарь, ранний сбор и полосы, приём свечей и поток, локальный API, кластерный поток, обработчик паттернов;
  - `history.py` — `HistoricalMarketServices`: те же службы для прогона истории (эмулятор, виртуальные часы, без полос и API);
  - `contour.py` — `TradingContour` и `ContourSettings`: каналы и шина, кластерный вердикт, торговая часть, оркестратор, отчёт истории.
- Контур получает данные только через `MarketServices`, а свои потребности (инструменты исполнения, обязательства незавершённых сделок, их таймфреймы) передаёт службам объектом `ContourDemand`. Службы больше не читают финансовую базу контура сами.
- Значения, которые различаются между контурами (вид, каталог состояния, часы и сессия прогона, каналы уведомлений, выбранные инструменты, источник данных), передаются объектом `ContourSettings`.
- `run.py` остаётся точкой входа: параметры, меню, выбор инструментов, план цепочки и предпроверка истории, а затем короткая сборка «службы → контур → запуск → остановка».
- Тесты, которые подменяют перенесённые функции через `run.<имя>`, переводятся на новые модули без изменения проверок.
- `ARCHITECTURE.md`: модули `assembly`, поток сборки.
- Поведение робота не меняется: те же вопросы, сообщения, порядок запуска и остановки, сделки и отчёты.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `orchestration`: требование раздельной сборки ядра и торгового контура с портом рыночных служб, объектом потребностей и объектом настроек контура.

## Impact

- `run.py`: `_launch` сокращается до сборки; функции данных, API, торговой части, оркестратора и отчёта истории переезжают в `src/assembly/`.
- Новый пакет `src/assembly/`.
- `tests/`: около 16 файлов подменяют функции `run.py`; подмены перенесённых функций переводятся на новые модули.
- `ARCHITECTURE.md`, `docs/architecture/core-contours.md` (П2).
- Нет изменений в стратегиях, торговле, журнале, рыночных данных, HTTP API и конфигурации.
