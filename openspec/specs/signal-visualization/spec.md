# Визуализация сигналов стратегий

## Purpose

Обеспечить наглядную визуализацию сигналов стратегий: для каждой стратегии из реальных snapshot-данных генерируются SVG-картинки событий BUY и SELL, показывающие свечу входа, состояние индикаторов под ней и словесное описание точки входа. Картинки встраиваются в спецификацию по root-relative пути и предназначены для чтения человеком при анализе стратегии.

## Requirements

### Requirement: Генерация SVG-картинок сигналов стратегии
Система ДОЛЖНА предоставлять утилиту `tools/visualize_signals.py`, которая по имени стратегии и snapshot-кейсу (`--strategy`, `--case`) генерирует SVG-файлы событий BUY и SELL. Утилита ДОЛЖНА уметь выбирать первое событие каждого направления из эталона кейса (`<стратегия>_expected_signals.csv`) и сохранять результат в `openspec/assets/signals/<стратегия>_<BUY|SELL>.svg`. Выбор стратегии ДОЛЖЕН идти через реестр `src.strategies`, а не хардкодиться в утилите.

#### Scenario: Генерация обеих направлений по умолчанию
- **WHEN** утилита запускается с `--strategy macd_rsi_stoch --case BR_1h`
- **THEN** создаются файлы `openspec/assets/signals/macd_rsi_stoch_BUY.svg` и `openspec/assets/signals/macd_rsi_stoch_SELL.svg`, каждый содержит валидный SVG

#### Scenario: Одно направление по требованию
- **WHEN** утилита запускается с `--direction SELL`
- **THEN** создаётся только файл для SELL, файл BUY не пересоздаётся

#### Scenario: Кейс без события направления
- **WHEN** в эталоне кейса нет ни одного события запрошенного направления
- **THEN** утилита завершается с ошибкой, сообщающей об отсутствии события

### Requirement: Состав SVG-рисунка сигнала
SVG-рисунок ДОЛЖЕН содержать: ценовой график с классическими барами OHLC и панели всех индикаторов стратегии под ним; жирный серый пунктир на свече входа и тонкий серый пунктир на границе окна анализа (за `STRATEGY_WINDOW` свечей до входа); стрелку с подписью `BUY ВХОД`/`SELL ВХОД`; горизонтальный текст справа от каждой панели индикатора с человекочитаемым описанием сигналов, сгенерированных за окно стратегии. На панелях осцилляторов (RSI, Stochastic) ДОЛЖНЫ быть отмечены зоны перекупленности и перепроданности.

#### Scenario: Отражение окна анализа на графике
- **WHEN** у стратегии `STRATEGY_WINDOW = 5` и строится рисунок входа на баре `ei`
- **THEN** жирный пунктир стоит на `ei`, тонкий — на `ei − 4`, разметка оси X показывает даты свечей

#### Scenario: Человекочитаемое описание события
- **WHEN** под свечой входа индикатор сгенерировал сигнал (например, бычий кроссовер MACD ниже нуля)
- **THEN** справа от панели этого индикатора отображается текст с событием и текущими значениями индикатора

#### Scenario: Зоны перекупленности и перепроданности
- **WHEN** строится панель RSI или Stochastic
- **THEN** на панели отмечены зоны перекупленности/перепроданности (RSI: 70+/30−, Stoch: 80+/20−)

### Requirement: Хранение и подключение картинок
Сгенерированные SVG ДОЛЖНЫ храниться в `openspec/assets/signals/` и подключаться в спецификацию по root-relative пути `/openspec/assets/signals/<файл>`. Атрибут изображения в markdown ДОЛЖЕН использовать этот путь, чтобы картинка корректно рендерилась и после переноса дельты в main-спек (перенос не меняет глубину root-relative ссылки).

#### Scenario: Root-relative ссылка переживает архивацию
- **WHEN** дельта с картинкой переносится из `openspec/changes/<change>/specs/<cap>/spec.md` в `openspec/specs/<cap>/spec.md`
- **THEN** путь `/openspec/assets/signals/...` остаётся корректным без ручной правки

#### Scenario: Файл картинки существует
- **WHEN** спецификация ссылается на `/openspec/assets/signals/<файл>`
- **THEN** файл существует в репозитории и содержит валидный SVG

### Requirement: Тестирование генератора
Генератор ДОЛЖЕН покрываться smoke-тестом `tests/snapshot/test_visualization.py`, который для стратегий с доступными данными генерирует SVG во временную директорию и проверяет: файл не пуст, начинается с префикса `<?xml` или содержит `<svg`, отрисована хотя бы одна панель. Тест НЕ должен зависеть от сети и ДОЛЖЕН использовать только существующие snapshot-фикстуры.

#### Scenario: Smoke-тест для стратегии с данными
- **WHEN** запускается `pytest tests/snapshot/test_visualization.py`
- **THEN** для каждой стратегии с данными создаётся валидный SVG без обращения к API

#### Scenario: Тест не обращается к сети
- **WHEN** smoke-тест выполняется в среде без сети
- **THEN** тест проходит, используя только локальные фикстуры
