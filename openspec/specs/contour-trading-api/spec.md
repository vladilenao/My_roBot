# contour-trading-api Specification

## Purpose
Позиции, сделки, итоги за период и счёт торгового контура (эмуляция, песочница) через API управления для карточки «Позиции и сделки» UI — только чтение журнала сделок контура (`trades.sqlite3`), без записи и без биржевых тикеров; доступ по ключу управления.

## Requirements

### Requirement: Ресурсы торговли контура
Нормативный уровень: MUST. Контуры «Эмуляция» и «Песочница» ДОЛЖНЫ отдавать одинаковые ресурсы только на чтение:

| Маршрут | Что отдаёт |
|---|---|
| `GET /api/v1/emulation/positions`, `GET /api/v1/sandbox/positions` | открытые позиции |
| `GET /api/v1/emulation/trades`, `GET /api/v1/sandbox/trades` | закрытые сделки за окно |
| `GET /api/v1/emulation/performance`, `GET /api/v1/sandbox/performance` | итоги периода и кривая результата |
| `GET /api/v1/emulation/account` | виртуальный счёт эмуляции |

Источник — журнал сделок контура `trades.sqlite3` в папке контура. Ресурсы ДОЛЖНЫ требовать ключ управления и проверять `Host`, как остальные маршруты контура. Ошибки ДОЛЖНЫ отдаваться в `application/problem+json`.

Ответ ДОЛЖЕН строиться и тогда, когда процесс контура не запущен, остановлен или упал. Если файла журнала нет или в нём нет таблиц журнала, ответ ДОЛЖЕН быть `200`:

- с пустыми списками;
- с нулевыми итогами;
- с кривой из одной начальной точки.

Деньги и цены ДОЛЖНЫ быть десятичными строками; все суммы — в рублях, ответ ДОЛЖЕН содержать `currency: "RUB"`. Время — UTC в формате ISO 8601.

Знаки сумм:

- комиссии (`fees`) — положительные суммы расхода;
- результаты (`gross`, `net`, `realized`, `unrealized`, точки кривой) — со знаком: убыток отрицательный;
- просадка (`max_drawdown.amount`) — не больше нуля.

Исполнения входа и выхода ДОЛЖНЫ отдаваться одной формой — `at`, `lots`, `price` — по времени исполнения; у исполнения выхода ещё `kind`, `code` и `label` по требованию «Вид выхода».

#### Scenario: Остановленный контур
- **GIVEN** эмуляция остановлена, в журнале 33 закрытые сделки
- **WHEN** приходит `GET /api/v1/emulation/trades`
- **THEN** ответ `200` со сделками из журнала

#### Scenario: Журнал песочницы без таблиц
- **GIVEN** `data/contours/sandbox/trades.sqlite3` существует, но таблиц журнала в нём нет
- **WHEN** приходит `GET /api/v1/sandbox/performance?period=day`
- **THEN** ответ `200`, `trades.count = 0`, `realized.net = "0"`, в `curve` одна точка с нулём

#### Scenario: Ключ экспорта
- **WHEN** `GET /api/v1/emulation/positions` приходит с ключом `MARKET_DATA_EXPORT_TOKEN`
- **THEN** ответ `401` с кодом `UNAUTHORIZED` в `application/problem+json`

### Requirement: Открытые позиции
Нормативный уровень: MUST. `…/positions` ДОЛЖЕН отдавать сделки журнала с ненулевым остатком позиции, новые сверху по времени первого входа. У позиции ДОЛЖНЫ быть:

- `id` — идентификатор сделки по требованию «Имена и привязки в ответах»;
- `binding` и `instrument` по тому же требованию;
- `side`: `long` или `short`;
- `lots` — текущий остаток;
- `entry_price` — средняя цена входа;
- `last_price`, `last_price_at` и `unrealized` по требованию «Нереализованный результат»;
- `stop` — подтверждённый стоп или `null`; `stop_pending` — стоп, который ещё переставляется, или `null`;
- `targets` — цели по возрастанию номера: `price`, `lots` (план), `filled`;
- `opened_at` — время первого исполнения входа;
- `entries` — исполнения входа, включая доборы;
- `exits` — исполнения частичных выходов, пустой список, если их не было;
- `phase`: `open`, `building` (идёт добор) или `reducing` (были частичные выходы);
- `fees` — все комиссии сделки на сейчас, включая комиссию входа;
- `fees_source` — источник комиссий: `broker` (сумма от брокера), `configured` (оценка из конфигурации, у эмуляции), `unknown` (не известна) или `mixed`, если у исполнений разные источники;
- `realized` — результат частичных выходов минус все комиссии сделки на сейчас (`net_realized_pnl` журнала). У позиции без частичных выходов это минус комиссия входа.

Ответ ДОЛЖЕН содержать сумму `unrealized` по позициям, признак `unrealized_complete` и `as_of` — момент ответа. Необязательный параметр `instrument` ДОЛЖЕН оставлять позиции одного инструмента.

#### Scenario: Позиция с частичным выходом
- **GIVEN** в эмуляции открыт лонг NG-11.26 на 3 лота по 2.874, 1 лот закрыт целью по 2.900
- **WHEN** приходит `GET /api/v1/emulation/positions`
- **THEN** позиция NG-11.26: `side = long`, `lots = 2`, `entry_price = "2.874"`, `phase = reducing`, первая цель с `filled = 1`
- **AND** в `entries` одно исполнение на 3 лота, в `exits` одно на 1 лот с `kind = target`
- **AND** `realized` — результат первой цели минус комиссии входа и выхода

#### Scenario: Свежая позиция
- **GIVEN** лонг BR-12.26 на 3 лота только что открыт, комиссия входа 6,20
- **WHEN** приходит `…/positions`
- **THEN** `fees = "6.20"`, `realized = "-6.20"`, `exits` пустой

#### Scenario: Отменённый вход не позиция
- **GIVEN** заявка на вход отменена, исполнений не было (фаза `CANCELLED`)
- **WHEN** приходит `GET /api/v1/emulation/positions`
- **THEN** этой сделки в ответе нет

### Requirement: Закрытые сделки
Нормативный уровень: MUST. `…/trades` ДОЛЖЕН отдавать сделки журнала в фазе `CLOSED` с хотя бы одним исполнением входа. Порядок — по `closed_at` (время последнего исполнения выхода), новые сверху. Параметры:

- `from` и `to` — окно `[from, to)` по `closed_at`, моменты ISO 8601 с зоной; `from` по умолчанию не ограничен, `to` — текущий момент;
- `limit` — 1…1000, по умолчанию 200;
- `instrument` — только сделки одного инструмента.

У сделки ДОЛЖНЫ быть:

- `id`, `binding`, `instrument`, `side`;
- `lots` — наибольший объём позиции за сделку;
- `entry_price` и `exit_price` — средние по исполнениям входа и выхода;
- `opened_at`, `closed_at`;
- `entries` — исполнения входа, включая доборы;
- `exits` — исполнения выхода;
- `exit` — последний выход: `kind`, `code`, `label`, и `scenario` — подпись всей цепочки выходов;
- `gross`, `fees`, `net`;
- `fees_source` — источник комиссий: `broker` (сумма от брокера), `configured` (оценка из конфигурации, у эмуляции), `unknown` (не известна) или `mixed`, если у исполнений разные источники;
- `result_r` или `null`, если начальный риск сделки неизвестен.

Подписи причин и сценарий ДОЛЖНЫ совпадать с CSV-проекцией «Позиции» журнала.

`_links.earlier` ДОЛЖЕН быть, если раньше последней отданной сделки в окне есть ещё. Он ведёт на те же параметры с `to`, равным `closed_at` последней отданной сделки. Сделки с тем же `closed_at`, что у последней отданной, ДОЛЖНЫ отдаваться в той же странице, даже сверх `limit`: на стыке страниц сделки не теряются и не повторяются.

Ответ ДОЛЖЕН содержать заголовок `ETag` — номер последнего события журнала. Запрос с `If-None-Match`, равным текущему `ETag`, ДОЛЖЕН получать `304` без тела.

`from` не раньше `to`, момент без зоны и `limit` вне диапазона ДОЛЖНЫ отклоняться `400 INVALID_REQUEST`.

#### Scenario: Сделка с частичным выходом
- **GIVEN** лонг NG-11.26 на 2 лота: 1 лот закрыт частичным выходом по 2.889, остаток — стопом по 2.870
- **WHEN** приходит `GET /api/v1/emulation/trades`
- **THEN** у сделки `lots = 2`, `exit.kind = stop`, `exit.label = стоп`, `exit.scenario = частичный выход (часть) + стоп (остаток)`
- **AND** в `exits` два исполнения: первое с `kind = partial`, второе с `kind = stop`

#### Scenario: Комиссия эмуляции — оценка
- **GIVEN** у всех исполнений сделки эмуляции `fee_source = configured`
- **WHEN** приходит `…/trades`
- **THEN** у сделки `fees_source = configured`, UI помечает комиссию как оценку

#### Scenario: Добор виден в исполнениях
- **GIVEN** шорт Si-12.26: вход 1 лот по 82 640, добор 1 лот по 82 700, закрытие обоих по цели
- **WHEN** приходит `…/trades`
- **THEN** в `entries` два исполнения по своим ценам, `entry_price = "82670"`, `lots = 2`

#### Scenario: Листание назад
- **GIVEN** в журнале 250 закрытых сделок
- **WHEN** UI запрашивает `…/trades`, а затем переходит по `_links.earlier`
- **THEN** первая страница — 200 последних сделок, вторая — остальные 50, без повторов и пропусков, у второй ссылки `earlier` нет

#### Scenario: Сделки инструмента для меток графика
- **WHEN** приходит `GET /api/v1/emulation/trades?instrument=ng-11.26&from=2026-10-30T00:00:00Z`
- **THEN** в ответе только сделки NG-11.26, закрытые с 30.10, с исполнениями входа и выхода: по ним UI ставит метки на свечи

#### Scenario: Журнал не изменился
- **GIVEN** UI получил `…/trades` с `ETag: "18342"`
- **WHEN** через 15 с приходит тот же запрос с `If-None-Match: "18342"`, а новых событий в журнале нет
- **THEN** ответ `304`

### Requirement: Вид выхода
Нормативный уровень: MUST. Каждое исполнение выхода ДОЛЖНО содержать:

- `code` — код причины журнала как есть;
- `label` — подпись, как в CSV-проекции «Позиции»;
- `kind` — вид выхода для короткой метки UI.

`kind` ДОЛЖЕН определяться так:

| Исполнение | `kind` |
|---|---|
| заявка цели (`TARGET`) | `target` |
| стоп (`STOP`) — защитный, трейлинг, безубыток | `stop` |
| частичный выход по правилу управления (`REDUCE`) | `partial` |
| закрытие (`CLOSE`) с кодом встречного сигнала или правила выхода: `raw-opposite-signal`, `opposite-signal-management`, `ma40-opposite-close` | `signal` |
| закрытие перед концом сессии: `intraday-session-end` | `session_end` |
| экспирация и переход: `contract-expiring`, `contract-rollover` | `expiry` |
| остановка контура и снятие из состава: `contour-stopping`, `contour-stop`, `instrument-removing`, `instrument-remove`, `binding-removing`, `binding-remove`, `core-lost`, `instrument-frozen` | `contour` |
| любой другой код | `other` |

Новый код причины, не внесённый в таблицу, ДОЛЖЕН давать `other`, а не ошибку. `exit` закрытой сделки — вид, код и подпись её последнего исполнения выхода.

#### Scenario: Закрытие по цели
- **GIVEN** сделка закрыта заявкой второй цели, код журнала `tp:tp-2`
- **WHEN** приходит `…/trades`
- **THEN** `exit.kind = target`, `exit.code = "tp:tp-2"`, `exit.label` совпадает с колонкой «Финальная причина» CSV

#### Scenario: Конец торговой сессии
- **WHEN** сделка закрыта перед концом сессии с кодом `intraday-session-end`
- **THEN** `exit.kind = session_end`, `exit.label = закрытие перед концом торговой сессии`

### Requirement: Нереализованный результат
Нормативный уровень: MUST. `last_price` открытой позиции ДОЛЖЕН быть ценой закрытия последней завершённой свечи `1m` её инструмента из рыночной базы ядра. `last_price_at` — время открытия этой свечи.

`unrealized` ДОЛЖЕН считаться так:

```
(last_price − entry_price) × lots × step_cost / price_step
```

со знаком «плюс» для `long` и «минус» для `short`. `price_step` и `step_cost` берутся из сделки журнала.

Если свечи нет, рыночная база не открыта или у сделки нет `price_step` и `step_cost`:

- `last_price` и `unrealized` ДОЛЖНЫ быть `null`;
- позиция НЕ ДОЛЖНА входить в суммы `unrealized`;
- `unrealized_complete` ДОЛЖЕН быть `false`.

Цена ДОЛЖНА браться из рыночной базы ядра и у эмуляции, и у песочницы; процесс контура в расчёте не участвует.

#### Scenario: Шорт в плюсе
- **GIVEN** шорт Si-12.26 1 лот по 82 640, `price_step = 1`, `step_cost = 1`, последняя `1m` закрылась на 82 455
- **WHEN** приходит `…/positions`
- **THEN** `last_price = "82455"`, `unrealized = "185"`

#### Scenario: Рыночная база не открыта
- **GIVEN** ядро стартует и ещё не открыло рыночную базу, в эмуляции две открытые позиции
- **WHEN** приходит `GET /api/v1/emulation/positions`
- **THEN** ответ `200`, у обеих позиций `last_price = null` и `unrealized = null`, `unrealized_complete = false`

### Requirement: Итоги периода и кривая результата
Нормативный уровень: MUST. `…/performance` ДОЛЖЕН принимать `period` — `day`, `week`, `month` или `all` — либо явные `from` и `to`. Без параметров — `day`. Границы периодов:

- `day` — с последних 19:00 МСК, не позже текущего момента: торговый день биржи начинается с вечерней сессии;
- `week` — с понедельника 00:00 МСК текущей недели;
- `month` — с 1-го числа 00:00 МСК текущего месяца;
- `all` — без нижней границы.

Конец периода — текущий момент или `to`. Сделка входит в период по `closed_at`. Ответ ДОЛЖЕН называть фактические границы в `period`: `name` (`day`, `week`, `month`, `all` или `custom` при явных `from` и `to`), `from`, `to`.

Ответ ДОЛЖЕН содержать:

- `realized` — `net`, `gross`, `fees` закрытых в периоде сделок и `fees_source` по их исполнениям (`null`, если сделок нет);
- `trades` — `count`, `winners` (нетто больше нуля), `losers` (нетто меньше нуля);
- `average_net` — средний нетто или `null` без сделок;
- `profit_factor` — сумма нетто прибыльных / модуль суммы нетто убыточных или `null` без убыточных;
- `curve`:
  - первая точка — ноль на начале периода (у `all` — на первом входе);
  - дальше точка на каждый `closed_at` с накопленным нетто;
- `max_drawdown` — наибольшее падение кривой от предыдущего максимума, начиная с нуля: `amount` (не больше нуля) и `at` — момент дна или `null`;
- `open` — открытые сейчас позиции: `count`, `realized` (сумма `realized` позиций — частичные выходы минус все комиссии), `unrealized`, `unrealized_complete`;
- `curve_now` — текущий момент и `net` = последняя точка `curve` + `open.realized` + `open.unrealized`;
- `_links.trades` — `…/trades` с началом периода. У `day`, `week`, `month` и `all` ссылка НЕ ДОЛЖНА содержать `to`: список сделок по ней доходит до момента своего запроса. У `custom` — с `from` и `to`.

Если точек кривой больше 500, `curve` ДОЛЖНА прореживаться так, чтобы сохранились первая и последняя точки и минимум и максимум каждого интервала. `max_drawdown` ДОЛЖЕН считаться по полной кривой.

`period` не из списка, `period` вместе с `from` или `to`, `from` не раньше `to` и момент без зоны ДОЛЖНЫ отклоняться `400 INVALID_REQUEST`.

#### Scenario: Торговый день вечером
- **GIVEN** сейчас 31.10.2026 20:10 МСК, сделки закрыты 31.10 в 15:20 и в 19:40 МСК
- **WHEN** приходит `…/performance?period=day`
- **THEN** `period.from = 2026-10-31T16:00:00Z`, в итогах одна сделка — закрытая в 19:40

#### Scenario: Итоги дня
- **GIVEN** в торговом дне шесть закрытых сделок с нетто +373, −70, +421, +105, −40, +97
- **WHEN** приходит `…/performance?period=day`
- **THEN**
  - `realized.net = "886"`, `trades = {count: 6, winners: 4, losers: 2}`;
  - `profit_factor = "9.05"` (996 / 110, до двух знаков);
  - в `curve` семь точек, первая — ноль на начале дня

#### Scenario: Просадка
- **GIVEN** накопленный нетто по сделкам периода: +105, +65, +25, +446
- **WHEN** приходит `…/performance`
- **THEN** `max_drawdown.amount = "-80"`, `at` — время закрытия третьей сделки

#### Scenario: Хвост кривой сходится со счётом
- **GIVEN** у эмуляции закрытые сделки на нетто −11 346,45 за всё время и одна открытая позиция с комиссией входа 6,20 без частичных выходов
- **WHEN** приходит `…/performance?period=all`
- **THEN** `open.realized = "-6.20"`, а последняя точка `curve` + `open.realized` равна `balance − initial` из `GET /api/v1/emulation/account`

#### Scenario: Свой период
- **WHEN** приходит `…/performance?from=2026-10-01T00:00:00Z&to=2026-10-15T00:00:00Z`
- **THEN** `period = {name: custom, from: "2026-10-01T00:00:00Z", to: "2026-10-15T00:00:00Z"}`, `_links.trades` с теми же `from` и `to`

#### Scenario: Неверный период
- **WHEN** приходит `…/performance?period=year`
- **THEN** ответ `400` с `code = INVALID_REQUEST`

### Requirement: Виртуальный счёт эмуляции
Нормативный уровень: MUST. `GET /api/v1/emulation/account` ДОЛЖЕН отдавать виртуальный счёт эмуляции из журнала:

- `initial` — начальный депозит;
- `balance` — баланс с учётом всех исполнений и комиссий;
- `realized_net` — накопленный нетто-результат;
- `fees` — накопленные комиссии;
- `updated_at` — время последнего изменения счёта.

Нет журнала → `initial` — депозит из конфигурации, остальное — ноль, `updated_at = null`. Ресурс НЕ ДОЛЖЕН отдавать `equity` журнала: в ней нет переоценки открытых позиций. Песочница такого ресурса не имеет: её деньги — `current.capital` от брокера.

#### Scenario: Счёт после убыточного месяца
- **GIVEN** депозит 100 000, накопленный нетто −11 346,45
- **WHEN** приходит `GET /api/v1/emulation/account`
- **THEN** `initial = "100000"`, `realized_net = "-11346.45"`, `balance = "88653.55"`, поля `equity` нет

### Requirement: Имена и привязки в ответах
Нормативный уровень: MUST. `instrument` в позициях и сделках ДОЛЖЕН быть коротким именем контракта или тикером акции из карты `instrument_names` журнала. Тикера нет в карте → `instrument = null`. Биржевой тикер контракта НЕ ДОЛЖЕН появляться ни в одном поле ответа.

`trade_id` и `signal_id` журнала содержат биржевой тикер и НЕ ДОЛЖНЫ отдаваться. `id` сделки ДОЛЖЕН быть непрозрачной строкой `t_` + первые 16 шестнадцатеричных знаков SHA-256 от `trade_id`: одна и та же сделка всегда получает один и тот же `id`, тикер из него не восстанавливается.

`binding` ДОЛЖЕН быть объектом `{id, strategy, timeframe}`:

- `id` — привязка сделки (`assignment_id`);
- стратегия и таймфрейм — из конфигурации привязок.

Привязки нет в конфигурации → `strategy = null`, таймфрейм — из `trade_id` сделки.

Фильтр `instrument` ДОЛЖЕН сравнивать короткое имя без учёта регистра; неизвестное имя → пустой список, не ошибка.

#### Scenario: Тикер не показывается
- **GIVEN** в журнале сделка с `instrument_id = SiZ6` и картой `SiZ6 → Si-12.26`
- **WHEN** приходит `…/trades`
- **THEN** `instrument = "Si-12.26"`, у сделки `id` вида `t_3f9a…` вместо `trade_id`, строки `SiZ6` нет ни в одном поле ответа

#### Scenario: Привязку убрали из конфигурации
- **GIVEN** сделка привязки `future-br-macd`, которой больше нет в `robot.toml`
- **WHEN** приходит `…/trades`
- **THEN** `binding = {id: future-br-macd, strategy: null, timeframe: "5m"}`

### Requirement: Ссылки контура на торговлю
Нормативный уровень: MUST. Ответы `GET /api/v1/emulation` и `GET /api/v1/sandbox` ДОЛЖНЫ содержать в `_links` ссылки `positions`, `trades` и `performance`. Ответ эмуляции — ещё `account`. Ссылки ДОЛЖНЫ быть при любом состоянии контура. Состояние контура по-прежнему НЕ ДОЛЖНО содержать сделки и баланс.

#### Scenario: UI находит ресурсы по ссылкам
- **WHEN** приходит `GET /api/v1/sandbox` при остановленной песочнице
- **THEN** `_links` содержит `positions`, `trades` и `performance` с адресами `/api/v1/sandbox/…`, а ссылки `account` нет

### Requirement: Чтение журнала не мешает контуру
Нормативный уровень: MUST. Ресурсы торговли ДОЛЖНЫ открывать журнал контура только на чтение:

- без записи;
- без смены режима журнала;
- без блокировки записи процесса контура дольше одной транзакции чтения.

Ответ ДОЛЖЕН строиться из одной транзакции чтения журнала. Ресурсы НЕ ДОЛЖНЫ обращаться к брокеру и процессу контура. Отказ чтения журнала, кроме его отсутствия, ДОЛЖЕН давать `503` с кодом `JOURNAL_UNAVAILABLE`, без пути к файлу и текста исключения в `detail`.

#### Scenario: Контур пишет во время чтения
- **GIVEN** процесс эмуляции фиксирует исполнение
- **WHEN** одновременно приходит `…/performance?period=all`
- **THEN** ответ строится по последнему зафиксированному состоянию, процесс контура записывает исполнение без ошибки

#### Scenario: Журнал не меняется
- **WHEN** приходят все ресурсы торговли эмуляции по очереди
- **THEN** содержимое и время изменения `trades.sqlite3` до и после совпадают
