# control-api Specification

## Purpose
Управление запуском торгового контура через локальный HTTP API робота: ожидание команды, запуск эмуляции выбранными инструментами, состояние контура и доступ по отдельному ключу управления. Первый этап перехода к ядру и торговым контурам (`docs/architecture/core-contours.md`).

## Requirements

### Requirement: Ожидание команды запуска
Нормативный уровень: MUST. При запуске с `--mode emulation --wait-command` или при выборе в меню «ждать команду API» робот ДОЛЖЕН выполнить ранний сбор рыночных данных, поднять локальный API и ждать команды запуска вместо выбора инструментов в консоли. Пока робот ждёт, полосы рыночных данных ДОЛЖНЫ работать как при выборе в меню, торговля НЕ ДОЛЖНА начинаться, а консоль ДОЛЖНА показывать адрес для команды запуска без значения ключа. Без заданного `ROBOT_CONTROL_TOKEN` ожидание команды НЕ ДОЛЖНО начинаться: запуск ДОЛЖЕН завершаться с кодом `2` и причиной. `--wait-command` ДОЛЖЕН быть допустим только с `--mode emulation` и НЕ ДОЛЖЕН сочетаться с `--instruments`.

#### Scenario: Робот ждёт команды
- **GIVEN** задан `ROBOT_CONTROL_TOKEN`
- **WHEN** робот запущен с `--mode emulation --wait-command`
- **THEN** полосы данных работают, торговли нет, в консоли — «Робот ждёт команду запуска: POST http://127.0.0.1:8101/api/v1/contours», а `GET /api/v1/contours` показывает состояние `waiting_command`

#### Scenario: Ключ управления не задан
- **WHEN** робот запущен с `--mode emulation --wait-command`, а `ROBOT_CONTROL_TOKEN` пуст
- **THEN** печатается, что ждать команды нельзя без ключа управления, процесс завершается с кодом `2`

#### Scenario: Несовместимые параметры
- **WHEN** робот запущен с `--mode emulation --wait-command --instruments NG`
- **THEN** печатается, что ждать команды и задавать инструменты одновременно нельзя, процесс завершается с кодом `2`

### Requirement: Запуск эмуляции командой API
Нормативный уровень: MUST. `POST /api/v1/contours` с телом `{"kind": "emulation", "instruments": [...]}` ДОЛЖЕН запускать торговлю эмуляции выбранными инструментами. Поле `instruments` НЕ ОБЯЗАТЕЛЬНО, его отсутствие ДОЛЖНО означать `all`. Токены инструментов ДОЛЖНЫ разрешаться и проверяться по тем же правилам, что параметры командной строки. Разрешение, сборка торговых компонентов и запуск ДОЛЖНЫ выполняться главным потоком робота, а не потоком HTTP.

Команда ДОЛЖНА приниматься, когда робот ждёт команду, а также после остановки (`stopped`) или падения (`failed`) контура: ядро ДОЛЖНО запустить процесс контура заново тем же процессом робота, без перезапуска приёма данных. Набор инструментов повторного запуска МОЖЕТ отличаться от прежнего. Принятая команда ДОЛЖНА записывать в `core.sqlite3` желаемое «работает» с новым номером поколения и выбранным составом.

Ответы:
- `201` — инструменты разрешены, торговля запускается; тело — состояние контура с выбранными контрактами, эквивалентной командой и номером поколения;
- `202` — проверка инструментов не уложилась в 60 секунд; тело — состояние `starting`, итог виден в `GET /api/v1/contours`;
- `400` — тело не JSON, неизвестные поля, `kind` не `emulation`, `instruments` не список строк;
- `401` — нет или неверный ключ управления;
- `409` — контур запускается или торгует (`ALREADY_RUNNING`) либо выполняет остановку и доживает сделки (`STOPPING`); тело содержит текущее состояние, набор инструментов не меняется;
- `422` — хотя бы один токен отклонён; тело содержит список отказов с токеном и причиной; торговля НЕ ДОЛЖНА начинаться ни по одному инструменту.

После `422` робот ДОЛЖЕН продолжать ждать команды. Контракты в ответах ДОЛЖНЫ называться коротким именем, а не биржевым тикером.

#### Scenario: Запуск газа и Сбера
- **GIVEN** робот ждёт команды, у NG и SBER есть привязки
- **WHEN** приходит `POST /api/v1/contours` с `{"kind": "emulation", "instruments": ["NG", "SBER"]}` и верным ключом
- **THEN** ответ `201` содержит NG-12.26 с днями до экспирации, SBER, строку `--mode emulation --instruments NG-12.26,SBER` и номер поколения, а торговля этими инструментами начинается

#### Scenario: Один инструмент отклонён
- **WHEN** приходит команда с `["NG", "AFLT"]`, а у AFLT нет привязок
- **THEN** ответ `422` называет AFLT и причину, торговля не начинается ни по NG, ни по AFLT, робот продолжает ждать

#### Scenario: Повторный запуск
- **WHEN** торговля уже идёт, а приходит новая команда запуска
- **THEN** ответ `409` с кодом `ALREADY_RUNNING` и текущим состоянием, набор инструментов не меняется

#### Scenario: История через API
- **WHEN** приходит команда с `{"kind": "history"}`
- **THEN** ответ `400`: в этом процессе API запускает только эмуляцию

#### Scenario: Долгая проверка у брокера
- **WHEN** проверка инструментов у источника заняла больше 60 секунд из-за лимитов
- **THEN** ответ `202` с состоянием `starting`, а `GET /api/v1/contours` затем показывает `running` или отказы

#### Scenario: Запуск после остановки другим набором
- **GIVEN** контур эмуляции торговал NG и SBER и остановлен командой, процесс завершился с кодом 0
- **WHEN** приходит `POST /api/v1/contours` с `{"kind": "emulation", "instruments": ["BR", "SBER"]}`
- **THEN** ответ `201` с новым поколением, ядро без перезапуска приёма данных запускает новый процесс контура с BR и SBER

#### Scenario: Запуск во время дожития сделок
- **GIVEN** контур остановлен командой `no_entries` и сопровождает открытую позицию NG
- **WHEN** приходит `POST /api/v1/contours`
- **THEN** ответ `409` с кодом `STOPPING`, остановка продолжается

### Requirement: Состояние контура
Нормативный уровень: MUST. `GET /api/v1/contours` с ключом управления ДОЛЖЕН возвращать список контуров процесса, `GET /api/v1/contours/{id}` — один контур или `404`. В режиме эмуляции в списке ДОЛЖЕН быть ровно один контур с `id` и `kind`, равными `emulation`. Поля контура:

- **Общее состояние:** `waiting_command`, `starting`, `running`, `stopping_no_entries`, `stopping_close_all`, `stopped` или `failed`.
- **О запуске:**
  - источник запуска: `cli`, `menu` или `api`;
  - выбранные контракты коротким именем с днями до экспирации;
  - время запуска;
  - эквивалентная команда;
  - отказы последней команды, если она отклонена.
- **Желаемое (`desired`)** из `core.sqlite3`:
  - `running` — `true`, если контур должен работать;
  - `stop_mode`;
  - `generation`.
- **Фактическое (`actual`)** из `status.json` контура или `null`, если файла нет или он не читается:
  - состояние;
  - `applied_generation`;
  - `open_positions`;
  - `pending_entries`;
  - `last_tick_at`.
- **Процесс контура:** `pid`, пока процесс жив, и `exit_code` после завершения.

Общее состояние ДОЛЖНО определяться так:

1. **Процесс завершился:** `stopped` при коде 0, `failed` при другом коде. Если процесс в этом запуске ядра не создавался — `waiting_command`.
2. **Процесс жив, желаемое «остановлен»:** `stopping_<режим>`.
3. **Процесс жив, контур ещё ни разу не подтвердил курсор ленты в этом запуске:** `starting`.
4. **Иначе:** `running`.

После рестарта ядра контур ДОЛЖЕН показываться в `waiting_command` с прежним желаемым из `core.sqlite3`. Сам контур НЕ ДОЛЖЕН запускаться: автоподъём — следующий этап. Ответ НЕ ДОЛЖЕН содержать сделки, баланс и секреты.

#### Scenario: Торговля запущена параметрами
- **WHEN** робот запущен с `--mode emulation --instruments NG`, контур подтвердил курсор, а затем приходит `GET /api/v1/contours`
- **THEN** контур `emulation` в состоянии `running` с источником `cli`, контрактом NG, `desired.running = true` и `pid` процесса контура

#### Scenario: Последняя команда отклонена
- **WHEN** команда запуска получила `422`, а затем приходит `GET /api/v1/contours`
- **THEN** контур в состоянии `waiting_command` и содержит отказы последней команды

#### Scenario: Процесс контура упал
- **WHEN** процесс контура завершился с кодом 1, а затем приходит `GET /api/v1/contours`
- **THEN** контур в состоянии `failed`, `pid` — `null`, `exit_code` — 1

#### Scenario: Ядро перезапущено, желаемое — работает
- **GIVEN** до рестарта ядра контур работал с поколением 5
- **WHEN** ядро запущено снова с `--wait-command`, а затем приходит `GET /api/v1/contours`
- **THEN** контур в состоянии `waiting_command`, `desired.running = true`, `desired.generation = 5`, процесс не запущен

#### Scenario: Фактическое отстаёт от желаемого
- **GIVEN** контур работает с применённым поколением 3
- **WHEN** приходит команда остановки, а `GET` выполняется до следующей границы тика
- **THEN** `desired.generation = 4`, `actual.applied_generation = 3`, общее состояние `stopping_no_entries`

### Requirement: Доступ к управлению
Нормативный уровень: MUST. Маршруты управления ДОЛЖНЫ требовать ключ `ROBOT_CONTROL_TOKEN` в заголовке `Authorization: Bearer` и НЕ ДОЛЖНЫ принимать его в адресе запроса или cookie. Ключ экспорта рыночных данных НЕ ДОЛЖЕН давать доступ к управлению, а ключ управления — к экспорту. Маршруты управления ДОЛЖНЫ отклонять запрос, если заголовок `Host` не равен `127.0.0.1`, `localhost` или `[::1]` с портом сервера. Сервер НЕ ДОЛЖЕН отдавать заголовки CORS. `ROBOT_CONTROL_TOKEN` ДОЛЖЕН быть в `secrets` журнала и НЕ ДОЛЖЕН печататься нигде.

#### Scenario: Ключ экспорта для управления
- **WHEN** команда запуска приходит с ключом `MARKET_DATA_EXPORT_TOKEN`
- **THEN** ответ `401`, торговля не начинается

#### Scenario: Чужой Host
- **WHEN** команда запуска приходит с верным ключом, но с заголовком `Host: evil.example:8101`
- **THEN** ответ `403`, торговля не начинается

#### Scenario: Ключ в адресе
- **WHEN** ключ передан параметром адреса, а заголовка `Authorization` нет
- **THEN** ответ `401`

### Requirement: Остановка контура командой
Нормативный уровень: MUST. `POST /api/v1/contours/{id}/stop` с телом `{"mode": "no_entries"}` или `{"mode": "close_all"}` ДОЛЖЕН записывать в `core.sqlite3` желаемое «остановлен» с режимом и новым поколением и отвечать `202` с номером поколения и состоянием контура. Повтор команды с тем же режимом ДОЛЖЕН отвечать `200` с прежним поколением и НЕ ДОЛЖЕН его менять. `close_all` поверх `no_entries` ДОЛЖЕН приниматься новым поколением. `no_entries` поверх `close_all` ДОЛЖЕН отклоняться `409`.

Остальные ответы:
- `409` — контур не работает: `waiting_command`, `stopped` или `failed`;
- `400` — неверный режим или лишние поля;
- `404` — неизвестный `id`;
- `401`/`403` — по правилам доступа к управлению.

Остановка НЕ ДОЛЖНА останавливать ядро, приём данных и локальный API. Ctrl+C ядра ДОЛЖЕН по-прежнему останавливать процесс контура после тика, не меняя желаемое состояние.

#### Scenario: Остановка без новых входов
- **GIVEN** контур работает, поколение 3
- **WHEN** приходит `POST /api/v1/contours/emulation/stop` с `{"mode": "no_entries"}`
- **THEN** ответ `202` с поколением 4, в `core.sqlite3` желаемое «остановлен, no_entries», ядро и приём данных продолжают работать

#### Scenario: Повтор остановки
- **GIVEN** уже принята остановка `no_entries` с поколением 4
- **WHEN** та же команда приходит снова
- **THEN** ответ `200` с поколением 4, в журнале команд исход `ignored`

#### Scenario: Закрыть всё поверх дожития
- **GIVEN** контур доживает сделки после `no_entries`, поколение 4
- **WHEN** приходит `stop` с `{"mode": "close_all"}`
- **THEN** ответ `202` с поколением 5, контур переходит к закрытию всех позиций

#### Scenario: Нечего останавливать
- **WHEN** контур в состоянии `stopped`, а приходит `stop`
- **THEN** ответ `409`, поколение не меняется

### Requirement: Желаемое состояние и журнал команд ядра
Нормативный уровень: MUST. Ядро ДОЛЖНО хранить желаемое состояние контуров в `data/core.sqlite3`: вид, должен ли работать, режим остановки, номер поколения, состав, источник и эквивалентную команду. Каждая команда управления ДОЛЖНА записываться в журнал `contour_commands`: время, действие, тело без секретов, поколение и исход (`accepted`, `rejected`, `conflict`, `ignored`).

Номер поколения ДОЛЖЕН расти монотонно на каждую команду, меняющую желаемое. Писать в `core.sqlite3` ДОЛЖНО только ядро, контур ДОЛЖЕН открывать её только на чтение. База ДОЛЖНА хранить версию схемы.

#### Scenario: Поколения растут
- **WHEN** подряд приняты запуск, остановка `no_entries` и остановка `close_all`
- **THEN** их поколения — 1, 2, 3, а журнал содержит три записи с исходом `accepted`

#### Scenario: Отклонённый запуск в журнале
- **WHEN** команда запуска получила `422`
- **THEN** в журнале запись с исходом `rejected` и причинами, поколение не меняется

### Requirement: Лог контура через API
Нормативный уровень: MUST. `GET /api/v1/contours/{id}/log?tail=N` ДОЛЖЕН отдавать последние `N` строк журнала процесса контура в `text/plain; charset=utf-8`. По умолчанию `N` равно 200, допустимо от 1 до 1000, иначе `400`. Неизвестный `id` даёт `404`, отсутствующий журнал — пустой ответ `200`.

Ответ ДОЛЖЕН содержать строки так, как они записаны в журнал, где секреты уже заменены на `[скрыто]`. Маршрут ДОЛЖЕН требовать ключ управления.

#### Scenario: Последние строки
- **GIVEN** в журнале контура 5000 строк
- **WHEN** приходит `GET /api/v1/contours/emulation/log?tail=3`
- **THEN** ответ — три последние строки журнала

#### Scenario: Слишком длинный хвост
- **WHEN** приходит `GET /api/v1/contours/emulation/log?tail=5000`
- **THEN** ответ `400`
