# control-api Specification

## Purpose
Управление запуском торгового контура через локальный HTTP API робота: ожидание команды, запуск эмуляции выбранными инструментами, состояние контура и доступ по отдельному ключу управления. Первый этап перехода к ядру и торговым контурам (`docs/architecture/core-contours.md`).

## Requirements

### Requirement: Ожидание команды запуска
Нормативный уровень: MUST. При запуске с `--mode emulation --wait-command` или при выборе в меню «ждать команду API» робот ДОЛЖЕН выполнить ранний сбор рыночных данных, поднять локальный API и ждать команды запуска вместо выбора инструментов в консоли. Пока робот ждёт, полосы рыночных данных ДОЛЖНЫ работать как при выборе в меню, торговля НЕ ДОЛЖНА начинаться, а консоль ДОЛЖНА показывать адрес для команды запуска без значения ключа. Без заданного `ROBOT_CONTROL_TOKEN` ожидание команды НЕ ДОЛЖНО начинаться: запуск ДОЛЖЕН завершаться с кодом `2` и причиной. `--wait-command` ДОЛЖЕН быть допустим только с `--mode emulation` и НЕ ДОЛЖЕН сочетаться с `--instruments`.

#### Scenario: Робот ждёт команды
- **GIVEN** задан `ROBOT_CONTROL_TOKEN`
- **WHEN** робот запущен с `--mode emulation --wait-command`
- **THEN** полосы данных работают, торговли нет, в консоли — «Робот ждёт команду запуска: POST http://127.0.0.1:8101/api/v1/contours», а `GET /api/v1/contours` показывает состояние `waiting_command`

#### Scenario: Ключ управления не задан
- **WHEN** робот запущен с `--mode emulation --wait-command`, а `ROBOT_CONTROL_TOKEN` пуст
- **THEN** печатается, что ждать команды нельзя без ключа управления, процесс завершается с кодом `2`

#### Scenario: Несовместимые параметры
- **WHEN** робот запущен с `--mode emulation --wait-command --instruments NG`
- **THEN** печатается, что ждать команды и задавать инструменты одновременно нельзя, процесс завершается с кодом `2`

### Requirement: Запуск эмуляции командой API
Нормативный уровень: MUST. `POST /api/v1/contours` с телом `{"kind": "emulation", "instruments": [...]}` ДОЛЖЕН запускать торговлю эмуляции выбранными инструментами. Поле `instruments` НЕ ОБЯЗАТЕЛЬНО, его отсутствие ДОЛЖНО означать `all`. Токены инструментов ДОЛЖНЫ разрешаться и проверяться по тем же правилам, что параметры командной строки. Разрешение, сборка торговых компонентов и запуск ДОЛЖНЫ выполняться главным потоком робота, а не потоком HTTP.

Команда ДОЛЖНА приниматься, когда робот ждёт команду, а также после остановки (`stopped`) или падения (`failed`) контура: ядро ДОЛЖНО запустить процесс контура заново тем же процессом робота, без перезапуска приёма данных. Набор инструментов повторного запуска МОЖЕТ отличаться от прежнего. Принятая команда ДОЛЖНА записывать в `core.sqlite3` желаемое «работает» с новым номером поколения и выбранным составом.

Ответы:
- `201` — инструменты разрешены, торговля запускается; тело — состояние контура с выбранными контрактами, эквивалентной командой и номером поколения;
- `202` — проверка инструментов не уложилась в 60 секунд; тело — состояние `starting`, итог виден в `GET /api/v1/contours`;
- `400` — тело не JSON, неизвестные поля, `kind` не `emulation`, `instruments` не список строк;
- `401` — нет или неверный ключ управления;
- `409` — контур запускается или торгует (`ALREADY_RUNNING`) либо выполняет остановку и доживает сделки (`STOPPING`); тело содержит текущее состояние, набор инструментов не меняется;
- `422` — хотя бы один токен отклонён; тело содержит список отказов с токеном и причиной; торговля НЕ ДОЛЖНА начинаться ни по одному инструменту.

После `422` робот ДОЛЖЕН продолжать ждать команды. Контракты в ответах ДОЛЖНЫ называться коротким именем, а не биржевым тикером.

#### Scenario: Запуск газа и Сбера
- **GIVEN** робот ждёт команды, у NG и SBER есть привязки
- **WHEN** приходит `POST /api/v1/contours` с `{"kind": "emulation", "instruments": ["NG", "SBER"]}` и верным ключом
- **THEN** ответ `201` содержит NG-12.26 с днями до экспирации, SBER, строку `--mode emulation --instruments NG-12.26,SBER` и номер поколения, а торговля этими инструментами начинается

#### Scenario: Один инструмент отклонён
- **WHEN** приходит команда с `["NG", "AFLT"]`, а у AFLT нет привязок
- **THEN** ответ `422` называет AFLT и причину, торговля не начинается ни по NG, ни по AFLT, робот продолжает ждать

#### Scenario: Повторный запуск
- **WHEN** торговля уже идёт, а приходит новая команда запуска
- **THEN** ответ `409` с кодом `ALREADY_RUNNING` и текущим состоянием, набор инструментов не меняется

#### Scenario: История через API
- **WHEN** приходит команда с `{"kind": "history"}`
- **THEN** ответ `400`: в этом процессе API запускает только эмуляцию

#### Scenario: Долгая проверка у брокера
- **WHEN** проверка инструментов у источника заняла больше 60 секунд из-за лимитов
- **THEN** ответ `202` с состоянием `starting`, а `GET /api/v1/contours` затем показывает `running` или отказы

#### Scenario: Запуск после остановки другим набором
- **GIVEN** контур эмуляции торговал NG и SBER и остановлен командой, процесс завершился с кодом 0
- **WHEN** приходит `POST /api/v1/contours` с `{"kind": "emulation", "instruments": ["BR", "SBER"]}`
- **THEN** ответ `201` с новым поколением, ядро без перезапуска приёма данных запускает новый процесс контура с BR и SBER

#### Scenario: Запуск во время дожития сделок
- **GIVEN** контур остановлен командой `no_entries` и сопровождает открытую позицию NG
- **WHEN** приходит `POST /api/v1/contours`
- **THEN** ответ `409` с кодом `STOPPING`, остановка продолжается

### Requirement: Состояние контура
Нормативный уровень: MUST. `GET /api/v1/contours` с ключом управления ДОЛЖЕН возвращать список контуров процесса, `GET /api/v1/contours/{id}` — один контур или `404`. В режиме эмуляции в списке ДОЛЖЕН быть ровно один контур с `id` и `kind`, равными `emulation`. Поля контура:

- **Общее состояние:** `waiting_command`, `starting`, `running`, `stopping_no_entries`, `stopping_close_all`, `stopped` или `failed`.
- **О запуске:**
  - источник запуска: `cli`, `menu` или `api`;
  - время запуска;
  - эквивалентная команда;
  - отказы последней команды, если она отклонена;
  - `recovery`: `autostart`, если процесс поднят ядром без команды; `adopted`, если подхвачен живым; иначе `null`. При автоподъёме и подхвате источник и команда ДОЛЖНЫ браться из желаемого.
- **Текущий желаемый активный состав (`instruments`):** контракты коротким именем с днями до экспирации. После изменения состава командой поле ДОЛЖНО показывать новый состав, а не состав запуска.
- **Участники (`members`):** все инструменты желаемого состава. У каждого:
  - короткое имя и тип;
  - желаемое: `active` или `removed`;
  - режим снятия;
  - фактическое из `status.json`: `warming`, `trading`, `draining`, `closing` или `null`.
- **Желаемое (`desired`)** из `core.sqlite3`:
  - `running` — `true`, если контур должен работать;
  - `stop_mode`;
  - `generation`.
- **Фактическое (`actual`)** из `status.json` контура или `null`, если файла нет или он не читается:
  - состояние;
  - `applied_generation`;
  - `open_positions`;
  - `pending_entries`;
  - `last_tick_at`;
  - `core_link`: `ok` или `lost` — видит ли контур пульс ядра.
- **Процесс контура:** `pid`, пока процесс жив, и `exit_code` после завершения. У подхваченного процесса код выхода неизвестен: `exit_code = null`.

Общее состояние ДОЛЖНО определяться так:

1. **Процесс завершился:** `stopped` при коде 0, `failed` при другом коде или неизвестном коде подхваченного процесса. Если в этом запуске ядра процесс не создавался и не подхватывался — `waiting_command`.
2. **Процесс жив, желаемое «остановлен»:** `stopping_<режим>`.
3. **Процесс жив, контур ещё ни разу не подтвердил курсор ленты в этом запуске ядра:** `starting`.
4. **Иначе:** `running`.

После рестарта ядра без автоподъёма и подхвата контур ДОЛЖЕН показываться в `waiting_command` с прежним желаемым из `core.sqlite3`. Ответ НЕ ДОЛЖЕН содержать сделки, баланс и секреты.

#### Scenario: Торговля запущена параметрами
- **WHEN** робот запущен с `--mode emulation --instruments NG`, контур подтвердил курсор, а затем приходит `GET /api/v1/contours`
- **THEN** контур `emulation` в состоянии `running` с источником `cli`, контрактом NG, `desired.running = true`, `recovery = null` и `pid` процесса контура

#### Scenario: Последняя команда отклонена
- **WHEN** команда запуска получила `422`, а затем приходит `GET /api/v1/contours`
- **THEN** контур в состоянии `waiting_command` и содержит отказы последней команды

#### Scenario: Процесс контура упал
- **WHEN** процесс контура завершился с кодом 1, а затем приходит `GET /api/v1/contours`
- **THEN** контур в состоянии `failed`, `pid` — `null`, `exit_code` — 1

#### Scenario: Ядро перезапущено, желаемое — работает
- **GIVEN** до рестарта ядра контур работал с поколением 5, источник `api`
- **WHEN** ядро запущено снова с `--wait-command`, контур подтвердил курсор, а затем приходит `GET /api/v1/contours`
- **THEN** контур в состоянии `running`, `recovery = autostart`, источник `api`, `desired.generation = 5`

#### Scenario: Подхваченный контур завершился сам
- **GIVEN** контур подхвачен и завершился, не записав `exited_at`
- **WHEN** приходит `GET /api/v1/contours`
- **THEN** контур в состоянии `failed`, `exit_code = null`

#### Scenario: Фактическое отстаёт от желаемого
- **GIVEN** контур работает с применённым поколением 3
- **WHEN** приходит команда остановки, а `GET` выполняется до следующей границы тика
- **THEN** `desired.generation = 4`, `actual.applied_generation = 3`, общее состояние `stopping_no_entries`

#### Scenario: Состав после изменения
- **GIVEN** эмуляция запущена с NG и SBER, затем добавлен BR и убран SBER с открытой позицией
- **WHEN** приходит `GET /api/v1/contours/emulation`
- **THEN** `instruments` содержит NG-12.26 и BR-12.26, а `members` — NG `active/trading`, BR `active/warming` и SBER `removed/no_entries/draining`

### Requirement: Доступ к управлению
Нормативный уровень: MUST. Маршруты управления ДОЛЖНЫ требовать ключ `ROBOT_CONTROL_TOKEN` в заголовке `Authorization: Bearer` и НЕ ДОЛЖНЫ принимать его в адресе запроса или cookie. Ключ экспорта рыночных данных НЕ ДОЛЖЕН давать доступ к управлению, а ключ управления — к экспорту. Маршруты управления ДОЛЖНЫ отклонять запрос, если заголовок `Host` не равен `127.0.0.1`, `localhost` или `[::1]` с портом сервера. Сервер НЕ ДОЛЖЕН отдавать заголовки CORS. `ROBOT_CONTROL_TOKEN` ДОЛЖЕН быть в `secrets` журнала и НЕ ДОЛЖЕН печататься нигде.

#### Scenario: Ключ экспорта для управления
- **WHEN** команда запуска приходит с ключом `MARKET_DATA_EXPORT_TOKEN`
- **THEN** ответ `401`, торговля не начинается

#### Scenario: Чужой Host
- **WHEN** команда запуска приходит с верным ключом, но с заголовком `Host: evil.example:8101`
- **THEN** ответ `403`, торговля не начинается

#### Scenario: Ключ в адресе
- **WHEN** ключ передан параметром адреса, а заголовка `Authorization` нет
- **THEN** ответ `401`

### Requirement: Остановка контура командой
Нормативный уровень: MUST. `POST /api/v1/contours/{id}/stop` с телом `{"mode": "no_entries"}` или `{"mode": "close_all"}` ДОЛЖЕН записывать в `core.sqlite3` желаемое «остановлен» с режимом и новым поколением и отвечать `202` с номером поколения и состоянием контура. Повтор команды с тем же режимом ДОЛЖЕН отвечать `200` с прежним поколением и НЕ ДОЛЖЕН его менять. `close_all` поверх `no_entries` ДОЛЖЕН приниматься новым поколением. `no_entries` поверх `close_all` ДОЛЖЕН отклоняться `409`.

Остальные ответы:
- `409` — контур не работает: `waiting_command`, `stopped` или `failed`;
- `400` — неверный режим или лишние поля;
- `404` — неизвестный `id`;
- `401`/`403` — по правилам доступа к управлению.

Остановка НЕ ДОЛЖНА останавливать ядро, приём данных и локальный API. Ctrl+C ядра ДОЛЖЕН по-прежнему останавливать процесс контура после тика, не меняя желаемое состояние.

#### Scenario: Остановка без новых входов
- **GIVEN** контур работает, поколение 3
- **WHEN** приходит `POST /api/v1/contours/emulation/stop` с `{"mode": "no_entries"}`
- **THEN** ответ `202` с поколением 4, в `core.sqlite3` желаемое «остановлен, no_entries», ядро и приём данных продолжают работать

#### Scenario: Повтор остановки
- **GIVEN** уже принята остановка `no_entries` с поколением 4
- **WHEN** та же команда приходит снова
- **THEN** ответ `200` с поколением 4, в журнале команд исход `ignored`

#### Scenario: Закрыть всё поверх дожития
- **GIVEN** контур доживает сделки после `no_entries`, поколение 4
- **WHEN** приходит `stop` с `{"mode": "close_all"}`
- **THEN** ответ `202` с поколением 5, контур переходит к закрытию всех позиций

#### Scenario: Нечего останавливать
- **WHEN** контур в состоянии `stopped`, а приходит `stop`
- **THEN** ответ `409`, поколение не меняется

### Requirement: Желаемое состояние и журнал команд ядра
Нормативный уровень: MUST. Ядро ДОЛЖНО хранить желаемое состояние контуров в `data/core.sqlite3`: вид, должен ли работать, режим остановки, номер поколения, состав, источник и эквивалентную команду. Каждая команда управления ДОЛЖНА записываться в журнал `contour_commands`: время, действие, тело без секретов, поколение и исход (`accepted`, `rejected`, `conflict`, `ignored`).

Номер поколения ДОЛЖЕН расти монотонно на каждую команду, меняющую желаемое. Писать в `core.sqlite3` ДОЛЖНО только ядро, контур ДОЛЖЕН открывать её только на чтение. База ДОЛЖНА хранить версию схемы.

#### Scenario: Поколения растут
- **WHEN** подряд приняты запуск, остановка `no_entries` и остановка `close_all`
- **THEN** их поколения — 1, 2, 3, а журнал содержит три записи с исходом `accepted`

#### Scenario: Отклонённый запуск в журнале
- **WHEN** команда запуска получила `422`
- **THEN** в журнале запись с исходом `rejected` и причинами, поколение не меняется

### Requirement: Лог контура через API
Нормативный уровень: MUST. `GET /api/v1/contours/{id}/log?tail=N` ДОЛЖЕН отдавать последние `N` строк журнала процесса контура в `text/plain; charset=utf-8`. По умолчанию `N` равно 200, допустимо от 1 до 1000, иначе `400`. Неизвестный `id` даёт `404`, отсутствующий журнал — пустой ответ `200`.

Ответ ДОЛЖЕН содержать строки так, как они записаны в журнал, где секреты уже заменены на `[скрыто]`. Маршрут ДОЛЖЕН требовать ключ управления.

#### Scenario: Последние строки
- **GIVEN** в журнале контура 5000 строк
- **WHEN** приходит `GET /api/v1/contours/emulation/log?tail=3`
- **THEN** ответ — три последние строки журнала

#### Scenario: Слишком длинный хвост
- **WHEN** приходит `GET /api/v1/contours/emulation/log?tail=5000`
- **THEN** ответ `400`

### Requirement: Состав контура командами
Нормативный уровень: MUST. `POST /api/v1/contours/{id}/instruments` ДОЛЖЕН менять состав работающего контура без его перезапуска. Тело содержит ровно одно из полей:

- **`{"add": [токены]}`** — токены ДОЛЖНЫ разрешаться по тем же правилам, что у запуска (`POST /api/v1/contours`), в главном потоке ядра. Карточку контракта ДОЛЖНО получать ядро. Отказ строгий: если хотя бы один токен отклонён, состав НЕ ДОЛЖЕН меняться (`422`).
- **`{"remove": [токены], "mode": "no_entries" | "close_all"}`** — токен ДОЛЖЕН сопоставляться с участниками контура: короткое имя контракта, тикер акции или код семейства, если в составе ровно один контракт этого семейства. Без `mode` ДОЛЖЕН применяться `no_entries`. Токен не из состава ДОЛЖЕН отклоняться `422`, состав не меняется.

Принятая команда ДОЛЖНА записывать изменение в таблицу `contour_members` базы `core.sqlite3` одной транзакцией и поднимать поколение контура один раз. Ответ — `202` с поколением и состоянием контура.

Повторы и переходы:

- **Повтор без изменений.** Если команда ничего не меняет — добавляется уже активный инструмент, повторно убирается с тем же режимом — ответ ДОЛЖЕН быть `200` с прежним поколением.
- **`close_all` поверх `no_entries`** у убираемого инструмента ДОЛЖЕН приниматься.
- **`no_entries` поверх `close_all`** ДОЛЖЕН отклоняться `409 MODE_CONFLICT`.
- **`add` убираемого инструмента** ДОЛЖЕН возвращать его в активный состав.

Остальные ответы:

- `409 NOT_RUNNING` — процесс контура не работает;
- `409 STOPPING` — контур выполняет остановку;
- `400` — неверное тело;
- `404` — неизвестный `id`;
- `202` без поколения — разрешение не уложилось в 60 секунд, итог виден в `GET`.

Запуск контура (`POST /api/v1/contours`) ДОЛЖЕН заменять желаемый состав составом запуска. Каждая команда состава ДОЛЖНА записываться в журнал команд.

#### Scenario: Добавить газ на ходу
- **GIVEN** эмуляция торгует SBER, поколение 1

### Requirement: Пульс ядра
Нормативный уровень: MUST. Ядро ДОЛЖНО вести в `core.sqlite3` таблицу `heartbeat`. Состав строки:

- pid и версия ядра;
- время старта;
- время последнего удара;
- состояние: `running` или `stopped`.

Ядро ДОЛЖНО обновлять время удара раз в `[contours] heartbeat_secs` (по умолчанию 5 с) отдельным потоком. Первый удар ДОЛЖЕН быть записан до подхвата или запуска процесса контура. При штатной остановке ядро ДОЛЖНО записать состояние `stopped` до ожидания выхода контура. Писать таблицу ДОЛЖНО только ядро. Конфигурация с `heartbeat_timeout_secs`, не превышающим `heartbeat_secs`, ДОЛЖНА отклоняться при загрузке.

#### Scenario: Пульс идёт
- **WHEN** ядро работает 20 секунд с `heartbeat_secs = 5`
- **THEN** время удара в `heartbeat` обновлялось не реже раза в 5 секунд, состояние `running`, версия равна версии робота

#### Scenario: Штатная остановка ядра
- **WHEN** пользователь нажимает Ctrl+C в консоли ядра
- **THEN** строка `heartbeat` получает состояние `stopped` раньше, чем ядро начинает ждать выхода контура

### Requirement: Автоподъём и подхват контура при старте ядра
Нормативный уровень: MUST. При старте ядро ДОЛЖНО определить судьбу контура эмуляции по `robot.pid` папки контура, её `status.json` и желаемому из `core.sqlite3`.

**Живой контур.** Контур считается живым при трёх условиях:

1. pid из `robot.pid` папки контура жив;
2. `status.json` называет тот же pid;
3. `alive_at` в `status.json` свежее `heartbeat_timeout_secs`.

- **Та же версия.** Ядро ДОЛЖНО подхватить живой контур: НЕ ДОЛЖНО запускать второй процесс, ДОЛЖНО следить за найденным процессом по pid и передавать стоп и состав через `core.sqlite3`. Поле `recovery` — `adopted`.
- **Другая версия.** Ядро ДОЛЖНО ждать выхода контура до 30 секунд. Контур выходит сам, увидев пульс другой версии. Если процесс не вышел, ядро ДОЛЖНО завершить его принудительно. Затем ядро ДОЛЖНО действовать так, как если бы живого контура не было.
- **Контур уже выходит.** `status.json` того же pid содержит `exited_at`, а процесс ещё жив. Ядро ДОЛЖНО ждать его выхода так же, как контура другой версии.
- **Процесс не подтвердил себя.** pid из `robot.pid` жив, но два других условия не выполнены. Ядро НЕ ДОЛЖНО завершать такой процесс и НЕ ДОЛЖНО запускать контур. Консоль и журнал ядра ДОЛЖНЫ назвать pid, который нужно завершить.

**Живого контура нет.**

- **Явный запуск** (`--instruments` или выбор инструментов в меню) ДОЛЖЕН записывать новое желаемое с новым поколением, как прежде.
- **Старт в ожидании команды** (`--wait-command` или «ждать команду API» в меню) при `[contours] autostart = true` (по умолчанию) и заданном `ROBOT_CONTROL_TOKEN` ДОЛЖЕН поднимать контур без команды в двух случаях:
  - желаемое «работает»;
  - желаемое «остановлен», а последний `status.json` показывает `stopping_*`, а не `stopped`.

  Иначе ядро ДОЛЖНО ждать команду.
- **Автоподъём:**
  - НЕ ДОЛЖЕН создавать новое поколение и менять режим остановки;
  - состав процесса — активные участники и снятые участники, которых последний `status.json` ещё показывал в `members`;
  - карточки контрактов ядро ДОЛЖНО запросить заново, при сбое — взять сохранённые;
  - поле `recovery` — `autostart`.

**Явный запуск при подхваченном контуре** ДОЛЖЕН отклоняться сообщением в консоли без изменения желаемого: контур уже работает, состав меняется командой `/instruments`.

Подхват ДОЛЖЕН работать и при `autostart = false`.

Итог выхода подхваченного процесса:
- `status.json` с `exited_at` позже подхвата — `stopped` с кодом 0;
- иначе — `failed` с `exit_code = null`.

При остановке ядра подхваченный процесс ДОЛЖЕН останавливаться по пульсу `stopped`. Если процесс не вышел за 30 секунд, ядро ДОЛЖНО завершить его принудительно. Ни при каком исходе на одной папке контура НЕ ДОЛЖНО работать два процесса.

#### Scenario: Рестарт после Ctrl+C
- **GIVEN** эмуляция торговала NG с открытой позицией, ядро остановлено Ctrl+C, контур завершился с кодом 0
- **WHEN** ядро запущено снова с `--wait-command`
- **THEN** ядро без команды запускает контур с NG и прежним поколением, `recovery = autostart`, позиция NG восстановлена из журнала и сопровождается

#### Scenario: Ядро убито, контур жив
- **GIVEN** ядро завершено `kill -9`, контур той же версии жив и пишет `alive_at`
- **WHEN** ядро запущено снова
- **THEN** второй процесс контура не запускается, `GET /api/v1/contours` показывает прежний pid и `recovery = adopted`, команда `stop` доходит до контура через `core.sqlite3`

#### Scenario: Обновление версии
- **GIVEN** контур версии 7.1.0 жив после аварийной смерти ядра 7.1.0
- **WHEN** запускается ядро 7.2.0 в ожидании команды
- **THEN** контур 7.1.0 видит пульс другой версии и выходит после тика, ядро 7.2.0 поднимает контур своей версии с прежним составом и поколением

#### Scenario: Остановка не дожила
- **GIVEN** контур выполнял `stop no_entries` с открытой позицией SBER, ядро и контур остановлены Ctrl+C
- **WHEN** ядро запущено снова с `--wait-command`
- **THEN** контур поднимается, продолжает остановку `no_entries`, после закрытия SBER выходит со `stopped` и больше не поднимается

#### Scenario: Контур был остановлен командой
- **GIVEN** желаемое «остановлен», последний `status.json` — `stopped`
- **WHEN** ядро запущено с `--wait-command`
- **THEN** контур не запускается, ядро ждёт команду

#### Scenario: Явный запуск важнее базы
- **GIVEN** желаемое «работает» с NG, живого контура нет
- **WHEN** ядро запущено с `--mode emulation --instruments SBER`
- **THEN** записано новое поколение с SBER, контур запускается с SBER

#### Scenario: Явный запуск при живом контуре
- **GIVEN** живой контур той же версии торгует NG
- **WHEN** ядро запущено с `--mode emulation --instruments SBER`
- **THEN** консоль сообщает, что контур уже работает и подхвачен, желаемое не меняется, контур продолжает с NG

#### Scenario: Чужой процесс с тем же pid
- **GIVEN** `robot.pid` папки контура называет живой pid, а `alive_at` в `status.json` устарел
- **WHEN** ядро стартует
- **THEN** процесс не завершается, контур не запускается, консоль называет pid, который нужно завершить

#### Scenario: Нет ключа управления
- **GIVEN** желаемое «работает», `ROBOT_CONTROL_TOKEN` пуст
- **WHEN** ядро запущено с `--wait-command`
- **THEN** контур не поднимается, запуск завершается с кодом `2`, как ожидание команды без ключа

#### Scenario: Автоподъём отключён
- **GIVEN** `[contours] autostart = false`, желаемое «работает», живого контура нет
- **WHEN** ядро запущено с `--wait-command`
- **THEN** ядро ждёт команду, `GET /api/v1/contours` показывает `waiting_command` с прежним желаемым

### Requirement: Состояние ядра
Нормативный уровень: MUST. `GET /api/v1/core` с ключом управления ДОЛЖЕН возвращать:

- версию, pid и время старта ядра;
- время последнего удара пульса и `heartbeat_secs`;
- сводку рыночных данных:
  - `producer_id` и наибольший номер изменения ленты;
  - число живых пар и их число по состояниям готовности;
- запросы к брокеру за последнюю минуту по сервисам: число, потолок, разбивку по полосам и паузу после ограничения.

Ответ НЕ ДОЛЖЕН содержать секреты, адреса и токены. Маршрут ДОЛЖЕН подчиняться правилам доступа к управлению. Ключ экспорта рыночных данных ДОЛЖЕН получать `401`.

#### Scenario: Состояние ядра
- **WHEN** приходит `GET /api/v1/core` с ключом управления
- **THEN** ответ `200` с версией робота, временем удара не старше 5 секунд, числом пар по состояниям и запросами котировок за минуту

#### Scenario: Чужой ключ
- **WHEN** приходит `GET /api/v1/core` с ключом экспорта рыночных данных
- **THEN** ответ `401`
