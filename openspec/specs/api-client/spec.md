# API-клиент

## Purpose

Обеспечивает доступ к Invest API Т-Банка (Тинькофф): аутентифицированная фабрика клиента и утилита поиска инструментов, которая преобразует тикер во внутренний UID, проверяя доступность свечных данных для инструмента.

## Requirements

### Requirement: Аутентифицированная фабрика клиента
- Система ДОЛЖНА предоставлять функцию `get_client()`, возвращающую аутентифицированный `t_tech.invest.Client` с использованием `TINKOFF_TOKEN`.

#### Scenario: Успешное создание клиента
- **WHEN** вызывается `get_client()` при наличии валидного `TINKOFF_TOKEN`
- **THEN** возвращается экземпляр `t_tech.invest.Client`, готовый к работе с API

### Requirement: Поиск инструмента по тикеру
- Система ДОЛЖНА предоставлять функцию `find_working_instrument(client, ticker, instrument_type)`, возвращающую UID найденного инструмента.

#### Scenario: Найден валидный инструмент со свечными данными
- **WHEN** `find_working_instrument` вызывается с тикером, который существует и имеет хотя бы одну дневную свечу за последние 30 дней
- **THEN** возвращается UID инструмента

#### Scenario: Тикер существует, но нет свечных данных
- **WHEN** `find_working_instrument` вызывается с тикером, который соответствует инструменту, но тестовая выборка свечей возвращает пустой список
- **THEN** система продолжает поиск среди других подходящих инструментов; если данных нет ни у одного, выбрасывается `ValueError`

#### Scenario: Тикер не найден
- **WHEN** `find_working_instrument` вызывается с тикером, который не соответствует ни одному инструменту в ответе
- **THEN** выбрасывается `ValueError` с сообщением, содержащим "не найден или недоступен"

### Requirement: Поддержка типов инструментов
- Параметр `instrument_type` ДОЛЖЕН принимать следующие значения: `"share"`, `"future"`, `"etf"`, `"currency"`.

#### Scenario: Неподдерживаемый тип инструмента
- **WHEN** `find_working_instrument` вызывается с `instrument_type`, не входящим в `["share", "future", "etf", "currency"]`
- **THEN** выбрасывается `ValueError` с сообщением "Неподдерживаемый тип инструмента"

### Requirement: Вызов соответствующего эндпоинта API
- Для каждого `instrument_type` система ДОЛЖНА вызывать соответствующий эндпоинт API Т-Банка (например, `client.instruments.shares()` для акций, `client.instruments.futures()` для фьючерсов).

#### Scenario: Поиск среди фьючерсов
- **WHEN** `instrument_type` равен `"future"`
- **THEN** вызывается `client.instruments.futures()` для получения списка инструментов

#### Scenario: Поиск среди акций
- **WHEN** `instrument_type` равен `"share"`
- **THEN** вызывается `client.instruments.shares()` для получения списка инструментов

### Requirement: Валидация свечными данными
- При нахождении совпадения по тикеру система ДОЛЖНА валидировать инструмент попыткой получить свечи за 30 дней. Если свечи возвращены (непустой список), UID инструмента считается валидным.

#### Scenario: Валидация проходит успешно
- **WHEN** тестовая выборка из 30 дневных свечей возвращает непустой список
- **THEN** UID инструмента считается валидным и возвращается вызывающему коду

#### Scenario: Исключение при запросе тестовых свечей
- **WHEN** `find_working_instrument` пытается получить тестовые свечи и перехватывается исключение
- **THEN** система переходит к следующему подходящему инструменту без проброса исключения
