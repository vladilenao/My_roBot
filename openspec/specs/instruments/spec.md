# Интерактивный выбор инструментов

## Purpose

Обеспечивает интерактивный двухэтапный выбор торговых инструментов (акции индекса РТС или фьючерсы) перед запуском основного цикла бота. Формирует список инструментов в формате `(display_name, ticker, instrument_type, short_name)` с валидацией через API, дедупликацией и единым форматом отображения.

## Requirements

### Requirement: Двухэтапный выбор типа инструментов
- Система ДОЛЖНА предоставить меню выбора типа: `1` — Акции (индекс РТС), `2` — Фьючерсы.

#### Scenario: Пользователь выбирает акции
- **WHEN** пользователь вводит `1`
- **THEN** отображается пронумерованный список акций индекса РТС

#### Scenario: Пользователь выбирает фьючерсы
- **WHEN** пользователь вводит `2`
- **THEN** система загружает фьючерсы через API и отображает список

### Requirement: Список акций индекса РТС
- Система ДОЛЖНА включать 15 акций: SBER, GAZP, LKOH, GMKN, ROSN, NVTK, YDEX, TCSG, VTBR, MTSS, PHOR, ALRS, MOEX, PLZL, TATN.

#### Scenario: Отображение списка акций
- **WHEN** пользователь выбрал пункт `1`
- **THEN** отображается пронумерованный список из 15 тикеров

### Requirement: Динамическая загрузка фьючерсов
- Система ДОЛЖНА загружать фьючерсы через API `client.instruments.futures()`.

#### Scenario: Фьючерсы успешно загружены
- **WHEN** API вернул список фьючерсов
- **THEN** отображается пронумерованный список, сгруппированный по базовому активу

#### Scenario: Ошибка загрузки фьючерсов
- **WHEN** при загрузке произошла ошибка
- **THEN** выводится сообщение об ошибке, пользователь может продолжить выбор

### Requirement: Поддерживаемые базы фьючерсов
- Система ДОЛЖНА включать фьючерсы для баз: RTS, BR, Si, SBRF, ED, NG, GOLD, SILV.

#### Scenario: Все базы присутствуют
- **WHEN** API вернул фьючерсы всех баз
- **THEN** каждая база представлена в списке

### Requirement: Фильтрация микро/мини и expired
- Система ДОЛЖНА исключать контракты с "микро"/"мини" в названии, а также с экспирцией менее 0 дней или более 183 дней от текущей даты.

#### Scenario: Микро-контракт исключён
- **WHEN** фьючерс содержит "мини" в названии
- **THEN** он не включается в список

#### Scenario: Истёкший контракт исключён
- **WHEN** `expiration_date < now`
- **THEN** контракт не включается

#### Scenario: Далёкий контракт исключён
- **WHEN** `expiration_date > now + 183 дней`
- **THEN** контракт не включается

### Requirement: Единый формат отображения фьючерсов
- Фьючерсы ДОЛЖНЫ отображаться в формате `{base_name} ({label}) — {contract_name}` (например, `NG (Природный газ) — NG-9.26`).

#### Scenario: Формат отображения
- **WHEN** фьючерс с тикером `NGU6` и именем `NG-9.26 Природный газ`
- **THEN** отображается `NG (Природный газ) — NG-9.26`

### Requirement: Двухуровневая сортировка фьючерсов
- Фьючерсы ДОЛЖНЫ быть отсортированы сначала по типу базового актива (в порядке FUTURES_BASES), затем по дате экспирации от ближайшей к дальней внутри каждого типа.

#### Scenario: Сортировка по базе и экспирации
- **WHEN** загружены RTS-9.26, RTS-12.26, BR-9.26, BR-12.26
- **THEN** порядок: RTS-9.26, RTS-12.26, BR-9.26, BR-12.26

### Requirement: Множественный выбор
- Пользователь ДОЛЖЕН иметь возможность выбрать несколько инструментов, указав номера через запятую.

#### Scenario: Выбор по номерам
- **WHEN** пользователь вводит `1,3,5`
- **THEN** выбираются инструменты под номерами 1, 3 и 5

#### Scenario: Выбор по тикерам
- **WHEN** пользователь вводит `SBER,LKOH`
- **THEN** выбираются соответствующие инструменты

#### Scenario: Пустой ввод
- **WHEN** пользователь нажимает Enter без ввода
- **THEN** ничего не выбирается

#### Scenario: Номер вне диапазона
- **WHEN** номер превышает количество доступных инструментов
- **THEN** выводится предупреждение

### Requirement: Валидация выбранных инструментов
- Каждый выбранный инструмент ДОЛЖЕН быть проверен через `find_working_instrument`.

#### Scenario: Инструмент валиден
- **WHEN** `find_working_instrument` вернул UID
- **THEN** инструмент добавляется в список с подтверждением `✓`

#### Scenario: Инструмент невалиден
- **WHEN** `find_working_instrument` выбросил исключение
- **THEN** выводится ошибка `✗` и инструмент не добавляется

### Requirement: Дедупликация
- Один и тот же тикер НЕ ДОЛЖЕН появляться дважды в результирующем списке.

#### Scenario: Повторный тикер
- **WHEN** пользователь выбирает один и тот же тикер в разных раундах
- **THEN** он включается только один раз (первое вхождение)

### Requirement: Повторные раунды выбора
- После каждого раунда система ДОЛЖНА спрашивать "Добавить ещё инструменты?".

#### Scenario: Пользователь хочет добавить ещё
- **WHEN** пользователь отвечает "да"/"y"/"yes"
- **THEN** начинается новый раунд выбора

#### Scenario: Пользователь завершает выбор
- **WHEN** пользователь отвечает "нет"/"n"/"no"
- **THEN** процесс выбора завершается

### Requirement: Минимум один инструмент
- Если после завершения выбора список пуст, система ДОЛЖНА потребовать повторить выбор.

#### Scenario: Пустой список
- **WHEN** выбрано 0 инструментов
- **THEN** выводится сообщение и процесс выбора начинается заново

### Requirement: Возврат списка инструментов
- Функция ДОЛЖНА вернуть список кортежей `(display_name, ticker, instrument_type, short_name)`, где `short_name` — краткое имя инструмента для уведомлений: для фьючерсов — читаемое имя контракта (первое слово имени контракта из API, например `BR-10.26`), для акций — тикер.

#### Scenario: Формат возврата для акций
- **WHEN** выбран `SBER`
- **THEN** возвращается `[("SBER", "SBER", "share", "SBER")]`

#### Scenario: Формат возврата для фьючерсов
- **WHEN** выбран `NGU6` с именем `NG-9.26 Природный газ`
- **THEN** возвращается `[("NG (Природный газ) — NG-9.26", "NGU6", "future", "NG-9.26")]`

### Requirement: Использование контекстного менеджера API
- Функция ДОЛЖНА использовать `client_context()` как контекстный менеджер.

#### Scenario: Клиент закрывается
- **WHEN** выбор завершается
- **THEN** контекстный менеджер клиента корректно закрывается
