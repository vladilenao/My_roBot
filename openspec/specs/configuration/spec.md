# Конфигурация

## Purpose

Централизованное управление всей конфигурацией времени выполнения: секреты из `.env`, маппинг таймфреймов, параметры стратегии и дефолтные значения для fallback. Единый источник истины для констант, потребляемых всеми модулями.

## Requirements

### Requirement: Загрузка переменных окружения
- Система ДОЛЖНА загружать переменные окружения из файла `.env` с помощью `python-dotenv` при импорте модуля `src.config`.

#### Scenario: Переменные загружаются при импорте
- **WHEN** другой модуль импортирует `src.config`
- **THEN** файл `.env` считывается и константы токенов заполняются

#### Scenario: Отсутствие файла `.env`
- **WHEN** файл `.env` не существует
- **THEN** константы токенов устанавливаются в `None`, исключение не выбрасывается

### Requirement: Экспорт секретов
- Система ДОЛЖНА предоставлять: `TINKOFF_TOKEN`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHANNEL_ID`.

#### Scenario: Токены доступны
- **WHEN** модуль `src.config` импортирован
- **THEN** все три константы доступны для чтения

### Requirement: Поиск файла конфигурации
Система ДОЛЖНА загружать параметры из файла `robot.toml`. Для собранного исполняемого файла конфиг ищется в папке самого исполняемого файла (`dirname(sys.executable)`); в режиме разработки (`python run.py`) — в корне проекта. Если файл не найден — параметры ДОЛЖНЫ браться из таблицы дефолтов, вшитой в сборку. Токены ДОЛЖНЫ оставаться вне файла конфигурации и читаться из `.env`/переменных окружения.

#### Scenario: Сборка с внешним конфигом
- **WHEN** рядом с исполняемым файлом сборки лежит `robot.toml`
- **THEN** параметры загружаются из этого файла, токены остаются в `.env`/переменных окружения

#### Scenario: Сборка без внешнего конфига
- **WHEN** `robot.toml` рядом с исполняемым файлом не найден
- **THEN** используются дефолты, вшитые в сборку, и робот продолжает запуск

#### Scenario: Разработка
- **WHEN** робот запускается как `python run.py`
- **THEN** `robot.toml` ищется в корне проекта, а не в текущей рабочей папке

### Requirement: Выбор канала уведомлений
Система ДОЛЖНА предоставлять строковую константу `NOTIFIER`, выбирающую единственный активный канал уведомлений; допустимые значения — `"telegram"` и `"console"`. Значение ДОЛЖНО задаваться каналом уведомлений в `robot.toml`; при отсутствии файла конфигурации — вшитым в сборку дефолтом `"console"`. Константа ДОЛЖНА оставаться импортируемой через `from src.config import NOTIFIER`. Активным может быть только один канал — список каналов в конфигурации НЕ ДОЛЖЕН поддерживаться.

#### Scenario: Чтение константы
- **WHEN** модуль читает `NOTIFIER`
- **THEN** возвращается одно строковое значение допустимого канала, взятое из `robot.toml` или вшитого дефолта

#### Scenario: Импорт константы
- **WHEN** выполняется `from src.config import NOTIFIER`
- **THEN** значение успешно импортируется

### Requirement: Маппинг таймфреймов
- Система ДОЛЖНА предоставлять словарь `TIMEFRAMES`, отображающий строковые ключи (`1m`, `5m`, `15m`, `30m`, `1h`, `4h`, `1d`, `1w`, `1M`) в `CandleInterval`.

#### Scenario: Допустимый ключ
- **WHEN** потребитель ищет `"1h"` в `TIMEFRAMES`
- **THEN** возвращается `CandleInterval.CANDLE_INTERVAL_HOUR`

#### Scenario: Тридцатиминутный ключ
- **WHEN** потребитель ищет `"30m"` в `TIMEFRAMES`
- **THEN** возвращается `CandleInterval.CANDLE_INTERVAL_30_MIN`

#### Scenario: Четырёхчасовой ключ
- **WHEN** потребитель ищет `"4h"` в `TIMEFRAMES`
- **THEN** возвращается `CandleInterval.CANDLE_INTERVAL_4_HOUR`

#### Scenario: Недопустимый ключ
- **WHEN** потребитель ищет недопустимый ключ
- **THEN** выбрасывается `KeyError`

### Requirement: Секция конфигурации профиля triple_screen
Система ДОЛЖНА читать параметры профиля `triple_screen` из секции `[strategies.filter.triple_screen]` файла `robot.toml` (или вшитого дефолта `default.toml`): `multiplier` (целое, не менее 2, дефолт 5), `macd_fast`/`macd_slow`/`macd_signal` (целые, дефолты 12/26/9), `stoch_k`/`stoch_d`/`stoch_smooth_k` (целые, дефолты 14/3/3), `oversold`/`overbought` (целые, дефолты 20/80). Незнакомые ключи секции ДОЛЖНЫ отклоняться с `ConfigError` и указанием файла и ключа. При отсутствии секции применяются дефолты.

#### Scenario: Дефолтные параметры
- **WHEN** секция `[strategies.filter.triple_screen]` отсутствует в конфигурации
- **THEN** применяются дефолты: множитель 5, MACD (12, 26, 9), Stochastic (14, 3, 3), пороги 20/80

#### Scenario: Переопределение параметров
- **WHEN** секция задаёт `multiplier = 3` и `oversold = 25`
- **THEN** эти значения используются в расчётах фильтра

#### Scenario: Незнакомый ключ секции
- **WHEN** секция содержит незнакомый ключ (например, `window`)
- **THEN** загрузка конфигурации завершается `ConfigError` с указанием файла и ключа

### Requirement: Валидация иерархии таймфреймов triple_screen
При загрузке конфигурации система ДОЛЖНА вычислять иерархию (`TF_int`, `TF_htf`) для каждой привязки с профилем `triple_screen` на основе лестницы `TIMEFRAMES` и заданного множителя. Если для рабочего таймфрейма привязки не существует допустимых `TF_int` или `TF_htf` (шаг множителя выводит за пределы лестницы) — загрузка ДОЛЖНА завершаться `ConfigError` с указанием привязки.

#### Scenario: Допустимая иерархия
- **WHEN** рабочее ТФ привязки — `5m` и профиль `triple_screen`
- **THEN** валидация проходит: `TF_int = 30m`, `TF_htf = 4h`

#### Scenario: Иерархия за пределами лестницы
- **WHEN** рабочее ТФ привязки — `1M` и профиль `triple_screen`
- **THEN** загрузка конфигурации завершается `ConfigError` с указанием привязки

### Requirement: Параметры стратегии
Система ДОЛЖНА предоставлять: `SLEEP_SECONDS`, `TIMEFRAME` и два словаря привязок стратегий:
- `SHARE_STRATEGIES` — точный тикер нефьючерсного инструмента → список привязок;
- `FUTURE_STRATEGIES` — двухбуквенный код базового актива в верхнем регистре (`"NG"`) → список привязок, без привязки к конкретному контракту.

Каждая привязка ДОЛЖНА содержать имя стратегии, профиль фильтрации (по умолчанию `"basic_levels"`) и таймфрейм. Таймфрейм привязки ДОЛЖЕН вычисляться каскадом: ключ `tf` инлайн-записи → ключ `timeframe` таблицы тикера → глобальный `TIMEFRAME` из раздела робота. Привязки ДОЛЖНЫ задаваться в `robot.toml` таблицами тикеров (`[strategies.share.<ТИКЕР>]`, `[strategies.future.<БАЗА>]`) с массивом `strategies`; при отсутствии файла — вшитыми дефолтами. Дублирование имени стратегии внутри одного тикера ДОЛЖНО быть допустимым при различных профилях фильтрации или различных таймфреймах. Глобальные `SIGNAL_WINDOW` и `STRATEGY_ASSIGNMENTS` по-прежнему ДОЛЖНЫ отсутствовать.

#### Scenario: Чтение параметров
- **WHEN** модуль импортирует параметры
- **THEN** возвращаются значения из `robot.toml` (или вшитые дефолты); `SIGNAL_WINDOW` и `STRATEGY_ASSIGNMENTS` отсутствуют

#### Scenario: Привязка инструментов к стратегиям
- **WHEN** модуль читает `SHARE_STRATEGIES` и `FUTURE_STRATEGIES`
- **THEN** для каждого ключа доступен список привязок; каждая привязка содержит имя стратегии, профиль фильтрации и таймфрейм; ключи `SHARE_STRATEGIES` — точные тикеры, ключи `FUTURE_STRATEGIES` — базовые активы в верхнем регистре без суффикса контракта

#### Scenario: Дубли стратегии с разными профилями
- **WHEN** в таблице тикера одна и та же стратегия указана дважды с разными профилями фильтрации
- **THEN** обе привязки присутствуют в списке и различаются профилем

#### Scenario: Дубли стратегии с разными таймфреймами
- **WHEN** в таблице тикера одна и та же стратегия указана дважды с разными `tf`
- **THEN** обе привязки присутствуют в списке и различаются таймфреймом

#### Scenario: Каскад таймфрейма — tf инлайна
- **WHEN** инлайн-запись стратегии содержит `tf = "15m"`, а таблица тикера — `timeframe = "1h"`
- **THEN** привязка получает таймфрейм `"15m"`

#### Scenario: Каскад таймфрейма — timeframe тикера
- **WHEN** инлайн-запись не содержит `tf`, а таблица тикера содержит `timeframe = "15m"`
- **THEN** привязка получает таймфрейм `"15m"`

#### Scenario: Каскад таймфрейма — глобальный дефолт
- **WHEN** ни инлайн-запись, ни таблица тикера не задают таймфрейм
- **THEN** привязка получает глобальный `TIMEFRAME` из раздела робота

### Requirement: Гибридная запись привязки стратегий
В таблице тикера массив `strategies` ДОЛЖЕН принимать элементы двух форм: строку с именем стратегии (профиль фильтрации и таймфрейм — дефолтные по каскаду) либо инлайн-таблицу с обязательным ключом `name` и опциональными ключами `filter` и `tf`. Таблица тикера ДОЛЖНА принимать опциональный ключ `timeframe`. Значения `tf` и `timeframe` ДОЛЖНЫ быть ключами словаря `TIMEFRAMES`. Любые иные ключи инлайн-таблицы, таблицы тикера и секций стратегий ДОЛЖНЫ отклоняться с `ConfigError` с указанием файла и ключа. Прежний плоский синтаксис `<ТИКЕР> = [...]` ДОЛЖЕН отклоняться с `ConfigError`. Элемент массива иного типа либо инлайн-таблица без ключа `name` ДОЛЖНЫ отклоняться с `ConfigError`.

#### Scenario: Строка — привязка с дефолтным профилем
- **WHEN** элемент массива `strategies` — строка `"flat_triangle"`
- **THEN** привязка содержит имя `flat_triangle` и профиль `"basic_levels"`

#### Scenario: Инлайн-таблица с переопределением профиля
- **WHEN** элемент массива — `{ name = "macd_rsi_stoch", filter = "raw" }`
- **THEN** привязка содержит имя `macd_rsi_stoch` и профиль `raw`

#### Scenario: Инлайн-таблица с переопределением таймфрейма
- **WHEN** элемент массива — `{ name = "macd_rsi_stoch", filter = "raw", tf = "15m" }`
- **THEN** привязка содержит имя `macd_rsi_stoch`, профиль `raw` и таймфрейм `"15m"`

#### Scenario: Инлайн-таблица без имени стратегии
- **WHEN** элемент массива — `{ filter = "raw" }` без ключа `name`
- **THEN** загрузка конфигурации завершается `ConfigError`

#### Scenario: Неизвестный ключ отклоняется
- **WHEN** инлайн-таблица или таблица тикера содержит незнакомый ключ (например, `window`)
- **THEN** загрузка конфигурации завершается `ConfigError` с указанием файла и ключа

#### Scenario: Недопустимый таймфрейм отклоняется
- **WHEN** ключ `tf` или `timeframe` содержит значение вне словаря `TIMEFRAMES` (например, `"2h"`)
- **THEN** загрузка конфигурации завершается `ConfigError` с перечнем допустимых таймфреймов

#### Scenario: Прежний плоский синтаксис отклоняется
- **WHEN** секция `[strategies.share]` содержит запись вида `SBER = ["macd_rsi_stoch"]`
- **THEN** загрузка конфигурации завершается `ConfigError`

### Requirement: Fallback-константы для инструментов
Система ДОЛЖНА предоставлять `INSTRUMENT_TYPE="future"`, `TICKER="NGU6"` как значения по умолчанию для случаев, когда интерактивный выбор не используется. Пользователь ДОЛЖЕН иметь возможность переопределить их в разделе инструментов `robot.toml`; при отсутствии файла конфигурации используются вшитые дефолты.

#### Scenario: Fallback используется
- **WHEN** `run_bot()` вызывается без аргументов
- **THEN** используются `TICKER` и `INSTRUMENT_TYPE` из `robot.toml` или вшитые дефолты

### Requirement: Файл карточек позиций
Система ДОЛЖНА читать опциональный ключ `positions_file` из секции `[trading]` файла `robot.toml` (или вшитого дефолта `default.toml`) — имя CSV-файла карточек позиций. При отсутствии ключа имя ДОЛЖНО выводиться из `journal_file`: к имени файла ленты добавляется суффикс `_positions` перед расширением (например, `trade_journal.csv` → `trade_journal_positions.csv`). Значение ключа ДОЛЖНО быть непустой строкой; при недопустимом значении загрузка ДОЛЖНА завершаться `ConfigError` с указанием файла и ключа.

#### Scenario: Ключ задан явно
- **WHEN** в секции `[trading]` задан `positions_file = "positions.csv"`
- **THEN** карточки позиций ведутся в файле `positions.csv`

#### Scenario: Ключ не задан
- **WHEN** ключ `positions_file` в секции `[trading]` отсутствует, а `journal_file = "trade_journal.csv"`
- **THEN** карточки позиций ведутся в выводном файле `trade_journal_positions.csv`

#### Scenario: Недопустимое значение ключа
- **WHEN** ключ `positions_file` задан пустой строкой
- **THEN** загрузка конфигурации завершается `ConfigError` с указанием файла и ключа

### Requirement: Импортируемость констант
- Все константы ДОЛЖНЫ быть импортируемыми через `from src.config import ...`.

#### Scenario: Прямой импорт
- **WHEN** выполняется `from src.config import TICKER`
- **THEN** значение успешно импортируется
