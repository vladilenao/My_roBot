# Конфигурация

## Purpose

Централизованное управление всей конфигурацией времени выполнения: секреты из `.env`, маппинг таймфреймов, параметры стратегии и дефолтные значения для fallback. Держатель единого портфельного процентного лимита `portfolio_pct` и экономических порогов (комиссии, проскальзывание, payoff), которыми пользуются риск, допуск и отчёты. Единый источник истины для констант, потребляемых всеми модулями.

## Requirements

### Requirement: Загрузка переменных окружения
- Система ДОЛЖНА загружать переменные окружения из файла `.env` с помощью `python-dotenv` при импорте модуля `src.config`.

#### Scenario: Переменные загружаются при импорте
- **WHEN** другой модуль импортирует `src.config`
- **THEN** файл `.env` считывается и константы токенов заполняются

#### Scenario: Отсутствие файла `.env`
- **WHEN** файл `.env` не существует
- **THEN** константы токенов устанавливаются в `None`, исключение не выбрасывается

### Requirement: Экспорт секретов
- Система ДОЛЖНА предоставлять: `TINKOFF_TOKEN`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHANNEL_ID`.

#### Scenario: Токены доступны
- **WHEN** модуль `src.config` импортирован
- **THEN** все три константы доступны для чтения

### Requirement: Поиск файла конфигурации
Система ДОЛЖНА загружать параметры из файла `robot.toml`. Для собранного исполняемого файла конфиг ищется в папке самого исполняемого файла (`dirname(sys.executable)`); в режиме разработки (`python run.py`) — в корне проекта. Если файл не найден — параметры ДОЛЖНЫ браться из таблицы дефолтов, вшитой в сборку. Токены ДОЛЖНЫ оставаться вне файла конфигурации и читаться из `.env`/переменных окружения.

#### Scenario: Сборка с внешним конфигом
- **WHEN** рядом с исполняемым файлом сборки лежит `robot.toml`
- **THEN** параметры загружаются из этого файла, токены остаются в `.env`/переменных окружения

#### Scenario: Сборка без внешнего конфига
- **WHEN** `robot.toml` рядом с исполняемым файлом не найден
- **THEN** используются дефолты, вшитые в сборку, и робот продолжает запуск

#### Scenario: Разработка
- **WHEN** робот запускается как `python run.py`
- **THEN** `robot.toml` ищется в корне проекта, а не в текущей рабочей папке

### Requirement: Выбор канала уведомлений
Нормативный уровень: MUST.
Система ДОЛЖНА поддерживать список активных каналов уведомлений; допустимые значения — `"telegram"` и `"console"`. Список ДОЛЖЕН задаваться ключом `channels` в секции `[notifier]` файла `robot.toml`; при отсутствии файла конфигурации — вшитым в сборку дефолтом `["console"]`. Список ДОЛЖЕН быть непустым, а порядок каналов в нём ДОЛЖЕН определять порядок доставки. Список каналов ДОЛЖЕН быть доступен через `from src.config import NOTIFIER_CHANNELS`.

Активным может быть несколько каналов одновременно. Запрет на список каналов снимается: разделение по каналам используется для разведения объёма отладочного вывода и сообщений для пользователя.

Секреты (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHANNEL_ID`, `CLOUDFLARE_URL`) ДОЛЖНЫ читаться только из `.env` и переменных окружения и НЕ ДОЛЖНЫ указываться в `robot.toml`.

Для каждого активного канала система ДОЛЖНА поддерживать список типов событий в секции `[notifier.<канал>]`; при отсутствии такой секции применяется состав по умолчанию.

Ключ `channel` прежней редакции ДОЛЖЕН приниматься как сокращение для списка из одного канала, с предупреждением о переходе на `channels`. Одновременное указание `channel` и `channels` ДОЛЖНО отвергаться как противоречивое.

Требование непустого списка ДОЛЖНО применяться только к боевому режиму. В историческом режиме уведомления ДОЛЖНЫ быть отключены независимо от содержимого конфигурации, и список каналов из `robot.toml` ДОЛЖЕН игнорироваться.

#### Scenario: Чтение константы
- **WHEN** модуль читает `NOTIFIER_CHANNELS`
- **THEN** возвращается непустой список допустимых имён каналов из `robot.toml` или вшитого дефолта, в порядке перечисления

#### Scenario: Импорт константы
- **WHEN** выполняется `from src.config import NOTIFIER_CHANNELS`
- **THEN** список допустимых имён каналов успешно импортируется

#### Scenario: Несколько каналов одновременно
- **WHEN** в `robot.toml` указаны `console` и `telegram`
- **THEN** конфигурация принимается, сообщения доставляются в оба канала независимо

#### Scenario: Пустой список отвергается
- **WHEN** список каналов пуст
- **THEN** загрузка конфигурации завершается ошибкой

#### Scenario: Неизвестный канал отвергается
- **WHEN** в списке указано неизвестное имя канала
- **THEN** загрузка конфигурации завершается ошибкой с перечнем допустимых каналов

#### Scenario: Обратная совместимость с одиночным каналом
- **WHEN** в `robot.toml` указан `channel = "console"`
- **THEN** конфигурация принимается как список из одного канала, с предупреждением о переходе на `channels`

#### Scenario: Противоречивые ключи
- **WHEN** одновременно указаны `channel` и `channels`
- **THEN** загрузка конфигурации завершается ошибкой

#### Scenario: История работает без каналов
- **WHEN** выполняется исторический прогон, а в `robot.toml` указан `channels = ["telegram"]`
- **THEN** уведомления не доставляются ни в один канал, список каналов конфигурации игнорируется

### Requirement: Маппинг таймфреймов
- Система ДОЛЖНА предоставлять словарь `TIMEFRAMES`, отображающий строковые ключи (`1m`, `5m`, `15m`, `30m`, `1h`, `4h`, `1d`, `1w`, `1M`) в `CandleInterval`.

#### Scenario: Допустимый ключ
- **WHEN** потребитель ищет `"1h"` в `TIMEFRAMES`
- **THEN** возвращается `CandleInterval.CANDLE_INTERVAL_HOUR`

#### Scenario: Тридцатиминутный ключ
- **WHEN** потребитель ищет `"30m"` в `TIMEFRAMES`
- **THEN** возвращается `CandleInterval.CANDLE_INTERVAL_30_MIN`

#### Scenario: Четырёхчасовой ключ
- **WHEN** потребитель ищет `"4h"` в `TIMEFRAMES`
- **THEN** возвращается `CandleInterval.CANDLE_INTERVAL_4_HOUR`

#### Scenario: Недопустимый ключ
- **WHEN** потребитель ищет недопустимый ключ
- **THEN** выбрасывается `KeyError`

### Requirement: Секция конфигурации профиля triple_screen
Система ДОЛЖНА читать параметры профиля `triple_screen` из секции `[strategies.filter.triple_screen]` файла `robot.toml` (или вшитого дефолта `default.toml`): `multiplier` (целое, не менее 2, дефолт 5), `macd_fast`/`macd_slow`/`macd_signal` (целые, дефолты 12/26/9), `stoch_k`/`stoch_d`/`stoch_smooth_k` (целые, дефолты 14/3/3), `oversold`/`overbought` (целые, дефолты 20/80). Незнакомые ключи секции ДОЛЖНЫ отклоняться с `ConfigError` и указанием файла и ключа. При отсутствии секции применяются дефолты.

#### Scenario: Дефолтные параметры
- **WHEN** секция `[strategies.filter.triple_screen]` отсутствует в конфигурации
- **THEN** применяются дефолты: множитель 5, MACD (12, 26, 9), Stochastic (14, 3, 3), пороги 20/80

#### Scenario: Переопределение параметров
- **WHEN** секция задаёт `multiplier = 3` и `oversold = 25`
- **THEN** эти значения используются в расчётах фильтра

#### Scenario: Незнакомый ключ секции
- **WHEN** секция содержит незнакомый ключ (например, `window`)
- **THEN** загрузка конфигурации завершается `ConfigError` с указанием файла и ключа

### Requirement: Валидация иерархии таймфреймов triple_screen
При загрузке конфигурации система ДОЛЖНА вычислять иерархию (`TF_int`, `TF_htf`) для каждой привязки с профилем `triple_screen` на основе лестницы `TIMEFRAMES` и заданного множителя. Если для рабочего таймфрейма привязки не существует допустимых `TF_int` или `TF_htf` (шаг множителя выводит за пределы лестницы) — загрузка ДОЛЖНА завершаться `ConfigError` с указанием привязки.

#### Scenario: Допустимая иерархия
- **WHEN** рабочее ТФ привязки — `5m` и профиль `triple_screen`
- **THEN** валидация проходит: `TF_int = 30m`, `TF_htf = 4h`

#### Scenario: Иерархия за пределами лестницы
- **WHEN** рабочее ТФ привязки — `1M` и профиль `triple_screen`
- **THEN** загрузка конфигурации завершается `ConfigError` с указанием привязки

### Requirement: Параметры стратегии
Система ДОЛЖНА предоставлять: `SLEEP_SECONDS`, `TIMEFRAME` и два словаря привязок стратегий:
- `SHARE_STRATEGIES` — точный тикер нефьючерсного инструмента → список привязок;
- `FUTURE_STRATEGIES` — двухбуквенный код базового актива в верхнем регистре (`"NG"`) → список привязок, без привязки к конкретному контракту.

Каждая привязка ДОЛЖНА содержать имя стратегии, профиль фильтрации (по умолчанию `"basic_levels"`) и таймфрейм. Таймфрейм привязки ДОЛЖЕН вычисляться каскадом: ключ `tf` инлайн-записи → ключ `timeframe` таблицы тикера → глобальный `TIMEFRAME` из раздела робота. Привязки ДОЛЖНЫ задаваться в `robot.toml` таблицами тикеров (`[strategies.share.<ТИКЕР>]`, `[strategies.future.<БАЗА>]`) с массивом `strategies`; при отсутствии файла — вшитыми дефолтами. Дублирование имени стратегии внутри одного тикера ДОЛЖНО быть допустимым при различных профилях фильтрации или различных таймфреймах. Глобальные `SIGNAL_WINDOW` и `STRATEGY_ASSIGNMENTS` по-прежнему ДОЛЖНЫ отсутствовать.

#### Scenario: Чтение параметров
- **WHEN** модуль импортирует параметры
- **THEN** возвращаются значения из `robot.toml` (или вшитые дефолты); `SIGNAL_WINDOW` и `STRATEGY_ASSIGNMENTS` отсутствуют

#### Scenario: Привязка инструментов к стратегиям
- **WHEN** модуль читает `SHARE_STRATEGIES` и `FUTURE_STRATEGIES`
- **THEN** для каждого ключа доступен список привязок; каждая привязка содержит имя стратегии, профиль фильтрации и таймфрейм; ключи `SHARE_STRATEGIES` — точные тикеры, ключи `FUTURE_STRATEGIES` — базовые активы в верхнем регистре без суффикса контракта

#### Scenario: Дубли стратегии с разными профилями
- **WHEN** в таблице тикера одна и та же стратегия указана дважды с разными профилями фильтрации
- **THEN** обе привязки присутствуют в списке и различаются профилем

#### Scenario: Дубли стратегии с разными таймфреймами
- **WHEN** в таблице тикера одна и та же стратегия указана дважды с разными `tf`
- **THEN** обе привязки присутствуют в списке и различаются таймфреймом

#### Scenario: Каскад таймфрейма — tf инлайна
- **WHEN** инлайн-запись стратегии содержит `tf = "15m"`, а таблица тикера — `timeframe = "1h"`
- **THEN** привязка получает таймфрейм `"15m"`

#### Scenario: Каскад таймфрейма — timeframe тикера
- **WHEN** инлайн-запись не содержит `tf`, а таблица тикера содержит `timeframe = "15m"`
- **THEN** привязка получает таймфрейм `"15m"`

#### Scenario: Каскад таймфрейма — глобальный дефолт
- **WHEN** ни инлайн-запись, ни таблица тикера не задают таймфрейм
- **THEN** привязка получает глобальный `TIMEFRAME` из раздела робота

### Requirement: Fallback-константы для инструментов
Система ДОЛЖНА предоставлять `INSTRUMENT_TYPE="future"`, `TICKER="NGU6"` как значения по умолчанию для случаев, когда интерактивный выбор не используется. Пользователь ДОЛЖЕН иметь возможность переопределить их в разделе инструментов `robot.toml`; при отсутствии файла конфигурации используются вшитые дефолты.

#### Scenario: Fallback используется
- **WHEN** `run_bot()` вызывается без аргументов
- **THEN** используются `TICKER` и `INSTRUMENT_TYPE` из `robot.toml` или вшитые дефолты

### Requirement: Файл карточек позиций
Система ДОЛЖНА читать опциональный ключ `positions_file` из секции `[trading]` файла `robot.toml` (или вшитого дефолта `default.toml`) — имя CSV-файла карточек позиций. При отсутствии ключа имя ДОЛЖНО выводиться из `journal_file`: к имени файла ленты добавляется суффикс `_positions` перед расширением (например, `trade_journal.csv` → `trade_journal_positions.csv`). Значение ключа ДОЛЖНО быть непустой строкой; при недопустимом значении загрузка ДОЛЖНА завершаться `ConfigError` с указанием файла и ключа.

#### Scenario: Ключ задан явно
- **WHEN** в секции `[trading]` задан `positions_file = "positions.csv"`
- **THEN** карточки позиций ведутся в файле `positions.csv`

#### Scenario: Ключ не задан
- **WHEN** ключ `positions_file` в секции `[trading]` отсутствует, а `journal_file = "trade_journal.csv"`
- **THEN** карточки позиций ведутся в выводном файле `trade_journal_positions.csv`

#### Scenario: Недопустимое значение ключа
- **WHEN** ключ `positions_file` задан пустой строкой
- **THEN** загрузка конфигурации завершается `ConfigError` с указанием файла и ключа

### Requirement: Импортируемость констант
- Все константы ДОЛЖНЫ быть импортируемыми через `from src.config import ...`.

#### Scenario: Прямой импорт
- **WHEN** выполняется `from src.config import TICKER`
- **THEN** значение успешно импортируется

### Requirement: Явная конфигурация управления сделками
Нормативный уровень: MUST.
Каждая привязка ДОЛЖНА иметь уникальный глобально непустой id, name, management, опциональные filter (basic_levels), tf с существующим каскадом и целый priority с дефолтом 0. Разные management при одинаковой стратегии/фильтре/ТФ разрешены. Профили ДОЛЖНЫ ссылаться на один из четырёх типов и содержать валидируемые параметры стопов, целей, доборов и выхода. Они принимают min_stop_atr, min_stop_ticks, stop_beyond_bar, max_stop_atr: конечные неотрицательные числа, min_stop_ticks — целое, заданный max_stop_atr не меньше min_stop_atr. Отсутствующие поддерживаемые параметры получают действующие дефолты; неизвестные ключи, несовместимые ориентиры, повторные ID, нечисловые/нефинитные уровни, отрицательные отступы, неверные доли/периоды ДОЛЖНЫ отклоняться до цикла с файлом и ключом.

`min_trade_risk_pct` ДОЛЖЕН оставаться явным дополнительным фильтром с дефолтом 0, конечным неотрицательным значением не больше `portfolio_pct`, а не отдельного лимита сделки. Его база — B, не уже вычисленный процентный бюджет. Неизвестный ключ геометрии отклоняется, отсутствие известных ключей включает дефолты. Commission/slippage — конечные неотрицательные оценки согласно требованию единиц расходов; поставляемые дефолты положительны, ноль допускается как явный выбор пользователя.

#### Scenario: Два профиля одной стратегии
- **WHEN** две привязки macd_rsi_stoch на 15m имеют разные id и management
- **THEN** планы независимы, но пользуются одним общим бюджетом риска счёта

#### Scenario: Несовместимая формация
- **WHEN** pattern_targets назначен стратегии без необходимых ориентиров
- **THEN** ConfigError до отправки заявки

#### Scenario: Профиль без геометрии стопа
- **WHEN** поддерживаемые геометрические ключи не заданы
- **THEN** профиль получает действующие дефолты

#### Scenario: Потолок волатильности ниже пола
- **WHEN** min_stop_atr=3 и max_stop_atr=2
- **THEN** ConfigError с файлом и ключом max_stop_atr

#### Scenario: Дробное число шагов
- **WHEN** min_stop_ticks=2.5
- **THEN** ConfigError с файлом и ключом min_stop_ticks

#### Scenario: Минимальный риск больше лимита риска
- **WHEN** min_trade_risk_pct=5 при portfolio_pct=2
- **THEN** ConfigError с ключом min_trade_risk_pct; устаревший trade_pct не определяет границу

#### Scenario: Нулевые расходы по умолчанию запрещены
- **WHEN** commission/slippage отсутствуют
- **THEN** применяются положительные поставляемые оценки

#### Scenario: Отрицательные расходы
- **WHEN** commission=−1
- **THEN** ConfigError с файлом и ключом commission

### Requirement: Настройки хранения риска и аудита
Нормативный уровень: MUST.
Система ДОЛЖНА читать `[trading] database_file` с дефолтом trades.sqlite3, пути journal_file/positions_file для автоэкспорта, единый процент `portfolio_pct`, предел количества и оценки расходов. Пути базы/CSV различаются. Опциональный logging.audit_file с дефолтом trade_audit.log хранит расчёты независимо от уровня пользовательского лога; ротация настраивается. Некорректные значения не заменяются молча дефолтами. Миграция старых отдельных процентных ключей выполняется согласно требованию «Единый процентный лимит и миграция старых настроек».

Изменение счётового portfolio_pct меняет бюджет будущих допусков и текущую агрегатную диагностику, не переписывая сохранённые планы/профили и не инициируя закрытие старых сделок. Удалённая из новых входов связка продолжает сопровождение сохранённой позиции. Эффективная счётовая политика сохраняется в аудите каждого допуска и проверяется заново для следующих кандидатов.

#### Scenario: Неверная доля
- **WHEN** доли целей превышают 1 либо процент риска NaN
- **THEN** запуск отклоняется с проблемным ключом

#### Scenario: Изменение конфигурации открытой сделки
- **WHEN** связка убрана из новых входов, но её сделка есть в SQLite
- **THEN** сохраняются её профиль/ТФ/позиция, а общий бюджет следующих допусков учитывает этот остаток

### Requirement: Единый процентный лимит и миграция старых настроек
Нормативный уровень: MUST.
Единственный процентный лимит риска счёта ДОЛЖЕН задаваться `trading.risk_limits.portfolio_pct`, конечным числом в [0,100], boolean не допускается. Поставляемый дефолт 2.0 означает 2% для всего портфеля. Явный другой процент также является общим, не индивидуальным; ноль выключает новые увеличения, но не сопровождение существующих позиций.

Наличие любого старого `trade_pct`, `instrument_pct`, `groups` в пользовательской конфигурации ДОЛЖНО давать ConfigError до цикла, в том числе при нуле/пустой таблице. Сообщение указывает файл, устаревшие ключи, их прежний смысл и переход: удалить отдельные лимиты и явно проверить/задать общий portfolio_pct. При наличии старого блока с portfolio_pct=6 он НЕ ДОЛЖЕН автоматически запускаться или преобразовываться в 2 либо в значение trade_pct. Поставляемый новый default.toml не содержит устаревшие ключи. Никакого источника принадлежности группам для этой версии не требуется.

#### Scenario: Единый дефолт
- **WHEN** portfolio_pct и старые ключи отсутствуют
- **THEN** эффективный общий лимит 2%, а не 2% каждой сделке

#### Scenario: Старый блок требует миграции
- **WHEN** в файле trade_pct=2, instrument_pct=4, portfolio_pct=6 и groups заданы
- **THEN** ConfigError перечисляет старые ключи и объясняет переход к единому проценту без запуска цикла

#### Scenario: Пустой старый ключ тоже не разрешён
- **WHEN** groups={} либо trade_pct=0 присутствует
- **THEN** сообщение требует удаления устаревшего ключа, он не игнорируется

#### Scenario: Явное переопределение общего процента
- **WHEN** пользователь явно задал portfolio_pct=1 без устаревших ключей
- **THEN** общий бюджет равен 1% B для всех позиций/резервов вместе

#### Scenario: Нулевой бюджет сохраняет выходы
- **WHEN** portfolio_pct=0
- **THEN** новые увеличения запрещены, подтверждённые исполнения и защитные/профильные выходы продолжаются

#### Scenario: Нефинитный или логический процент
- **WHEN** portfolio_pct равен NaN, infinity либо boolean
- **THEN** ConfigError с файлом и ключом portfolio_pct

### Requirement: Единицы расходов и экономические пороги
Нормативный уровень: MUST.
В `[trading.risk_limits]` `commission` ДОЛЖНА означать рубли на контракт за одну сторону, `slippage` — рубли на контракт за полный круг; поставляемые значения 1.5 и 1.0. Запас круга распределяется поровну на вход и выход. Ноль допустим как явный выбор; отрицательные, boolean, нечисловые и нефинитные значения отклоняются с файлом и ключом до торгового цикла.

Новые ключи ДОЛЖНЫ иметь следующие типы, единицы и дефолты:

| Ключ | Значение по умолчанию | Допустимые значения | Выключение |
| --- | --- | --- | --- |
| `min_risk_cost_ratio` | 2.0 | конечное число ≥0, отношение R/C | 0 |
| `min_net_payoff` | 1.5 | конечное число ≥0, чистая прибыль/R полного плана | 0 |
| `max_slippage_r` | 0.25 | конечное число ≥0, верхнее S/R | 0 |

Выключение `max_slippage_r=0` ДОЛЖНО означать отсутствие этого ограничения, а не запрет любого проскальзывания. Экономические параметры НЕ ДОЛЖНЫ меняться у открытых сделок после изменения файла. `min_trade_risk_pct` сохраняет отдельное значение 0 и базу капитала. Неизвестные ключи, в том числе выдуманные `liquidity_floor` и пользовательская версия алгоритма, отклоняются.

#### Scenario: Круговая оценка для десяти контрактов
- **WHEN** комиссия 1.5, запас 1 и Q=10
- **THEN** комиссия круга 30 ₽, запас круга 10 ₽, C=40 ₽; комиссия не трактуется как 1.5% оборота

#### Scenario: Новые дефолты
- **WHEN** новые пороги не заданы
- **THEN** для нового плана используются 2, 1.5 и 0.25, и эти значения попадают в снимок

#### Scenario: Явное выключение
- **WHEN** все три порога заданы нулём
- **THEN** новые пороговые проверки выключены, существующие бюджетные ограничения и `cost-exceeds-reward` сохраняются

#### Scenario: Нефинитный порог
- **WHEN** `min_net_payoff` равен NaN либо boolean
- **THEN** загрузка завершается ConfigError с указанием файла и ключа

### Requirement: Порог BE и формы лестницы трендового профиля
Нормативный уровень: MUST.
`levels_rr` и `pattern_targets` ДОЛЖНЫ принимать `min_be_r`: конечное неотрицательное число, дефолт 1.5, 0 снимает только условие продвижения, не условия TP1/улучшения/рынка. `atr_trend` ДОЛЖЕН принимать `target_R` и `shares`: непустые списки одинаковой длины, положительные строго возрастающие R, доли в (0,1), сумма строго меньше 1. Дефолт `[1,2]` и `[0.25,0.25]`. Нефинитные значения, boolean и нечисловые элементы отклоняются.

Для совместимости явная старая пара `tp1_R`/`tp1_share` ДОЛЖНА однозначно преобразовываться в одноэлементную лестницу для новых планов. Полная пара требуется; одновременное явное указание новой формы и хотя бы одного старого ключа запрещено. Выбор формы выполняется по ключам пользователя до наложения поставляемых дефолтов, поэтому неявные дефолтные списки не конфликтуют со старой явной парой. Legacy-снимки открытых сделок не нормализуются в новую версию. Версия алгоритма назначается системой, не конфигурацией.

#### Scenario: Указана старая пара
- **WHEN** пользователь явно задал `tp1_R=1.2`, `tp1_share=0.5` и не задавал новые списки
- **THEN** новый план имеет лестницу `[1.2]`, `[0.5]`, несмотря на поставляемые дефолтные списки

#### Scenario: Смешаны две формы
- **WHEN** явно заданы `target_R` и `tp1_R`
- **THEN** ConfigError на конфликт формы до цикла

#### Scenario: Не оставлен трейлинговый остаток
- **WHEN** сумма shares у atr_trend равна 1
- **THEN** ConfigError с ключом shares; тот же запрет не переносится на levels_rr полного выхода

#### Scenario: Порог BE выключен
- **WHEN** `min_be_r=0`
- **THEN** после TP1 перенос по-прежнему требует допустимого рынка, известной экономики и улучшения защиты

#### Scenario: Системная версия не подменяется
- **WHEN** в TOML задан `algorithm_version`
- **THEN** неизвестный пользовательский ключ отклоняется

### Requirement: Горизонт блокировки экспирации фьючерсов
Нормативный уровень: MUST.
Система ДОЛЖНА читать неотрицательное целое значение `contract_expiry_block_days` из секции `[trading]` файла `robot.toml` (или вшитого дефолта `default.toml`) — количество календарных суток до момента экспирации фьючерсного контракта, в течение которых вход в сделку запрещён, а существующие сделки закрываются. При отсутствии ключа применяется дефолт `2`. Недопустимое значение (отрицательное, нецелое, нечисловое) ДОЛЖНО завершать загрузку конфигурации `ConfigError` с указанием файла и ключа.

#### Scenario: Дефолтное значение
- **WHEN** ключ `contract_expiry_block_days` отсутствует в конфигурации
- **THEN** применяется порог `2` календарных суток

#### Scenario: Переопределение порога
- **WHEN** в секции `[trading]` задан `contract_expiry_block_days = 3`
- **THEN** порог блокировки и закрытия составляет `3` календарных суток

#### Scenario: Недопустимое значение
- **WHEN** ключ `contract_expiry_block_days` задан отрицательным числом или нецелым значением
- **THEN** загрузка конфигурации завершается `ConfigError` с указанием файла и ключа

### Requirement: Настройка разрешённых направлений по типам инструментов
Нормативный уровень: MUST.
Пользователь ДОЛЖЕН иметь возможность задать в конфигурации `[trading.directions]` список направлений входа отдельно по типам инструментов (фьючерсы, акции и т.д.). Ключ таблицы — тип инструмента (`share`, `future` и любые иные), значение — список строк `long` и/или `short` (нижний регистр). Таблица опциональна: отсутствие секции либо конкретного типа означает обе разрешённые стороны для этого типа.

Значения ДОЛЖНЫ валидироваться до торгового цикла строго: любой элемент вне набора `long`/`short`, верхний регистр, несписок либо пустой список дают `ConfigError` с указанием файла и ключа. Неизвестные ключи типов в таблице не отклоняются, так как набор типов инструментов открыт. Действующие разрешённые направления системой нормализуются при загрузке и применяются в допуске входа (см. требование допуска в спеке `trade-management`).

#### Scenario: Настройка только лонга для акций
- **WHEN** задано `[trading.directions] share = ["long"]`
- **THEN** для акций разрешён только длинный вход, значения читаются без ошибки

#### Scenario: Обе стороны для фьючерсов
- **WHEN** задано `[trading.directions] future = ["long", "short"]`
- **THEN** для фьючерсов разрешены обе стороны

#### Scenario: Отсутствие настройки направления
- **WHEN** секция `[trading.directions]` отсутствует
- **THEN** запуск не отклоняется, обе стороны разрешены для любых типов

#### Scenario: Недопустимое значение направления
- **WHEN** `[trading.directions] share = ["LONG"]` либо `["upper"]`
- **THEN** `ConfigError` с файлом и ключом, запуск останавливается до цикла

#### Scenario: Несписковое значение таблицы
- **WHEN** значение `share = "long"` (строка, а не список)
- **THEN** `ConfigError` с файлом и ключом

#### Scenario: Пустой список
- **WHEN** `share = []`
- **THEN** `ConfigError` с файлом и ключом; пустой список не является явным запретом всех направлений
