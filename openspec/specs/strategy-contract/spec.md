# Контракт стратегий

## Purpose

Определяет архитектуру подключаемых торговых стратегий: изолированные пакеты, единый контракт, реестр для динамической диспетчеризации, привязку инструментов к стратегиям и строгое разделение решения и форматирования.

## Requirements

### Requirement: Реестр стратегий
Система ДОЛЖНА предоставлять реестр в `src/strategies/__init__.py`: функцию `register`, декорирующую класс стратегии, функции доступа `get_strategy(name)`, возвращающую экземпляр по имени, `all_strategies()`, возвращающую все зарегистрированные стратегии, и `strategy_names()`, возвращающую отсортированный список имён. Поиск неизвестного имени ДОЛЖЕН завершаться ошибкой с перечнем доступных имён. Повторная регистрация уже существующего `NAME` ДОЛЖНА завершаться ошибкой. Регистрация выполняется при импорте пакета стратегии, при этом пакеты стратегий ДОЛЖНЫ загружаться лениво и идемпотентно при первом обращении к функциям доступа реестра: сам импорт `src.strategies` и его подмодуля `names` НЕ ДОЛЖЕН подтягивать пакеты стратегий или библиотеку индикаторов. Движок, тесты и скрипт скачивания НЕ ДОЛЖНЫ ссылаться на конкретные стратегии иначе как через реестр.

#### Scenario: Получение известной стратегии
- **WHEN** вызывается `get_strategy("macd_rsi_stoch")`
- **THEN** возвращается экземпляр зарегистрированного класса стратегии

#### Scenario: Неизвестная стратегия
- **WHEN** вызывается `get_strategy("nonexistent")`
- **THEN** выбрасывается ошибка, содержащая список зарегистрированных имён

#### Scenario: Ленивая регистрация при первом обращении
- **WHEN** после чистого импорта `src.strategies` вызвана любая функция доступа к реестру
- **THEN** пакеты стратегий загружаются один раз, все зарегистрированные стратегии доступны для запроса

#### Scenario: Повторные обращения не перезагружают пакеты
- **WHEN** функции доступа к реестру вызываются повторно после первой загрузки
- **THEN** повторного импорта пакетов стратегий не происходит, содержимое реестра не меняется

### Requirement: Статический перечень имён стратегий
Система ДОЛЖНА предоставлять отдельный лёгкий модуль `src/strategies/names.py` с типом `StrategyName` (Literal-перечень всех зарегистрированных имён стратегий) — единственным ручным перечнем для статических подсказок IDE. Модуль НЕ ДОЛЖЕН импортировать реестр, пакеты стратегий или тяжёлые зависимости (только `typing`). Конфигурация ДОЛЖНА аннотировать `STRATEGY_ASSIGNMENTS` как `dict[str, list[StrategyName]]`. Перечень ДОЛЖЕН оставаться консистентным с реестром: множество Literal-имён совпадает с множеством зарегистрированных `NAME`.

#### Scenario: Перечень совпадает с реестром
- **WHEN** сравниваются `get_args(StrategyName)` и имена из реестра стратегий
- **THEN** множества равны: в Literal нет устаревших имён, ни одна зарегистрированная стратегия не пропущена

#### Scenario: Лёгкость импорта
- **WHEN** конфигурация импортирует только `src.strategies.names`
- **THEN** пакеты стратегий и библиотека индикаторов не загружаются

### Requirement: Контракт Strategy
Каждая стратегия ДОЛЖНА реализовать контракт: атрибуты `NAME` (уникальный идентификатор — ключ реестра и имя файла эталона) и `STRATEGY_WINDOW` (собственное окно агрегации); методы `compute(df)` — боевой расчёт сигнальных колонок поверх DataFrame свечей, `decide(ta)` — решение на последней свече, возвращающее `Decision` (`SignalType`, цена), `expected_events(ta)` — события BUY/SELL за всю историю для эталона snapshot-тестов, `required_history()` — минимальная глубина истории (окно + прогрев индикаторов стратегии). Потребители ДОЛЖНЫ работать со стратегиями только через этот контракт.

#### Scenario: Единый интерфейс для любой стратегии
- **WHEN** движок обрабатывает очередную стратегию из реестра
- **THEN** используются только методы контракта без проверок типа конкретной стратегии

#### Scenario: Окно принадлежит стратегии
- **WHEN** у стратегии задан `STRATEGY_WINDOW`
- **THEN** агрегация и `required_history()` рассчитываются от этого значения

### Requirement: Тип решения без форматирования
Метод `decide()` ДОЛЖЕН возвращать решение в виде `SignalType` (`BUY`, `SELL`, `HOLD`) и цены; формирование человекочитаемых текстов в стратегии ЗАПРЕЩЕНО. Сила сигнала и иные дополнительные параметры решения в этой смене не вводятся.

#### Scenario: Решение как перечисление
- **WHEN** все сигнальные суммы стратегии положительны на последней свече
- **THEN** `decide()` возвращает `SignalType.BUY` и текущую цену без какого-либо текста сообщения

### Requirement: Формирование уведомлений отдельным модулем
Тексты уведомлений ДОЛЖЕН формировать общий модуль `src/notifier/formatter.py`: перевод `Decision` в сообщение (эмодзи, округление цены до 3 знаков, префикс `[instrument_label]`). Наблюдаемое поведение сообщений сохраняется прежним: ПОКУПКА — «🚀 ПОКУПАТЬ! Цена: X», ПРОДАЖА — «📉 ПРОДАВАТЬ! Цена: X», УДЕРЖАНИЕ — «😴 Отдыхаем, сигналов нет.».

#### Scenario: Сообщение о покупке
- **WHEN** formatter получает `SignalType.BUY`, цену 3.14159 и label «NG»
- **THEN** сообщение содержит `[NG] 🚀 ПОКУПАТЬ! Цена: 3.142`

### Requirement: Привязка инструментов к стратегиям
Конфигурация ДОЛЖНА предоставлять словарь `STRATEGY_ASSIGNMENTS`, отображающий тикер в список имён активных стратегий («многие ко многим»). Включение или выключение стратегии на инструменте ДОЛЖНО выполняться правкой конфигурации без изменения кода стратегий. Инструмент, отсутствующий в словаре или с пустым списком, ДОЛЖЕН пропускаться с записью в лог. Значения привязок ДОЛЖНЫ валидироваться против реестра до старта основного цикла; неизвестное имя ДОЛЖНО вызывать ошибку с перечнем неизвестных и доступных имён.

#### Scenario: Несколько стратегий на тикере
- **WHEN** тикеру назначены две стратегии и данные загружены
- **THEN** обе стратегии обрабатывают одни и те же свечи независимо друг от друга

#### Scenario: Тикер без привязки пропускается
- **WHEN** тикер не входит в `STRATEGY_ASSIGNMENTS`
- **THEN** запрос данных для него не выполняется, в лог пишется запись о пропуске

#### Scenario: Невалидная привязка останавливает запуск
- **WHEN** в `STRATEGY_ASSIGNMENTS` указано имя незарегистрированной стратегии
- **THEN** выбрасывается ошибка с перечнем неизвестных и доступных имён; основной цикл не запускается

### Requirement: Изолированный пакет стратегии
Каждая стратегия ДОЛЖНА располагаться в собственном пакете `src/strategies/<имя>/` с файлом класса и подпакетами собственных индикаторов и сигналов. Стратегия ДОЛЖНА владеть своей математикой, правилом событий и окном; глобальные параметры расчёта стратегий в `src.config` НЕ ДОЛЖНЫ существовать (глобальный `SIGNAL_WINDOW` удаляется). Добавление новой стратегии НЕ ДОЛЖНО требовать правки движка, unit-тестов других стратегий, snapshot-раннера или скрипта скачивания.

#### Scenario: Добавление новой стратегии
- **WHEN** создан новый пакет стратегии с регистрацией в реестре и запись добавлена в `STRATEGY_ASSIGNMENTS`
- **THEN** стратегия работает в боте, покрывается единым snapshot-раннером и доступна скрипту скачивания без правки их кода

### Requirement: Изоляция отказов стратегий
Отказ одной стратегии (исключение в `compute`, `decide`) НЕ ДОЛЖЕН прерывать обработку остальных стратегий того же инструмента и следующих инструментов цикла; факт отказа ДОЛЖЕН фиксироваться в логе.

#### Scenario: Падение первой стратегии не мешает второй
- **WHEN** `compute()` первой стратегии тикера выбросил исключение
- **THEN** вторая стратегия того же тикера выполняется штатно, ошибка первой зафиксирована
