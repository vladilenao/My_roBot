# Контракт стратегий

## Purpose

Определяет архитектуру подключаемых торговых стратегий: изолированные пакеты, единый контракт, реестр для динамической диспетчеризации, привязку инструментов к стратегиям и строгое разделение решения и форматирования.

## Requirements

### Requirement: Реестр стратегий
Система ДОЛЖНА предоставлять реестр в `src/strategies/registry.py`: функцию `register`, декорирующую класс стратегии, функции доступа `get_strategy(name)`, возвращающую экземпляр по имени, `all_strategies()`, возвращающую все зарегистрированные стратегии, и `strategy_names()`, возвращающую отсортированный список имён. Поиск неизвестного имени ДОЛЖЕН завершаться ошибкой с перечнем доступных имён. Повторная регистрация уже существующего `NAME` ДОЛЖНА завершаться ошибкой. Регистрация выполняется при импорте пакета стратегии, при этом пакеты стратегий ДОЛЖНЫ загружаться лениво и идемпотентно при первом обращении к функциям доступа реестра: сам импорт `src.strategies` и его подмодуля `names` НЕ ДОЛЖЕН подтягивать пакеты стратегий или библиотеку индикаторов. Движок, тесты и скрипт скачивания НЕ ДОЛЖНЫ ссылаться на конкретные стратегии иначе как через реестр. Реестр ДОЛЖЕН использовать `pkgutil.iter_modules` для обнаружения пакетов стратегий вместо хардкода импортов.

#### Scenario: Получение известной стратегии
- **WHEN** вызывается `get_strategy("macd_rsi_stoch")`
- **THEN** возвращается экземпляр зарегистрированного класса стратегии

#### Scenario: Неизвестная стратегия
- **WHEN** вызывается `get_strategy("nonexistent")`
- **THEN** выбрасывается ошибка, содержащая список зарегистрированных имён

#### Scenario: Ленивая регистрация при первом обращении
- **WHEN** после чистого импорта `src.strategies` вызвана любая функция доступа к реестру
- **THEN** пакеты стратегий загружаются один раз, все зарегистрированные стратегии доступны для запроса

#### Scenario: Повторные обращения не перезагружают пакеты
- **WHEN** функции доступа к реестру вызываются повторно после первой загрузки
- **THEN** повторного импорта пакетов стратегий не происходит, содержимое реестра не меняется

#### Scenario: Auto-discovery новой стратегии
- **WHEN** создан новый пакет стратегии с файлом `__init__.py` и декоратором `@register`
- **THEN** стратегия автоматически обнаруживается реестром при первом обращении к функциям доступа

#### Scenario: Type hints доступны в IDE
- **WHEN** разработчик вызывает `get_strategy("macd_rsi_stoch")`
- **THEN** IDE показывает возвращаемый тип `Strategy`

### Requirement: Статический перечень имён стратегий
Система ДОЛЖНА предоставлять отдельный лёгкий модуль `src/strategies/names.py` с типом `StrategyName` (Literal-перечень всех зарегистрированных имён стратегий) — единственным ручным перечнем для статических подсказок IDE. Модуль НЕ ДОЛЖЕН импортировать реестр, пакеты стратегий или тяжёлые зависимости (только `typing`). Конфигурация ДОЛЖНА аннотировать оба словаря привязок (`SHARE_STRATEGIES` и `FUTURE_STRATEGIES`) как `dict[str, list[StrategyName]]`. Перечень ДОЛЖЕН оставаться консистентным с реестром: множество Literal-имён совпадает с множеством зарегистрированных `NAME`.

#### Scenario: Перечень совпадает с реестром
- **WHEN** сравниваются `get_args(StrategyName)` и имена из реестра стратегий
- **THEN** множества равны: в Literal нет устаревших имён, ни одна зарегистрированная стратегия не пропущена

#### Scenario: Лёгкость импорта
- **WHEN** конфигурация импортирует только `src.strategies.names`
- **THEN** пакеты стратегий и библиотека индикаторов не загружаются

### Requirement: Контракт Strategy
Каждая стратегия ДОЛЖНА реализовать контракт: атрибуты `NAME` (уникальный идентификатор — ключ реестра и имя файла эталона) и `STRATEGY_WINDOW` (собственное окно агрегации); методы `compute(df)` — боевой расчёт сигнальных колонок поверх DataFrame свечей, `decide(ta)` — решение на последней свече, возвращающее `Decision` (`SignalType`, цена), `expected_events(ta)` — события BUY/SELL за всю историю для эталона snapshot-тестов, `required_history()` — минимальная глубина истории (окно + прогрев индикаторов стратегии). Стратегия ДОЛЖНА принимать `StrategyConfig` через конструктор. Конфиг ОБЯЗАТЕЛЕН — fallback на дефолты запрещён. Потребители ДОЛЖНЫ работать со стратегиями только через этот контракт.

#### Scenario: Единый интерфейс для любой стратегии
- **WHEN** движок обрабатывает очередную стратегию из реестра
- **THEN** используются только методы контракта без проверок типа конкретной стратегии

#### Scenario: Окно принадлежит стратегии
- **WHEN** у стратегии задан `STRATEGY_WINDOW` через `StrategyConfig`
- **THEN** агрегация и `required_history()` рассчитываются от этого значения

#### Scenario: Стратегия принимает StrategyConfig
- **WHEN** создаётся `MacdRsiStochStrategy(config)`
- **THEN** параметры индикаторов и окно берутся из `config`, а не из хардкода

#### Scenario: Config обязателен
- **WHEN** создаётся `MacdRsiStochStrategy()` без параметров
- **THEN** выбрасывается `TypeError` (отсутствует обязательный аргумент config)

### Requirement: Тип решения без форматирования
Метод `decide()` ДОЛЖЕН возвращать решение в виде `SignalType` (`BUY`, `SELL`, `HOLD`) и цены; формирование человекочитаемых текстов в стратегии ЗАПРЕЩЕНО. Сила сигнала и иные дополнительные параметры решения в этой смене не вводятся.

#### Scenario: Решение как перечисление
- **WHEN** все сигнальные суммы стратегии положительны на последней свече
- **THEN** `decide()` возвращает `SignalType.BUY` и текущую цену без какого-либо текста сообщения

### Requirement: Формирование уведомлений отдельным классом
Тексты уведомлений ДОЛЖЕН формировать общий класс `DecisionFormatter` в пакете `src/notifier`, внедряемый в нотификаторы через конструктор: перевод `Decision` в сообщение (эмодзи, округление цены до 3 знаков, префикс `[instrument_label]`). Наблюдаемое поведение сообщений сохраняется прежним: ПОКУПКА — «🚀 ПОКУПАТЬ! Цена: X», ПРОДАЖА — «📉 ПРОДАВАТЬ! Цена: X», УДЕРЖАНИЕ — «😴 Отдыхаем, сигналов нет.».

#### Scenario: Сообщение о покупке
- **WHEN** форматтер получает `SignalType.BUY`, цену 3.14159 и label «NG»
- **THEN** сообщение содержит `[NG] 🚀 ПОКУПАТЬ! Цена: 3.142`

### Requirement: Привязка инструментов к стратегиям
Конфигурация ДОЛЖНА предоставлять два словаря привязок «многие ко многим»:
- `SHARE_STRATEGIES` — точный тикер нефьючерсного инструмента → список имён активных стратегий;
- `FUTURE_STRATEGIES` — двухбуквенный код базового актива в верхнем регистре → список имён активных стратегий; запись действует на любой контракт этого актива.

Включение или выключение стратегии на инструменте ДОЛЖНО выполняться правкой конфигурации без изменения кода стратегий. Значения привязок обоих словарей ДОЛЖНЫ валидироваться против реестра до старта основного цикла; неизвестное имя ДОЛЖНО вызывать ошибку с перечнем неизвестных и доступных имён.

#### Scenario: Несколько стратегий на тикере
- **WHEN** инструменту назначены две стратегии и данные загружены
- **THEN** обе стратегии обрабатывают одни и те же свечи независимо друг от друга

#### Scenario: Фьючерсная привязка действует на любой контракт актива
- **WHEN** в `FUTURE_STRATEGIES` есть запись `"NG"`
- **THEN** любой контракт базового актива NG получает назначенные ей стратегии без дополнительной настройки

#### Scenario: Тикер без привязки пропускается
- **WHEN** тикер отсутствует в словаре своего класса инструментов или его список пуст
- **THEN** запрос данных для него не выполняется, в лог пишется запись о пропуске

#### Scenario: Невалидная привязка останавливает запуск
- **WHEN** в любом из словарей `SHARE_STRATEGIES` или `FUTURE_STRATEGIES` указано имя незарегистрированной стратегии
- **THEN** выбрасывается ошибка с перечнем неизвестных и доступных имён; основной цикл не запускается

### Requirement: Изолированный пакет стратегии
Каждая стратегия ДОЛЖНА располагаться в собственном файле `src/strategies/<имя>.py`. Стратегия ДОЛЖНА владеть своей математикой, правилом событий и окном; глобальные параметры расчёта стратегий в `src.config` НЕ ДОЛЖНЫ существовать. Добавление новой стратегии НЕ ДОЛЖНО требовать правки движка, unit-тестов других стратегий, snapshot-раннера или скрипта скачивания.

#### Scenario: Добавление новой стратегии
- **WHEN** создан новый файл стратегии с регистрацией в реестре и привязка добавлена в соответствующий словарь (`SHARE_STRATEGIES` или `FUTURE_STRATEGIES`)
- **THEN** стратегия работает в боте, покрывается единым snapshot-раннером и доступна скрипту скачивания без правки их кода

### Requirement: Изоляция отказов стратегий
Отказ одной стратегии (исключение в `compute`, `decide`) НЕ ДОЛЖЕН прерывать обработку остальных стратегий того же инструмента и следующих инструментов цикла; факт отказа ДОЛЖЕН фиксироваться в логе.

#### Scenario: Падение первой стратегии не мешает второй
- **WHEN** `compute()` первой стратегии тикера выбросил исключение
- **THEN** вторая стратегия того же тикера выполняется штатно, ошибка первой зафиксирована
