# Исполнение решений

## Purpose

Выходной слой принятых решений робота: абстрактный порт исполнения и конкретная реализация, которая сейчас уведомляет трейдера. Является точкой расширения для будущего торгового исполнения ордеров без изменения контура сигналов.

## Requirements

### Requirement: Абстрактный порт исполнения
Система ДОЛЖНА предоставлять абстрактный интерфейс `ExecutionPort` с методом `execute(decision, instrument)`, принимающим решение (`Decision`) и инструмент, и возвращающим результат исполнения. Интерфейс НЕ ДОЛЖЕН зависеть от конкретного нотификатора или биржевого клиента.

#### Scenario: Вызов порта
- **WHEN** оркестратор принимает решение по инструменту
- **THEN** вызывается `execute(decision, instrument)` единственного активного порта исполнения

### Requirement: Уведомляющая реализация порта
Система ДОЛЖНА предоставлять `NotifyOnlyExecutionPort` — реализацию `ExecutionPort`, которая доставляет решение через нотификатор (уведомляет трейдера), не выполняя реальных сделок.

#### Scenario: Уведомление вместо ордера
- **WHEN** решение передано в `NotifyOnlyExecutionPort`
- **THEN** решение доставляется нотификатором как уведомление, торговые ордера не создаются

### Requirement: Единственная активная реализация
В каждый момент активна ровно одна реализация порта исполнения, выбранная в точке сборки (`run.py`). Таким образом поддерживается единый конечный путь для принятых решений.

#### Scenario: Подмена реализаций
- **WHEN** активна реализация X и заменяется на реализацию Y
- **THEN** оркестратор и стратегии не изменяются; вызывается `execute` реализации Y

### Requirement: Будущее торговое исполнение
Порт исполнения ДОЛЖЕН быть спроектирован так, чтобы его можно было расширить до выполнения реальных ордеров (открытие/закрытие позиций, управление стопами) без изменения контура сигналов и оркестратора.

#### Scenario: Расширение до торговли
- **WHEN** появляется торговая реализация порта
- **THEN** она реализует тот же интерфейс `ExecutionPort`; сигнальный слой и `TradingBot` не модифицируются
