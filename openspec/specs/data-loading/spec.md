# Загрузка данных

## Purpose

Загружает исторические OHLCV-данные свечей из Invest API Т-Банка для заданного инструмента, таймфрейма и диапазона дат. Возвращает pandas DataFrame, готовый к техническому анализу. Все вызовы API защищены механизмом повторных вызовов.

## Requirements

### Requirement: Основная функция загрузки свечей
- Система ДОЛЖНА предоставлять функцию `load_candles(ticker, instrument_type, timeframe, start_date=None, end_date=None, token=None)`.

#### Scenario: Успешная загрузка свечей
- **WHEN** свечи доступны для запрошенного диапазона
- **THEN** возвращается кортеж `(DataFrame, instrument_id)`, где DataFrame содержит столбцы `['datetime', 'open', 'high', 'low', 'close', 'volume']`

### Requirement: Использование контекстного менеджера клиента
- Клиент ДОЛЖЕН получаться из источника данных прогона, а не создаваться напрямую, и ДОЛЖЕН использоваться в форме контекстного менеджера (`with ... as client:`) для доступа к API.
- Форма вызовов методов клиента ДОЛЖНА быть одинаковой для боевого и исторического источников: загрузчик ДОЛЖЕН работать через тот же контракт запроса и разбора ответа.

#### Scenario: Клиент автоматически закрывается
- **WHEN** загрузка завершается (успешно или с ошибкой)
- **THEN** контекстный менеджер клиента корректно закрывается

#### Scenario: Источник подменён без изменения кода загрузчика
- **WHEN** прогон выполняется на историческом источнике
- **THEN** загрузчик запрашивает свечи через тот же контракт вызовов, что и в боевом режиме, без отдельной ветки кода

### Requirement: Валидация таймфрейма
- Если `timeframe` не ключ словаря `TIMEFRAMES`, система ДОЛЖНА выбросить `ValueError`.

#### Scenario: Недопустимый таймфрейм
- **WHEN** `timeframe="2h"`
- **THEN** выбрасывается `ValueError` "Неподдерживаемый таймфрейм"

### Requirement: Диапазон дат по умолчанию
- Если `start_date=None`, используется `now() - timedelta(days=30)`.
- Если `end_date=None`, используется `now()`.
- Значение `now()` ДОЛЖНО браться из источника рыночного времени прогона, а не из системных часов: в историческом прогоне границы по умолчанию отсчитываются от текущего рыночного момента.

#### Scenario: Дефолтный диапазон
- **WHEN** обе даты `None`
- **THEN** загружаются свечи за последние 30 дней

#### Scenario: Дефолтный диапазон в историческом прогоне
- **WHEN** обе даты `None`, а рыночное время прогона равно `2023-05-10 12:00`
- **THEN** запрашиваются свечи с `2023-04-10 12:00` по `2023-05-10 12:00`, а не до текущей системной даты

### Requirement: Парсинг строковых дат
- Строковые даты разбираются в формате `%Y-%m-%d`.

#### Scenario: Строковые даты
- **WHEN** `start_date="2025-01-01"`
- **THEN** строка преобразуется в `datetime`

### Requirement: Валидация порядка дат
- Если `start_date >= end_date`, выбрасывается `ValueError`.
- Перед сравнением обе границы ДОЛЖНЫ быть приведены к единому tz-aware UTC состоянию, чтобы сравнение naive- и aware-значений никогда не происходило.

#### Scenario: Неверный порядок
- **WHEN** `start_date >= end_date`
- **THEN** `ValueError` "Дата начала должна быть меньше даты окончания"

#### Scenario: Границы без часового пояса не падают
- **WHEN** `start_date` задан как naive (без пояса), а `end_date` получен как aware (с поясом) или наоборот
- **THEN** обе границы приводятся к единому aware-UTC перед сравнением, сравнение выполняется без ошибки типа

### Requirement: Определение UID инструмента
- Система ДОЛЖНА вызывать `find_working_instrument(client, ticker, instrument_type)` для получения UID инструмента. Разрешённый UID ДОЛЖЕН кэшироваться на время сессии и переиспользоваться при повторных загрузках свечей того же инструмента: повторный вызов `find_working_instrument` НЕ ДОЛЖЕН выполняться, если UID уже известен.

#### Scenario: UID определён
- **WHEN** тикер доступен и UID инструмента ещё не известен
- **THEN** вызывается `find_working_instrument`, возвращённый UID используется для запроса свечей и кэшируется

#### Scenario: Переиспользование UID
- **WHEN** UID инструмента уже разрешён и выполняется повторная загрузка свечей того же инструмента
- **THEN** используется кэшированный UID, повторное разрешение через `find_working_instrument` не выполняется

### Requirement: Конвертация формата цен
- Цены конвертируются из формата `units + nano/1e9` в `float`.

#### Scenario: Конвертация units+nano
- **WHEN** `open.units=3` и `open.nano=500000000`
- **THEN** `open = 3.5`

### Requirement: Удаление часового пояса
- Столбец `datetime` ДОЛЖЕН иметь `tz_localize(None)`.
- Внутри робота время naive по соглашению, а на исходящей границе к API `start_date`/`end_date` ДОЛЖНЫ приводиться к aware-UTC (клиент Tinkoff не принимает naive `from_`/`to`).

#### Scenario: Время без таймзоны
- **WHEN** DataFrame возвращён
- **THEN** `datetime` не содержит информации о часовом поясе

#### Scenario: Aware-границы к API
- **WHEN** `start_date` или `end_date` передаются в API
- **THEN** они приведены к tz-aware UTC, согласованно с требованием клиента Tinkoff, и не смешиваются с naive внутри робота

### Requirement: Обработка пустого результата
- Если свечей нет, возвращается `(пустой DataFrame, instrument_id)`.

#### Scenario: Нет свечей
- **WHEN** API вернул 0 свечей
- **THEN** возвращается `(pd.DataFrame(), instrument_id)`

### Requirement: Повторные вызовы API
- Все вызовы API (`get_all_candles`, `find_working_instrument`) обёрнуты в `api_call_with_retry`.
- Потоковая загрузка свечей (`get_all_candles`) представляет собой серверный поток: ошибка лимита может возникать как при открытии потока, так и во время итерации по его элементам. В обоих случаях загрузчик ДОЛЖЕН повторить загрузку повторным открытием потока с экспоненциальной задержкой, ограниченной `ratelimit_reset`, пока не исчерпан максимум повторов; после исчерпания повторов последняя ошибка ДОЛЖНА пробрасываться вызывающему коду.

#### Scenario: Rate-limit при загрузке свечей
- **WHEN** API возвращает RESOURCE_EXHAUSTED при запросе свечей
- **THEN** вызов повторяется с экспоненциальной задержкой

#### Scenario: Rate-limit во время итерации потока
- **WHEN** `RESOURCE_EXHAUSTED` возникает при итерации по уже открытому потоку свечей
- **THEN** загрузчик повторно открывает поток и продолжает загрузку с экспоненциальной задержкой, ограниченной `ratelimit_reset`

#### Scenario: Лимит повторов исчерпан
- **WHEN** количество повторов достигло максимума и ошибка повторяется
- **THEN** последнее исключение пробрасывается вызывающему коду

### Requirement: Инкрементальная дозагрузка
Нормативный уровень: MUST. Загрузчик ДОЛЖЕН поддерживать дозагрузку новых баров поверх уже имеющейся истории с явным началом и концом диапазона, без полного пересбора накопленной истории. Обычное окно ДОЛЖНО оставаться ограниченным заданным backfill_window. В текущем режиме нижняя граница такого окна ДОЛЖНА при необходимости расширяться до времени открытия последнего ожидаемого закрытого бара данного ТФ, чтобы скользящее окно не исключало этот бар в середине периода. Проверка финализации последнего ожидаемого бара закрытой сессии ДОЛЖНА использовать отдельный диапазон ровно этой свечи, а не весь промежуток до текущего времени. Более старые пробелы ДОЛЖНЫ оставаться задачами отдельного recovery-бюджета. В историческом режиме существующие границы инкрементального запроса ДОЛЖНЫ сохраняться.

#### Scenario: Дозагрузка с момента последнего бара
- **WHEN** последний известный бар начинается в T и T находится в пределах допустимого свежего окна
- **THEN** запрашивается диапазон от T до заданного конца без полного повторного чтения истории

#### Scenario: Ограничение окна дозагрузки
- **WHEN** последняя известная свеча значительно старше свежего окна
- **THEN** обычный запрос не перечитывает накопленную историю; более старые пробелы восстанавливаются отдельно

#### Scenario: Часовая свеча в середине часа
- **WHEN** сейчас 09:30 UTC, свежее окно равно одному часу и ожидается закрытая свеча 08:00–09:00
- **THEN** нижняя граница включает 08:00 и не отсекает свечу границей 08:30

#### Scenario: Последний бар закрытой сессии
- **WHEN** рынок закрыт, а финальная свеча предыдущей сессии ещё не завершена источником
- **THEN** её финализация проверяется диапазоном от открытия до закрытия этой свечи, без запроса всех ночных интервалов

### Requirement: Согласованность готовности свечи с таймфреймом
Данные, предоставляемые для анализа, ДОЛЖНЫ быть согласованы с границей закрытия свечи таймфрейма: незакрытая текущая свеча не включается в данные, передаваемые в контур принятия решений.

#### Scenario: Исключение незакрытой свечи
- **WHEN** текущая свеча таймфрейма ещё не закрыта
- **THEN** её бар не включается в набор данных для анализа до наступления границы закрытия

### Requirement: Полное чтение диапазона свечей
Нормативный уровень: MUST.
Если источник данных отдаёт свечи постранично, система ДОЛЖНА дочитывать запрошенный диапазон полностью: читать первую страницу и затем последовательно запрашивать следующие по курсору источника, пока курсор не станет пустым. Потолок свечей в одной странице ДОЛЖЕН задаваться явно, а не полагаться на поведение источника по умолчанию.

Граничная свеча ДОЛЖНА не дублироваться между страницами: следующий запрос берёт свечи строго после времени, указанного в курсоре предыдущей страницы. Чтение ДОЛЖНО быть устойчивым к повторному курсору: если источник вернул тот же курсор, что и на предыдущей странице, чтение ДОЛЖНО прерваться с явной ошибкой, а не выполняться бесконечно.

Частично прочитанный диапазон ДОЛЖЕН быть обнаружимым: если источник сообщает общее число свечей в диапазоне, а система получила меньше, это ДОЛЖНО фиксироваться в лог как предупреждение с указанием ожидаемого и фактического количества. Молчаливая обрезка данных, при которой усечённый диапазон выглядит как полный, НЕ ДОЛЖНА оставаться без следов.

#### Scenario: Диапазон дочитывается постранично
- **WHEN** источник отдаёт первую страницу из 20 000 свечей и курсор на время последней свечи, а следующая страница содержит оставшиеся свечи и пустой курсор
- **THEN** система возвращает все свечи диапазона, то есть 20 000 плюс оставшиеся

#### Scenario: Граничная свеча не дублируется
- **WHEN** следующая страница запрашивается с курсором предыдущей страницы
- **THEN** свеча, чьё время совпадает с курсором, в результат не попадает повторно

#### Scenario: Повторяющийся курсор не зацикливает чтение
- **WHEN** источник возвращает курсор, равный курсору предыдущей страницы
- **THEN** чтение прерывается с явной ошибкой о повторяющемся курсоре

#### Scenario: Обрезка не остаётся незамеченной
- **WHEN** источник сообщает `total` больше числа полученных свечей
- **THEN** в лог пишется предупреждение с ожидаемым и фактическим количеством свечей

#### Scenario: Однополосный источник читается как раньше
- **WHEN** источник возвращает все свечи диапазона одной страницей и пустой курсор
- **THEN** чтение завершается после первой страницы без дополнительных запросов
