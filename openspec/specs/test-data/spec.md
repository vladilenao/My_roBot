# Тестовые данные: скачивание и хранение

## Purpose

Обеспечивает воспроизводимый набор компактных исторических данных (свечей) для snapshot-тестов торговых сигналов: однократное скачивание из Invest API с жёстким лимитом глубины истории, статическое хранение фикстур в репозитории и зафиксированное тестовое окружение.

## Requirements

### Requirement: Скрипт скачивания тестовых данных
Система ДОЛЖНА предоставлять отдельный скрипт (вне pytest-прогона) для однократного скачивания свечей и записи их в файл фикстур. Скрипт ДОЛЖЕН принимать параметры: тикер, тип инструмента, таймфрейм, имя стратегии (ключ реестра) и кейс. Свечи ДОЛЖНЫ записываться в `tests/snapshot/data/<case>/candles.csv`. Эталон ДОЛЖЕН вычисляться методом `expected_events()` выбранной из реестра стратегии и записываться в `tests/snapshot/data/<case>/<strategy_name>_expected_signals.csv`; собственная математика эталона в скрипте НЕ ДОПУСКАЕТСЯ. Перед записью файлов скрипт ДОЛЖЕН запросить у стратегии `required_history()` и убедиться, что после прогрева индикаторов остаётся достаточно строк для окна стратегии; иначе файлы НЕ ЗАПИСЫВАЮТСЯ, работа завершается ошибкой. Дефолтная глубина запроса остаётся равной абсолютному потолку 300 свечей (см. «Жёсткий лимит глубины истории»).

#### Scenario: Скачивание фикстуры Природный газ 1h
- **WHEN** скрипт запущен для тикера NGU6 (тип future), таймфрейм 1h, стратегия `macd_rsi_stoch`, кейс `NG_1h`
- **THEN** свечи записываются в `tests/snapshot/data/NG_1h/candles.csv`, а эталон — в `tests/snapshot/data/NG_1h/macd_rsi_stoch_expected_signals.csv`, рассчитанный методом `expected_events()` этой стратегии

#### Scenario: Недостаточная история для окна стратегии
- **WHEN** после прогрева индикаторов строк меньше, чем требует `required_history()` стратегии
- **THEN** ни `candles.csv`, ни эталон не записываются; выводится ошибка с указанием требуемой и фактической глубины
### Requirement: Жёсткий лимит глубины истории
Запрос к API ДОЛЖЕН ограничивать глубину истории так, чтобы объём скачанных данных не превышал 300 свечей на один тест-кейс. Глубина запроса ДОЛЖНА по умолчанию составлять абсолютный потолок — 300 свечей — и НЕ ДОЛЖНА зависеть от `SIGNAL_WINDOW` или иных параметров `src.config`. Граница `from_` ДОЛЖНА вычисляться явно как `end − (глубина × длительность таймфрейма)`; диапазон по умолчанию `load_candles` (30 дней) НЕ ДОЛЖЕН использоваться.

#### Scenario: Дефолт равен потолку
- **WHEN** скрипт скачивания формирует запрос без явного указания глубины
- **THEN** запрашивается окно на 300 свечей таймфрейма; параметры `src.config` на объём запроса не влияют

#### Scenario: Независимость от глобальных параметров конфигурации
- **WHEN** в `src.config` изменены глобальные параметры (таймфрейм, пауза цикла и т.п.)
- **THEN** глубина запроса скрипта не меняется и остаётся равной 300 свечам

#### Scenario: Часовой таймфрейм, потолок 300
- **WHEN** расчётная глубина превышает 300 свечей
- **THEN** запрашиваются последние 300 свечей; полный доступный период истории не запрашивается

#### Scenario: Запрет дефолтного диапазона
- **WHEN** скрипт формирует запрос
- **THEN** `start_date` и `end_date` передаются в загрузчик явно; значение по умолчанию (30 дней ≈ 720 часовых свечей) не применяется
### Requirement: Защита от превышения лимита
Если API вернул свечей больше жёсткого потолка, скрипт ДОЛЖЕН завершиться ошибкой (`SystemExit`) без записи файлов: превышение означает ошибку в расчёте границ запроса. Обрезка загруженного DataFrame до лимита НЕ ДОЛЖНА применяться.

#### Scenario: Получено больше лимита
- **WHEN** API вернул больше 300 свечей
- **THEN** скрипт завершается ошибкой с указанием фактического числа свечей и лимита; `candles.csv` и эталон не записываются

#### Scenario: Меньше лимита
- **WHEN** API вернул меньше 300 свечей (торговые сессии, праздники)
- **THEN** обрабатываются все полученные строки; решение о достаточности принимает проверка `required_history()`
### Requirement: Структура хранения фикстур
Фикстуры ДОЛЖНЫ храниться по плоской структуре внутри хранилища snapshot-тестов: кейс — папка `tests/snapshot/data/<ИНСТРУМЕНТ>_<ТАЙМФРЕЙМ>/` (например `BR_1h`) с ровно одним файлом входа `candles.csv`; эталоны стратегий лежат рядом с ним под именами `<strategy_name>_expected_signals.csv`. Уровень стратегии в путях НЕ ДОПУСКАЕТСЯ. Структура ДОЛЖНА поддерживать произвольное число стратегий на общих свечах и произвольное число кейсов без правки кода тестов. Глубина истории `candles.csv` выбирается при скачивании так, чтобы удовлетворить все стратегии кейса; если новой стратегии нужно больше истории, кейс скачивается заново, а эталоны регенерируются штатным механизмом.

#### Scenario: Добавление нового кейса
- **WHEN** создана новая папка `tests/snapshot/data/BTC_15m/` с корректными файлами
- **THEN** кейс подхватывается тестами автоматически при следующем прогоне

#### Scenario: Общие свечи для нескольких стратегий
- **WHEN** вторая стратегия добавляет в существующий кейс свой файл `<другая_стратегия>_expected_signals.csv`
- **THEN** обе стратегии тестируются на одном `candles.csv` без дублирования фикстуры свечей

#### Scenario: Запрет уровня стратегии
- **WHEN** в `tests/snapshot/data/` появляется подпапка, названная именем стратегии, без файла `candles.csv`
- **THEN** такая структура считается нарушением правила наименования; тесты её не обнаруживают как кейс
### Requirement: Формат файла фикстур
Файл `candles.csv` ДОЛЖЕН содержать столбцы `datetime,open,high,low,close,volume`, идентичные выводу `load_candles`. `datetime` ДОЛЖЕН храниться в ISO-формате без часового пояса; цены — с точностью, достаточной для обратимого чтения float.

#### Scenario: Совместимость с load_candles
- **WHEN** `candles.csv` прочитан через `pd.read_csv`
- **THEN** DataFrame структурно идентичен результату `load_candles` (столбцы, порядок строк)
### Requirement: Зафиксированное тестовое окружение
Версии pandas, pandas-ta-classic, numba и pytest ДОЛЖНЫ быть жёстко зафиксированы в отдельном файле `requirements-dev.txt` по фактически установленным в проекте версиям.

#### Scenario: Воспроизводимость на другой машине
- **WHEN** тестовое окружение разворачивается из `requirements-dev.txt`
- **THEN** версии библиотек совпадают с версиями, для которых сгенерированы эталоны
### Requirement: Изоляция тестов от сети
Snapshot-тесты НЕ ДОЛЖНЫ выполнять сетевых вызовов; единственный источник данных — статические файлы. Сеть разрешена только скрипту скачивания.

#### Scenario: Запуск без токена
- **WHEN** pytest выполняется на машине без `TINKOFF_TOKEN`
- **THEN** snapshot-тесты проходят, используя только локальные файлы
