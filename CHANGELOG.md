# История изменений

Все заметные изменения робота фиксируются в этом файле.
Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версионирование — [SemVer](https://semver.org/lang/ru/).

## Unreleased

### Изменено (BREAKING)

**Что важно знать:** сделки теперь хранятся в собственном файле-базе и переживают
перезапуски, а вести открытую позицию (стоп, цели, доборы, выходы) робота учат
новые «профили управления». Придётся один раз обновить `robot.toml`; старые файлы
журнала при первом запуске сохраняются как бекап с пометкой `.legacy.<дата>`.

1. **Новый формат привязок в `robot.toml`.** Стратегия указывается не строкой,
   а связкой с уникальным `id`, профилем `management` и приоритетом `priority`:

   ```toml
   strategies = [
       { id = "ng-macd", name = "macd_rsi_stoch", management = "levels_rr", tf = "15m", priority = 10 },
   ]
   ```

   Если файла `robot.toml` нет — робот использует встроенный конфиг, и ничего
   перенастраивать не нужно.

2. **Позицией управляет профиль, а не стратегия.** Стратегия лишь подаёт сигнал
   на вход; стопы, цели и выходы ведёт выбранный профиль:
   - `levels_rr` — стоп за уровнем S/R и цели 1:1 / 1:2; нет уровня — сделка не открывается;
   - `atr_trend` — стоп по волатильности (ATR), часть прибыли фиксируется на первой цели, остаток идёт за трейлингом;
   - `ma_cloud` — знакомый вход по облаку МА 10/40 с выходом по МА, но добор/выход теперь считаются по фактически открытой позиции;
   - `pattern_targets` — вход по подтверждённому AB=CD с целями до точки D.

3. **Журнал и карточки позиций переехали в базу.** Теперь состояние хранится в
   `trades.sqlite3`, а читаемые `journal.csv` и `positions.csv` робот автоматически
   пересоздаёт после каждой операции и при старте. Открыли файл в Excel? Робот
   подождёт, пока файл освободится, и обновит его — сделки при этом не теряются.
   Руками файлы править не нужно: изменения всё равно перезапишутся.

4. **Лента событий стала понятнее.** Добавлены записи `ПЛАН`, `СТОП` и `ОТКАЗ`;
   сокращение по сигналу показывается как `ВЫХОД` с количеством и причиной,
   перенос защитного стопа — со старым и новым уровнем.

5. **Комиссии и прибыль считаются честно.** Комиссия берётся за каждую операцию
   (вход, добор, выход), а не только за закрывающие; в карточке виден отдельно
   валовой и чистый результат.

6. **Новый файл `trade_audit.log`.** Показывает, почему робот сделал тот или иной
   вывод: почему открыл сделку, почему добор не прошёл, как посчитал размер позиции.
   Можно проверить любое решение задним числом.

7. **Риск ограничивается по-новому.** Размер позиции считается от риска счёта,
   инструмента и портфеля (настраивается в `[trading] risk_limits`) и
   резервируется на время исполнения заявки. Закрытие и сокращение не
   блокируются лимитами на новые входы.

8. **Риск сделки считается по геометрии тейка.** В журнале и карточке позиции
   `risk_rub` теперь фактический риск сделки `(полный тейк − стоп)/шаг × шаг₽ ×
   qty`, а не плоский бюджет. Если риск больше бюджета — объём урезается (вход
   сохраняется); суммарный риск открытых позиций + новой не может превышать
   бюджет, иначе вход отклоняется. Для профилей без фиксированной полной цели
   (трейлинг, облако МА) риск считается по стоп-дистанции, как раньше.

## 3.0.0 — 15.09.2026

### Изменено (BREAKING)
- **Новая структура журнала сделок**: единый CSV заменён на пару файлов —
  лента `journal.csv` (append-only источник истины, по 18 колонок с типами
  операций `ЗАЯВКА/ВХОД/ДОБОР/ТЕЙК/ВЫХОД/СНИМОК/ОТМЕНА`) и производный
  `positions.csv` (карточки позиций: средняя цена, стоп, итоговый PnL,
  комиссии, статус). Старые `trade_journal.csv` не читаются — формат сломан,
  история позиции восстанавливается только из новой ленты. Карточки
  пересчитываются реплеем из ленты при старте, исполнения связываются с
  заявками по `order_id`.
- **МСК-времена в файлах**: журнал и карточки пишутся в московском времени,
  внутренние расчёты остаются в UTC.
- **Короткие имена контрактов**: пользовательский вывод (журнал, карточки,
  сообщения событий) использует читаемое имя вида `NG-10.26`/`SI-12.26`;
  внутри системы — сырой тикер.
- **Миграция легаси-журнала**: при старте в торговом режиме старый
  `trade_journal.csv` копируется в `trade_journal.csv.bak`, и формируются
  чистые `journal.csv`/`positions.csv` (путь к позициям настраивается через
  `[trading] positions_file`, по умолчанию — рядом с лентой).

## 2.1.1 — 13.09.2026

### Исправлено
- Логгер падал при обращении к реальному API: записи сторонних библиотек
  (`t_tech` и др.) не содержат `service_uid`/`correlation_id`, и форматтер
  `RotatingFileHandler` бросал `ValueError: Formatting field not found in
  record: 'service_uid'`. Теперь контекстные поля встраивает фильтр на
  хэндлере — работает для любых источников записей, включая сигналы
  выборки свечей (`GetCandles`).

## 2.1.0 — 12.09.2026

### Добавлено
- **Мульти-таймфреймный ритм**: у каждой пары «тикер × стратегия» может быть
  свой таймфрейм. Бот просыпается на ближайшей границе закрытия свечи среди
  всех активных таймфреймов и обрабатывает только те привязки, чья свеча
  закрылась. Тренд и уровни для фильтра считаются на таймфрейме задачи.
- **Каскад таймфрейма в `robot.toml`**: `tf` в инлайн-записи стратегии →
  `timeframe` таблицы тикера → глобальный `[robot].timeframe`:
  ```toml
  [strategies.share.SBER]
  timeframe = "1h"        # база тикера (можно не писать — возьмётся из [robot])
  strategies = [
      { name = "macd_rsi_stoch", filter = "raw", tf = "15m" },  # скальпер на 15m
      "flat_triangle",                                          # на 1h
  ]
  ```
- Одна и та же стратегия на разных таймфреймах работает как независимые
  задачи с отдельными инстансами (внутренняя память стратегий не смешивается).
- Fallback-пауза после сбоя больше не может проспать частые границы:
  ограничена периодом наименьшего активного таймфрейма.

## 2.0.0 — 12.09.2026

### Добавлено
- **Профили фильтрации сигналов** для каждой пары «тикер × стратегия»:
  - `basic_levels` — профиль по умолчанию: блокирует сигналы против тренда
    (поведение прежних версий);
  - `raw` — без фильтров контекста: сигнал стратегии проходит как есть;
  - новые профили добавляются регистрацией в коде без правки главного цикла.
- Уведомления теперь показывают профиль фильтрации и явно сообщают
  об отклонении сигнала фильтром:
  `● SBER (1h) 10:00 | macd_rsi_stoch [raw] ➜ 🟢 ПОКУПКА (BUY) — Цена: X`,
  `● ED-9.26 (1h) 10:00 | flat_triangle [basic_levels] ➜ ❌ Отклонено фильтром.`

### Изменено (требует миграции конфигурации)
- **Новый формат привязки стратегий в `robot.toml`**: каждый тикер — своя
  таблица с массивом `strategies`, где элемент — строка (имя стратегии,
  профиль по умолчанию) или инлайн-таблица с точечным профилем.
  Одна стратегия может встречаться на тикере несколько раз с разными
  профилями — это независимые задачи.

  Было:
  ```toml
  [strategies.share]
  SBER = ["macd_rsi_stoch", "flat_triangle"]
  ```
  Стало:
  ```toml
  [strategies.share.SBER]
  strategies = [
      { name = "macd_rsi_stoch", filter = "raw" },
      "flat_triangle"
  ]
  ```
- Прежний плоский формат и незнакомые ключи (например, `timeframe`/`tf`
  в секциях стратегий) отклоняются с понятной ошибкой при запуске.

## 1.2.0 — 12.09.2026

### Добавлено
- Новая двусторонняя трендовая стратегия **MA Cloud RSI MACD**:
  - вход — по третьему подтверждению направления из трёх индикаторов:
    пересечение облака MA (SMA 10/40), пересечение RSI уровня 50,
    пересечение MACD нулевой линии (за окно до 6 свечей);
  - **добор** позиции при ретесте облака — объём до 50% текущей
    позиции, максимум 3 контракта;
  - **ступенчатый выход** в зависимости от размера позиции:
    при 1 контракте — только по MA40, при большем — частично по MA10
    и по облаку, полностью по MA40;
  - работает с фьючерсами (NG, BR, SI, ED) и акциями (SBER), включена
    по умолчанию в `default.toml`.
- Два новых индикатора в `src/strategies/indicators/`: MA-облако (SMA 10/40)
  и MACD (пересечение сигнальной линией нуля).
- У сигналов стратегии теперь есть признаки для различения типов сделки:
  `action` (вход/добор) и `exit_reason` (причина выхода).

## 1.1.0 — 11.09.2026

### Добавлено
- Технический журнал робота: рядом с исполняемым файлом создаётся файл `bot_debug.log`, в который записываются все подробности работы:
  - **данные** — например, загруженные свечи по инструменту «NG»;
  - **ошибки** — например, сбой при обращении к API или ошибка тика;
  - **предупреждения** — например, превышение лимита запросов или задержка публикации свечи.
- Каждая запись журнала помечена временем и номером тика — например, `2026-09-11 11:21:50 [ID:tick-379072ce]`. По этой метке удобно искать конкретный момент, если что-то пошло не так.
- Журнал работает «из коробки»: настройка не требуется, при желании параметры можно изменить в разделе `[logging]` файла `robot.toml`.

### Изменено
- Консоль больше не засоряется техническими сообщениями: там остались только торговые уведомления (сигналы, сердцебиение, ошибки). Подробности — в `bot_debug.log`.
