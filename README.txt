========================================================================
ИНСТРУКЦИЯ ПО СБОРКЕ ИЗОЛИРОВАННОГО ПРИЛОЖЕНИЯ (MACOS И WINDOWS)
========================================================================

Данная инструкция описывает процесс сборки торгового робота в один
самодостаточный исполняемый файл для macOS и Windows. PyInstaller НЕ
умеет кросскомпиляцию: бинарь каждой ОС собирается на своём компьютере
(либо автоматически в GitHub Actions, см. п. 2).

------------------------------------------------------------------------
1. ПОДГОТОВКА И УСТАНОВКА СБОРЩИКА
------------------------------------------------------------------------
Перед сборкой убедитесь, что терминал находится в папке проекта
и виртуальное окружение (.venv) активно.

Установите или обновите утилиту PyInstaller (в .venv проекта):

$ .venv/bin/pip install --upgrade pyinstaller

------------------------------------------------------------------------
2. КОМАНДА СБОРКИ ПРОЕКТА
------------------------------------------------------------------------
Имена итоговых файлов фиксированы:
  * macOS:   robot-vX.Y.Z_macOs
  * Windows: robot-vX.Y.Z_win   (PyInstaller сам добавит расширение .exe)

macOS (запустите из корня проекта):

$ PYINSTALLER_NAME="robot-vX.Y.Z_macOs" .venv/bin/pyinstaller run.spec --noconfirm

Windows (на компьютере под Windows, в виртуальном окружении проекта):

> set PYINSTALLER_NAME=robot-vX.Y.Z_win
> pyinstaller run.spec --noconfirm

(в PowerShell то же самое через $env:PYINSTALLER_NAME="robot-vX.Y.Z_win")

Что происходит:
* run.spec сам: подхватывает pandas_ta_classic и t_tech (включая
  SSL-сертификаты), исключает Qt-библиотеки и вшивает default.toml
  (значения конфигурации по умолчанию).
* PYINSTALLER_NAME задаёт имя итогового файла с номером версии и
  платформой; пример: PYINSTALLER_NAME="robot-v1.3.0_macOs".
  Если переменную не задавать, файл соберётся под именем run.
* --noconfirm убирает вопросы перезаписи при повторных сборках.

Результат появится в папке dist/ в виде одного файла:
  dist/robot-vX.Y.Z_macOs     (на Mac)
  dist/robot-vX.Y.Z_win.exe   (на Windows)

Автоматическая сборка в GitHub Actions:
workflow .github/workflows/build-release.yml собирает оба бинаря
(jobs на образах macos-latest и windows-latest) при пуше тега vX.Y.Z
или вручную через вкладку Actions (Run workflow). Готовые файлы — во
вкладке Actions → build-release → артефакты прогона.

------------------------------------------------------------------------
3. ПУБЛИКАЦИЯ И ЗАПУСК В ИЗОЛЯЦИИ
------------------------------------------------------------------------
После завершения сборки:

1. Соберите оба бинаря в одной папке: robot-vX.Y.Z_macOs (из dist/
   после локальной сборки на Mac) и robot-vX.Y.Z_win.exe (из артефакта
   GitHub Actions либо со своего Windows-ПК).
2. Положите рядом файл конфигурации robot.toml (рабочий, без токенов —
   лежит рядом с собранным файлом в dist/).
3. Положите рядом файл тезисов изменений robot-vX.Y.Z.txt — секцию
   текущей версии из CHANGELOG.md (копируется при выпуске).
4. Создайте свой файл .env с токенами доступа и положите его рядом
   с исполняемым файлом той ОС, где будете запускать. .env НЕ передают
   другим людям — только свой.

Структура изолированной папки для запуска должна быть такой:
My_Bot_App/
├── robot-vX.Y.Z_macOs    (исполняемый файл macOS)
├── robot-vX.Y.Z_win.exe  (исполняемый файл Windows)
├── robot.toml           (конфигурация; без файла берутся вшитые значения)
├── robot-vX.Y.Z.txt      (тезисы изменений этой версии)
└── .env                 (файл с API-токенами)

------------------------------------------------------------------------
4. ЗАПУСК
------------------------------------------------------------------------
macOS: откройте Терминал в изолированной папке и запустите файл:

$ ./robot-vX.Y.Z_macOs

Windows: откройте Командную строку или PowerShell в изолированной папке
и запустите файл:

> robot-vX.Y.Z_win.exe

Программа работает автономно: конфигурация читается из robot.toml,
токены — из .env. Вы можете продолжать вносить любые правки в исходный
код в PyCharm/VS Code — на работу запущенного файла это не повлияет.

ВАЖНО:
- Номер версии задаётся единственным местом — src/__init__.py
  (__version__ = "X.Y.Z"), формат SemVer; при выпуске секция из
  CHANGELOG.md переносится в robot-vX.Y.Z.txt.
- Исполняемый файл собирается под архитектуру и ОС вашего текущего
  компьютера и будет работать на других машинах с такой же архитектурой
  и ОС (Apple Silicon/Intel для macOS, x64 для Windows).
